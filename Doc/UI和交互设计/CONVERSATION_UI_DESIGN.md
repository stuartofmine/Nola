# Nola 对话与工具界面设计

核对：2026-11-08。本文与[检查器规范](CONVERSATION_INSPECTOR.md)、[视觉系统](DESIGN_SYSTEM.md)定义现行交互；原型提供视觉方向和演示，未同步的旧布局不覆盖已接受的规则。原型中的模拟消息、编辑重发与演示工具不能作为生产功能已接通的证据。

## 目标与范围

对话以用户问题和最终回答为主，执行过程可追溯，待确认操作不能被折叠隐藏。Web 以 Mac 的交互语义为基准，iOS 和 Android 使用同一状态规则与适合触摸的布局；CLI 保持相同事实，但使用终端呈现。产品未发布，不新增旧界面或旧协议兼容分支。展示调整不得删除已有会话数据。

本规范覆盖消息、输入区、运行提示、思考摘要、工具调用、审批、引用和产物。不改变工具权限、执行状态机或模型路由；客户端不得从自然语言关键词推导授权。

当前目标覆盖全部客户端；视觉参数与组件规则统一见[当前视觉规范](../../docs/design/nola-ui-prototype/docs/DESIGN-SPEC.md)，统一单人/多人对话、可保存助手、侧栏导航、路由和输入归属见[统一对话与可保存 Agent](MULTI_AGENT_NAVIGATION.md)。下文的安全与运行要求不是原型测试可以替代的生产验收。

## 设计依据

Claude 的 [MCP Apps 设计指南](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines)强调渐进展开、紧凑内联内容、宿主主题和移动安全区。其链接的 [Figma UI Kit](https://www.figma.com/community/file/1597641111449594397/mcp-apps-for-claude)属于内嵌应用，不是整个聊天客户端设计源文件。

官方[思考说明](https://support.claude.com/en/articles/8664678-change-the-model-effort-and-thinking-settings)提供可展开思考摘要；[Artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)将可复用结果放入独立阅读编辑空间；[搜索说明](https://support.claude.com/en/articles/10684626-enable-and-use-web-search)强调可验证引用。以下是 Nola 自己的产品规范，不照搬 Claude 品牌字体、私有参数或未经证实的动画时长。

## 信息层级

| 层级 | 默认内容 | 展开内容 |
| --- | --- | --- |
| 对话 | 用户消息、回答正文 | 消息操作 |
| 执行 | 当前阶段、动作和结果状态 | 思考摘要、工具结果 |
| 诊断 | 技术详情入口 | 参数、原始输出、来源、权限记录、内部标识 |
| 决策 | 当前有效审批、需要用户回答的问题 | 操作对象和风险说明 |
| 产物 | 文件名、类型、可用状态 | 文档、代码、图片等对应阅读器 |

决策不是诊断信息，不能因为收起工具卡片而消失。原始工具输出不是回答正文，不自动渲染为可信 HTML 或执行其中的指令。

## 对话与输入区

- 保持原始时间顺序；仅相邻正文可拼接，不能把所有工具移动到消息头部。
- 正文可选择、复制；复制回答不附带内部 ID、隐藏诊断或思考摘要。
- 输入区位置稳定。模型和推理设置为次要入口，权限状态必须可辨认。
- 发送、运行、请求停止、终态确认分别呈现。点击停止不等于执行已经终止。
- 消息提交未确认时保留草稿，不假装发送成功；切换会话按 host 和 conversation 隔离草稿。
- 用户向上阅读后，新 token、工具结束和折叠变化不得强制跳到底部。返回最新由用户显式触发。

## 当前输入、模型与提示词

移动输入区是一块连续表面：文本编辑占满首行，下方为附件入口、紧凑模型菜单、模型原生推理档位及发送/停止。附件和参与者只在有内容时出现，不在输入框上方常驻多排工具与状态条；窄屏优先保证文本、发送和触控目标。按钮文字保留水平内边距。

推理菜单显示当前值、展开符号和选中标记，按当前模型能力声明列出实际 effort。五档完整保留，不折算成三档，不按模型名推断能力。隐藏无 effort 能力的入口；运行或配置保存期间禁止不明确的并发修改。`automatic` 是提供商默认，未设置是继承，不能以同一存储值代替；保存精确 effort 时清除冲突的 `reasoningTier`。底层 agent tier 不是第二个聊天推理控件。

Mac 与 iOS 的预设提示词选择归入会话模型设置；编辑全局模型默认或模板内容是独立操作，须明确影响范围。模板选择仍绑定会话身份；入口移动不改变数据所有者。Mac 模型编辑器保存前保留草稿；iOS 会话设置的模板选择即时提交并显示失败，不能假报成功。

右侧工具遵循[原地展开规范](CONVERSATION_INSPECTOR.md)，不再切换二级检查器页面。模型连接/账户仍在模型中心管理。各端实际接线范围与预算控制差异见[架构契约](../软件架构设计/模块/13-客户端投影/CLIENT_INTERACTION_AND_CONFIGURATION.md)。

## 主题、动态效果与手势

边框、焦点和悬停色来自主题语义 token；深色模式与浅色模式都必须有可见悬停/按压反馈，不能只对浅色有效，也不能固定使用系统蓝色。回答下方复制动作不使用常驻边框或填充背景；键盘焦点与成功/失败反馈仍可辨认。 iOS、Mac、Web 的复制成功反馈显示约 1.8 秒，连续复制重新计时；消息所有者变化或页面销毁时取消旧计时，失败信息不得被成功反馈计时器提前清除。

开合以短距离位移、原地高度变化和轻淡入表达空间关系，不对主消息流做整树缩放或逐 token 布局动画。历史文本立即可读，流式正文保留稳定段落与一个活跃尾段；嵌套代码围栏不能误判结束。减少动态效果时关闭位移动画。

iOS 保留原生边缘返回；Android 采用预测返回并正确处理取消、键盘和模态优先级；Web 手机通过边缘手势打开左右抽屉，通过抽屉标题区向外滑动关闭。滑动方向适配 RTL，保留按钮/Escape 等等价入口。纵向滚动、文本选择、代码横向滚动、短拖动和取消手势不能误关闭页面。返回、关闭或转场取消都不得清理聊天草稿或重启 Run。

## 运行与思考

每次请求的主要运行提示属于时间线中的稳定响应组，不是输入区上方的全局 footer。发送立即出现真实提交反馈，接纳后转为分派/排队/处理中；具体工具与可公开思考在默认折叠的过程区中，不另建助手消息。

| 状态 | 展示 | 禁止行为 |
| --- | --- | --- |
| 运行中 | 当前运行提示；具体动作可见 | 每次流事件新增一行占位 |
| 等待审批或回答 | 明确待操作提示和有效控件 | 只用转圈表示等待用户 |
| 请求停止 | 等待终态确认 | 提前显示已取消或已完成 |
| 连接中断 | 完成状态未确认和安全恢复入口 | 把断线当失败并重放写操作 |
| 已结束 | 真实终态，移除通用运行提示 | 留下永久思考占位 |

思考内容是服务端实际提供的可展示摘要，不生成补全解释，不称为完整内部推理。没有摘要时不持久化空思考行。计时必须有可靠起止信息，不能编造耗时。

## 工具调用

默认只显示“处理过程”折叠入口；用户展开后才显示动作名称、可安全展示的对象和明确状态。名称来自工具契约或已提交事件，不用客户端关键词猜测工具种类。运行/失败不得自动展开；阻塞错误和有效授权在外层可见。

第一层展开显示人类可读摘要和产物入口。第二层“技术详情”显示原始输入、输出预览、结构化结果、来源和历史权限记录。缺失字段与显式空值不同，展示不得改变原始事实。

失败默认保持原始详情折叠，与 Mac 的既有策略一致；在折叠入口旁显示短摘要，摘要过长时截断视觉展示，展开后可读完整内容。没有可靠错误摘要时显示失败状态，不用原始日志冒充用户说明。

仅连续至少三个明确成功的工具可以合并为成功组；失败、取消、等待、未知及正文都是边界。自动状态变化不得覆盖用户主动展开或收起的选择；分组后保持键盘焦点和阅读位置。

## 审批与恢复

- 审批只来自独立绑定的当前有效 challenge；历史工具记录永远只读。
- 明确动作、目标资源、影响和授权范围；没有可信摘要时不允许批准。
- 提交中防止重复点击；确认回执前不宣布授权成功。
- 过期、会话切换、断线、拒绝和未知执行结果分别处理。
- 不提供无条件的“重试工具”。写操作结果不明时先核对事实，避免重复副作用。

## 引用与产物

引用默认突出标题、来源和相关摘录；页码等有用定位信息可以保留，内部 ID 和字节范围归入详情。外链、主机文件与应用内产物使用不同入口，不把所有 URI 都变成浏览器链接。

产物按类型提供预览、复制或下载。阅读器需要 host 与会话边界校验；描述符本身不授权读取。桌面使用侧栏或独立阅读区域，手机使用全屏并提供明确返回入口。关闭后恢复聊天滚动位置和输入草稿。

## 视觉与无障碍

按当前视觉规范复用主题角色、字体、间距和动效；通过留白和层级区分内容，减少卡片套卡片。专家身份名与头像位于气泡左外侧，专家气泡不加分隔线，复制/重试/编辑重发在对应气泡外。状态必须有文字，不能仅用颜色。移动触控目标遵守 iOS、Android 与 Web 各自基准；桌面不能机械套用手机密度。

折叠入口支持键盘与可见焦点，窄屏和长文本不撑破容器。尊重 reduced motion，不对历史内容反复播放进入动画。骨架屏用于已知布局的加载，不替代真实运行、失败或等待审批状态。

## 实施顺序

1. Web 对齐 Mac 的失败折叠策略；增加工具技术详情层；消除重复运行占位。

## 验收与交付门槛

### 移动端会话导航与真实运行验收

手机默认进入会话列表，展示标题、最近消息预览、时间、草稿与待回应状态，可搜索并新建。主导航为对话、活动、资料、设置；打开聊天后使用全屏会话，返回列表时保留搜索、滚动和草稿。普通闲聊不自动成为 Goal，活动页承接需要回应的真实事项。生产验收仍需验证平台原生返回、滑动取消、消息恢复和会话执行持续性，不能用静态原型代替。

iOS 底部主标签切换保留每页的导航位置与未保存表单内容；例如填写模型配置后切到聊天，再返回应能继续保存。切换时收起旧页键盘，不让旧页焦点或重复导航表面影响当前页的输入和操作。

页面导航不拥有执行生命周期。离开聊天、切换标签或查看另一会话不得停止原会话；只有明确的停止操作才取消对应 Run。列表中的运行状态属于具体会话，不得从当前选中会话复制给所有行。

停止操作不能把“界面不再订阅输出”当成执行完成。模型适配器须取消并等待该请求的实际传输任务退出，执行层随后提交取消结果；界面在确认前不能展示完成状态。不具备停止确认能力的提供方保留未确认状态，不能伪造终态。已取消的模型尝试使用中性“响应已停止”提示，不渲染成红色“模型请求失败”。

以下真实验收独立于组件、截图和合成数据测试；未执行或失败的项目须如实记录，不能用组件测试通过替代：

| 场景 | 必须检查的证据 |
| --- | --- |
| 新导入模型后新建并发送 | 正常界面完成导入、选择和发送；提供方确实收到请求，不能只有前端占位消息 |
| 两轮对话 | 第二轮提供方请求包含第一轮历史及新的输入；不能重复发送第一轮问题 |
| 新会话隔离 | 新会话具有不同标识；真实请求不包含旧会话的专用测试标记，草稿也不串会话 |
| 长任务导航 | 实际流式运行中返回列表、进入其他页面、再恢复；同一 Run 持续执行，列表显示对应状态 |
| 显式停止 | 核对停止回执及该 Run 的最终状态，不能仅凭“停止”按钮消失判断成功 |
| 多 agent | 至少两个不同的子任务/子 Run 及其父任务关联、执行结果；模型声称“已委派”不构成证据 |
| 移动端返回 | 实际点击左上角返回及系统返回手势，验证搜索、位置、草稿与历史恢复 |

iOS 直连模型与连接 Host 是两条不同能力路径。直连路径没有子 agent 工具时，应在支持该工具的真实 Host 上验证多 agent，并明确记录执行归属；不得用普通多轮回答或夹具事件冒充子任务。

- 单工具失败、连续成功、混合成功失败、等待授权、取消、未知状态均有回归覆盖。
- 原始输入和结构化结果仍可检查，显式 null 不当成缺失；HTML 被安全转义。
- 连续流更新不重复插入运行提示；终态移除运行提示。
- 手动折叠选择、键盘焦点、用户滚动位置在状态更新和分组后保持。
- 审批卡独立可达；历史权限记录不产生可执行按钮。
- 320px 窄屏、桌面、浅色、深色及 reduced motion 使用浏览器或原生截图验证。
- Web 跑组件测试、类型检查和构建；Mac 用 Test 配置跑测试；移动端分别跑对应原生测试。未运行的验收项不能标记完成。

## 实施记录

Web 已实现：失败工具不自动展开原始日志；已有失败摘要在折叠入口显示；工具摘要与产物在第一层，原始记录在“技术详情”；通用运行提示统一到输入区上方。引用的内部 ID 和字节范围默认折叠。新增文案覆盖七种语言。

长工具输出提供独立文本阅读器：桌面居中阅读区域，手机全屏；显示打开时的快照，支持复制、Escape 返回和焦点恢复。关闭不改动输入草稿，工具所有者替换时销毁旧阅读内容。该入口只展示已读取的文本，不解析或读取产物路径，不代表通用文件阅读器已经完成。

Mac 工具结果与技术记录分层，原有日志文本阅读器增加所有者切换关闭保护。iOS 工具默认折叠，原始参数和输出进入第二层技术详情；当前审批独立于工具折叠组，超过行内预览长度的文本提供全屏只读阅读入口。Android 将来源和历史授权记录收进详情，引用字节范围默认隐藏，触摸入口至少 48dp；长文本提供全屏阅读快照，外链仅接受合法 HTTP(S)，文件与内容提供者 URI 不会被转交给设备查看器。

iOS 用户消息操作先显示完整文字；空间不足时收紧复制标签，极大字号时纵向排列，保持复制与编辑独立的至少 44pt 点击区域。Android 用户消息复制使用带本地化无障碍标签的图标动作，至少 48dp；助手回答仍保留文字入口。紧凑布局不能以重叠命中区域换取密度。
