# 统一对话与可保存 Agent

状态：领域对象与执行归属契约。本文规定对话身份、成员、提交及恢复语义，不是当前 UI 视觉规范。当前会话列表优先、桌面顶栏/侧栏/检查器与消息身份呈现以[现行对话规范](CONVERSATION_UI_DESIGN.md)和[检查器规范](CONVERSATION_INSPECTOR.md)为准；[视觉规范](../../docs/design/nola-ui-prototype/docs/DESIGN-SPEC.md)为尺寸与样式基线。原型是演示，不能证明底层统一模型或生产导航已经实现。生产代码状态须按[能力覆盖矩阵](../../docs/design/nola-ui-prototype/FEATURE-COVERAGE.csv)和当前源码核验。本文取代 Room 与普通 Conversation 并列的旧产品方向；历史 Apple 实施证据见 [Apple 实施记录](APPLE_ROOM_MAINLINE_20261019.md)，只证明所记录实现。

设计主张：**用户从唯一的“新对话”入口开始，再在对话内选择或添加助手。** 对话始终是一条历史、一个输入区、一份草稿。助手是可保存和反复使用的配置，不是一段不断累积所有聊天内容的永久会话。

## 1. 产品对象与关系

| 对象 | 用户理解 | 所有内容与边界 |
| --- | --- | --- |
| 助手（Agent） | 可以反复找来工作的助手 | 名称、头像、职责、工作指令、默认模型和能力配置；有独立 ID 与配置版本 |
| 对话（Conversation） | 围绕一个主题持续交流 | 标题、参与者、用户消息与公开回复、附件、草稿、任务和审批；唯一用户可导航的交流对象 |
| 参与者（Participant） | 本段对话中的某位助手 | 引用 Agent，并保存本段采用的配置快照、模型覆盖和独立执行上下文 |
| 执行上下文（Context） | 内部实现，无独立侧栏入口 | 模型历史、工具证据、运行、压缩与恢复；归属精确的对话和参与者 |

本文所有 ID 均带所属 authority/store 的数据空间；跨 Host 不凭裸 ID 合并。助手目录与固定偏好按所属数据空间持久化，不因侧栏显示而宣称已经跨设备同步。

一段对话有一位或多位助手；同一助手可以参与多段对话。对话不属于某一个助手目录：在多个助手筛选中出现时仍是同一个 conversation ID，消息和草稿不复制。

- 删除 Room 作为独立产品对象、一级入口、创建流程和发送协议。单人/多人是参与者状态，不是必须选择的会话类型。
- 单助手对话加入第二位助手，原地成为协作对话；URL/身份、历史、草稿、当前运行及审批不变，不执行“转换房间”。移出成员同样不转换类型。
- 同一对话中一个 Agent 只加入一次。需要两个不同角色时，先复制 Agent 并赋予不同职责，避免同名实例难以辨认。
- 独立 Context 仍然必要：统一产品对象不意味着混合多个模型的私有历史、运行状态或授权。
- 模型是助手的执行配置。改变模型不创建新的助手或对话；切换助手也不等于切换模型。

## 2. 左侧边栏：助手与对话在同一处

下列信息架构要求不规定当前栏宽、排列或桌面分栏；这些可见布局以现行对话与检查器规范为准。桌面侧栏类别/搜索只改变左侧列表，不替换当前主内容；右侧工作工具只定位或展开检查器区段；只有明确选择其他会话才切换会话上下文。手机默认会话列表，活动、资料和设置分别承接其职责；不能把桌面三栏机械缩小，也不能把演示数据误称为真实自动整理结果。

桌面在唯一 48px 全局顶栏下组织左侧导航/会话列表、中央内容标签和可选的右侧检查器；不增加独立 Room 窗口、助手会话树或第二套聊天列表。下面的示意图仅表示助手/对话/工作区的归属清单，不规定当前栏、标签或检查器的视觉排布。

```text
Nola                         [收起]
[＋ 新对话]                  [搜索]

助手                          [＋]
  Nola
  研究助手
  代码助手
  写作助手
  全部助手…

对话                 [全部 / 研究助手 ×]
  发布方案                     待确认
  数据库性能分析                 处理中
  周末安排
  更多历史…

工作区
  资料 · 自动化 · 模型 · 技能与 MCP
设置
```

- 助手区域展示固定的常用助手；新建成功默认固定，可排序、取消固定。默认展示至多五项，完整目录通过“全部助手”访问，不让助手数量挤没历史。
- 对话只有一份列表，可按时间分组、置顶、搜索和归档。单人/多人都在这里；多人条目可显示紧凑头像组，不能出现两条同名入口或泄露内部 Context。
- “助手”代表可复用配置；“对话”代表历史主题。单击助手打开配置详情，单击对话打开聊天；当前页面只对应一个选中项。按助手筛选历史是对话列表内的独立筛选操作，不与助手详情导航混用。
- 搜索区分助手名称/职责与对话标题/消息结果，显示清楚的结果类别；返回某段对话只打开该唯一对象。
- 状态归具体对话，优先显示待确认，其次失败/处理中；不能仅用颜色。打开助手目录不标记相关对话已读。
- 资料、自动化、模型、技能与 MCP 保留可达入口，但排在日常对话之后；不把所有管理表单塞进边栏。

### 唯一新会话入口与助手导航

1. 只有侧栏顶部“新对话”启动新会话流程。菜单与键盘快捷键调用同一个创建动作；助手条目、详情、搜索结果、保存成功页均不提供“开聊”“用此助手新建”或试聊入口。
2. 点击“新对话”进入统一未发送草稿，默认使用 Nola；在该草稿的参与者入口选择或添加已保存助手。不继承刚浏览的助手、历史筛选或其他对话的成员配置。
3. 首次发送才原子创建正式对话并提交消息，捕获参与者配置版本。重复点击“新对话”恢复本窗口的未发送新会话草稿；失败保留草稿与同一个提交身份，不生成空会话。
4. 单击侧栏助手打开该助手的配置详情，可查看、编辑、复制、固定或归档。页面没有聊天输入框，不创建聊天草稿，不改变当前对话成员，也不自动筛选或打开历史。
5. 打开助手详情前保存原对话草稿和阅读位置；返回原对话时恢复。助手配置编辑草稿与新会话草稿、已有对话草稿分别拥有身份。
6. 点击具体历史主题才恢复该对话。对话列表可以独立按助手筛选，筛选本身不创建会话；从其他入口打开不符合筛选的对话时清除筛选并显露选中项。

固定、排序与筛选是导航偏好，不改变助手权限、参与关系或执行状态。“助手 ＋”仅创建助手配置，“新对话”仅创建对话，两者不能互相附带执行。所有操作可通过键盘和读屏访问，不能只有悬停入口。

## 3. 创建、保存与管理助手

“助手 ＋”打开短表单，默认只展示三项：

| 字段 | 用途 | 规则 |
| --- | --- | --- |
| 名称 | 在侧栏、成员列表和消息中辨认 | 必填；默认首字头像，可选图标；重名不作为身份 |
| 职责简介 | 帮用户选择，也给协调者判断适用任务 | 简短公开描述，不自动充当完整系统指令 |
| 工作指令 | 这个助手如何完成工作 | 自由编辑，可为空；明确与职责简介分开保存 |

“更多设置”按需展开：默认模型、该模型支持的推理强度和生成参数、语言/回复风格、可用 Skill/MCP/资料来源及记忆设置。复用模型和能力目录，保存稳定引用，不复制 API Key、登录凭据、工具实现或历史会话。

- 主要操作“保存助手”；只有实际保存回执成功后才加入侧栏。保存后留在该助手详情并显示已保存；不跳到聊天、不创建会话或聊天草稿、不调用模型、不启动后台任务。
- 模型默认选用应用当前默认值，编辑器显示“跟随默认”或具体模型。创建对话时解析并冻结实际选择；以后应用默认模型变化不悄悄改变旧对话。
- 用户可以从现有对话的成员设置执行“另存为助手”。只复制可复用配置，预览将保存的字段；不复制消息、附件、执行中的任务、权限批准或临时工作目录。
- 复制助手产生新 ID；编辑助手保持 ID 并提交新 revision。草稿、保存中、保存成功、保存失败明确区分；冲突保留草稿，不用最新 revision 强行覆盖。
- 能力配置只是这个助手可选用的范围，不是授权。隐藏工具不能借提示词重新获得；显示工具也不表示用户已允许具体操作。敏感读取沿用 `sensitive_read_reason` 与 Core 审批契约。
- 某个模型/能力在当前 Host 不可用：允许保存配置并显示明确的缺项；发送时在受影响成员上提示选择替代或修复，不静默改用另一模型、另一 Host 或另一助手。
- 默认 Nola 是可识别的默认助手，首次建立身份由明确的新建/初始化事务完成，不在读取列表时偷偷写数据。不要求用户先配置自定义助手才能聊天。

### 配置生效、记忆与归档

- Agent 保存的是默认配置；参与者捕获加入当时的配置快照。编辑 Agent 默认只影响以后创建的对话/新加入的参与者，不热改正在执行的 Run。
- 已有对话在成员详情可见“助手配置有更新”，可显式应用到该成员的后续消息；活动任务继续使用原快照。参与者已有覆盖不被无提示清空，变更前展示会受影响的设置。
- 消息作者身份记录发送当时的名称和 participant ID，改名不会让旧内容冒充另一位作者；详情可定位当前 Agent。
- 保存 Agent 不自动建立跨会话记忆。各段对话历史独立；只有用户明确启用、当前可用且获准的记忆/资料来源可跨对话使用，不把所有曾经聊天内容自动喂给同一 Agent。
- 默认提供“归档助手”和“取消固定”。归档从新建候选移除，不删除历史、不停止活动任务；已有对话仍可依照已保存快照继续，前提是模型和能力仍可用。恢复后重新出现在目录。
- “从对话移出”只改变本段参与关系；“归档助手”改变目录可见性；“归档对话”隐藏主题。三个动作文案和后果必须分清。

## 4. 对话内部：从一位助手自然扩展到协作

```text
[侧栏]  数据库性能分析         [研究助手 · 代码助手 ＋] [进度] [资料] [设置]

        用户：这两种实现怎么选？
        研究助手：……
        代码助手：……
                    处理过程 ▸

        [发送消息，@ 指定助手                         发送]
```

- 标题描述主题，旁边的成员入口说明“谁在这里”。一位助手时显示名称；多位时显示紧凑头像组与数量，点击才展开成员详情。
- 单人直接由该助手回答，不经过路由模型。增加成员通过标题栏“＋”选择已保存助手；临时需要新角色时可“创建助手并加入”，不另建匿名永久配置。
- 只有一位助手时，输入区的模型快捷菜单调整该参与者；多位时模型选择归成员详情，并显示“仅本对话”。没有一个实际不存在的“群聊统一模型”。
- 增删参与者后保留同一输入区和草稿；mention 失效就地提示，不能清空用户内容或静默改派。
- 新成员取得加入时明确可见的有界公共摘要，以及之后交付给它的消息、显式引用/附件。添加面板说明此范围。它不自动读取其他成员私有工具记录，也不获得 Agent 在别处的历史。
- 移出成员仅影响之后的新提交。已经接纳/排队的任务保留原 owner，可继续、确认或单独停止；其结果仍显示作者与“已移出”身份。不得因侧栏隐藏而丢失审批入口。
- 不能移出最后一位可回复成员；可选择替换助手，保留历史和旧参与者记录。替换从后续消息生效，不接管旧任务。

### 自动分派和 @

- 无 @ 时默认由协调者选择一位合适成员，不默认全部回答。协调者是对话内职责，由首位成员默认承担；不另造一位必须管理的“主控 Agent”，不每轮多插入一条安排消息。
- 协调者使用职责简介、可用状态、当前消息、引用和有界公共上下文做语义决策；不得按自然语言关键词、工具名称或语言列表路由。原协调者移出时，用户在成员操作中明确选择接替者。
- 点名直接交付对应成员，跳过自动路由。多 @ 只产生一条用户消息、多个目标 delivery；不隐式广播给其他人，也不自动创建助手。
- @ 候选只含本对话可接收新消息的成员；用户选中后绑定 participant ID。粘贴的 @名称、邮箱、代码均是普通文本；重名附加职责/头像区分。
- 增删 @ 不切换草稿，发送后不把目标黏到下一条。引用只提供上下文，不暗中改变目标；自然跟进由协调者结合公开上下文选择。
- 候选上下键选择，Enter 确认候选不同时发送，Esc 关闭，退格按 token 删除；中文输入法 composition 不发送。附件菜单提供可访问的“提及助手”入口。
- 找不到合适成员或分派失败，在原响应区域澄清/提示重试或 @ 指定；不能随机选人、无限重试或改成广播。已经接纳的调用不重新问模型并重复派发。

## 5. 反馈、草稿和任务归属

点击发送即显示“正在发送”；持久接收后才显示“正在安排助手/助手处理中”。每条用户提交形成稳定响应组，多个成员回复保持明确署名，工具过程默认折叠；审批、必要追问和失败必须在会话里直接可见。

- 保存一份 conversation 草稿，含正文、附件、mention、引用和编辑版本；未发送的新对话草稿使用稳定 draft ID，首次提交后绑定 conversation ID。它与助手编辑草稿不同。
- 冻结提交捕获成员/配置 revision、草稿版本和幂等 ID。迟到 ACK 只清除原版本，不覆盖用户已经继续输入的内容；失败保留可恢复提交。
- 打开助手详情、切换历史筛选、对话或窗口不取消运行。不同对话独立，同一对话中的不同参与者可并发；同一 Context 的队列顺序由执行层决定。
- 停止、重试和审批针对精确任务/目标。停止一位成员不停止整个对话；部分失败只重试失败目标，不能重放已成功任务。
- 连接中断显示“结果待确认”，先核对原身份，不直接重发。重启恢复正式接收/交付/Run，不靠 UI 缓存或模型记忆重建执行。
- 手动上滑不强制回底；新状态、晚到正文、参与者变化不重建整页。完成后停止动画；思考/过程披露仍按当前会话展示契约，不因统一导航增加额外日志面板。
- 本地提交反馈 p95 ≤100ms 是待测目标；不得未经测量标成已实现。无真实活动证据时不能用“仍在处理”无限转圈。

## 6. 布局与跨平台适配

沿用 [DESIGN_SYSTEM](DESIGN_SYSTEM.md) 的语义色、字体、间距、浅深色和高对比配对，不再新增一套 Agent 品牌色。身份靠名称/头像，状态靠文字/图标；侧栏不堆叠彩色卡片，聊天正文维持安静阅读面。

- macOS：`NavigationSplitView` 风格侧栏，沿用约 244pt 理想宽度；内容随窗口伸缩。助手编辑使用独立 sheet/详情表单，成员详情按需打开；标准新建、搜索和显示侧栏操作可由菜单/键盘访问。
- Web：同一导航语义，侧栏可折叠；窄宽度变为抽屉或列表页，不在正文上方长期堆一整屏导航。使用可访问的列表、菜单和明确焦点。
- iPhone/Android：顶层“对话”展示唯一新对话动作与统一历史；常用助手入口只进入配置详情，助手列表是同一导航的展开页/抽屉，不把 Room 做成独立 tab。聊天页回到原筛选与滚动位置；成员、编辑表单使用平台 sheet/页面。平板可展开为侧栏。
- CLI：仍是一种 conversation/session；新会话只有一个创建动作；助手管理只保存配置，不能隐式开聊。交互选择器可按助手筛选历史、创建/编辑已保存助手，并在对话内加入成员。具体命令须在实现时确定并更新帮助，不在设计文档中宣称尚不存在的命令可用。
- 控件命中区遵守平台基线（iOS 44pt、Android 48dp、macOS 28pt）；文字缩放后允许名称/状态换行。长名字、空列表、目录失败均有专门状态。读屏播报作者、选中范围和待确认，不逐 token 打断。
- Reduced Motion 不做列表位移动画；保留焦点、选中与状态文字。最大辅助字号、窄窗口、深浅色与键盘/读屏必须实际验证。

本次移除的界面元素是独立 Room 入口、收件人常驻栏和重复会话树。个性由“可随时找来的助手”与清楚的参与者身份体现，不依靠装饰或增加导航层级。

## 7. 领域与持久化收敛

以下是实施约束，不能只合并侧栏就宣布完成：

| 层 | 统一后的职责 |
| --- | --- |
| AgentDirectory | 已保存助手及配置版本、归档状态；明确分离公开职责与工作指令；导航固定顺序归用户偏好 |
| Conversation | 唯一公开聚合，拥有成员、公共消息流、提交/响应组、协调设置和会话级政策；关联设备草稿，不代替 DraftRepository 的写权 |
| Participant | Agent 来源与 revision、独立配置快照、active 状态、Context 绑定；不再拥有独立用户会话入口 |
| Context / Run | 私有执行历史、工具证据、压缩与恢复；绑定 conversation + participant + context + run，不能依据当前屏幕选中项执行 |
| Submission / Delivery | 单条用户消息、冻结目标/路由结果、逐成员接纳与结果；持久幂等，接收和原消息提交有事务关系 |
| ConversationDirectory / Presenter | 同一分页/搜索目录与同一聊天呈现；助手只是筛选条件，不能用前端拼接两套列表假装统一 |

当前 `PersistentAgent`、配置 revision/CAS、`capture_defaults` 和 Room 的持久交付提供可复用基础。但现有 `AgentDefaults` 仅允许部分默认字段，不能假定已经支持独立工作指令、头像或能力范围；这些需扩展正式领域契约并接入所有客户端。

当前单一 `ConversationOwner(agent_id, conversation_id)` 不能继续作为多参与者对话的唯一执行归属；须收敛为精确参与者/Context owner。现有 `context_conversation_id` 的内部历史用途也不能继续充当另一个公开 conversation。消息正文保留唯一规范来源，公共消息引用精确来源和作者，避免在“房间消息”和“普通消息”中双写。

公开时间线按已提交顺序及响应组关系呈现，不只按各 Host 墙上时间排序；每个成员内部保持 canonical Part 顺序。搜索、归档、附件、权限、恢复、缓存计量和会话深链都使用同一 conversation 身份，不能漏改隐藏入口。

实施时删除独立 Room 聚合/创建/发送/导航接口和旧字段别名，不保留旧路由重定向或双读/双写。旧实现证据可留在实施记录，但不构成兼容要求。若当前存储格式无法直接满足新模型，明确拒绝不匹配格式；不自动转换、删除或重建用户数据。使用隔离新格式库开发验收，不把发布切换或数据处置悄悄附带在 UI 改造中。

### 7.1 数据所有权：来源、作用域与生命周期

下表定义目标契约。拥有引用不等于拥有原数据；物理文件放在共享对象库不改变逻辑归属。所有引用必须带 authority/store，Host 只表明执行地点，不能取代数据所有者。

| 数据 | 逻辑所有者 / 唯一写入者 | 可见与复用范围 | 生命周期 |
| --- | --- | --- | --- |
| 助手名称、头像、职责、工作指令、默认模型/能力引用 | Agent 配置；Application 的 Agent 配置命令 | 可被多段对话引用；不附带聊天内容、任务或授权 | Agent revision；归档保留历史来源 |
| 对话标题、成员关系、协调设置、公共消息流 | Conversation；对应领域命令经 Application 提交 | 本对话公共内容；助手筛选仅查询相同对象 | conversation ID 稳定；归档不删除 |
| 参与者实际工作指令、模型/参数、能力和资料选择 | Conversation 内的 ParticipantConfiguration；成员配置命令 | 只作用于这一段对话中的这一位助手 | 加入时快照＋成员配置 revision；显式更新影响后续提交 |
| 用户消息及公开回复 | Conversation 中的 canonical Message/Part；Core transition → Application | 时间线只有一份正文；作者、响应组和来源执行可追溯 | 追加/版本化修订；不被模型摘要覆盖 |
| 用户提交附件 | 暂存时归 Draft；接收后归 Conversation 的 Message/Attachment 关系 | 只向明确交付的成员暴露选定引用；不因加入而加载所有附件 | 接收时固化引用与内容版本；未接收附件不进入历史 |
| 模型上下文、摘要及压缩 lineage | 本对话的 Participant Context；Context 决策 → Application | 同一参与者在本对话内延续；不跨对话共享 | context ID、generation、原文来源和压缩记录可核验 |
| 协调上下文 | Conversation 的独立协调 Context | 只含职责、可用状态和有界公共上下文；不得读取成员私有执行历史 | 与成员 Context 分开；路由结果归 submission/delivery |
| Run、Attempt、工具调用/原始结果、检查点 | 具体 Participant Context 下的 Run；Core/Application/Supervisor 各守其写权 | 可被用户在本对话中查看；其他成员不能凭同 Agent 或文件路径读取 | 原调用身份、版本和终态封存；切页不变 |
| 任务产物 | Run 的 Artifact 记录，公共发布关系归 Conversation | 返回文件引用；其他成员只有获得明确可用引用才可读取 | 保留生产调用、文件版本和引用；不能随 Agent 删除 |
| 审批请求、授权与决策 | Core 权限对象；Application 事务提交 | 绑定主体、Host、操作、资源、调用及有效期限 | 单次精确消费；会话授权仅在明确匹配范围内复用 |
| 长期记忆、资料库/外部数据源 | 各自独立存储与来源 owner | 按配置、授权和检索来源引用；不属于 Agent 的私有聊天缓存 | 按各自保留/撤销规则，不随某段对话压缩而改写 |
| API Key、登录状态和 OS 授权 | 账户安全存储 / 平台 Host | 配置只存引用；使用前验证当前有效性 | 撤销立即影响后续准入，不复制到快照 |
| 新会话/已有对话草稿 | 设备本地 DraftRepository，按 window/editor owner 条件写 | 新会话为 device/store/draft；已有对话再绑定 ConversationRef | 唯一新建动作恢复本窗口草稿；无 Agent 专属聊天草稿 |
| Agent 编辑草稿、筛选、固定、滚动/展开 | 配置编辑器 / 用户导航偏好 / 窗口展示状态 | 不进入模型上下文，不授予读写权限 | 各有 owner；导航不能写执行状态 |

共享资料中的原文仍归资料库，附件 blob 可以去重，但每个 Conversation 的引用与披露范围独立。模型可引用的正文、用户在 UI 中可见的诊断、Provider 收到的数据是不同投影，不能相互代替。工具输出若明确发布给其他成员，发布的是带来源和范围的引用，不把整个私有工具历史变成公共历史。

### 7.2 上下文的组成和读取规则

**对话拥有公共交流记录，参与者拥有各自的模型上下文；Agent 配置本身没有一份跨会话滚动增长的上下文。** 单人对话也走同一 Participant/Context 结构，不另开一种存储路径。

每次模型调用显式组成并冻结输入清单：

1. 当前系统政策与已准入工具契约；不是助手自行保存的授权。
2. 该参与者采用的 Agent 配置快照和本对话覆盖，含精确指令内容或可恢复的不可变版本引用。
3. 本次交付的用户消息、选定引用和附件；记录 submission/delivery 身份。
4. 本 Context 已有的有效历史与摘要，保留原文、摘要 generation 和覆盖范围。
5. 截止明确 transcript cursor 的有界公共对话材料。只有实际提交的用户消息/公开回复可选入；其他成员的私有思考、工具原始输出及未公开内容不进入公共摘要。
6. 本次确实检索且获准使用的长期记忆/资料片段，带来源、版本及访问范围。

同设备同一已有对话使用一份逻辑草稿，多窗口以 draft revision/编辑身份核对写入，冲突保留编辑，不用最后一次整包覆盖；尚未发送的新会话草稿按窗口保持独立。

输入清单是派生快照，不成为另一套可独立编辑的消息历史。没有检索到、未授权或超出预算的内容不声称已经看过；共享公共记录不意味着每个模型每轮都收到完整记录。

- A/B 两段对话都使用“研究助手”时，得到两个独立 Participant Context；相同 Agent ID 仅证明配置来源相同，不可据此读另一段对话。
- 新增成员创建本对话的新 Participant/Context，从明确的公共摘要与交付起步，不复制它在其他对话中的 Context。
- 协调者即便使用某一成员的模型配置，也通过独立协调 Context 判断路由；协调职责不额外授予该成员读取所有人的内部历史。
- 切换同一参与者的模型保留 Context 的规范历史，重新按新模型契约准备请求；Provider 无法表达的内容或能力明确提示，不静默拼接不兼容的内部状态。
- “应用助手配置更新”只更新后续调用的配置版本，不清空历史、不重新归属已有 Run。工作指令的改变有版本记录，不能把可变模板 ID 当成冻结内容。
- 压缩只作用于明确 Context；摘要引用来源与范围，不修改公共时间线，不把压缩摘要当长期记忆，也不重建失效授权。
- 加入、移出、替换成员不会重命名或搬移已有 Context。移出后原任务仍归原 participant/context/run；若以后重新加入，必须显式选择恢复该参与关系或建立新的上下文，不能按 Agent ID 偷偷接回旧状态。
- 能力选择与权限分别约束上下文/执行。会话级权限批准只在 Core 已记录的主体、Host、能力和资源范围内匹配；不能因同处一个对话就把一次批准转给另一位成员。

### 7.3 引用、提交与恢复不变量

- 执行身份至少包含 ConversationRef、participant ID、context ID、Run ID；路由辅助调用有独立 coordination context/operation 身份。UI 当前选择、Agent ID 或某个裸 conversation ID 都不足以定位执行者。
- 首次发送由 Application 在同一正式事务中创建 Conversation、参与者快照和用户 submission；客户端收到回执后再绑定本地 draft ID。若 ACK 丢失，用原幂等提交身份核对，不能假设本地草稿与远端 Store 是一个原子事务。
- 多 @ 仍只保存一份用户消息，分别建立 delivery 引用。公开回复有唯一 canonical 来源，时间线/搜索是投影；禁止房间表与会话表两套正文双写。
- 读取资料或工具输出时同时验证源 authority/store、owner、版本和披露范围。知道路径或引用 ID 不等于得到访问权；普通跨目录文件访问规则不能替代内部工具证据的会话隔离。
- 修改、归档或复制 Agent 不级联改写对话、上下文、消息、产物或权限。归档对话只改变目录可见性，活动 Run、审批和恢复记录继续可定位；删除数据须是明确的独立操作，不能通过引用计数错误误删其他会话仍引用的 blob。
- 切换执行 Host 不改变 ConversationRef，不携带旧 Host 的 OS 授权或凭据。恢复仍核对原执行身份与来源回执；结果不明不自动换 Host 重跑。
- 统计从物理 Attempt/Run 按唯一身份记账，再汇总到对话；Agent 视图只能按来源聚合，不拥有另一份可写费用或 token 计数。

## 8. 实施次序与验收

1. 先完成统一 Conversation、Participant/Context owner、Agent 配置及事务契约；证明单人和多人可用同一提交/恢复链。
2. 接通统一目录与侧栏、助手保存/编辑/归档、单人新建、历史恢复与草稿。先保证最常用的一对一入口没有额外步骤。
3. 接通原地加入/移出成员、@、协调、配置快照更新和逐目标状态；更新 Mac/iOS/Android/Web/CLI 的当前调用者，删除独立 Room 路径。
4. 最后进行真实模型、恢复与跨端视觉/键盘验收；文档、静态原型和组件测试不能代替运行证据。

必须覆盖：

- 唯一“新对话”入口 → 选择一位助手 → 加入第二位 → 多目标回复 → 移出成员，始终同一个 ID、历史和草稿，无第二个列表项。
- 单击助手、搜索助手、保存/复制助手均只打开或更新配置，不出现输入框、不创建聊天草稿、不发模型请求、不修改当前成员。唯一新对话动作及其快捷键进入同一流程；首次发送失败/重试/重启只创建一次。
- Agent 保存后重启可见；复制、重名、改名、归档/恢复、排序/取消固定、大目录与保存冲突；配置失败不显示已保存。
- 修改 Agent 不改变既有对话/活动 Run；显式应用只影响指定参与者后续消息；模型失效不静默回退。
- 同 Agent 在 A/B 对话无历史、草稿、权限、工具输出泄漏；新成员只收到规定公共上下文，不继承其他成员私有上下文。断言实际模型请求的输入清单，不只检查 UI。
- 公共摘要的 transcript cursor/来源范围、压缩前后原文引用、协调 Context 隔离、可变提示模板更新、附件/产物跨成员显式披露，以及归档后引用保留。
- 多 @ 用户消息只存一次；丢失首次 ACK 后幂等恢复；跨 Host 相同裸 ID 不合并；共享 blob 的删除不破坏其他对话引用。
- 活动/排队/待审批成员被移出后原任务仍可定位、停止或确认；归档 Agent/对话不丢活动 owner，也不复活已拒绝调用。
- 单成员零路由 LLM、多成员语义路由、中文/英文自然跟进、“search/current”等歧义、未知工具恢复和显式多 @；不加关键词名单。
- 晚到 ACK、不同时区/Host 时钟、部分失败、取消、断连和冷恢复，无重复用户消息、重复副作用或错误时间线排序。
- 所有客户端复用同一对话契约；移动端返回、桌面侧栏隐藏、多窗口、最大字号、长名称、浅深色、焦点和 IME。

## 9. 设计依据与范围

本次使用 apple-design 的 accessibility、layout、typography、color、designing-for-macos、sidebars、split-views、toolbars、generative-ai 与跨平台参考。关键依据：`layout.md › Visual hierarchy` 的 “Use progressive disclosure”；`sidebars.md › Best practices` 的 “let people customize the contents of a sidebar”；`generative-ai.md › Best practices` 的 “Keep people in control”。Android/Web 采用信息层级和可访问性原则，不套用 Apple 平台控件规则。

统一对话对象、唯一新会话入口、助手仅作配置管理、快照版本及上下文隔离是 Nola 的产品/架构判断，不是 HIG 的指定实现。本轮完成设计与代码边界核对，未修改运行时代码，未执行功能、性能或视觉验收。
