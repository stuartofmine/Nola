# Nola 原型设计决策

> **历史记录：本提案已由 2026-10-28 的 [当前原型交互规范](../../docs/design/nola-ui-prototype/docs/UI-INTERACTION.md)与[视觉规范](../../docs/design/nola-ui-prototype/docs/DESIGN-SPEC.md)取代。** 下文记录设计演进依据，不作为当前配色、手机导航、桌面分栏或尺寸的执行标准；生产实现状态另见能力覆盖矩阵。

日期：2026-10-24。范围：当前独立交互原型；不表示生产客户端已经同步实现。

## 设计主张

**让答案和资料成为主角，让操作在需要时出现。** Nola 是跨端个人助手，既需要长时间阅读，也需要清楚知道专家、资料和授权属于哪段对话。辨识度来自纸白、墨色、山青以及清楚的消息身份，不来自满屏玻璃、重复卡片或装饰性仪表盘。

“世界上最好的 UI”不存在一个客观排名。本次研究选取有成熟公开设计资料、与 Nola 任务相关的产品，提炼其原则，而不照搬品牌皮肤。

## 研究与采用

| 来源 | 学到什么 | Nola 的具体决定 |
| --- | --- | --- |
| [Apple HIG · Layout](https://developer.apple.com/design/human-interface-guidelines/layout)；[Materials](https://developer.apple.com/design/human-interface-guidelines/materials) | 内容、导航和临时控件的层级要清楚；材质服务于功能 | 一层主导航；正文保持不透明阅读面，模糊只用于弹层背幕；取消原型默认展开的检查栏 |
| [Apple HIG · Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) | 控件面积、文字对比和输入方式比视觉缩小更重要 | 手机正文 17px；独立图标目标 44px；整个列表行可点击；按钮有可读名称与焦点样式 |
| [Telegram · Android redesign](https://telegram.org/blog/crafting-android-design-and-more) | 主入口容易切换，导航和搜索直接可达 | 手机先显示会话列表，三个具名底部入口；进入具体会话后使用返回导航与单个输入区 |
| [Linear · A calmer interface](https://linear.app/now/behind-the-latest-design-refresh) | 功能逐渐堆积会让界面失去一致性；辅助导航不应争夺内容注意力 | 桌面安静侧栏、稳定标题栏；列表仅显示一行主要信息和必要摘要；同类动作位置一致 |
| [OpenAI · UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines) | 对话内组件应单一目的、少量操作、避免内部导航与嵌套滚动 | 安排卡只保留保存和调整；复杂编辑使用独立弹层；不用第二个输入框或卡片内多层导航 |

Apple 具体规则还交叉读取本地 apple-design 的 design-principles、accessibility、typography、color、layout、tab-bars、toolbars、generative-ai 参考。Android 生产端应映射到 Material/系统导航组件，不复制 iOS 控件外壳。以上是设计借鉴，不宣称获得原产品的用户研究或性能数据。

## 原型审查与改动

| 优先级 | 原有问题 | 修订 |
| --- | --- | --- |
| 高 | 默认侧栏、聊天、检查器三栏同时竞争注意力 | 默认两个区域：侧栏 + 内容；手机一个内容区域 |
| 高 | 手机顶部同时放标题、模型与多枚同级图标 | 返回、整块可点击的标题/模型、更多；只有一个导航层 |
| 高 | 手机上正文约 13px，多个辅助标签 8–10px，图标按钮 32px | 正文 17px；主要行标题 16px；辅助文字 12–13px；独立图标 44px |
| 高 | 权限、模型参数、正常状态长期占据输入区 | 输入区只有附件、文本、发送；审批出现在所属回复里，正常权限状态进入设置 |
| 高 | Room 与普通对话形成两套产品入口 | 唯一对话列表、唯一新建动作；专家作为配置目录，不提供开聊按钮 |
| 中 | 多轮 CSS 覆盖互相叠加、不同管理模块使用不同样式 | 替换为一套命名 token、列表行、标题、详情、表单和单弹层样式 |
| 中 | 所有信息都铺底色或套卡片 | 正文无容器；结构化结果、审批、失败才使用边界 |
| 中 | 弹层、表单、输入和返回行为缺少完整状态 | 增加焦点返回、未保存提示、草稿恢复、@ 键盘选择、明确取消与重试 |

保留既有设计约束：单个新会话入口、专家不直接开聊、选中项以边框表达、不铺灰青选中底、资料归属明确、平台原生点击尺寸。

## 信息架构

手机：

```text
对话列表                 工作区                 设置
  搜索 / 新对话            资料                    专家 / 模型
  单列历史                 记忆                    技能与连接
    ↓ 点击                 计划                    外观 / 系统访问
返回  主题 / 模型  更多      记录                    交互场景（原型）
       消息
       结构化结果
  附件  输入内容  发送
```

桌面：

```text
侧栏 232–252px       主内容区
Nola                主题标题                         模型  更多
新对话
对话 / 专家          阅读区最大 720px
工作区               正文、结构化结果、所属回复的执行状态
模型 / 技能与连接
最近对话             单一输入区
设置
```

- 专家、模型等低频管理从手机设置进入；桌面侧栏直接可达。手机设置充当管理目录，不制造“更多”底栏。
- 会话更多菜单：参与专家、资料与附件、任务进度、对话设置。标题区域整体打开模型选择。
- 详情页面用返回导航，编辑是单个短表单弹层。弹层不叠弹层，关闭恢复原焦点。
- 原型浏览器边缘返回采用从左侧向右滑的常见返回手势，始终保留可见返回按钮。
- 在已有会话中选择模型仅改变该会话的后续消息；模型中心设为默认仅作用于新会话。
- 新会话首次发送才进入历史。重复打开未发送新会话恢复草稿和已选专家，不制造空历史。

## 视觉系统

复用仓库 `Doc/UI和交互设计/DESIGN_SYSTEM.md` 的颜色语义，避免原型成为另一套品牌系统。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面底层 | `#F5F6F2` | `#101715` |
| 阅读面 | `#FFFFFC` | `#18211E` |
| 次级容器 | `#EBEFE9` | `#24312B` |
| 正文 | `#202B25` | `#E5ECE6` |
| 次级文字 | `#58665D` | `#ACBAB0` |
| 交互强调 | `#356B52` | `#9AC7AC` |
| 强调色前景 | `#FFFFFF` | `#10251A` |

WCAG 相对亮度实际计算：正文/阅读面 **14.62:1 / 13.70:1**；次级文字/次级容器 **5.20:1 / 6.72:1**；主按钮前景/强调色 **6.22:1 / 8.56:1**。数字针对上述不透明色对，不代表每个动态叠加状态已经通过完整无障碍审计。

- 字体：系统字体栈。界面桌面 15px，手机基础 17px；长回复两端 17px。标题 22–30px；主要列表标题 16px；元信息 12–13px。
- 留白：手机内容左右 20px，输入区 12px；桌面内容 36–48px。正文最大 720px，管理页最大 1080px。
- 圆角：行/按钮 12px，结构化结果 16–18px，输入区 26px，弹层 24px。不把每个文本段落套圆角。
- 图标：统一单色线性 SVG。状态同时使用文字；专家消息每条只出现一次完整姓名，头像使用图标。
- 选中态：保留透明边框占位，只改变边框与可读状态，不移动布局。
- 动效：200ms 选中反馈、220ms 弹层进入、短页面进入。流式更新只改文本节点，不重建整段正文；阅读位置优先于自动滚动。

## 关键交互规范

### 对话与长任务

- 处理摘要在活跃回复下逐步出现；允许折叠；不从模型正文伪造隐藏思考。原型文本明确标为预设演示。
- 发送键在当前回复运行时变为停止，避免重复的整行停止按钮。
- 用户向上阅读时不追逐新内容。距底部超过 180px 才显示 44px 最新按钮，点击返回底部。
- @ 面板靠近输入区；方向键切换、Enter 选择不发送、Escape 关闭；鼠标或触摸可点整个候选行。
- 专家标签表示下一条消息的收件人，属于输入状态；每条回复署名只显示一次，运行状态不重复姓名。
- 手机输入 Enter 换行，发送由按钮或硬件键盘快捷键完成；IME composition 不触发发送。

### 资料与权限

- 工作区统一包含资料、记忆、计划、记录。来源详情显示归属和相关计划；计划显式引用一个来源，记忆编辑保留独立的归属范围。合并导航不合并权限，也不把全部资料自动提供给计划。
- 审批卡显示具体资源、操作、仅本次授权范围。允许和拒绝都能继续当前对话，不能只有一个确定按钮。
- 系统权限是外部事实，原型不使用假开关宣称授权；验证连接明确是演示。
- 记忆删除需要二次确认；取消不改变原数据。

### 表单与恢复

- 短表单只显示必要字段；名称必填，错误就地显示，不清空已输入内容。
- 关闭有修改的表单，提供继续编辑和丢弃，避免静默丢失。
- 连接中断保留用户消息；重试继续该请求，不追加重复问题，不另建对话。
- 深色和浅色使用相同信息层级，不靠大面积青色区分选中或状态。

## 验证边界

`verify.py` 使用安装在本机的 Google Chrome，以点击、输入、滚动和键盘操作验证原型，不直接调用内部函数来伪造完成状态。

覆盖列表搜索、模型选择、对话设置保存、结构化卡片编辑、@ 补全、草稿恢复、停止、专家保存、未保存表单处理、资料与记忆、自动化、模型管理、能力开关、浅深色、审批拒绝、失败重试、长回复阅读位置，以及 320/390/820/1440px 布局。

原型不实现实际 A2UI parser、Core 状态机、持久化、跨会话执行队列、系统凭据、下载、真实模型输出或操作系统导航。单次演示只运行一个任务；这些限制不能用原型通过来替代客户端真实验收。生产端实施继续复用 Rust Core 和原生渲染器，不能把此处的演示 JavaScript 当作第二套业务 Runtime。

- @ 键盘选择不误发送，草稿与收件人恢复、增量显示、停止、新会话选择隔离。
- 专家新建/编辑，未保存更改保留或丢弃，无专家开聊入口；记忆删除确认、来源添加与详情。
- 自动化创建/启停/试运行，模型连接添加与设为默认，能力开关，主题切换。
- 审批拒绝、错误重试不重复问题、长回复不抢历史阅读位置、最新按钮返回底部。
- 320 / 390 / 820 / 1440px、390×420 矮视窗、浅深色、所有桌面模块；手机聊天可见按钮目标至少 44×44px；Escape 关闭弹层恢复焦点。

测试发现并修复：流式增长使“最新消息”的平滑滚动目标落后，改为明确跟随状态；无任务的新草稿比较空身份导致空对象写入，增加任务存在条件；触屏悬停残留导致非选中项出现底色，悬停限制在支持 hover 的输入设备；选择模型不再误写全局默认；对话设置保存有实际的原型状态；来源详情绑定当前会话内容。

矮视窗仅模拟可用空间缩小，不等于真实 iOS/Android 输入法验收。没有执行真机、真实推理、跨会话任务队列、实际系统授权或 A2UI 协议测试。


## 工作区与指令输入修订（2026-10-24）

### 合并的含义

资料是工作的输入，计划是围绕资料持续执行的工作，共用“工作区”比两个一级入口更自然。移动端主导航从四项减为“对话 / 工作区 / 设置”，桌面同样只有一个工作区入口，不保留第二个自动化入口。

工作区内仅一层分段导航：**资料、记忆、计划、记录**。当前工作区名称显示在分段导航上方，避免作用范围含糊。资料页用一行计数代替三块大数字。添加操作随当前分段变化：添加资料、添加记忆、新建计划；记录页不显示无意义的加号。

- 计划编辑明确选择资料，保存稳定来源 ID。新计划默认暂停，保存不自动运行，也不扩大授权。
- 计划详情可以进入所引用来源；来源详情反查真正引用它的计划，不列出无关计划。
- 计划运行记录出现在工作区“记录”，点击回到对应计划；资料使用记录的实际写入仍由产品运行时负责。
- 返回详情后恢复原分段。全局记忆仍有独立范围标识，放在同一工作区页面不意味着改变数据归属。

### `/` 指令输入

和 @ 共用一个输入建议层，互斥展示，不叠两份浮层。只识别**输入开头的显式 / 命令**；普通正文里的斜线或 URL 不参与路由。原型中的静态命令表是 UI 命令 schema，不以自然语言关键词猜测工具。

| 指令 | 作用 |
| --- | --- |
| `/model` | 选择当前对话后续使用的模型 |
| `/experts` | 选择下一条消息的收件人 |
| `/resources` | 查看本段对话资料 |
| `/permissions` | 打开本段对话设置，不自动批准操作 |
| `/plan [任务说明]` | 打开计划编辑器，预填任务，确认时间与资料后保存 |
| `/search [关键词]` | 打开会话搜索，不调用模型 |
| `/stop` | 停止当前对话正在生成的回复，不影响其他对话 |
| `/help` | 查看可用命令和说明 |

候选支持指令前缀和中文名称筛选；显示命令名、用途和参数提示。点击、Enter 或 Tab 只补全输入，第二次 Enter 或“执行指令”按钮才执行。移动端完整命令也可直接 Enter 执行；普通消息仍遵循原来的换行规则。Escape 关闭候选，保留输入；IME composition 时不触发选择或发送。

已知指令立即进入对应 UI 操作，不追加用户消息、不调用模型、不进入 Agent 队列。运行中输入 `/model`、`/permissions` 可以立即打开面板；`/stop` 直接停止本段回复。未知指令、禁止的额外参数、没有活动回复时的 `/stop` 均就地提示并保留输入，不能把错误命令送给模型处理。`/allow` 不在原型命令表中，不伪造授权。

生产实施应由共享命令目录提供 schema 和可用条件，平台只负责候选与输入；执行仍走现有可信命令入口和 Core 权限规则。此处仅为交互原型，不是各端命令系统已经完成的声明。

### 验证

`verify_commands.py` 在 Chrome 的 390px 手机、1440px 桌面、320px 小屏完成点击/键盘验收：三入口、资料与计划双向定位、统一记录、命令筛选、补全不发送、参数预填、模型与权限在运行中直接打开、停止、未知命令/额外参数拒绝、正文斜线不误触发、搜索以及新计划默认暂停。控制台错误 0。原有 6 组原型回归同步改为工作区导航后通过。

证据：`.artifacts/prototype-workspace-commands-20261024/`。所有结果仍限于虚构数据的原型，不是实际模型、CLI 或真机指令执行验收。
