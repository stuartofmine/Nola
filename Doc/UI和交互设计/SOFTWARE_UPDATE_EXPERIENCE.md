# 软件更新交互

更新：2026-11-08。当前提供手动检查与用户明确下载/安装，不默认后台联网或静默替换运行中的应用。架构与发布合同见[更新架构](../软件架构设计/总体设计/SOFTWARE_UPDATE_ARCHITECTURE.md)。

## 入口与反馈

- iOS：设置 → 软件更新；Mac：设置 → 通用；Android：设置 → 关于；Web/Windows：设置 → 通用。CLI：`nola update check`、`nola update download <绝对目录>`，模型配置错误不影响入口。
- 展示当前版本与 build、新版身份和纯文本发布说明。保留主题色、系统焦点与触控基准，不添加固定蓝色边框或强制更新弹窗。
- 未配置源明确显示“尚未配置更新发布源”，不能显示最新；未检查、检查失败、当前超前、平台无包、新版数据不匹配是不同状态。
- 网络或校验失败保留可重试入口，不显示成功或默认清空错误；检查失败后不得继续沿用旧的可下载 offer。检查/下载期间避免重复操作；旧页面任务不触发自动安装。
- 打开下载必须出于用户操作。重新校验 publication identity，已变化时要求重新检查。版本说明不得变成 HTML、外部图片或命令。

## 平台交接

| 平台 | 用户下一步 |
| --- | --- |
| iOS | 前往已验证的 App Store/TestFlight 链接，由系统渠道更新 |
| Android 商店包 | 前往 Play Store；该构建不申请 APK 安装权限 |
| Android 直装包 | 校验摘要与 APK 应用 ID/版本后打开系统 APK 安装器；若未允许来源，前往 Nola 的来源设置，返回后再次打开安装器 |
| Mac 直装包 | 下载后显示文件或打开 DMG/PKG；不会直接杀掉运行中的 Host |
| Windows | 原生保存对话框；完成后显示文件夹，用户打开完整安装器 |
| 浏览器 | 新下载窗口向当前 Host 请求校验后的完整包；校验完成后由浏览器流式保存，失败显示在该窗口。“已请求”不能写成“下载成功” |
| CLI | 返回已校验包路径及明确安装指引，不覆盖正在执行的 nola 或在后台执行 shell 安装脚本 |

安装前提示用户结束相关任务。页面关闭不能自动停止会话，也不能在后台悄悄打开安装器。新版数据格式不同则不提供更新下载，现有数据保留；不通过“重置数据”按钮绕过。

当前未实现百分比进度、断点续传、自动后台检查与自动重启；原生请求在 IO worker 执行且有时长上限，导航取消只保证不继续展示或交接安装，不能立即中断已进入的阻塞网络传输。不得将这些能力标记为完成。

验收区分组件夹具、原生 ABI、签名互验和实际发布安装。未配置生产源或真实签名包时不能宣称完成线上更新或真实跨版本安装。
