# Android 多会话执行所有权

本工程只有单一内部开发版本。本次不提供旧版本兼容、数据转换或双读路径；不删除真实用户数据。整批源码已进入统一验收，Android JVM 实际结果见文末；不将测试夹具或恢复机制当作旧版本兼容。

## 所有权与资源

ViewModel 的选中会话只是展示订阅，不拥有执行生命周期。运行注册表按稳定会话/提交身份持有 Job、独立 ChatUiState 投影、Core coordinator、权限会话、远端 receipt/journal/observer/task cursor 和能力激活缓冲。A 切换至 B 不取消 A；迟到事件只更新原运行的投影，只有当前选中 owner 的快照发布到屏幕。返回 A 重新订阅原运行，不重发。

运行携带明确 coroutine execution context；所有 run-bound 挂起恢复及子观察任务继承该 owner，不在恢复后读取选中会话决定执行身份。UI 意图在入口捕获选中运行，再以其 execution context 执行权限、取消、任务操作。后台运行继续验证/持久化 journal 与 terminal，不能因不可见而丢弃事件。

仅 Local 模型申请进程内设备模型槽；Cloud/API 与 WebHost 使用独立执行，不申请该槽。同一 owner 不允许重叠新提交，Local 槽占用时返回明确资源等待并保留草稿。槽租约在原生成 Job 真正 completion 时条件释放，而非 Main 发起 cancel、`isActive=false` 或删除时释放；IO/native/NonCancellable 清理仍占槽，旧运行不能释放新租约。

## 选择与恢复

普通历史读取使用 selection generation fence。选中已有运行时优先恢复运行内投影，不让新历史快照覆盖乐观消息、权限或活动 Run。远端观察按运行 owner 持有，不再受其他会话 selection generation 影响；后台/前台只控制当前展示订阅，不取消 original dispatch。

配置版本/父位置在提交前冻结并传 Core CAS，草稿既有持久条件写与墓碑保留。运行结束不冒充持久提交成功；提交身份、receipt、journal、terminal 仍由现协议独立验证。

发送意图同步冻结草稿 owner、对象身份、编辑 revision 和当时的保存 Deferred（或已加载磁盘 revision），等待该具体保存后形成 submission ticket；新编辑不能替换 ticket 的保存版本。canonical Admitted/remote admitted 回执只消费原 session 的 ticket。退休在 IO 前后核对对象和编辑 revision，磁盘事务只清空冻结 revision；不按当前选择、最新 revision 或文本相等来清理。跨窗口新版、同文重编辑、附件与期间输入保留，重复回执不再退休新版。

提交清空匹配版本但不墓碑 pending owner，避免清理 IO 期间排队的新保存无法落盘；durable pending owner 保持可写，submission UUID 独立生成。只有显式删除写墓碑并推进 pending index。准备期取消不退休未准入草稿。

Main Stop 与物理停止、canonical interrupt 是不同事实。model/tool/compact effect 在挂起期间通过 select 接收所属 owner 的取消，立即取消精确 effect 子任务，在 NonCancellable 内提交 Core interrupt，然后等待真实 IO/native teardown；父 worker 取消也先提交 interrupt，不等非协作清理结束才写取消。取消幂等，不以 Job.cancel 返回或 Main 已恢复推断工具外部 side effect 未发生；未知外部结果保留 exact recovery，不伪造确定失败或 cancellation_confirmed。

## 源码验收点

A API 运行期间提交 B API；A→B→A 事件与权限恢复；B Stop 不取消 A；A 迟到 journal/permission 不污染 B；Local A 占槽时 Local B 等待但 API B 可执行；旧 Job finally 不释放新槽；owner 删除取消其任务/观察且禁止迟到发布。

## 已落地源码

- `ChatRunRegistry`/`ChatRunSession` 拥有每 owner 的 SupervisorJob、状态投影、coordinator、权限、观察器、journal、receipt、任务游标及能力缓冲；执行上下文用 coroutine context element 跨线程/挂起恢复，不使用切换后的 selected owner 路由回调。
- 同 owner 后继提交创建新 session，而非重用前一 Run 的可变容器；前一 scope/投影订阅退休，迟到旧权限/清理不会写入后继 Run。Stop 携带捕获的 ownerKey/responseId，权限卡携带 request ID，不从点击后的新选择猜测目标。
- `ChatViewModel` 选择、新会话、后台事件不再取消其他 owner；返回活动 owner 直接订阅已有投影。Core/API 与远端事件都进入原运行状态，屏幕发布按当前 owner 过滤。
- 本地模型独占槽单独申请/条件释放；API/Web 运行不经过该槽。同会话重复提交拒绝，资源等待不退休原草稿。
- Local 槽是进程级资源，取消/删除以及 ViewModel 重建均不提前释放；只有所属 Job 真正完成（包括 native/NonCancellable teardown）才释放。已取消但仍在清理的运行仍阻塞另一个 Local 请求，不阻塞 API/Web。
- 取消、任务操作、权限意图捕获所属 session；系统权限迟到回调根据 request ID 找回原 owner。删除 owner 取消其整个子任务生命周期及观察器。
- 远端任务取消、指导、观察显式传原 Host 配置，不读切换后的 provider 默认配置；发送带冻结配置版本/父位置，现有会话 UI 配置版本变化先拒绝并保留草稿。
- 新增源码回归：API A/B 同时活动、B取消隔离、迟到A投影、草稿冻结保存期间新输入与同文重编辑、跨窗口CAS、pending ACK 后排队保存、Local槽/API并发、旧lease释放隔离、权限回原owner、协程线程切换、A远端observer在B删除后继续。
- 静态交叉审计补修：准备期 Stop 不依赖尚未绑定的 runtime owner，恢复提交前投影；草稿退休移至明确 canonical Admitted/remote admitted receipt。model/tool/compact effect 用 select 及时接收 Stop，物理子任务取消后先持久化 Core interrupt，随后等待真实清理；工具外部结果未知不发送虚假的 cancellation_confirmed，不映射成确定 tool failure。worker cancellation同样保留exact recovery，重复取消幂等。
