# 主动取消与正式封存

SIGINT/Esc 只提交停止意图。当前执行的同步权限等待确已返回，且同一个 execution control 已请求停止，才将它分类为 `StopRequested`；普通传输断开仍是未知/待恢复，不构成取消或拒绝。

Host 的精确停止事实与业务响应被 Core 接纳是两个边界。同步模型 worker/权限等待实际返回可证明该本地工作不再继续；它不能证明任意外部工具已停止或副作用回滚。取消控制启动前须有精确停止事实，或实际持有可停止并等待的 worker；没有证明不进入 `ExecutionStarted`，保留控制供正式恢复，不伪造 seal。取消批次跳过业务请求时继续处理控制请求。

同批尚未派发的 target 只能在当前已绑定的 conversation/Run 下记录局部 NotStarted：请求须属于当前 Host/catalog、持有有效且未启动的 delivery，且无旧响应 cursor、已启动模型标记或 active/delegated worker。证明来自该请求仍在本 Host 实际队列中且未执行，不来自队列缺席、冷恢复或注册表为空。恢复请求、已启动/外来 owner 均不得取得此证明。只记录这个 target 的精确停止事实，随后仍由独立 Cancel 控制正式确认。

普通工具的 Rust 调用返回、线程 join 或 `ToolCompleted` ACK 本身不能覆盖物理不确定性。只读当前 typed ToolResult 的 execution receipt：明确 `Unknown`/`Partial`/`Deferred` 不生成 quiescent 证明，`Failed` 也不是停止事实。`Completed`/`NotStarted` 可结合本地返回和正式 ACK 使用；只有可信冻结 effect 声明为 `Investigate` 的普通同步 read 可保留显式缺失 receipt 的当前边界，禁止从工具名、业务 data、输出文字或伪 `_nola_execution` 提升证明。非 read producer 若缺 receipt，取消时真实限制是需要对账，不能伪造完成或自动重试。已知启动前拒绝和实际 owned-worker/tree stop 事实独立保留，绝不声称未知子进程已停。

Application 只对当前 Run 的完整冻结身份、有效 delivery、已退休 target、精确 Cancel 关系均成立的响应作只读 ACK。模型回应还须绑定同一个正式 Attempt。该 ACK 不接纳旧正文、不修改终态 Attempt/usage、不代表取消已完成；只有后续 `CancellationConfirmed` 才推进正式 `Cancelled` 和 seal。

主动取消收尾不得把空领取误认为完成，亦不得重复提交已存在的 Interrupt。尚为 `Cancelling` 时返回明确待对账错误；成功退出须有正式终态 seal，绝不本地伪造终态。

## 权限等待返回与 boundary poll 的取消竞态

同步权限等待可能在 100ms boundary poll 前直接返回，此时停止事实已经存在，但 Core 尚未接收 Interrupt。外层不得另造 UUID 取消，再让后续 drain 的 boundary source 提交第二次取消。同一个 foreground execution 与正式 Run 使用唯一的 boundary cancellation identity；生成、待提交/重排和正式 ACK 分开，只有 Application 成功回执后才记录 ACK。RuntimeDriver 在首次领取 effect 前也处理正式 boundary 输入，保证无业务响应或空领取时仍有取消准入机会；提交失败保留原输入和原错误，不按错误文字忽略。

SessionStore 将用户 Interrupt 适配到现有 `RequestRunCancellation`，冻结原 conversation/Run/assistant 并核验正式回执，再读取同一 Run 的控制与 journal。已有取消/终态只采用该命令的 typed disposition，不把回显 cancellation_id 当成先前提交身份，也不修改 Core 对重复 Interrupt 的严格拒绝。外层正常/错误/恢复收尾仅排空这一正式控制，不再生成不同身份的第二个 Interrupt。当前 Run 已更换则拒绝，绝不将旧 token 的取消施加给继任 Run。

回归同时覆盖先 boundary poll 与先权限返回：两序只提交一次正式 Interrupt；原 Cancel 控制凭精确停止事实完成后才允许 cold sealed Cancelled。另覆盖 ACK 丢失后的同身份重试、原拒绝保留、已有 Cancelling、跨 Run/外来 owner 拒绝，以及普通 Disconnected 不生成停止事实。权限等待/投影代码按现有 include 分层提取为独立实现单元，保持可见性与断言，不提高源码限额。Android 权限 SSE 正例使用唯一当前 challenge 4，旧 3/未来 5 的拒绝须用不同 request 身份证明，不能由相同请求去重掩盖。

## 本地停止事实与业务结果分离

唯一当前 ToolResult V2 的 execution receipt 必填 `local_stop`（没有实际证明时为 null）。Unknown/Partial 业务结果可以独立携带真实 owned process group/Job 停止事实，但它不改变业务状态、effects、checks 或可重放性。Host 为每个当前内建/内部工具 invocation 生成私有随机 nonce，绑定完整 Host/Core session/Run/effect/request/call 和实际 delivery attempt（未领取不能伪造）；只在真正 handler 线程进入私有 RAII TLS，nested 调用退出恢复原绑定，未绑定的线程不继承。producer 只能在真实 OS 停止观察完成后复制该身份，不能从 arguments/data 取值。

Host 消费时校验完整当前身份、当前 ToolCompleted call 和 typed scope；错 owner、旧 nonce、错 effect/request/call/attempt 均不能形成停止证明。MCP 不获得这一内建本地执行凭据。这个物理事实在同步 dispatch 已返回后可独立保留，不因业务响应 ACK 失败被抹除；正式 Cancel 仍须经过精确独立控制与 seal，未知业务结果不能获得 ActionCompleted 或安全重试信用。移动原生 producer 没有这样的 owned OS 证明时只提交 local_stop:null。

停止缓存保留完整 observed stop、request 与实际 delivery attempt，Host/session/Run/effect 仅是查询索引，不能在入账后丢失 nonce/fence。普通派发和 isolated batch 在准备该请求时撤除整个旧凭据，即使后续 progress 交付失败、未启动 worker，也不能沿用前次停止事实。Cancel 不新增目标字段：Application 在 Interrupt 同事务退休 target outbox，普通 pending/interrupted 领取都只取 pending outbox，正式 Cancel delivery 仍验证自身 lease 和精确 target 关系。这里不声称冷 Host 或未观察到的其他物理执行已停止；没有当前本地事实继续保持待对账。

回归覆盖真实 stdin-open SIGINT、普通断流、停止证明与响应拒绝分离、冷/跨 owner 拒绝、取消批次控制、终态 Attempt 守恒，以及 Esc/resize 后下一条命令。此轮先收齐源码，之后统一编译和测试。

## 委派 target 晚到确认的验收边界

正式 Interrupt 已提交后，精确 retired target 的 `DelegatedAgentEvent::CancellationConfirmed` 可以收到 `applied=false` 的无副作用 ACK；它不是独立 Cancel effect 的 `HostResponse::CancellationConfirmed`，不能替代后者，也不能产生 seal。验收同时比较完整 checkpoint/body/replay、Host inbox/outbox、canonical events、delivery/Attempt/委派账本、command receipt 和 assistant journal/terminal 状态不变；只检查返回成功或 `applied=false` 均不充分。真实 `Completed`、外来 invocation/Host/delivery/Attempt 等仍应拒绝且状态不变。

SQLite 夹具继续要求正式 Cancel 控制生成真实 Cancelled seal，冷重开和重复确认保持 seal 不变且无 pending effect。非 SQLite port 夹具不提供真实封存能力，正式 Cancel 或正常完成必须原子拒绝并回滚；回滚后的精确晚到 target 确认仍是同一无副作用 ACK，不能为通过夹具伪造 terminal source。这两类夹具共同证明“可接收旧传输尾帧”不等于“接受旧业务结果或确认物理停止”。本轮源码收齐后统一验证，尚不声明动态通过。

## 集中验收夹具的当前边界

### 初次派发前取消的正式 NotStarted 来源

真实 Escape 在第一个模型领取之前发生时，初始 boundary 正确提交 Interrupt，但 Host 从未接到原 target，不能从本地缓存缺席推断停止。当前整改在同一 Application 写事务中核对正式原 target/outbox、全部 delivery 历史及精确 Run/request；任何历史已 ExecutionStarted、未知状态或来源不完整均不得产生证明。Prepared/Leased 必须先以原 revision 原子撤销为 RejectedBeforeExecution，使迟到 ExecutionStarted 在物理动作入口前拒绝。原 target 的可执行 outbox、撤销记录和精确 Cancel 的 target_not_started 证明一起提交或一起回滚。

Cancel 的该字段为当前必填 nullable typed 来源，绑定 conversation/Core session/Run/Host、control 与 target 的 effect/request、target payload identity、提交 revision 及撤销 attempt/revision；Core 自建时为 null，只允许 Application 的正式绑定补入且不得替换已有证明或目标。Host 可消费该正事实通过原停止 guard，仍须以独立 Cancel delivery 提交 ExecutionStarted 和 CancellationConfirmed 后正式封存，证明不等于业务成功或外部效果回滚。已启动与 Unknown 仍走原 owned-stop/对账边界，不允许自动重放或 fake seal。唯一当前格式为 Application 52、Store 79、checkpoint 30；缺字段和旧格式明确拒绝，不转换用户数据。全部历史超过 256 条时不截断造证，而是保守无证明。

移动串行 Host 的本地停止事实只来自本次实际返回的操作或本次 handler 前置检查确实退出且从未进入 native executor；每次新派发先撤旧事实，Run owner 退出时清空。冷恢复空集合不表示停止；nullable proof 必须存在，非 null 必须严格校验所有字段及当前 canonical conversation/Run/control 绑定。已经记录的真实物理不确定性优先拒绝，不能被证明对象覆盖。原 publication 已 ACK/不存在或同次 buffered reduction 已移除 pending target 时仅不产生新证明，不能由缺席推断未执行或拒绝原有合法取消事务。

活动 Run 的取消恢复夹具须在初次准入前提供合法冻结 Host invocation binding；它仍走正式精确恢复接口和完整 checkpoint 比较，不因测试无实际 provider 就跳过恢复约束。同 call 的失败 mutation 事务重投不得再执行 handler 或生成新的物理 invocation nonce；新 request/call/effect 才用于验证新 nonce 与旧停止凭据拒收。初始 boundary 拒绝保持零 claim、零 ACK、零 abort；验证两个已派发 effect 在在途 boundary 失败后全部 abort 的夹具，必须在 dispatch_batch 内才注入失败，并继续拒绝后续尾帧，不能把 claim 前拒绝混作在途取消证据。此小节仅记录夹具修订约束，不声明修订后已运行通过。
