## 目标与约束

修复最近三次 Mac 会话暴露的机制性问题，不按话题、语言、测试题或用户文本关键词特化。
先修改架构和交互规范、自审，再实施全部代码，最后集中测试。测试代码随实现一起编写，但暂不执行。
生产数据库和日志只读；使用隔离数据库及明确的测试浏览器/自动化目标，不发送真实私人消息。
不把用户主动取消算作崩溃，不把连接中断算作已失败，不把有最终文字算作完成外部操作。

### 补充深审：不能只修报错文字

本节为 2026-10-16 的只读轨迹与源码复核；沿用上述三个会话、七个 Run，不把开发工作区尚未验证的修改当作用户正在运行的版本。未执行编译或测试，未更改生产数据。

1. **目标替换（B05）确实出现。** 浏览器会话最后一次用户输入明确要求“系统 chrome”。该 Run 在 attached 启动/状态失败后又调用 `browser_navigate(target=managed)`，随后同时使用两种浏览器的工具。不能把托管浏览器拿到内容当作履行原目标；也不能简单禁止模型选择工具或用用户关键词强制路由。目标由模型解释为显式执行约束，Core/Host 对具体调用检查，改变目标需明确说明或重新获得指示。
2. **浏览器 schema 与执行前置条件不一致（B05）。** `cli/src/tools/parts/catalog.rs` 的 `browser_click` 无 required 条件，`browser_type_text` 只要求 text；Host `validate_unified_browser_args` 却在 managed 下要求 ref，底层又校验 revision。轨迹中两次 managed 点击分别用 text/selector，均被拒绝。修复应在工具契约表达 target 对应的合法参数组合，并让快照返回可直接消费的 ref，而非只加一段报错提示。
3. **Skill 证据引用没有真实来源绑定（S01）。** 检索 Run 的 `skill_update(action=verification)` 使用描述式 `conversation-search-evidence:…` 字符串，passed=true 后完成。`SkillRuntimeCommand::RecordVerification` 只验证引用非空和 verifier 已声明，`validate_skill_completion` 只检查 passed。不能由此说真实搜索不存在；缺陷是该“验证引用”未解析到搜索记录，也未区分模型自评与实际检查回执。
4. **自动化展示关联错位（A03）。** `MacActivityStore.recordAutomationRun` 将 `receipt.notificationID` 写入 sourceID；`MacAutomationCenterView.automationRow` 却按 `automation.id.uuidString` 找最新记录。Store 的通知 ID 为 `automation-result:{occurrence}`，并非定义 ID。即使后续补上启动失败终态，此处仍不能正确展示执行历史，不能只修 worker。
5. **准备数据的所有权过宽（A04）。** `refreshExecutionSources` 只要遇到任一 personal_data 引用就调用全局 `MacPlatformDataService.refresh`；后者同时刷新联系人、日历、提醒、通知及健康快照。原规格中单个 reminders 引用不应被扩大成整个个人数据包。已有 A01 的规格保真与此处按引用执行都要修；最初启动异常没有保存，不能将范围扩大说成已证实的异常原因。
6. **UI 预览重载与历史导航（U03）。** `MacManagedBrowserSurface.updateNSView` 在 URL 未变但 updatedAt 变化时仍调用 WKWebView.load；页面本身已有帧刷新循环。这是重载触发点，不是本轮已测的闪烁帧率。`MacTranscriptView` 两个历史导航按钮均被 isRunning 禁用；只读历史与执行 busy 不应共用开关。
7. **缓存不是三个会话全为零（C01/C03）。** 去重读取物理 `run_attempts`：浏览器会话 43 次，输入 1,839,263、读取缓存 817,539，累计约 44.45%；跨会话 9 次，170,815 / 57,807，约 33.84%；提醒 3 次，58,500 / 0，为 0%。这不是新性能验收，只是已存 Provider 回执核对。不能把最后一轮比例当累计值，也不能因某次未命中声称服务端不支持缓存。
8. **用量来源缺少可理解的边界（C03）。** 108 个 context_updated 中，相邻实测/估算来源切换 99 次；上一物理请求的实测与下一请求估算本可合法不同，不应直接判为数据倒退。当前 UI snapshot 无 request/上下文 generation 身份；canonical 消费函数构造 snapshot 时也没有传入 promptCacheDiagnostic，Inspector 该诊断分支因此不能靠 canonical 冷读恢复。需拆开当前预算估算、已测用量、累计账单和实际前缀诊断，不能用“永远优先实测”掩盖下一请求增长。
9. **恢复后历史失败不等于当前阻塞（U04）。** `MacJournalProcessProjection.requiresAttention` 遇任何历史 failed tool/modelAttempt 都返回 true；主状态虽可由正式终态覆盖，但默认展开/告警判断仍混入已恢复尝试。编码 Run 实际修正编译错误并成功执行，初次编译失败本身不是 harness 缺陷；UI 应保留过程且区别历史失败与仍未解决的阻塞，不能一刀切隐藏失败。
10. **浏览器并发/回收的代码风险（B06）。** Playwright RPC 及预览 input 直接异步进入同一 session 的 activePage/refs，容量回收只看 lastUsedAt 与 session 数量，没有在途操作引用；CLI 直连子进程路径还持全局 mutex 阻塞 read_line，无独立响应期限。需按 owner 管理动作序列、页版本与在途租用，不把一个浏览器的等待拖住另一个，也不能为了释放锁盲目重做未知动作。本次没有竞态复现实验，不把这些风险冒称为现场点错页的已知原因。

补充设计自审：验证来源与模型判断不同；自动化定义与每次执行/通知身份不同；公开读取与敏感数据包不同；当前请求估算与历史计费事实不同；浏览器选择与已授权页不同。新增项并入同一主任务，没有把原有 P01—U02 降为非目标，也没有提前完成声明。

TaskPromoted 的 Store 来源核验须与 Core 同步接通，不能将新观察直接套入仅有 tool_completed 的输出/回执字段。Store 分开验证两种现役来源：普通完成仍按原 Host outcome/原始 receipt 核验；promotion 仅接受 Deferred、receipt=None，并对同事务同 revision、观察之前的唯一 Core TaskUpdated 逐项核对 Task ID、session/turn owner、完整 lineage、初始非终态及 Host promotion 原字段。创建索引时仍核原 outbox 的 effect/request/call/capability，parent_call_id 只准由同一原调用补入；冷读仍核原 Core/Host immutable digest 及原 TaskUpdated。Core 内部 ToolCompleted 转为 Journal 输出，不虚构一个不存在的独立 Core event，不依赖事务后面才建立的子 Run/Task binding，也不把 Task 创建解释为执行成功。最后一个工具被移交时仍可能触发已耗尽的 no-progress 预算，因此只有 BudgetExhausted 触发器可接入经过上述完整来源验证的 promotion；空模型响应和未完成控制两类触发器保持模型来源限制。先补源码与真实 SQLite 正负/冷读回归，再集中验证；第九轮重跑因该生产接线缺失主动中止，部分结果不得称为完整通过。

来源必须覆盖所有现役 Task kind/非终态，不限于 Agent/Queued 准入事件，故 Application 为所有 TaskUpdated 保留原 Core envelope。乱序工具回应的 flush 输入并非每个后续事实的来源：BudgetExhausted 若由同 revision 的工具观察触发，应读取已验证观察绑定的原 inbox 回应作为停止事实来源；当前 flush 输入仍须属于同一 Run。回归通过真实失败决策耗尽预算、先返回后一工具 promotion、再以前一工具失败触发 flush，要求停止事实冷读仍绑定原 promotion，绝不能把先前故障工具的回应或下一 revision 当成其来源。无该 revision 工具观察的模型触发沿用其原模型来源，不新增猜测式回退。

归档工具来源使用共享 `ToolSourceClaim`，单独的 ToolSource 清单项不覆盖可见 Part 的 JSON。客户端 body reference 只是声明：Application 必须核验本 restore/conversation/part 的 sealed upload、完整长度及 SHA，再生成本地 reference。Store staging 要求目标消息和 Tool Part 已声明；最终替换前复核所有正文完整性，重建消息后在同一事务安装 Archive 来源，不能恢复 AcceptedRun/VerifiedLocalDerivation 权威。同步归档最终 commit 必须等待这些独立原文 body seal 与所有 staging 项确认；接收端保留外来声明来源。失败不得留下半替换目录或提升来源，原文保存本身不构成执行授权。
