  经已有 `ApplicationCommand::Context` 的 `prepare_compaction` 冻结源见证，摘要后读取当前尾部，
  调用共享 Context Core 重新核验摘要与尾部预算，再通过 `commit_compaction` 条件提交。
- 源见证含 conversation_id、message_count、source_fingerprint、context_fingerprint。
  原前缀允许新增尾部；修改原消息/Part/正文引用、删除源或修改已有摘要 lineage 都使提交冲突。
  事务还比较预算核验时的完整 validated_source，避免核验后追加内容绕过预算。
  条件满足时只合并 sessionMemory、compactedMemoryEntries、lastCompactedAt；原文、配置、标题保持各自写权。
- `replace_summary` 使用同一源条件事务支持显式人工摘要编辑；保留已有 archive lineage。
  删除无人调用的 `summarizeOldMessages` 旧字符串出口。
- Swift 通过窄 `ConversationContextStore`，由 LocalConversationStore / IOSApplicationRuntime 适配。
  prepare 返回 `IOSContextCompactionSource`；commit/replace 返回 Bool。

- `summarizeMessages` 传播 provider 错误、取消和空结果，不再把源前 2000 字当成功摘要。
  请求前、响应后和条件提交前检查取消。
- `ModelService.generateSummary` 每次仅执行一个 provider 请求，移除隐藏指数重试及其语言相关 TLS 错误分类。
  Scheduler 响应后检查取消，取消失败不再触发通知 fallback。

## R03 接续前的缺口与约束

接续前的 `ModelAttemptRecord` 和 `run_attempts` 绑定真实 Run / effect / Part，表的 run_id 外键不可用于
无会话的 event_summary；不得伪造 conversation 或 Run 来绕过。现有 `LLMSummaryInvocation` 只有进程内冻结，不能算持久账本完成。

接续须复用并扩展现有 Attempt 账本的 owner scope（Store/Host 或 Conversation/Run）、operation/scenario 与冻结预算，
由 Application 提供 prepare/admit、physical-attempt-start、usage/terminal-receipt、cancel-intent 端口。
每个实际请求只有一个 Attempt；失败/取消也保留 unknown usage，晚 usage 修订原身份。
持久冻结只保存安全 route/config/credential 引用，不能保存密钥或临时服务对象。
Scheduler、ProcessingAgent、ContextManager 均须迁移到该端口；禁止在 Swift wrapper 自建第二账本。

## R03 本轮接续已落源码

- Domain 新增 `AuxiliaryInvocationOwner`（Conversation / Account / 真实 Task）、scenario、冻结配置/input digest、
  operation、physical Attempt、预算及取消/回执命令；Application 提供 Admit / StartAttempt / RecordReceipt / Cancel / Inspect。
- `auxiliary_operations` 保存 operation 事实；模型尝试全部进入原 `run_attempts`，增加 operation_id 分支，
  该分支 run_id、text/reasoning Part 为 NULL。SQL CHECK 要求恰为真实 Run 或 operation owner，未创建占位 Run/Part。
  同一 predecessor 链、Attempt ID、revision CAS 与终态约束继续参与完整性校验。
- StorePort 仅暴露 operation 查询与 operation + 同表 Attempt 原子提交；Store savepoint 保持取消/终态/计量原子性。
  Application 控制最大尝试数、操作总时长及输出 token 总预算；每次尝试按冻结 provider 输出上限预留，
  usage 缺测或失败不释放该预算。Swift 当前每 operation 一次，不恢复 facade 隐藏重试。
- `LLMSummaryInvocation` 现在经 IOSApplicationRuntime 准入及持久物理 Attempt，dispatch 后保存成功/失败/取消回执；
  Task 取消单独提交持久取消意图。重复 StartAttempt 不再获得 dispatch 许可，重启保留 Running/unknown 而不盲重试。
- Scheduler 与 ProcessingAgent 采用 Store 内明确 local-account 作用域；ContextManager 采用原 Conversation UUID，
  原 owner/config revision/provider 对象在 await 前冻结，不借当前窗口创建假 Run。
- OpenAI Chat/Responses 回执保存 provider 原始 usage 与归一输入/输出；缓存缺测为 null。
  已取得 usage 后输出解码失败仍保存该计量。Local 没有可信原始读数时保存 unknown；估算遥测不进入 canonical 账本。
- late usage 修订原 Attempt，不追加计数；已知计量不能降回 unknown，终态不能因 late receipt 重开。
- 新增未执行测试源码：两败一成恰三同表 Attempt、无任何 Run、重复派发拒绝、重启保留、取消、
  跨 operation 回执拒绝、late usage 去重；Swift facade 测试使用隔离 canonical DB，并核对一次失败及 unknown。
