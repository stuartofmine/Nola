## R05 待核验及明确限制

- 旧 Run 没有 descriptor 时明确 blocked；不从最新全局配置猜测。
- URL query secret 尚无安全引用解析端口，捕获返回无 descriptor，重启明确 blocked。
- 现有 Host binding 对 credential SHA256 作 exact 比较；当前密钥轮换会保守阻断。
  支持有效轮换需同时升级 managed secret provenance 与全部物理绑定检查，不能只放松恢复比较。
- 原生临时模型通道的重新租用仍需平台 Host resolver；不会持久化可恢复 OS/进程句柄。
- 编译、真实模型/进程重启、两会话取消及资源等待统一由主任务验收；源码存在不代表已经通过。

## R04/R05 超过 64 会话的调度接续

- 已解除 Supervisor 的总注册 64 会话限制；CLI 持久发现可把全部未完成 owner 注册进调度集合。
  物理 worker 数仍由 maximum_concurrent_runs 约束，每 Conversation 最多一个活动 worker。
- 调度通过稳定 BTree keyset cursor 首尾轮转；每次查询最多 schedule_limit 个 owner，且协议上限仍为 64。
  删除当前 cursor、插入新 owner 不会把查询永久重置到字典序前缀。
- 多于一个可用批次时，每次 long-wait 最多 200ms；单批保持原 long-wait。
  因而前 64 个空闲会话不会长轮询 30 秒才发现尾部工作；backoff 的更早截止时间仍优先生效。
- 稀疏结果证明该批候选已经读尽，推进整个批次；结果达到 limit 时可能被某 owner 的多个 Run 占满，
  因此从同一边界二分查询范围，必要时收窄至单 owner，再推进，避免隐藏其他 owner。
  取消/失败的查询也推进轮转，不把它们当成已经读尽的批次。
- 活动 worker、尚在 backoff 的 owner 与 panic 隔离 owner 仍被排除；资源等待、定向取消、租约/fencing、
  panic 隔离与 shutdown drain 沿用既有实现，查询轮转不授予新的执行权限。
- 已补未运行测试源码：141 owner 有界批次覆盖、cursor 被删除、饱和结果隐藏 owner、
  小 limit 与取消轮转、活动/隔离/backoff 排除、140 个实际注册后的尾部 ready 派发。
  后者同时检查查询上限与 200ms 批等待，并沿用有界 worker 与 shutdown 取消断言。
- 已执行 rustfmt 与 git diff --check；未编译、未运行测试，不声明并发或端到端验收通过。

## 外部发送 CAS 接线接续

- Config / HostSessionRequest 新增 caller 的 expected_configuration_revision / expected_parent_message_id，
  private worker 序列化也保留这两个读取见证；native JSON 严格校验整数版本与稳定 parent identity。
- native desktop 请求、移动/Web bridge 仅传递原请求的值；canonical_begin_turn_input 原样交给 BeginAssistantTurn。
  不在 Host/Begin 处查询最新版本，不把冲突改成自动刷新后重放。
- 纯 CLI prepare_submission 在已有 canonical 配置解析之后，读取受限 TailSnapshotV1（一个可见消息，Part各一个单位），
  该查询同一 pinned snapshot 返回配置版本和父位置；必须与实际用于解析的 Config 对象保留的读取版本相同，
  才冻结两个发送前置值。配置在两读间改变即报冲突；后续变化由 Begin 原事务再次比较。
  该版本不再从可被另一调用者覆盖的进程 baseline map 临时取出，避免混合两个准备对象的读取见证。
- 新增未执行测试源码覆盖 native witness 解析/拒绝非法值、private worker 往返、Config克隆冻结、
  CLI配置/父位置版本匹配与拒绝跨owner/混合快照、canonical Begin不重写caller版本、恢复接口拒绝发送字段。
- 派生 Task/automation request、冷恢复描述清除原 parent caller 的一次性 CAS 字段，避免跨 owner 继承。
  Goal maintenance / queued successor 继续使用独立的内部准入协议，不靠伪造外部快照过关。

创建见证缺口已关闭：CreateConversation 正式返回 `initial_configuration_revision`，只对本事务新建 owner 有值；
已有 owner 或创建竞争返回 created=false 时不能用最新版本补调用者见证。CLI/native 恢复继续与新发送协议分离。
