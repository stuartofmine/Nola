## 唯一配置入口与结果

`ApplicationCommand::PatchConversationConfiguration` 保持 wire 输入
`conversation_id / expected_revision / patch_json / updated_at_ms`。
`patch_json` 在线路上仍是 JSON 字符串，Rust Domain/Store Port 实际类型已是
`ConversationConfigurationPatch`：构造及反序列化校验，内部保存已解析字段，Store 不重复解码。
字段验证及模型 reasoning 规则移到 Domain；Application 仅引用同一实现。

结果为 Domain `ConfigurationCommitResult`，线路形状：

- `{"status":"committed","snapshot":{...}}`：快照键沿用 camelCase，版本为 `configurationRevision`。
- `{"status":"conflict","conversation_id":"...","expected_revision":n,"actual_revision":m}`：本次不改配置。
- `{"status":"not_found","conversation_id":"..."}`：owner 不存在，不创建或复活。

HTTP PATCH 使用相同结果，分别为 200 / 409 / 404。
快照包含共享模型、参数、权限、Host、memory/retrieval、知识文档和 native 配置字段，
并包含唯一共享 `executionPolicy`，不再用客户端名称定义 Store 写政策。
业务领域内嵌模型/provider declarations 目前仍有 `serde_json::Value`；不声称所有载荷已完全枚举化。

## A03 Web 接续实施

`WebConversation` 仅为 canonical 只读投影；包含 `revision`（标题提交见证）和 `configurationRevision`。
新建与 branch 不保存 Web 配置整包，也不根据 owner 制定业务规则。
模型选择与初始参数仍通过既有共享配置事务初始化；branch 从同版本源读取 canonical 配置，
保留模型参数、权限、记忆策略等字段，不以 Web 投影的有限字段覆盖共享设置。

HTTP `PATCH conversations/:id` 的配置编辑带调用者 `expectedConfigurationRevision`，
按实际出现的字段构造统一配置 patch；不读取最新版本代替调用者版本。
标题编辑带 `expectedRevision`，复用 RenameConversation，新增可选 typed `title_source`；
标题与来源在同一事务提交。混合标题/配置命令明确拒绝，要求分别提交两个独立对象操作。
首消息标题也使用读取时的标题版本；并发用户重命名不会被旧自动标题覆盖。

删除 Web 整包 profile 方法和 CLI Application Port 的旧 profile 协议入口，迁移实际调用及 replica fixture。
运行时明确拒绝旧 wrapper，不提供 importer、按客户端旧格式读取或 fallback。

原 `session-memory` 写口已移至 Context ReplaceSummary 的来源条件提交，知识字段使用配置 CAS。
`GET conversations/:id/session-memory` 只在编辑场景按需返回 `contextSource` 与 `configurationRevision`；
来源在读取前后比较，避免将旧文本配上新 witness。列表和常规 GET 不计算全历史来源。
PATCH 摘要携带 `expectedContextSource` 原对象，PATCH 知识携带 `expectedConfigurationRevision`；
混合摘要/知识编辑须分别提交，不通过另一种整包覆盖实现。

新增/迁移源码测试覆盖 canonical Web 投影、拒旧 wrapper、跨客户端只读不写默认值、

### 最终验收补充：外部子进程快速退出采样竞态

真实 external crash 回归暴露：子进程在资源采样的 `ps` 快照前退出，旧路径把“根 PID 已消失”
直接当作采样失败，覆盖了子进程实际退出状态。现由 `ExternalExecutionBudgetMonitor::check`
持有真实 `Child`，采样前与缺失根 PID 后均通过 `try_wait` 确认退出；只有真实退出证据才跳过
该次资源采样，不制造零值，不丢弃 stdout 或覆盖退出码。活进程缺失与采样命令错误仍明确失败。
`process_tree_usage_if_present` 提供有证据的可选快照，原严格查询仍拒绝缺失根进程。
已补真实 shell exit 23 保留退出状态回归；等待主代理统一 CLI 重跑验收。
