# 工具原文冷来源闭合

## 已确认事实与实施边界

真实上下文恢复已得到正式 Answered、一次显式注入 400 后真实服务恢复及压缩记录，但独立 `session sources` 缺历史 `requirements_update` 的 ToolCall/ToolResult 两个来源。可见 Tool Part 与 AgentItem 是不同身份，原控制结果不能由 preview 或 ID 前缀还原。旧失败现场保留，不删除来源断言。

本次在 Store 80 当前 schema 新增 `canonical_tool_sources`，沿用 canonical text 分块而非新增正文数据库。Application 仅在实际 changed Tool Part 的接受事务中，从已验证 checkpoint transcript 按 typed call ID 与 Core item ownership 建立不可变来源；与 checkpoint、Part、journal、seal 同工作单元回滚。Call 可先提交，Result 后追加；正文、原 owner 和 item ID 不可覆盖。没有结果的取消/失败关闭不制造结果，已完成工具缺原始 pair 明确失败。

冷来源读取固定 conversation revision，校验正式 owner、visibility、创建 revision、body reference 与 digest，不读取最新 checkpoint/outbox。历史模型水合保留原 item ID，但调用另映射历史命名空间，并经过 `ModelToolEvidence` 安全投影；超预算不读半截 JSON 伪装为完整 item。`session sources` 有界正文同样投影；大型原文仍由现有 UTF-8 range 规则读取，缺失显式报告。

本地分支通过已存 `PartDerivation` 在相同事务建立 `VerifiedLocalDerivation`，原 item ID 按会话命名空间保留，原 accepted owner 仅为事实快照；正文为分支独立所有，删除原会话后仍可读。派生不赋予执行权限。

## 尚未覆盖的同步边界

本批不宣称跨端/归档工具原文来源闭合。现有 `part_derivation_sync.rs` 的 `enqueue_message`、接收 apply 及 canonical text chunk/seal 需要把新的绑定作为同提交的正式事实传输；接收端须核目标 owner、原文摘要/完整性、来源与 receiver-owned provenance，不能复制本机 `LocalBranch` 标签当作可信权限。当前缺少该绑定的接收端显式省略历史 pair，不以展示内容或最新 checkpoint 回退。

## 同步与归档补全设计（实现中，尚未验证）

复用既有 canonical text chunk/seal、sync 不可变事实回执及归档 staging/commit，不增加正文库或并行传输协议。`ToolSourceClaim` 只含原 item/call/kind/name、实际 canonical owner、original accepted owner 快照、独立正文引用/SHA 与可选派生声明；不接受发送方指定可信 provenance。读取关系的创建 revision 是接收端当前 revision，不拿发送端的会话版本充当本机 fence。

发送方在原接受/branch 事务内排入正文 chunk/seal 与有界 `canonical_tool_source` 元数据事实。只有正文 seal 已确认，且正式目标 Part/派生依赖按现有顺序交付后，才发送来源事实；branch 最终 lineage 还等待来源事实确认。接收页在同一事务核完整 UTF-8、原文字节 SHA、当前 AgentItem 结构与精确 item/call/name/Part 关系后安装。Replica 与 Archive 标签由接收入口生成，最多授予历史读取与模型安全投影，不生成 Host execution evidence、执行恢复或权限。已有本地证明不因重放被降级或升级；不同正文、owner 或逻辑 item 明确冲突。

删除后的有界不可变事实回执继续保留，tombstone 阻止旧消息/来源复活。重放即使 operation 已见仍比对 canonical claim SHA；不能凭队列裁剪或目标不存在推断未接收。分支独立保留原文与原 item 身份，并保留其来源的 receiver provenance，不把导入历史升级为 AcceptedRun。

归档 Manifest 增加独立 `tool_source {claim,upload_id}` 条目，原 Tool Part 的 `content_json` 不被占用。上传仍经已有 sealed UploadOwner 和流式准备；外来 claim.body 只声明原始 owner/长度，不能选本地 content_id，Application 生成正式本地引用替换后再 staging。所有来源随原 manifest digest/目标 CAS 和最终 commit 一次可见，恢复失败整批回滚。导出通过独立有界 metadata/range 读原始字节，CLI/Mac 当前载体同步，Mac 唯一备份格式升 3，不接受旧格式或缺省新字段。
