# 权限资源事实实现说明

本说明记录共享权限实现边界，主任务及总体设计仍为验收依据。

## 可信风险与资源解析

Host 冻结目录的 `input_normalization.permission_contract` 声明风险与可选资源计划。风险为 `ordinary_read`、`new_file`、`overwrite`、`delete`、`sensitive_read`、`external_send`、`new_connection`、`unknown`。缺少声明按未知效果处理，不使用模型的 `operation_kind`、工具名拆词或普通参数中的自报风险。

需要真实资源状态的调用先产生 `ResolvePermissionResources`，包含原调用 ID、目标 Host、版本化规范输入摘要和完整资源需求。Host 只读解析后返回 `PermissionResourcesResolved`；Core 校验原 effect 响应权限以及 resolution、Host、输入摘要和每个需求的绑定，再对同一调用准入，不重新请求模型。解析请求保存在调用状态中，可跨 checkpoint 恢复。

CLI 文件解析区分缺失目标、已有内容和敏感资源；新建普通文件放行，覆盖、删除、敏感读取及未知效果确认。目录树使用有界元数据核验，达到预算仍不宣称普通读取。实际执行再次核验同一事实，状态变化返回 `permission_resource_changed` 并标记业务工具未执行，需要重新解析。普通公开检索、普通只读工具不按查询内容逐次确认。

仅声明了真实预览语义的工具才能通过 `preview_when_true` 将资源计划转换为读取；模型自己添加 `dry_run` 不形成权限事实。`memory_save` 的 `supersedes` 非空由可信契约提升为覆盖风险。模型阶段用的执行/验证标签保持独立。

有限的普通 shell 读取需要通过 Host 支持的字面 argv 和实际路径核验；其他程序、复杂语法及后台执行保持未知效果。已核验的短读取执行固定系统程序、关闭登录初始化及环境脚本/导入函数，保持解析与执行一致。

审批资源身份包括 Host、具体能力、操作和解析后的资源，排除偶然查询/参数摘要。敏感目录树额外绑定目标证据，避免 symlink 换目标沿用批准。个人记忆、联系人、日历和提醒的读取有明确稳定范围，选择会话内批准后改变查询不扩大已显示的数据范围。

## 活动政策与物理执行边界

Core 生成请求时的 `Dispatched` 仅代表生成封套。Host 必须等 `ExecutionStarted` 被正式提交后才能开始物理执行。

活动政策更新将仍为 `Dispatched` 的工具 effect 撤出并对原调用重新准入；不重复工程阶段准入，不生成新模型请求。已经准入、拒绝、取消或完成的调用保持原生命周期。ACK 事件携带不受此次修改影响的已准入 effect ID。

Store 在同一 checkpoint/outbox 提交事务中对旧 Leased delivery 做 revision CAS，记录 `RejectedBeforeExecution` 和 `permission_policy_changed`，再关闭旧 outbox。旧 worker 的 `ExecutionStarted` 因租约状态不匹配不能提交；已经 `ExecutionStarted` 的 attempt 不能被此路径撤销。事务回滚保留原状态。提交回执读取包含 delivery facts 的真实 Run event frontier。

配置 CAS 与政策通知的原有事务、精确 owner/Run 校验及专用 Apply 命令保持其单一责任。较旧政策通知在已有更新 ACK 后幂等消费，不回退活动政策；同一 revision 的冲突仍拒绝。

## 尚需统一验证的边界

测试源码覆盖资源事实分类、恢复、输入身份、symlink、模型标签无授权、模式降级及租约 fencing，现已进入主任务统一验证阶段；测试源码存在不等于全部验收通过。各端实际结果与待复跑范围以主任务集中验收记录为准，本说明不宣称所有平台或系统版本均已验证。

CLI 资源解析器实现文件、有限进程和 Browser Host 的 owner/page 平台事实。浏览器预检只读 owner、连接代次、page/document ID 与来源，不启动、重连、切页或读取 DOM/cookie；认证状态固定 `unknown`，页面内容观察按敏感读取处理。同一 owner/代次/page/来源的观察共用批准范围，不因快照选项变化重新询问；新连接、跨来源导航和未知交互仍确认。原始浏览器事实随正式 ExecuteTool 保存，在顺序/并行执行通道重验后以线程局部 RAII 作用域传给 Host，最后在浏览器 owner 队列内执行前再次比对；模型不能提供此断言。

其他未实现 locator 明确失败。原生平台工具由各端可信目录提供声明，无资源计划的普通工具不发解析请求；不支持资源解析的原生端显式拒绝，不能伪造资源事实。

直接/内部工具入口同样经过当前严格 schema、可信契约和 Host 资源事实；不再用 `read_only`、无权限域或模型自报标签跳过权限。直接入口的会话批准只绑定解析资源范围，不读取旧工具级通配缓存；owner 重绑清除该局部批准。设备桥只消费正式 Core ExecuteTool 的权限快照，直接未准入调用明确拒绝。代码图粗回退及仓库指令预检也走上述入口；指令预检仅检查声明候选文件的元数据，不因无关 `.env` 文件要求普通指令读取确认。

配置规则通过独立的已验证资源参数匹配正式 Host 事实，不能把普通 `FullInput` JSON 解析成资源证明。文件目录 Allow 必须覆盖全部已解析资源，Ask/Deny 匹配任一资源即适用；显式配置 `*` 与会话批准中的字面 `*` 分离。进程事实保留必填 Host command/cwd，command 回绑原始需求、完整输入摘要仍独立核验，命令规则不从摘要猜测；未知执行风险不因此变成普通读取。普通目录观察绑定稳定文件系统身份并重扫敏感集合，不因无关日志修改时间失效，新增敏感资源或目录替换仍拒绝沿用旧事实。

CLI runtime.permissions 只保存用户实际配置的声明。删除先注入 read/browser 等 Allow、edit Ask 再统一标成 UserGlobal 的内建默认表；产品默认完全由 Kernel profile 与可信操作契约判定。新加载不制造用户授权，也不按规则文本猜测、清洗或改写现有生产数据。

正式关联的 Host 目录刷新在刷新边界清除工作集中已撤销或已改变的声明，之后使用新目录投影；未改变声明保留原始 schema 字节。普通执行阶段/恢复提示仍不能重新定义已暴露 schema，损坏 checkpoint 不通过此刷新边界获得兼容恢复。

会话原文检索按 Host 绑定的 requester owner 和明确结构化 scope 解析：只选当前会话为普通读取，跨会话或全本地历史为敏感读取；原文 Part 的 conversation ID 不能通过声称 current scope 降险。查询词不进入批准资源身份，变更查询不重新确认同一已批准范围。

`spawn_agent` 只创建当前 owner 的子 Task，声明普通新建；不授予子 Task 外部工具、数据或新连接权限，子任务权限快照、owner/binding 及每个具体工具仍独立准入。`goal_complete` 仅发布当前 Goal 声明，不绕过证据验收。后台 Bash 仍为进程契约，不能随 Task 创建降险。CLI `--yes` 只确认 `init/wiki` 模型联网，不推导 `allow_all`；资源授权提示明确指向此资源，不宣称工具级或同类操作的通配批准。
