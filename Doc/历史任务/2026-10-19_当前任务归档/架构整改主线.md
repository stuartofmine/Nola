## 四、封装后的对象协作

以下名称表示职责，优先改造已有类型；Rust 保留值对象、trait 和纯 reducer，Swift/Kotlin 使用合适对象/协议，不要求一律新增 class/crate。

| 对象/端口 | 封装状态与不变量 | 输入 → 输出 |
|---|---|---|
| ConversationConfiguration | 模型、参数、权限、Host 选择与配置版本 | 已读版本+字段变更 → ConfigCommitReceipt/Conflict |
| ConversationMetadata | 明确允许的非业务展示字段 | MetadataPatch → MetadataReceipt |
| Plan/Goal | 约束、步骤、依赖、版本与验收证据 | Create/Edit/Replan/Result → 已提交计划/冲突 |
| SendConversationTurnUseCase | 准入、消息/Run 创建与幂等 | owner+command+配置/父消息版本 → TurnReceipt |
| ConversationDraftRepository | 本设备编辑、附件版本、CAS 与墓碑 | scoped draft+版本 → 异步快照/写回执 |
| ContextOperation | 源范围、fingerprint、候选与提交条件 | Prepare/Commit → CompactionReceipt/Failure |
| InvocationResolver/Attempt 调度 | 场景配置冻结、预算、物理请求身份 | scenario+owner+输入引用 → Invocation/AttemptReceipt |
| RunSupervisor | 资源、执行句柄、子取消作用域 | 已提交工作 → Dispatch/Wait/Blocked |
| ConversationRunController | 单个 Run 观察与用户控制 | RunRef+Control → scoped 状态/控制回执 |
| WorkspacePresentation | 选中会话、滚动、折叠、展示订阅 | Selection+Projection → 只读界面状态 |
| 原生/Web/CLI adapter | wire、系统和展示端口适配 | 领域类型 ↔ 外部协议，不新增业务权威 |

跨模块不传整个可变 Workspace/Config 供随意读写；注入端口限定消费者能力。
Plan 与 Goal 在表中同属任务领域，仍保留各自所有者与命令，不合并为一个可变大聚合。
业务规则在领域/用例处封装，Store 保持事务完整性，adapter 负责翻译。事务不能为“面向对象”被拆成多次独立提交。

## 六、设计文档复核后的统一决定

本轮已修正文档，代码整改状态仍按前述 17 项。整体复核结论见[设计复核记录](架构文档整体复核_20261015.md)。

1. 公共协议按 Application/Account、Store/Host、Conversation、Run 明确 scope，非会话操作不伪造 conversation ID。
2. Application 信封统一沿用 request_id/protocol_version；Host request_id 是独立 delivery 命名域。
   Accepted、Committed、提交结果不明分别表达，不能把断连当作已拒绝。
3. “会话聚合”应表达逻辑归属与事务边界，不建成包含所有可变业务状态的巨型对象。
   configuration、transcript、Plan、draft 各自封装版本与端口，跨边界不变量由用例事务核验。
4. “统一 LLM 场景”复用配置解析、Attempt、计量、取消与恢复；各场景保留自己的输入投影和输出 schema。
   不创建一个重新拥有所有业务决定的万能 LLM 管理器。
5. 性能数字先有真实基线；源码结构只证明同步等待或串行执行存在，不直接证明用户观察的具体延迟由它造成。
