# iOS / Android 会话权限配置的正式 owner

## 设计边界

权限提交、状态展示和 ACK 观察共用正式 owner，不能用 UI 的 `blocksInput/isRunning` 代替 Run 生命周期。以 Application `active_run` 与精确 conversation/run/root assistant 定位；source Host、client 只能来自已 admitted 的正式 submission identity，观测 receipt 与持久 intent 同时存在时必须一致。独立检查正式 terminal；历史 journal/已结束 stream 不是活动 owner。

iOS 冷选会话的异步 journal catch-up 尚未将 UI 置 streaming 时、断流或显式 presentation reset 后，仍须对源端活动 Run 做配对 read/CAS，不得仅保存本地镜像并显示 saved。来源缺失、身份冲突、恢复未知时保留选择并报待核；只有正式 terminal 或已确认没有活动 Run，才允许按下一轮设置本地保存。源 CAS 成功但镜像失败时，源 ACK 仍归原 owner，不以重放 CAS 修补展示。

Android 的保存协程必须进入捕获的 `ChatRunSession` coroutine context，跨 suspend/切会话继续使用该 session 的状态、admission、transport 与配置；不能借 `executionSession` 在恢复后回退到新选会话。`activeResponseId` 只作辅助 identity fence，正式 terminal/active_run 才决定是否活动。终态后残留 `remoteJournalTurn` 不得被误作新权限更新目标。未确认来源仍拒绝 mirror-only 保存。

读端和政策轮询同样不依赖 busy。轮询前后复核精确 owner，合法的旧会话迟到回执只更新旧 owner 状态；若 terminal 或新 Run 已替代原 owner则停止。配置已提交与政策已生效分开：无精确 active_policy ACK 不能显示 active；未知 owner 不能显示 saved。

冷选择与显式重连各刷新一次 owner，并按精确 identity 异步水合源配置。请求中与成功水合分开记录；首次网络失败必须释放请求标记，允许下一次选择/重连重新读取，不按 token/快照无限重试。未知展示独立 checking，而非“已保存等待生效”。权限编辑的完成、失败和清理同时绑定原 conversation 与 change UUID，A→B→A 不允许旧请求覆盖新编辑。

## 静态自审与待集中验证

不修改 Core 权限算法、pairing/nonce、源端 CAS、工具准入或 Run seal；不伪造 admitted identity、不从 UI 文本推断目标。新增回归覆盖 idle/error + 活动远端 Run、正式 terminal + 残留 journal、缺 admission/外来 identity、异步会话切换、精确 ACK revision。iOS/Android 当前完整门禁继续保留，源码收齐后集中运行，本说明不宣称动态验收通过。
