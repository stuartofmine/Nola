## 3. P2 决策：不立即新增 Code Mode 或 CSV 工具族

**Code Mode 暂不实现。** Codex 的 exec/wait 包含持久 cell、嵌套工具委托、输出预算与等待协议，并非把 JavaScript eval 包装成工具。Nola 目前已支持同轮工具调用与 TaskSupervisor；还没有证据证明主要延迟来自模型必须逐轮编排可确定的调用。新增第二执行调度器会扩张授权、取消、恢复和输出的责任面。

后续仅在真实样本显示独立工具链等待占主导时考虑：原型必须委托现有 Core admission 和 TaskSupervisor；逐个嵌套调用保留执行身份/权限/结果；不可通过脚本获得额外能力。对同一批实际任务比较模型往返次数、端到端 p50/p95、总 token、失败率和重启可恢复性，不能只比较单次脚本速度。

**CSV 批量代理暂不实现。** Codex 按 CSV 行建立 job item、稳定身份、结果提交及汇总导出；它不是普通 spawn_agent 的别名。当前需求没有明确的大规模逐行独立任务，不能为工具清单对齐造重复作业系统。少量独立工作继续通过现有子任务执行。

触发条件：真实批量任务需要逐项结构化结果、有限并发、失败重试与断点恢复。届时增加 TaskSupervisor 的 batch 聚合对象而非第二套 worker；行 ID 不等于可信指令，worker 结果 schema 校验、owner、幂等提交、取消传播复用现有契约。收益以失败项恢复成本与结果完整率验收。

上述两项是有条件延期的架构决策，不是声称 Nola 已有等价能力，也不是永久排除。

## 9. 权限夹具复跑发现的生命周期边界缺口

第二次 fixture 运行仍 exit 65，错误为 `Host invocation requires an explicit model endpoint`。该错误不能直接归因于第二轮模型配置丢失：共享断言末尾调用真实 `deleteSession`，CLI `SessionDelete` 先调用 `end_agent_core_session`，后执行 canonical delete；前者错误地获取完整模型 Host，因此纯生命周期操作也验证模型 endpoint。模型提交和生命周期关闭必须分离，不能为清理注入虚构 endpoint。

进一步检查发现，仅改成 checkpoint 恢复加 idle reducer 并不完整：Core `CloseSession` 无条件产生 `RunLifecycleHook(SessionEnd)`，而 Application `reduce_and_commit_idle_submission` 明确拒绝外部 Host effect。配置 endpoint 之后仍会暴露这一矛盾。现有实际执行器是 `CliAgentHost` 的 `RunLifecycleHook` 分支及 `run_lifecycle_hooks`，可以复用；现有 durable Host delivery/response 绑定 Run，不能通过在内存中执行 hook 或直接删除会话跳过账本。

修复约束：无模型的生命周期命令从当前严格 checkpoint 恢复；active Run、待处理输入和未知/进行中效果仍拒绝关闭；SessionEnd 按现有 Host effect 协议持久化、执行、确认后才能 canonical delete。不能清空 pending effects、伪造 Completed、吞掉 hook、自动改写不兼容 checkpoint，不能把验收清理失败误报为权限验收通过。

实施采用既有 Maintenance Run，不增加第二套执行账本。Application/Core 扩展 CloseSession maintenance admission；CLI 从当前 checkpoint 获取 Core 配置并使用同一 `CommittedRuntimeDriver` 交付效果。提取普通 driver 的共享 `LifecycleHookExecutor`，无模型 `LifecycleOnlyDriver` 只接受 SessionEnd，拒绝其他能力；warm Host 保留已安装 hook registry 和 handler。当前生产 cold CLI 没有注册 hook handler 的配置接线，此次不假称增加了冷启动插件 hook 支持。两个删除调用者不再构造模型配置。新增 `lifecycle_close_needs_no_model_endpoint_and_preserves_active_owner`，检查 active 原 checkpoint 不变、无模型 idle 关闭及幂等已关闭读取。等待统一编译和 fixture 复跑，尚不能计为通过。

后续审计纠正：原观察 hook 执行器在失败/超时时仅发布 LifecycleHookUpdated，而该事件不阻止 Core 接受外层 Completed；因此机械提取本身不足以保证“不删除”。新增仅关闭路径的严格成功要求：非法计划/规则/投影或非 Succeeded 结果立即返回错误，不发送 Completed；超时明确保留外部执行尚可能活动的不确定性。重复执行拒绝，不能由进程内去重转成成功；普通非阻塞观察 hook 语义保持。四个 `lifecycle_close_failure_tests` 覆盖失败、超时、非法计划/规则、重复及普通观察语义；真实超时夹具使用 100ms 通道等待，退出前显式释放并确认 handler 结束。当前新增失败分支测试待统一执行。
