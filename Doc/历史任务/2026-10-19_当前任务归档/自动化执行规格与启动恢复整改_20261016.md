# 自动化执行规格与启动恢复整改

本说明对应主任务 A01—A04。代码及测试源码已修改；尚未运行编译、测试、语法检查器或真实模型验收。生产数据库未修改。

## 规格与依赖

Mac `nola_orchestrate` 必须接收原始 `execution_spec`，校验 prompt、workspace、政策、Skill 与精确数据引用；保存、独立读回和 Host 准入使用同一个规格。Mac 定义 metadata 保存 `submittedExecutionSpecSHA256`，读回核对原提交对象及摘要。不能拿 Host 重建后的两份值相互证明。

个人数据引用只接受 `platform:contacts`、`platform:calendar`、`platform:reminders`、`platform:health`；不接受聚合别名。执行逐引用验证和读取，不调用全局平台数据刷新。准备服务使用该自动化 Store 的数据授权注册表。网页来源使用显式 UUID，与冻结引用一致，不由 Host 静默生成替代身份。CLI 创建路径保留原 prompt 与网页来源 ID，独立读回核对原提交规格；没有数据 adapter 的 Web Host 仍明确拒绝非空数据引用。

## 领取、准入与失败

底层 occurrence 的 `running` 状态保留现有租约表示；正式 observation 区分 `claimed`、`preparing`、`admission_pending`、`admitted`。Preparing/AdmissionRequested 是持久 worker facts；admitted 必须存在同事务提交的 Run binding，不能由进程启动或 HTTP 成功推导。

启动异常以当前 worker、lease、definition revision 提交。Store 在同一写事务检查 binding：没有 binding 时保存异常并关闭为 `launch_failed`，使迟到的准入请求失效；已经绑定时保存断连事实，保持原 Run。观测落库失败明确留下未对账状态，不假报完成。诊断按字符及序列化预算有界，保留截断标志。

running 租约过期不再允许直接重新领取。冷恢复先观察绑定；无绑定的过期记录以原 lease 原子 fencing 后关闭，不启动替代执行。恢复说明明确原始异常未知，不将恢复发现的过期状态编造为最初异常。已有绑定只恢复其精确 Run，副作用是否可重试仍由正式 Core 恢复协议决定。

启动失败没有 Run 或 Run terminal seal，因而不创建伪造的 execution receipt。Web 结果携带定义和 occurrence，Run/conversation 为 null，前端不生成对话跳转。

## 展示身份

Mac 活动记录使用 `AutomationIdentity` 分别携带 definitionID、occurrenceID、可选 runID 和 notificationID。任务卡按定义查找，正式通知身份用于投递去重。冷启动从 canonical occurrence/receipt 重建缺失活动投影。活动文件不匹配当前身份结构时明确报错并阻止自动覆盖，保留原文件；没有数据转换或旧字段别名。

## 后续统一验收

测试源码覆盖原规格冷读、Host 重写回执不构成原意图验证、引用不扩大、绑定前异常持久化、租约过期不重跑、准入 ACK 丢失不关闭已绑定 Run、阶段持久化、错误 revision fencing、通知与定义身份分离、无 Run 的 Web 失败及无跳转。

待主任务所有实现完成后统一编译测试，并使用隔离数据做真实模型/Host 与 Mac UI 验收。空个人数据集当前仍遵循已有“无可用上下文即准备失败”的保守行为；本批未将其伪报为成功读取，也未实测系统数据权限、通知展示或 UI 性能。
