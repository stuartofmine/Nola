# R03 远端辅助调用专用端口

约束：单一内部开发版本；不保留旧协议兼容、不做数据转换；不伪造 Run、不调用完整 Agent Run 代替物理请求、不在客户端与 Host 重复记 physical Attempt。先完成源码与回归源码，统一由根代理编译及真实本地 192 模型服务验收。

## 权威与协议

新增经过现有 mobile proof/bearer 验证、加密响应的 `auxiliary/invoke`、`auxiliary/inspect`、`auxiliary/cancel` 专用端口。请求绑定 expected_host_id、operation_id、attempt_id、场景、冻结模型 profile id/revision、输入及总超时。Host 从已验证访问凭据导出仅当前授权 epoch 有效的 opaque authority id，构造 SourceAuthority owner；绝不接受客户端 iOS Conversation UUID 作为 Host 本地 Conversation owner，也不接受客户端指定账本 owner。

模型必须来自 Host 当前启用的 configured profile 且 revision 一致，凭据经 Host vault 解析；每个 operation 最多一个物理请求，关闭自动 retry/fallback，不含工具。首次调用先 Admit、StartAttempt 原子落同一个 run_attempts 表，再发送一次物理模型请求；重复调用不得重发。response/inspect 均携带 source_host_id、operation/attempt 原始身份和账本 receipt；成功输出仅在终态账本持久后发布。网络丢失不代表失败，客户端保留 identity 并 inspect，不能换新 operation 自动重试。

取消先持久 cancellation intent 再通知活动 transport。断线或 Host 重启后仍 Running 的 Attempt 作为 unknown 未决，禁止重发；不伪造 provider 终态。provider 已结束但 usage 缺失记 unknown；有真实原始 usage 时记录 normalized counters 与 provider_raw。JSON 输出解码失败仍保留原始 usage。客户端只处理远端回执，不生成本地 physical row。

## 客户端与查询

LLMSummaryInvocation 在本地 Admit 前识别远端辅助能力并交由 WebAgentProvider 的专用方法；本地 provider 仍走原单账本路径。远端 provider 先查询 profile catalog，冻结选中 profile revision，再请求辅助端口。禁止复用原 generateSummaryStream 的完整 Run 实现。

供缓存/费用投影的窄接口：按 owner 与分页游标枚举 AuxiliaryOperation，按 operation_id 枚举同表 AuxiliaryModelAttempt；聚合必须区分 source authority、未知 coverage、provider raw 及 measured cache counters，不能跨 Host 把远端 receipt 再计一份物理行。具体实现及未完项见后续实施记录。

## 已落源码及边界

手动展示刷新已接：`ListConversationAuxiliarySources` 为 Conversation owner 返回 unknown/未决来源的最多16个引用及keyset cursor，不携历史输出；ModelService 按手动次数分页，同 paired Host 才 inspect/Observe，跳过其他 Host 并返回跳过/失败/待确认计数。ChatContextSheet 仅手动 reload 按钮调用异步刷新；Cancel 独立 onDiscard 只重载本地。ChatView 捕获 conversationID，await 后核对当前 owner 才更新 contextUsage/notice。普通读取与 token 更新不联网。

压缩资格：该 ContextSummary 是独立小型辅助摘要，不是热分叉。CLI 主压缩仍通过 `agent_host_driver_parts/compaction_summary.rs` / `PreparedModelRequest` / `CompactionFork` 复用已接受的原请求 prefix、tools 与 thinking。Swift `ChatManager.compactConversationContext`→`ContextManager.compactConversationCore` 当前为独立摘要后本地提交，不能宣称热分叉资格；未在本批扩大重写远端 Run 压缩协议。已有 Host Web compact 入口位于 `cli/src/web_parts/routes.rs` 的 conversation/compact 分支及 `compact_response`，内部调用 `compact_agent_core_session`（`core_agent_runtime.rs`）。

来源 physical owner 固定：`UNIQUE(source_host_id,operation_id)` 与 Store 同事务异 owner 检查，禁止同一来源 Attempt 在两个本地产品 owner 下重复归属。晚 usage 当前不是全量自动同步：`ModelService.refreshAuxiliarySource(scope:sourceHostID:operationID:)` 显式 inspect 同一来源并更新原 mirror、不派发物理请求，成功 ObserveSource 会触发实际 owner 的 projection invalidation；展示/手动刷新可接该窄接口。原来源凭据或路由不可用时明确失败，不替换成当前另一 Host。

- `auxiliary/prepare` 读取真实 Host 默认 configured profile/revision；`auxiliary/admit` 冻结 input_json 精确字节摘要及模型请求契约，返回 Ready 来源回执。Swift 本地 ObserveSource 成功后才调用 `auxiliary/invoke`，故初始网络结果丢失亦有持久原身份。`inspect/cancel` 仅接受同 source Host、同授权 epoch、同 operation、确定性 `operation_id:physical`。
- 远端 operation 硬限一个 Attempt。Chat Completions/Responses/Anthropic 均使用当前正式请求构造器，单次 HTTP 不重试、不 fallback、不调用工具。完整 HTTP 回应保存真实 raw usage（包括输出 JSON 失败）；发送/读取超时不宣称物理终态，保留 Running/unknown，禁止换身份自动重发。取消意图持久后通知执行 context；HTTP 总时长有界，不能将“已请求取消”伪报为 provider 已停止，晚到 usage 仍在原 Attempt。
- `AuxiliarySourceObservation` 仅在 `auxiliary_source_observations` 保存来源回执，不在本地 run_attempts 插入第二行；Ready 允许 attempt:null，开始后必须有唯一 exact Attempt。拒绝假本地 Conversation owner、跨 Host、替换冻结配置、回退 revision、已测 usage→unknown、同 local owner 本地 physical operation 重复包装。Attempt.output 随终态原子保存，丢失输出可 inspect。
- 本地辅助 ledger 与来源 ObserveSource 在同一 Store 事务只增加 conversation.revision，Application 实际 command receipt 路径按真实 owner 发 bounded projection invalidation；不修改 configuration_revision。owner 查询及镜像查询有 scope expression index。
- Rust 与 Swift 实现已实际编译，主代理已完成统一 Rust 验证及真实 192 服务验收：远端辅助共 2 次真实 HTTP（成功与丢弃真实响应），unknown 持久化、重启后重复 invoke 不产生新 HTTP，证据 `/tmp/nola-real-auxiliary-be3bc8aa7dec4288a725fd3299839e18.json`。iOS 先前未完整封装批次中，远端成功、取消、foreignHost 拒绝、丢响应 inspect、unknown 不重发、新 UUID 不绕未决 slot 共 6 个用例有实际通过日志；它们不是完整正式结果包。最后修正的来源终态释放 slot 用例与只读分类、缺失查询无 pending mutation、真实 pending 写入不可越过共 4 条，已正式 4/0/0 通过（`/tmp/nola-r03-ios-20261015-10.xcresult`）。Mac 相关 12 suite 正式 122/0/0 通过。早先全量失败及 partial 结果仍如实保留，详见运行与恢复实施，不宣称全端真机覆盖。

调用方恢复边界：已有 operationID 可从本地镜像继续 inspect 原来源。Scheduler/ProcessingAgent 当前没有持久批次 invocation intent，不能把相同内容或候选集合摘要当同一逻辑请求。已落实明确的 local_owner+scenario 单未决 worker slot（跨 source Host 亦不能换 Host 绕过），Store partial UNIQUE index 在并发 ObserveSource 时兜底；新逻辑请求遇到前次 Ready/Running，仅 inspect 原来源，未终态即返回带旧身份的 ScopeBlocked，不新派发、不把旧输出交给新输入。旧终态单调落库才释放 slot。相同 operationID 的显式重进仍恢复原操作。此为资源未决门禁而非内容去重，也不伪造 Task/Run；更完整 occurrence/job durable intent 可在调用方真实工作流中独立扩展。

真实服务验收脚本：`NOLA_RUN_LIVE_AUXILIARY_E2E=1 python3 scripts/test_real_remote_auxiliary.py --binary <CLI nola路径> --config /Users/gaojc/.nola/config.json`。必须使用支持 `web` 子命令的 CLI `nola`，不能传独立 `nola-service`。脚本只创建隔离 Host 数据库；读取配置但不打印凭据，真实模型 HTTP 与故意丢弃真实响应的 unknown 恢复分别验证，不模拟模型输出。

Swift 平台边界：纯 Codable/Sendable `AgentCoreJSONValue` 只有一个定义，位于两端已共享编译的 `LLMClient.swift`，供真实 usage DTO 共同使用；依赖 `IOSApplicationRuntime` 的 `LLMSummaryInvocation` 与 scope wire 实现仅在 iOS 编译。Mac 当前没有该 invocation 调用者，不引入 iOS runtime，也不制造无账本物理调用或 unsupported 替身 API。

验证暴露的分类遗漏已修：Swift 将 `inspect_source` 与辅助 slot/operation/page 查询归入只读观察，查询缺失不得生成 pending mutation journal；否则首次正常不存在的 source lookup 会阻断随后 ObserveSource。新增缺失查询不留 pending、后续写入可执行的回归。仍存架构项：Swift 只读集合当前是 Core `is_read_only_query` 的手写保守子集，并未消除双份语义。现有 FFI `application_execute` 通过门禁后会实际执行查询，不是纯分类入口；后续应提供 Core 严格解析的纯 command classification 契约或生成接口，不能把实际执行当分类探针，也不能用未知命令默认只读。
