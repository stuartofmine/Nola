## 文件约束声明与执行闭合：候选设计，暂不实施

### 现有能力核对与待选路线

现有PermissionRule仅有capability/resource/decision/source，没有按NewFile/Overwrite/Delete匹配的任务限制；这些风险是Host观察后的审批依据。已有`absent:v1`、锁内预像与原子no-clobber可以支持保守create-only：保护激活后只允许受控结构化工具新建当前不存在的目标，已有路径拒绝。这不是回合开始全量快照，且会保护激活后其他主体新建的文件。若允许修改本Run新工件，还需正式创建回执及版本绑定的可恢复归属索引。

最小闭合版本必须同时拒绝无法证明副作用范围的shell、MCP、插件、子代理及写入后的外部formatter，不能只限制write_file。现有macOS显式路径只读保护不足以直接实现任意目录的动态create-only。因此它会改变工作流能力，不作为一次模型失败的默认补丁。当前已向用户列出三条路线：更强模型对照、完整任务文件约束、或保留失败并交付已验证整改；等待方向，不先添加不可绕行保证不完整的机制。

本节评估一个通用能力缺口，不将单次模型失败自动升级为新的必做强制流程。当前没有新增文件 ledger、模型调用、权限策略或执行器；是否实施应根据 Host 可执行性及成本整体决定。首次语义解释仍由模型作出，持久化不能证明解释正确。

### 已有机制及不能替代的责任

- [ExecutionConstraintLedger](../../../core/nola-agent-engine/src/agent/runtime/execution_constraints.rs) 已包含不可就地修改的 entries、原 `source_input_refs`、用户输入 frontier、来源 scope，以及 `replaces_constraint_id`。输入来自 Core 已准入的 message/admission，声明来自当前模型调用的冻结 requirement binding；模型不能引用自己的回答或工具错误作为用户许可。
- 该 ledger 的 suspend/bind 保留历史来源，而不将旧要求伪装成新回合输入。当前 [领域类型](../../../core/nola-domain/src/execution_constraints.rs) **仅有 BrowserTarget**；[工具准入](../../../core/nola-agent-engine/src/agent/runtime/tool_driver.rs) 在权限解析和派发前验证目标，不能据此声称已有文件保护。
- plan `success_criteria`、requirements assessment 和 Goal 文本是任务/证据描述，不是文件系统执行隔离。现有权限风险与资源计划可以复用，但“可申请覆写权限”不等于“本任务允许覆写”；自动批准也不应解除任务约束。
- [ProcessPreservation](../../../cli/src/tools/parts/process_preservation.rs) 已能在 macOS 给被保护资源及祖先删除设置进程限制，当前连接的是 Git 保存边界，不是任意文件约束。不能只增加 write_file 的检查，却允许 bash、MCP、子代理或远端工具绕行。

### 候选契约及所有权

模型可在需要执行文件副作用时，通过同一个 execution-constraint 通道声明文件操作约束，而不是修改 plan 文本充当授权。候选策略为 `read_only`、`create_only`、显式范围的 `scoped_mutation`；没有用户文件限制时是否需要显式 `unconstrained` 属于待决产品成本，不默认让所有对话多走一个必调工具。该声明不是完成评估，不要求 requirements_update，也不增加独立模型评审。

声明至少绑定：当前 scope/Run、已准入用户输入引用、当前用户 frontier、实际 Host/root 身份、策略及资源范围、解释理由、上一声明 ID。根路径和文件身份须经 Host 解析确认，模型提供的路径只是请求。Core 使用当前冻结输入 binding 验证来源；不得以自然语言关键词生成或授权约束。原始输入保持可追溯，压缩只改变展示，不改变约束来源。

**同一用户 frontier 内只允许重复确认或收紧，禁止放松。** 声明错误不能靠工具失败后改成 unconstrained 解除。放松必须引用后续真正准入的用户方向并精确替换旧声明，应用到新的执行边界；旧调用仍受原冻结版本约束。新用户插入当前执行时，必须先停在准入边界，不能让旧已批准调用借新声明换参数。新用户输入本身也不证明确实要求放松，语义仍由模型解释；若需高保证，应由用户确认明确的结构化范围，而不是声称引用 ID 能验证自然语言含义。

### “已有文件”的时间基准

必须分开三个身份：会话、当前 Run/用户输入边界、文件。不能按“是助手写的”或“Git 未跟踪”判新旧。

- 基准绑定本轮用户请求开始的 Host 观察快照及其根目录身份；首轮生成的审计文件在第二轮基准中属于已有文件。
- `create_only` 允许通过原子不存在检查首次创建；成功创建回执登记 `created_by_run` 及版本。若产品允许完善本轮新产物，同 Run 后续修改仅能操作具有该真实创建回执、当前版本仍匹配且没有外部接管证据的文件；模型自报来源不算。
- 下一 Run 不继承 `created_by_run` 豁免。需要修改先前产物时，必须有当前用户范围允许的策略，不能凭会话作者身份放行。
- 精确保护“回合开始时已有的全部文件”需要有界完整清单；按首次访问时存在性判断只能提供更窄/不同保证，必须另命名，不能冒充开始时快照。根不可读、超预算、清单不完整或文件身份不稳定时不得给出完整保护承诺。
- 不在每次对话无条件扫描整仓库。若采用用户声明后才采集基准，须证明此前没有相应副作用，并清楚将时间定义为保护激活边界；不能回溯伪造回合开始时状态。全根精确保护与启动延迟的取舍是实施前必须决定的成本。

### 所有执行入口的闭合条件

| 入口 | 必需能力 | 无法证明时 |
|---|---|---|
| 结构化文件工具、patch、rename | 用同一资源解析结果检查全部读写/删除/源目标；锁内复核版本和约束 revision；新增文件原子创建；结果记录实际效果 | 准入前明确拒绝；执行后观察不确定保留 unknown，不自动回滚用户数据 |
| shell、脚本、构建、后台进程 | Host 将同一冻结约束编译为有效进程树限制；覆盖 rename/unlink、父目录移动、链接及工具可访问其他路径 | 不把 operation_kind=inspect、输出声明或退出零视为证明；无可用隔离后端则拒绝该不透明调用 |
| MCP、插件、远端工具 | 真实 Host 声明并验证该操作的资源效果契约，或在可控沙盒中执行；远端身份、约束摘要、版本与执行回执绑定 | 没有资源语义/隔离证明的工具在受保护范围内不可执行；不能默认相信模型或插件自报只读 |
| 子代理 | 派发时继承约束来源和不可扩大的有效策略；子任务独立权限不得扩大父任务约束；共享工作区使用同一资源账本 | 派发拒绝或缩小到可强制的只读工作，不复制成可任意改写的提示文本 |
| Mac/iOS/Android/Web | 客户端投影同一 Core 决策，实际执行 Host 报告支持矩阵；远端执行能力不能由客户端 OS 推断 | 不支持时给机器可读原因和用户可理解说明，不回退为无保护执行 |

已冻结调用应绑定 `constraint_revision` 与基准摘要，恢复时验证相同来源/版本，不以当前 UI 配置代替。未知效果不得通过删除约束或重放解决。约束冲突返回具体资源、动作与声明来源，明确不是“再点全部允许即可”。

### 实施门槛及有界验收

实施前须先完成：Host 基准模型和预算、结构化工具资源闭包、opaque 进程/远端支持矩阵、子代理继承及跨端错误投影。仅添加 Core enum 和 write_file guard 不构成完整实现，反而会造成虚假的安全保证。可选择先交付明确受限的结构化文件策略，**但必须拒绝所有不能保证该策略的旁路**，不能默许 shell/MCP 回退。

有界验收应涵盖：本轮新建后修改、下一轮同文件变已有、旧用户引用不能放松、插入新用户输入使旧准入失效、压缩/冷恢复约束不变、batch 内先声明后执行、patch/rename 多资源、shell 绕行拒绝、MCP 未知效果拒绝、子代理不扩大、外部版本变化及 unknown 结果。真实模型样本检验解释和完成任务；确定性测试检验约束实施，两类证据不能互相替代。无需增加强制完成评估，也不以该设计保证模型首次判断永远正确。

### 2026-10-18 只读核对：保守 create-only 的边界

`PermissionRule` 只有 capability/resource/decision/source，虽支持 Turn 来源，却没有 risk/effect 匹配条件。Host 的 NewFile/Overwrite/Delete 观察目前影响确认需求，并非独立不可放松的任务限制。可以复用 `file_mutations.rs` 的 absent:v1、锁内预像复核，以及 `checkpoints_review.rs` 的原子 no-clobber 和 ResourceEffect，在保护激活后仅允许实际不存在的目标；已有目标默认拒绝，本 Run 新建工件的再次编辑须有同身份、同版本的正式回执。这里是**保护激活边界，不是回合开始的全仓快照**；对激活后外部新建的文件也拒绝，是保守加强而非精确历史重建。

现有 macOS ProcessPreservation 保护显式路径，不是动态 create-only 文件系统策略；Git 调用还有 unrestricted 跳过分支，不能直接当成任务约束。无覆盖性隔离时必须拒绝 shell/MCP/插件/子代理旁路，也必须处理 write_file 后的外部 formatter。若要求保留这些工作流，则需要额外 Host 隔离设计。因此此候选当前不实施，不由一次失败扩成强制机制；它与下面已选择的结构化任务范围整改不同。

## 2026-10-18 已选择方案：可选结构化任务范围清单

### 已有接口与实际缺口

- `requirements.rs` 内部 `ControlOperation::ReviseScope` 已支持新增 requirements、retain/replace/withdraw dispositions、来源引用和依赖；scope revision/frontier CAS、事务失败回滚、来源与旧 requirement 完整处置已有实现。
- 但模型可见 `requirements_update` schema 只有 outcome/answer/assessments；`requirement_control.rs::bind_model_task_result` 只绑定最终结果。它声明会结束回合，**模型目前不能使用内部 revise_scope 来规划或细化 r1**。仅更新提示词让模型“拆分需求”无法解决接口不可达。
- `RunRequirement` 当前只有 description/source_refs/dependency_ids/goal_requirement_ref，没有结构化对象清单、用户排除与助手建议的区分。单个默认 r1 的笼统 description 不能机械比对全体对象与执行子集。
- ConversationPlan 保存步骤与执行引用，可展示/调度工作，但不应成为第二份权威范围。范围归 Core requirements，计划只引用该范围并消费投影。

### 最小完整接口与所有权

保留当前最终结果工具语义；新增一个**可选、非终结**范围更新入口，复用内部 ReviseScope，而不暴露内部 ID/CAS 让模型拼写。模型使用冻结请求中的 rN/uN/eN 等别名；Host/Core binder 解析为同一请求绑定的真实 ID、scope revision 和 input frontier。新入口允许：细化 r1 为多个具名交付项、显式处置每个原条目、补充对象清单。不是独立评估请求，不强制每轮调用，不增加模型前置调用，不从用户语言关键词触发。

建议把对象清单附于 requirement（可空），而非新建平行 ledger。每项至少包含本地 key、目标对象引用、预期动作/交付说明、来源分类与引用。对象必须来自已观察的资源或模型明确声明的待解析目标；后者不能伪称 Host 已确认身份。新对象以已有 eN/资源引用绑定 Host 观察时，才能核对 receipt 的规范 resource_uri。实际字段命名由实施方统一，不能把任意路径文本当已验证实体。

来源明确区分：用户要求、用户排除、助手建议。用户排除须引用当前范围中真实 user 输入，助手推断/建议不得自动升级成用户排除。来源引用只证明输入存在，不证明语义正确；系统不做自然语言真值判断。未经用户采纳的助手建议可以列出，但不能缩减原需求或制造用户授权。当前 r1 细化时必须以 replace 的 successors 显式承接，禁止静默丢弃旧条目；如无需细化，也可保留 r1 并附对象集合。

### 声明覆盖与执行覆盖分离

对已声明对象，用既有工具观察和正式 ExecutionReceipt 比对：未执行、已有匹配动作/版本的效果、效果未知、版本后续失效。失败 receipt 的已发生效果不能忽略；成功进程退出不等于对象覆盖。仅 resource_uri 相同不够，还应核对动作和相关版本；不支持的工具效果只能标记未知。

此检查只能证明“声明对象集合的执行覆盖”，不能证明声明集合穷尽自然语言请求，也不能凭一次 git 子集提交认定全任务完成。目录检索结果中遗漏的对象仍须模型解释并保留未确认状态；用户排除和助手建议分别展示。清单是任务状态，不是安全权限；不据此自动 git add 全部、不自动提交、不产生 shell 文件禁写策略。

### 持久化、计划接线与验收

清单随现有 requirement scope/revision/source event 与 checkpoint 保存、压缩后重建投影；新 CurrentTurn 输入使旧请求绑定失效。计划若关联 requirement，使用稳定 ID 与版本并显式处理修订，不复制可独立修改的范围文本。后续独立 Run 的继承须保留原用户来源和本轮采纳关系，不能把助手总结当新用户排除。

确定性验收覆盖：模型可见非终结入口实际可调用；单 r1 细化与保留；来源角色拒绝；漏 disposition 回滚；旧 revision/frontier 拒绝；声明两对象而 receipt 只有一对象时另一仍未覆盖；失败/未知/后续改写不误报；压缩冷恢复保留清单；未调用范围工具的直接回答仍可完成。真实多轮样本保留原路径与保护断言，不放宽 oracle；清单改善可核查性，不宣称保证模型不会首次遗漏。

本节为实施设计；本次文档变更未修改生产代码、未运行测试。

### 实施接线（2026-10-18，待统一测试）

已增加可选非终结 `task_scope_update` schema 与 Core 调度，复用 ReviseScope，不改变直接回答或最终评估的可选性。冻结请求包含 sN 来源和真实 user 子集；Domain binder 解析别名并注入 frontier，模型不能指定 frontier。Declared 清单持久化到 RunRequirement；同 frontier 保留旧 required，实际缩减须新增用户来源及显式处置。来源仍是模型解释，不等于用户接受或授权。

独立 `task_scope_coverage.rs` 对 satisfied 做声明对象覆盖核验：无 predicate 时匹配真实 effect 的资源/动作/版本；有 predicate 时匹配同 receipt 的操作与该资源的 passed Postcondition/版本，因此 Git 可用真实 `.git` effect + 每路径 check，不伪造源文件写入。process_exit 不代替后置条件；只把相关版本的实际变更视为失效，不把读取或内容 hash 与不可变 commit SHA 混比。新增 Core/coverage unit 尚待主代理统一执行，当前不宣称通过真实多轮样本。
