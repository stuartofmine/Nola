# Android 本地草稿聚合

未发送草稿以持久 UUID 标识；文本、安全附件及模型身份/生成参数属于同一快照。
模型只存 profile/id/source 等公开身份，不存端点凭据；恢复后仍通过模型目录解析执行配置。
已有 canonical 会话不从草稿恢复配置，草稿只保存其输入文本和附件。

仓储使用设备 noBackupFilesDir，单进程串行队列与跨进程文件锁包围读取、revision CAS、
原子替换。实例首次读取的 revision 为编辑基线；写入成功才前进，冲突不可读取最新版本后
自动覆盖。删除留下不含正文的墓碑，旧实例不能复活；提交已有会话输入使用清空快照而非
删除整个会话草稿身份。未发送身份提交后退休并生成新身份。

输入层保留冲突的本地文本/附件，显示保存失败提示；切换仅恢复目标 owner，不保存当前
全局配置到目标。模型/参数编辑捕获未发送 UUID，防止两个 null conversationID 混淆。

本轮先完成实现及回归用例，不运行构建，由主代理统一验证。真实多窗口 UI、跨进程文件锁
系统行为与重启交互仍需设备验收，不以纯仓储测试替代。

## 实施状态

- `ConversationDraftRepository` 增加 owner/revision/deleted envelope；单队列加文件锁，CAS失败不
  前进编辑基线。删除落墓碑；未发送配置与文本原子保存，限制快照大小，canonical owner拒绝配置。
  附件JSON按UUID+内容摘要不可变存储，manifest引用具体版本；CAS在写blob前检查，manifest失败
  或另一owner重用附件UUID均不能改动旧快照内容。读取验证摘要。
  退休未发送owner时仅在pending索引仍指向它时更新索引；重启在锁内检测索引指向的墓碑并
  分配新身份，修复“墓碑已写、索引未写”中断窗口，不替换其他窗口已创建的新pending。
  显式用户删除与提交退休分开：提交前校验编辑revision，退休再次CAS，只有成功才移除内存
  输入/导入owner。失败不发模型请求、不删除另一窗口文本。新建canonical会话与本地退休仍是
  两个存储事务，竞争失败可能留下空canonical会话，不能宣称跨存储原子提交。
- `ConversationComposerDrafts` 保持本地冲突输入并发布保存错误；未发送身份提交退休，已有会话
  提交只清空草稿快照，后续输入不被删除墓碑误拒绝。迟到配置编辑按pending UUID拒绝。
- `ChatViewModel` 启动恢复未发送配置，恢复存在的未发送草稿时不跳到最近会话；新草稿重新使用
  应用默认，而非复制上一会话参数。模型切换和参数编辑显式写原pending owner。
  自动目录默认值标记 `userConfigured=false`，空默认草稿不阻断最近会话恢复；有文本/附件或
  用户显式修改配置才恢复pending。目录异步读取捕获请求序号、selection generation与草稿UUID，
  只允许原owner应用模型/参数与持久化；应用级模型列表可独立更新。最近会话读取返回时再次检查。
- 新增用例覆盖跨实例CAS、删除重建防复活、配置恢复/canonical拒绝配置、提交后继续输入、
  迟到pending配置、冲突文本保留及错误提示。仅静态审查，等待统一运行。

剩余边界：模型公开身份沿用现有 `ModelInfo`（不含token/API key），实际凭据仍由模型目录获取；
全端 modelSelectionID 统一非本模块。附件资源GC未实现；跨窗口冲突需先复制本地文本后显式重开，
不提供强制覆盖按钮。同步读取仍等待后台写队列，需要设备量测重附件场景；本轮不宣称性能数字。
