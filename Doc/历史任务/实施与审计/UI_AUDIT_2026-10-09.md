## 优先整改的交互契约

### 1. 保存必须有明确的事务边界

Android 的 API 配置调用异步保存后立即关闭弹层；编辑字段只存在于弹层的 `remember` 状态。保存失败时，父状态保留旧配置，重新打开不能恢复本次草稿。依据：`android/app/src/main/java/com/nola/ui/screen/models/ModelsScreen.kt:150`、`:1076`；`ModelsViewModel.kt:379`。

iOS 的 API 配置保存失败会保留弹层，但错误写到被遮住的父页 `statusMessage`，弹层自身没有接收错误内容。依据：`Nola/UI/ModelsView.swift:131`、`:801`。

统一为 `draft → saving → saved / failed`：成功后再关闭；失败就地呈现原因并保留输入；保存中防重复提交；取消与放弃修改含义明确。自动保存页面则必须可感知保存状态，不与显式取消混用。

### 2. 页面内容与呈现方式分离

Android 数据页使用局部 `activeScreen` 切换子页，并未将这些子页纳入导航栈；需要让顶部返回与系统返回遵循同一状态转换。依据：`android/app/src/main/java/com/nola/ui/screen/home/HomeScreen.kt:75`。实际返回手势行为待设备验收。

iOS 智能面板同时被 Tab、push 和 sheet 使用，但页面本身隐藏导航栏。Tab 的外观选择不应强加给 push 或模态入口。依据：`Nola/UI/Chat/PersonalIntelligenceDashboardView.swift:81`；调用入口见 `MainTabView.swift`、`SettingsView.swift`、`ChatBubble.swift`、`ChatMoreSettingsSheet.swift`。

应由呈现容器管理标题、返回、关闭和未保存保护，内容页管理业务内容；避免每个复用入口自行修补退出按钮。

### 3. 删除操作必须说明范围并提供恢复或确认

Mac 会话菜单直接调用删除；实际删除链路不仅移除列表项，还清除草稿、附件引用及会话工作空间。菜单没有表达这一范围，也没有确认或 Undo。依据：`NolaMac/Features/Sidebar/MacConversationSidebarView.swift:273`；`NolaMac/Features/Chat/MacWorkspaceModel.swift:1667`、`:1687`。

应区分移除展示、删除会话记录、删除工作空间文件。不能只把按钮染成红色就视为已告知后果。

### 4. 无障碍与布局应成为组件契约

逐平台报告记录了无标签图标操作、仅点击手势的交互、固定小字号及缺少滚动容器的表单。共同治理点是共享组件的语义标签、键盘焦点、触控区域、长文案与大字体适配，而不是逐屏补局部尺寸。

Apple 平台参考 apple-design 附带 HIG 的 `accessibility.md`、`layout.md`、`windows.md` 和 `modality.md`。Android 采用自身导航、返回与 Material 组件语义，不照搬 Apple 的窗口行为。具体缺陷和适用规则见平台报告。
