### 当前权限整改的准确边界

- 已接线：请求来源保存、关闭事务、取消与批准仲裁；去除 CLI 项目根自动扩大、
  Host 替换 Core resource、Conversation 数据隐式 glob 等入口。具体范围和测试见专题。
- 只有纯契约：`permission_resource_plan` 的提取/关联、`permission_scope` 的 matcher、
  frozen offers 和 selection。它们不能授予执行权，不证明 Host 来源或资源新鲜度。
- 待纵向完成：资源声明→目标 Host 解析→Core 决定主体/范围→Application 绑定 canonical offers→Store 选择事务→
  统一 grant 消费→Host 执行前身份复核→真实客户端展示与恢复；完成后删除旧字符串路径。
  原始 Core 决定不得携带猜测的数据库 Run 身份，分工及拒绝顺序见
  [A09 生产接线契约](../../软件架构设计/模块/05-执行与恢复/RECOVERY_AND_AUTHORITY.md#a09typed-资源到授权消费的生产接线契约)。
- `/allow` 的 Turn 显式策略不是某次调用的 Conversation 授权：前者允许配置通配且
  限 live origin，后者不能从输入中的星号制造通配。两者不能为统一表面类型而混淆。

## 单一当前版本政策

项目尚未发布，只维护当前协议、checkpoint 和数据库 schema；不提供旧版本升级链、字段别名、
缺失必填字段的兼容默认或旧格式猜测。版本标记用于拒绝不匹配，不代表维护多版本。
全新空库一次事务建立当前结构；已有不匹配库明确拒绝，不自动迁移、重建或删除用户数据。
测试使用隔离新库；旧版本专属迁移测试删除，当前格式的损坏、原子性、幂等与拒绝错误版本仍须覆盖。
历史执行记录中的迁移说明只描述当时结果，不是当前支持承诺。合法第三方协议适配、可选字段的
业务默认以及读取当前格式的历史消息，不属于旧版本兼容，不能据名称一并删除。

```text
       │          纯语义决定                │
       └────── Store 原子提交 ◄────────────┘
                    │
          committed outbox / projection cursor
              ┌─────┴────────────────────┐
              ▼                          ▼
       Runtime supervisor           Client projection
              │                          │
              ▼                          ▼
       Host adapters                Native / Svelte / CLI presentation
       模型 / 工具 / OS
              │ Receipt / Observation（不是业务状态写入）
              └────────► Application
```

Core 的“状态所有权”指唯一语义决定权；Store 的“事实所有权”指唯一已提交记录。
两者不是两个独立状态机。Application 协调提交；Host 的进程句柄、客户端的展示缓存均不具有事实权威。
网络断线仅是观察状态改变，不证明运行失败；模型 stop 仅是请求结束，不证明任务完成。

### 重试时必须保持哪一种身份

不同层的身份不能互相替代，尤其不能把“已读到消息”当作“操作已提交”。

| 边界 | 身份与唯一所有者 | 重试规则 |
|---|---|---|
| 客户端发送意图 | 客户端 journal 保存原 request ID、owner 和完整载荷 | ACK 不明时先查原 receipt；不得生成新 ID 伪装恢复 |
| Application 提交 | Store received-command receipt | 同请求重放返回原提交事实，内容冲突明确拒绝 |
| Goal 语义命令 | Core GoalProjection 的 operation ID 与命令摘要 | 即使换了传输请求，也不重复执行；改时间或 CAS 同样属于内容冲突 |
| Host 副作用 | 已提交 effect、attempt 与当前执行权 | 没有结果不等于没执行；未知副作用走显式恢复协议 |
| 展示与订阅 | canonical projection cursor / Run seal | 游标只决定读取和去重，不能授予执行权或完成任务 |

Goal 语义重放返回当前投影，不回灌历史快照，也不冒称原传输回执。
新的外层提交可能推进 Store CAS revision，但不得据此伪造新的 Goal 进展或执行事件。
具体实现状态及待执行反例见对应专题契约与 VERIFICATION；本表不代表已完成运行验收。

## 不变量与删除目标

- INV-01：副作用派发必须引用已提交 effect；相同 effect 不因重连产生新执行身份。
- INV-02：启动执行的用户提交在幂等作用域内只有一个 Run 和稳定的初始 Assistant Message；
  同轮 steering 追加到当前执行范围，排队的新轮通过独立准入启动新 Run。
  后续 Assistant Message 必须有显式消息准入，不得从重放或客户端推断生成。
- INV-03：Host 只报告其能观察的事实，不能把模型声明、exit=0、展示文本提升为任务完成证明。
- INV-04：TaskOutcome 与 Run 生命周期、工具执行状态、证据状态分别建模。
- INV-05：原始 transcript 不被压缩覆盖；摘要、工作集、缓存快照都是有来源引用的派生数据。
- INV-06：授权身份绑定具体能力与资源，不能从自然语言、工具名或 UI 勾选状态猜测。
- INV-07：任何等待/受阻状态有 reason、owner、可观察的解除条件；没有自动恢复动作就不排队重试。
- INV-08：只有新事实、有效重试策略或明确用户操作才触发下一次执行；不得原样请求模型消除内部记账错误。
- INV-09：未提交内容不 ACK、不发布；重放不得重复记账、生成消息或触发副作用。
- INV-10：UI 从已提交业务投影恢复；删除诊断 Trace 不损坏正文、权限、任务与统计。
- INV-11：模型配置每次 Attempt 冻结；凭据不入业务 JSON、日志或快照。
- INV-12：文档目标、代码实现、实际验收三者分别记录，缺一不能标记整改完成。

删除的是重复语义与无合法出口的控制逻辑，不是机械删除目录。
优先消除：布尔验证债务作为唯一收尾条件、Host 自定任务终态、客户端以连接状态覆盖 Run、
Trace 恢复业务事实、维护请求自设生成上限、不同客户端重复解析模型配置。
当前尚未逐项证明这些重复逻辑已全部清除。

## 变更纪律

每个架构变更必须同时说明：契约 ID、反例、涉及模块、事务边界、状态转换、性能影响、测试及尚未覆盖的环境。
不得以“多加一次重试”“放宽成功条件”“硬编码命令关键词”替代缺失的跨模块契约。
产品未发布，不新增旧接口兼容分支；用户现存数据库也不能因开发规则被自动清空。
协议切换须有明确的不匹配错误与受控开发重建流程，破坏性数据操作另行获得授权。
