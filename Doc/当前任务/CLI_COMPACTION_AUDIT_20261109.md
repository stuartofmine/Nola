## 修复

- 软阈值维护要求归档估算减去摘要预算及封装后，预计至少回收 512 个历史估算 token。小归档继续积累；手动压缩、provider 超限恢复和完整请求达到硬上限时不受此软门槛限制。后续完整请求仍经过硬预算准入。
- 压缩请求与完成后的用量保留非历史成本及普通业务校准；进展比较历史工作集的前后估算。维护费用仍累计，维护请求不校准业务请求。
- 热摘要、续写和改写保留完整工具目录，但显式禁用工具调用；provider 违规返回工具调用时仍拒绝摘要，绝不执行。
- OpenAI 的 auto/none 共用稳定前缀诊断身份；Anthropic 在修改 tool_choice 会丢失消息缓存时走同一模型的有界冷摘要。外部依据：[OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[Anthropic Tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)。最终缓存命中仍由实际 provider usage 证明。

实现契约见 [上下文与计量](../软件架构设计/模块/09-上下文与压缩/CONTEXT_AND_ACCOUNTING.md)。没有新增历史格式兼容或数据转换。
