# 首次压缩直接要求完整上下文减半

## 当前行为

第一次摘要请求即写入“完整上下文输入至少减少 50%”，并给出压缩前完整输入估算、减半后的目标、已扣除保留内容和固定开销的摘要大小上限。50% 是完整输入的相对减量，不是只缩短归档文本，也不是窗口占用降到 50%。

Core 在调用模型前决定范围：近期事务和旧摘要能放进减半预算时保留它们；否则第一次请求直接合并旧摘要与全部已完成历史，要求生成一份完整摘要。已删除“普通压缩后不足 50% 再启动交接”的判定和调用路径。提交第一份有效摘要后直接继续或结束维护，不按减量比例默认追加第二轮。

最新用户请求、系统指令、附件、未结束及异常工具事务保持原文，call/result 不拆散。原始历史、来源指纹、权限边界和校准开销不变。维护收尾保留完整请求估算，不退回只有历史大小的数字。

固定内容可能使完整上下文无法减半。此时仍在首次请求中要求尽力压缩，并给出合理的有界摘要预算；不强制一 token 摘要、不删约束、不提高窗口，也不伪报达标。模型输出截断或超出已准入摘要预算，仍按原有有界续写/改写合同处理；这不属于默认再执行一轮压缩。

## 回归与真实模型验收

合同测试核对首次请求中的 50% 文案及具体目标数字、首次范围选择、旧摘要合并、冷恢复同一次请求、提交后不产生第二个 Compact，以及收尾计量保留固定前缀。

真实模型测试使用当前选定模型与透明转发，隔离数据库和项目。窗口 65536、阈值 45875（约 70%），用合成历史制造压力，再通过真实交互式 `/compact` 验证首次摘要。实际请求体由只读 observer 检查，确认第一次摘要已经携带完整上下文减半目标。旧随机事实只在归档的用户消息及摘要中，项目文件没有该事实；冷启动且禁用工具后检查精确召回。此专项不算新的数百步验收。

## 首次请求方案的真实结果

构建 SHA-256 `c48ac3add33b2cacb7723c1c841cd5f251e0c0838285b616dbb66a538566e471`，证据 `nola-real-handoff-49wn683m`：当前已选模型 `gpt-6.1-terra` 共 **4 次真实请求全部成功**，仅 **1 次摘要请求**。只读 wire observer 确认第一次摘要已经携带完整上下文减半目标；Core 事件也只有一次请求与一次提交，没有后续比例补救。来源指纹重算、原始历史保留及冷启动精确召回全部通过，零注入回复、零传输错误。

同一压力夹具的两阶段基线为 5 次真实请求和 2 次摘要；当前改为 4 次和 1 次。占用从 47116（71.89%）到首次摘要并收尾后的估算 34904（53.26%）。该大输入样例仍未整体减半，不能将明确写入目标等同于达标；当前用户原文仍完整保留。

所有实际请求输入加已准入输出均在 65536 窗口内。完整输入最大 47912，加输出额度的最大分配为 56104，未越过 54068 的估算输入准入线。夹具为合成日志压力测试，不与自然数百步任务混为同一验收。

## 回归与构建结果

CLI 全量 2360 项通过、8 项忽略；Core engine 593 项、Kernel 195 项、Core Host 合同 158 项、压缩重试/冷恢复 5 项、摘要预算 3 项、Application 压缩事务持久化 1 项均通过。独立证据及夹具隔离 12 项通过。

首次构建的 strip 因磁盘空间不足失败并留下无效可执行文件，该输出未用于验收；清理本次公开克隆中明确命名的旧生成构建产物后，删除无效输出并重新链接，得到上述经过真实调用验证的构建。用户数据、源文件和已有验收记录没有删除。Apple 链接器既有的较大 unwind section 警告仍存在。
