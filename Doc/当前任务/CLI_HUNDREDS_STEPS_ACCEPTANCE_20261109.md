# CLI 数百步真实模型验收

日期：2026-11-09。范围：macOS Apple Silicon 的生产 CLI 与共享 Core。使用已有默认模型 `gpt-6.1-terra`、OpenAI Responses；未创建或更换凭据。这里只证明所列受控文件审计与权限流程，不代表其他平台实机、任意开发项目或数百次写入/外部调用均已通过。

## 最终通过

- 同一 canonical Run 顺序读取 **320 个随机、不透明文件节点**；每一步只能从前一节点得知下一路径，未用脚本批量遍历或代理代做。
- 主流程 **368 次真实请求**，386 个完成工具调用，其中一次为预设缺失文件错误；随后读取恢复映射继续。主流程耗时 **1525.75 秒**。
- **12 次非空实际上下文压缩**。窗口保持 65,536，输出额度 8,192。最终用例的软压缩阈值为 30,000，使工具/策略必需前缀以上有可达的压缩目标；前两次失败用例阈值为 18,000。没有扩大硬窗口、注入长历史或拆分主 Run 来取得通过。
- **16 份批次文件和 report.json** 经独立 oracle 逐记录、逐批次核对；320 条记录完整、顺序及值一致，总和 **16319**。全部原始输入哈希保持不变；流事件序列未倒退或重复。
- 退出后用新 CLI 进程打开同一会话，读报告、计算奇数索引记录总和 **7861**、创建并读回 odd-sum.json，准确回答最初的随机 CONTINUITY 标记。标记未出现在项目任何文件中。冷启动耗时 **33.62 秒**。
- 主流程为一个 Answered Run；冷追问后共两个 Answered Run。当前 Core 允许执行后的直接 Answered 回复；文件成功由独立 oracle 证明，不从文本或 seal 名称推断。
- 主流程加冷追问 **372 次真实请求全部 HTTP 200**，没有传输错误、生成响应注入或模型 fallback。

最终长链与权限恢复的二进制 SHA-256：`151cbe49846d6ebbcc496fdea3d19b0a2cbd92632f34d481eab9f2de2818f042`。透明 relay 只原样转发选定生成路由，凭据仅驻留 relay 内存，CLI 子进程不接收 provider key。目录探测被本地拒绝且未转发；不把这类本地 403 当成 provider 生成失败。

## 预算与资源

provider 累计 input **13,848,269**、output **26,051**、cached input **5,020,808** token，非账单价格估算。主流程每三秒采样一次，峰值 CLI RSS **112.38 MiB**、CLI 与自有服务进程树 **327.08 MiB**；不含 Python 测试器与 relay，不是跨版本性能基准。最终数据库 **320,638,976 bytes**。

全部 372 份成功请求都有 provider usage。最大实际输入 **55093**，加请求预留输出最大 **63285 < 65536**，峰值剩余 **2251**。其中 **4 次实际输入超过估算准入线 54068**，消耗部分安全余量。这里证明实际输入与输出分配未越总窗口，不宣称字符估算器等同于精确 tokenizer。

## 实际失败与修复

1. 原实现读取 105 个节点、110 次真实请求后以 `context.input_budget_exceeded` 受阻。自动维护计数按整个 Run 消耗；早期无可压缩空间的尝试会禁止后续压缩。现在只对同一待发请求之间的维护尝试计数，新的非空业务模型结果重新获得机会；连续维护防循环及硬预算检查仍保留。回归在原实现失败，在修复后通过。
2. 仅修复计数后仍在 **275 个节点、298 次真实请求、5 次实际压缩**时受阻。Core 每轮重新附带全部旧工具观测，使必需前缀持续增长。现在仅省略旧的、未被评估引用且没有 typed receipt 的成功观测，保留最近 32 条；全部 typed receipt、失败和 assessment 依赖继续投影。持久事实不删除、不改写，省略数明确显示；请求 alias binding 与可见集合一致，省略别名不被接受。500 条观测回归确认原记录与冷恢复不变，失败检查和评估引用未丢失。大量必要回执、失败或评估依赖仍可能达到输入预算，不能称无限长任务窗口已解决。
3. 多个 CLI 竞争启动时出现服务独占锁冲突；启动父进程退出还会切断其他客户端响应。增加进程间启动协调、仅对可证明尚未发送的原 envelope 有界恢复；服务退休先停止新连接，再排空已接收/排队请求。追加修复按实际数据库所有权锁等待交接，避免只等待固定 250ms 后再次启动冲突服务。写入/读取后的未知结果仍查询原 receipt，禁止盲目重放。
4. Linux CI 的外部协议夹具偶发 ETXTBSY；夹具在独立子进程内写可执行脚本，避免其他测试 fork 继承暂时可写的 inode。没有修改生产执行器来掩盖该夹具问题。

中间一轮在 109 个节点、一次实际压缩后人为取消以替换构建，未计入通过；一次真实 TLS EOF 后以同内容请求重试成功，保留失败和恢复证据。初始短 smoke 与夹具调试也不算数百步验收。已有失败 receipt、日志及数据库继续保留；为处理本机链接时空间不足，仅移除了已结束用例的重复可执行副本，最终通过的长链构建仍保留。没有删除用户数据。
