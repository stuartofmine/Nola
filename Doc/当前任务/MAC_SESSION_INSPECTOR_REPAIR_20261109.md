# Mac 会话失败与右侧检查器修复（2026-11-09）

## 已确认的会话证据

以只读 SQLite 连接检查本机 Mac 最近会话及运行事件。最近一次保存的调用发生在 2026-11-08 23:21，走 ChatGPT Responses；attempt 开始后约 10 ms 失败，保存代码只有 `provider_failed`，文本只有通用请求失败，没有 HTTP 状态或原始 Host 错误。现有证据不足以区分账户授权、请求预检和网络原因，不将推测写成根因。

旧开发数据库 schema 83 保持原样，未转换、删除、重建或通过当前 Store 打开。此次没有调用真实模型、续期账户、修改凭据或重放用户会话。

## 修复

1. ChatGPT Host 的明确登录、续期、绑定变更和请求设置错误不再统一降成通用失败。只匹配固定 Host 错误码，不匹配用户输入或供应商任意文本。
2. 错误消息说明对应恢复操作，并提供模型中心入口；没有自动重发模型或工具。诊断日志保留安全分类，移除原始 provider/model 标识，保留结构指标及摘要。
3. 八个一级分区使用整行展开操作，主题语义色提供悬停/按下反馈。选中但已折叠的分区再次从工具栏打开时先展开，不误关闭检查器。
4. 知识点、Wiki、回忆入口展开上下文后，等待布局并滚到准确子区；初始深链接也生效，其他已展开分区保留。
5. 知识搜索清除按钮增加点击边距和无障碍名称；文本编辑器遵守减少动态效果设置，通用信息行允许长标题换行。
6. 审阅刷新包括当前工作区路径，并保护异步读取所有者；换文件清除旧 diff/错误，切换远端不残留 loading。diff 只保留横向滚动，由检查器承接纵向滚动。
7. 默认沙盒不是 Git 仓库时显示中性提示和“选择文件夹”，不把正常初始状态渲染为红色故障。
8. 产物名支持多行，概览导航、工具管理入口增加鼠标反馈和舒适内边距。
9. 数据源的读取/保存错误直接显示；读取失败可重试，加载期间有状态提示。
10. Chrome 安装只打开一次扩展页；安装或打开失败可见，不吞掉异常。窄栏中的操作自动改为纵向排列。
11. 目标和约束使用带内边距的编辑器，恢复日期标签独立排布；切换会话清除旧表单状态，旧请求错误不污染新会话。补齐“目标”多语言标题和占位文案。

## 第二轮：非空内容与异步状态（2026-11-09）

- 目标草稿及提交中状态按会话保存于检查器生命周期内；折叠/重新展开不丢失，旧请求完成后只更新原草稿，避免清空新会话内容或把错误写入新会话。
- 将“可继续展示旧内容”与“控件已确认可用”分开。读取失败或重试尚未确认时保留可读内容但禁用操作；提交入口也复核当前 owner 与已确认状态。活动目标缺控制令牌时不再变成新目标表单；开始按钮尊重来源 `can_submit`。
- 审阅页区分工作区读取错误和单文件 diff 错误，单文件任务不再清除工作区故障。所选文件有可见选中态，差异及加载状态直接显示在该文件下方。
- 原生复核发现水平 diff 区域需要明确高度。现按行数计算预览高度，最长预览 24 行，用有界遍历识别截断；提供明确缩短提示及完整标签页入口，避免巨量 diff 撑长检查器或横向滚动区留白。
- 网页产物经现有 URL 策略打开；本地文件仍同时要求已确认本地来源和读取权限，远端 file URI、脚本或自定义 scheme 不放行。用真实同一渲染组件覆盖长文件名、长横向 diff 和长专家名称。
- 目标操作的中文反馈补齐；编辑器占位文字提升为次级对比度并增加无障碍名称。
- 诊断分类改为只在实际失败路径记录 `model_attempt_failure`，包括发出 HTTP 之前的错误；正常请求不再误带通用失败代码，日志继续不复制原始错误或凭据。
