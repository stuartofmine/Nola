# 模型配置：一级页面直接完成

本设计替代“模型中心 → 连接与账号 → 新增连接 → 发现 → 勾选 → 应用”的首次配置路径。iOS 已切换为直接配置及三来源标签；Android 已接入直接编辑表单及来源切换。真实使用与补充测试证据记录在页面对齐任务中，不能将代码切换等同于全平台验收。

## 一级页面

手机使用单一导航标题“模型”，保留返回/关闭。标题下方常驻三个可点击标签：服务地址 / 本地模型 / 宿主机。默认进入服务地址，配置表单直接可见，不加连接方式导航大厅或重复大标题。切换来源保留本次服务编辑草稿；密钥只留在编辑会话内存中。

1. 服务地址：必填，示例仅作为 placeholder，不预填真实服务。
2. API 密钥：安全输入，按服务要求填写；匿名服务允许留空。不在错误、日志、URL、快照中回显。
3. 默认模型 ID：必填，使用服务提供的标识，不要求提前请求 `/models`。
4. “高级设置”默认收起：接口协议、可选连接名称。连接名称为空时使用域名；同域名连接允许明确改名解决冲突。协议默认 Chat Completions，明确展示当前选择，支持 Responses / Anthropic Messages，不能静默猜测或自动切换。
5. 简短说明：保存后启用，并设为默认模型。无需先发现模型。
6. 唯一主按钮“保存并使用”。

下方是次级“已配置模型”列表，默认收起；每行显示名称、服务来源、默认标记，点击进入配置/参数/测试。第一次配置时不展示大块空态或空列表分组。存在可用模型时，管理页仍直接保留新增配置表单，而非重新恢复导航大厅。

本地模型目录和宿主机配置直接属于对应标签，不折叠在“其他方式”中。本地下载是明确选择本地模型后才进入的专门流程。删除“连接与账户”独立导航页，底层账号与凭据绑定继续由 Core/宿主管理。“发现模型”位于服务地址页模型 ID 附近；只需地址即可发起，按服务要求使用输入的或同一已保存服务的凭据，不要求先保存模型。发现结果仅为可选项；选择后填入默认模型 ID，再明确保存启用。发现失败、空目录或取消均允许手填保存。地址、密钥、协议或连接名称变化会取消旧请求，旧结果不能覆盖新草稿。桌面沿用同样的信息顺序，表单阅读宽度约 560–640，不拉伸成整屏大输入框；移动端按可用宽度自适应。

## 对话入口与返回

- 没有可用模型：对话空态主动作改为“配置模型”，模型菜单同样显示“配置模型”；两者打开同一个一级配置页面，禁止直接进入本地下载。
- 在对话中配置成功：关闭配置页，回到发起配置的会话并选中新模型，保留草稿、附件、专家选择、历史和滚动状态；不自动发送用户消息、不新建会话。
- 从管理入口配置成功：留在模型页，显示“已保存并设为默认模型”，新增模型出现在已配置列表中；不擅自跳转聊天。
- 取消/返回：不写配置；保留原会话及草稿。未保存的非敏感表单可保留到本次页面关闭，密钥不进入长期草稿存储。
- 保存失败：留在当前表单，保留输入，在对应字段附近提示可修复原因；不得显示成功或改变当前模型。

## 保存语义与状态

“保存并使用”是本机配置操作，不发起模型发现、推理或付费能力探测。手动模型 ID 是用户提供的路由，不是 provider 发现结果；能力保持未知，不能伪造已验证工具/推理能力。保存成功显示“已启用 · 未测试”，不能使用“已连接”“测试通过”等含糊状态。

复用现有 Core `ModelCommand::ImportConnection` 事务入口录入手动连接和单个模型，`enable_models=true`。凭据由可信宿主安全存储，Core 持有引用；客户端不另存一套可用模型数组。当前使用一次 Core import 事务提交账号、连接与启用 profile，再通过现有 checked product-setting 写入默认选择；读取 `chat.default_model` 确认默认选择，不只改 UI 状态。默认选择未确认时不报告“保存并使用”成功，并重试原已保存模型，避免创建第二份连接。这个两步实现尚不等同于默认选择与导入整体原子事务。不得回填内置推荐列表冒充可用配置。

配置与网络可用性分开：地址暂不可达也可以保存模型配置；第一次实际请求失败时提供修改配置/重试，不能因此删配置。发现按钮失败不影响已经手动添加的模型；目录刷新不得抹掉手动选择。协议、工具能力、模型来源继续遵守当前 Core 数据格式，不引入旧版字段或兼容回退。

## 原型与验收

`docs/design/nola-ui-prototype/app.js` 的模型页已改为直接表单；保存演示后默认启用并设置默认模型；对话模型弹层增加“配置新模型”入口并演示原位返回。原型不保存密钥、不联网，不作为真实服务成功证据。

真实实施验收依次为：空模型会话进入正确配置页 → 手填地址/密钥/模型 ID → 无 `/models` 前置请求保存 → Core 中启用且成为默认 → 回到同一会话且草稿不丢 → 实际发送。再检查取消、字段错误、事务拒绝、重复连接、协议选择、保存后冷启动、服务离线以及已有模型不被目录刷新清除。实际使用先行，测试补充事务及回归证明。原型语法检查已完成；iOS 已实际点击对话配置入口、目视三标签和直接表单，并用配置文件中的地址/模型 ID 保存成功、返回原会话并选中模型。发现按钮最终版本与三标签切换的实际 XCTest 点击及截图复核已通过，服务可达性与真实推理仍不在已有成功证据中。

## 底部归属

移动端保留“今日”任务视图，底部固定四项：今日 / 对话 / 信息 / 设置。资料与数据源、计划、长期记忆、记录与结果集中到“信息”；设置作为直接底部页面，承载模型和应用偏好，不再藏在今日管理菜单内。聊天详情保留常规返回语义，不为显示底栏挤压消息和键盘。已对应修改 iOS、Android 和移动 Web；桌面客户端不套用手机底栏。
