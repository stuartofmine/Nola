# 用户引导与权限申请检查（2026-11-10）

## 发现与修复

- iOS、Mac、Android 的引导页此前展示运行方式和来源选择，但保存的键未进入实际执行配置。改为真实接入步骤与按需来源说明，不再要求用户作无效选择。旧键保留、不重写；聊天以正式配置的模型/Host 为准。
- iOS 与 Android 增加跳过入口，Mac 保留已有跳过。Android 完成操作在启动协程前锁定，避免同一帧重复点击。仅保存完成状态，不下载、不自动联网、不请求系统授权。
- 模型接入说明指向“设置 → 模型”，说明添加连接、启用/选择和本地模型下载。CLI 纠正 `nola init` 的错误指引，改为 `nola model manage`。
- Mac 数据来源的系统申请不再吞掉异常：按来源保留错误、显示等待、禁止重复请求，并允许明确重试。拒绝/受限显示设置恢复路径，返回应用刷新状态；不同资料分别打开对应设置页。
- iOS 截图复核发现深色引导主按钮使用默认浅色填充与白字，已显式应用主题动作底色与对应文字色；回归增加实际渲染颜色检查，防止只通过布局截图却漏掉不可读按钮。大字体时隐藏品牌副标题，步骤显示为紧凑计数并保留完整读屏标签，减少顶部占用。
- 旧权限说明中“资料永远不会离开设备”与远程模型不符，改为解释系统读取权限与上下文发送策略的区别。
- 本地化检查发现模型设置、默认值与来源说明有 72 项语言缺口，已补齐；将引导和权限说明加入验证范围后，macOS 333 个关键文案在 8 种语言验证通过，Android 176 个关键文案在 7 种语言验证通过。引导新增/改写文案覆盖 iOS/Android 的 7 种语言和 Mac 相应语言。

设计依据：apple-design 本机参考 `onboarding.md` 的快速、可跳过、按场景教学，以及 `privacy.md` 的明确用途、按需申请与透明说明数据去向。引导卡片为说明内容，不伪装成已配置的开关。

Android 首次仪器运行在完成引导后等待底栏超时。读取隔离偏好确认完成标记已写入；新用户的 160 dpi 使应用进入平板导航，而该用例要求手机底栏。切换用户后显式设置 420 dpi，重新执行首次引导及导航用例通过。该结果覆盖手机布局，不冒充 Android 平板导航验收。

iOS 首轮截图发现主按钮对比度不足后修复并重跑，最终结果包为 `ios-guidance-complete.xcresult`；不得引用修复前截图作为当前主题验证。测试均使用隔离偏好、资料注册表与模拟器用户；系统申请注入可控结果，既不申请真实系统授权，也不调用真实模型。Windows/Web 本轮没有代码改动，不能将此前测试表述为本轮原生 Windows 验收。
