## 已修复问题与测试自身问题

实际产品修复是 Android 丢弃安全审阅文本，以及长权限卡片使决定按钮难以触达。完整审阅文本和执行范围进入可滚动详情，紧凑卡片保留决定操作。审阅文本超过 32 KiB UTF-8 的事件被拒绝，不退化为可批准的空文本。设备桥接保留原有权限呈现路径。

测试定位也经过修正：旧模型页导航假设失效；Compose 合并语义导致原助手消息文本定位失败；外围脚本原来把 `ls -la` 也算成重复启动作业。这些是测试问题，不记为产品缺陷。最终以具体作业命令、物理启动次数、连续进度、canonical Run/结果和正确助手消息共同判定，不仅依赖回复文案。

## 实际验收计数

- Web 正式长任务：200 条记录、10 个检查点、一个完成 Run；另一个会话为取消 Run 加一次成功追问。236 次生成路线请求中 234 次成功，两次真实上游传输错误恢复后完成；没有伪造生成响应。测试中继拒绝非指定模型或非生成路径，这些本地拒绝不计为上游错误或成功生成。
- Host 冷启动追问：一次真实请求成功，原任务不重放，确认两次非空压缩的持久上下文仍能使用。
- Android 两分钟轮次：五次真实生成请求全部成功；最终一个 `answered` Run、一次物理作业启动、120 次连续进度与随机结果正确。后续 90 秒收尾复跑另计，不将两轮混成一条连续任务。
- Android 权限事件/SSE/切换会话回归 16 项、缺少审阅文本的界面测试 1 项、独立长任务 oracle 回归 7 项通过。
- 新原型：2,082 个适用平台/主题状态检查、220 个唯一状态、429 条交互边实际点击，288 张主图册截图；320px 大字两主题检查全部适用状态；补充 60 个尺寸组合及六平台两色 12 张长任务预览通过。
- 既有完整原型：10 组流程、134 张截图通过。两个原型的浏览器异常和外部请求均为 0。原型计数只属于合成设计回放，不混入真实模型验收。

## 复现入口

真实模型脚本会产生模型费用，要求使用当前明确选择的模型路线和独立 Store；不能拿生产数据库代替夹具。Android 必须显式指定专用模拟器与可丢弃次要用户，不能使用主用户或用户真机。

```sh
PYTHONPATH=scripts python3 scripts/test_real_remote_host_long_tasks.py --nodes 200 --timeout 3600
PYTHONPATH=scripts python3 scripts/test_real_remote_host_long_tasks.py --resume-evidence <上一步通过的隔离证据目录>
PYTHONPATH=scripts python3 scripts/test_real_android_remote_long_task.py --serial <模拟器> --user <隔离次要用户> --avd <指定AVD> --steps 120
```

`--smoke` 只有 4 个节点，只验证脚本，不计入数百步验收。冷启动追问会新增一次正常 Run，因此原来的“仅一个 Run”在追问前检查；原回执保留，冷启动回执另存。不得重跑单 Run 断言并覆盖原始结果。

原型不需要 Host 或模型，运行及检查见[原型入口](../../docs/design/nola-ui-prototype/README.md)、[业务清单](../../docs/design/nola-ui-prototype/docs/BUSINESS-SCENARIOS.md)和[回放范围](../../docs/design/nola-ui-prototype/docs/VALIDATION.md)。场景清单是 `BUSINESS-SCENARIOS.json`，生成 Markdown/CSV 与 Web 路由同步检查不能取代客户端契约。

## 本机证据与隐私

真实链路日志入口在 `/tmp/nola-remote-long-20261110/`，各次运行回执位于脚本打印的独立临时目录。原型回执与图册位于 `/tmp/nola-prototype-business-20261110/` 的 `final/`、`layout/`、`existing/`。这里仅记录位置和汇总结论，不公开日志、SQLite、令牌、截图或账户配置；临时目录不保证永久保留。源码脚本和公开回执格式用于复现，不将缺失原始文件伪装为新通过结果。

## 尚未关闭的验证范围

- Mac、iOS 原生客户端未执行同等 200 步远端长任务；Windows 没有本轮原生系统运行验收。
- 双设备真实 Wi-Fi、Bonjour、防火墙、网络切换、物理手机挂起与系统后台限制未覆盖。
- CLI 图片粘贴、所有权限引导、全部账户重新授权，以及所有 provider、字号/语言/系统版本组合不因本轮通过而关闭。
- 原型中的授权、OAuth、更新安装、MCP 连接和运行进度是合成状态，不代替真实服务、系统权限或生产配置持久化。

当前产品部署为本地客户端、Application/Store 和用户拥有的执行 Host；没有作为当前必需组件的独立 Backend。后续版本继续维护重新发布的 1.0.0 基线：Nola 自有协议、ABI、数据库格式/epoch 从 1 开始，未知格式拒绝，保护原始数据；外部标准协议不改号。
