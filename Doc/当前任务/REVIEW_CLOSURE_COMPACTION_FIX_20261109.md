# 审查闭环与压缩摘要输入修复（2026-11-09）

本次针对三题轨迹分析的第 4、5 项修改 Nola 通用机制，不修改题目实现、原始试跑记录或评分器，也不为具体用例加入语言路由规则。

## 已采纳审查意见

复用原有任务范围、版本化观察和事务控制，不建立第二份任务账本：

- 每条已采纳意见以独立 requirement/resource claim 保存 `review.source_evidence` 和原失败 `counterexample_evidence`，模型只能使用当前冻结请求的 eN 别名。构造反例前可保留未知 predicate/反例，状态始终 pending；同一用户输入范围下只能补全未知项，不能删来源、换已知反例或减弱检查。
- `bash.regression_test_files` 显式固定测试代码、夹具和本地依赖；它们须为前台 validate 范围内的普通文件。Host 以命令、规范 cwd、测试内容和目标 URI 集合计算检查身份。真实非零失败保留类型化凭据，改变测试或运行边界则得到另一个身份；拒绝、信号、未结束或运行中资源变化不能充当反例。
- 关闭必须绑定同 Host/Turn 的原失败、其后修复动作、最终资源新版本上的同一检查通过。普通 exit=0、子任务文字、其他资源与相似规模测试均不满足。后续编辑或再次失败使旧证明失效；冷恢复和上下文投影保留来源及 pending 状态。
- 原工作区集成只有仓库 patch 身份，不能与文件验证联结。现补充实际差异路径的 create/write/delete 内容版本，包含重命名两端和删除 tombstone，并保留原分支、索引、快照和审批保护。
- 新闭环是明确进展，解除过时的无进展状态；恢复请求账本、协议恢复与其余债务不重置。重复已经关闭的检查不反复获得信用。
- 不匹配的 URI 在登记入口拒绝；工具 schema 现在与实际 declared scope 必填字段一致。只读审查不自动产生修复义务；未登记的潜在问题不由关键词识别。

这验证的是固定回归与指定文件版本的证据链，不能证明断言完整、依赖无遗漏或全部自然语言要求满足。误把未验证猜测采纳为硬性修复要求，也不能靠一句成功说明撤销。
