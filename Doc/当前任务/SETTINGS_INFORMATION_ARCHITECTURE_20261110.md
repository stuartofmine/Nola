# 设置分组收敛（2026-11-10）

设置首页只展示稳定的管理领域。外观、语言、通知、更新、启动和版本信息按平台
实际能力归入“通用”，在同一页按主题排列，不为每个偏好增加一层设置页面。
模型、Agent 默认行为、能力与账户、连接、隐私/数据和诊断保留明确入口。

| 平台 | 通用包含 | 首页调整 |
| --- | --- | --- |
| iOS | 外观、通知偏好及系统授权状态、软件更新 | 独立外观/通知/更新合并为通用；移除记忆内容和计划管理的重复入口 |
| macOS | 外观、通知授权及事件、软件更新、登录启动 | 通知并入已有通用；保留模型、Agent、连接、数据、诊断 |
| Android | 外观、通知中心/系统通知入口、版本、更新、设备标识 | 外观/通知合并为通用；关于从隐私移入通用；数据来源/计划沿用资料库/活动入口 |
| Web / Windows 共享页面 | 语言、外观、通知、软件更新、原生宿主支持的启动选项 | 通知并入通用，说明文字与实际内容一致；其余管理领域保留 |

隐私页继续承载导出、数据说明和清除操作，危险操作不混入通用。对话内的模型
选择、推理档位、检索与记忆覆盖仍在对话上下文中；分类调整不迁移或重置偏好，沿用既有通知授权同步行为。
移动端记忆内容从资料库进入；计划从活动进入，不能因移除设置捷径而移除功能。

Web 通知默认只显示简短用途说明；工作区跟踪、标签页关闭等限制放入可展开
的“通知的工作方式”，保留授权前可查阅的信息。

## 返回路径和已有入口

- Android 的通用状态与可保存页面状态由设置容器持有，进入通知中心再返回时
  恢复通用及滚动位置；从通用返回才回设置首页。不申请新的系统授权。
- Mac 已保存的 notifications 分类及已有初始分类入口映射到 general，避免
  打开一个侧栏没有选中项的旧分类。通知授权状态也在通用出现时同步。
- Web 的 `section=notifications` 仍能打开通用中的通知区，包括嵌入工作区的
  页面作用域；不改写外层会话的 URL。首页、分类栏只保留一个通用入口。
- 不迁移偏好存储、不改动协议/ABI/数据库版本，不删除用户数据或账户。

## 验证

通过实际设置页导航覆盖通用与返回路径；iOS 额外滚到更新操作，Android 进入
通知中心后返回通用并检查关于区。Web 覆盖浅深色、三种宽度及已有通知链接，
桌面工作区使用作用域定位，避免拿外层 URL 误判嵌入页面。Mac 使用 Test 配置
原生窗口验证分类导航及设置画面，保留正常 Debug 签名身份。

已完成：Mac 原生设置画面/默认模型 18 项、分类导航 2 项通过，零失败、零跳过；
Android 692 项 JVM 测试（2 项显式选择型测试跳过）零失败，手机及两种侧栏
布局页面测试通过，共 92 张浅深色页面截图。手机额外确认从通知中心返回通用，
以及滚动到更新按钮。Web 类型检查零错误/警告、614 项单测及生产构建通过，
178 个浅深色/三宽度页面布局和已有通知链接回放通过。

iOS 通知策略 3 项、实际设置浅深色导航 1 项通过，复核 28 张页面截图；另行
验证从活动进入计划管理及返回，1 项通过。Android 额外的非零滚动偏移往返
回归通过，确认恢复的是原阅读位置。

补跑 iOS 计划入口时曾因磁盘不足在依赖解析阶段失败；清理闲置 Mac 索引缓存
后重跑通过，保留编译产物、签名应用和所有 Codex 任务记录。
原生 Windows 系统行为沿用既有实现，本轮共享设置页通过浏览器回放验证，不将其
称为 Windows 实机测试。
