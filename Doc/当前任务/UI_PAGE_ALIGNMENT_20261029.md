# 按原型逐页重做与验收

本轮以最终页面与连续使用体验为准。此前的编译、单元测试和局部点击记录保留，但不作为页面已对齐的证明。

基线：[设计规范](../../docs/design/nola-ui-prototype/docs/DESIGN-SPEC.md)、[交互规范](../../docs/design/nola-ui-prototype/docs/UI-INTERACTION.md)、[能力范围](../../docs/design/nola-ui-prototype/FEATURE-COVERAGE.csv)。原型中的模拟回复与演示状态不移入产品。

## 工作顺序

1. 在相同尺寸、主题和内容状态下打开原型与产品，逐页截图，先列布局、层级、默认可见控件、导航和内容密度的差异。
2. 逐页调整并重新目视对照。原生导航可采用平台组件，但页面分工、主次关系和动作归属必须一致。没有原型对应的页面按共同设计语言处理，不声称像素对齐。
3. 连续使用真实产品：从入口到任务结束，包含取消、返回、切换、恢复及异常；修复使用中发现的问题。
4. 页面与完整流程成立后，测试补充验证协议、状态与回归边界。测试数量不等于视觉或使用验收。

## iOS 闪烁的验收边界

先在真实产品录下：发送、连续流式输出、展开/收起思考、向上阅读、键盘开关、返回列表再进入、切换会话、前后台恢复。对照检查正文是否短暂消失、历史是否重放、列表是否跳动、控件是否改变布局。

之后才沿具体画面与时间点检查视图身份、订阅生命周期、部件重组、滚动及动画事务。源码中出现 `animation`、`id` 或 `onChange` 不足以证明根因；禁止通过关闭全部动效、隐藏思考或丢弃历史来消除现象。本项当前明确未修复。
