## 实现

- Host 在根 Run 准入前准备项目专属的独立私有工作区目录，冻结精确范围。Unix 检查真实目录、当前用户所有者及 0700 权限；拒绝已有 symlink、其他所有者或宽松权限，不改写已有目录。Core 从独立授权范围选择目标，`/app` 不再要求授权 `/`。子任务继续使用已有冻结绑定，不扩大权限、不自动集成或清理。
- 协调器只依据具体源码文件写入资源要求委派。cwd 不能证明进程会编辑源码，也不能证明它只读；运行和验证命令继续走原有 Host 风险解析、权限审批、资源保护及已配置沙箱，未增加 operation_kind 或语言关键词放行规则。显式文件写入仍受协调约束，协调角色不宣称是 OS 安全边界。
- `git_commit` 在执行 filter 或修改真实 index 前验证作者和提交者身份。新增 `author.name/email`，仅影响本次 Git 命令，不修改仓库/全局配置；真实模型已实际使用 Nola Agent / nola@localhost 提交。
- 新文件 intent-to-add 在私有 index 中准备，以 index.lock 和精确 HEAD/index 前像比较发布。提交失败仅在 HEAD 与工具登记 index 均未变化时恢复前像；锁冲突或并发变化保留现场，不覆盖其他写者。钩子或签名仍执行，索引恢复不等于撤销钩子其他副作用。
- 检查点改用私有 index 创建 Git 快照，真实 index 字节保持不变。intent-to-add 仅在快照 index 中归一化，快照保存实际文件内容；未跟踪文件仍不冒充已受保护。内部快照使用明确的 Host 身份，不依赖用户 Git 身份，保持取消和 60 秒超时。原先的“先检查点才能修检查点”闭锁已由回归覆盖。
- 补齐普通与压缩后的模型指引：集成/部署后在实际目标位置、最终解释器及依赖环境重新验证，子工作区或临时 venv 的通过不能直接证明交付成功。

独立工作区也避免默认路径产生“嵌套 worktree 自己让源仓库变脏”的集成冲突；手动选择嵌套目录时仍执行原有 clean/baseline 检查，没有通过删除文件或改 shared info/exclude 绕过检查。
