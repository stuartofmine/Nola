# 执行权限与证据边界

日期：2026-10-16。性质：规范性目标设计，实施与验收见[历史实施记录](../../历史任务/2026-10-19_当前任务归档/会话执行与权限根因整改_20261016.md)。
不是增加一层 JSON 包装；已有领域类型应扩展并替换调用者，禁止同一事实出现平行判断。

## 1. 模块端口与所有权

| 对象 | 输入 | 输出 / 唯一责任 | 禁止混入 |
|---|---|---|---|
| ConversationConfiguration | owner、expected revision、类型化 patch | 已提交配置及 receipt；独立于 streaming 节流 | 当前窗口 busy、整段 transcript |
| ActivePermissionPolicy | Run/owner、已提交 policy revision、更新命令身份 | 后续未派发操作的政策；精确 ACK | 未提交下拉框值、其他会话配置 |
| PreparedModelRequest | 冻结调用、实际 schema、稳定 system、追加上下文 | 唯一 provider 请求及实际前缀身份 | UI 控制 URL、密钥明文 |
| ToolExecutionReceipt | effect/call、精确目标、执行事实 | 动作是否执行及结果确定性 | 观察超时推导的未执行 |
| ModelEvidence | 内容/来源/可读引用、语义观察身份 | 有界模型证据，可按引用继续读取 | bearer token、UI session 控制句柄 |
| UIControl | owner、已提交工具结果引用、平台控制句柄 | 仅 UI/Host 可用的预览与控制 | 追加到 messages、摘要或召回原文 |
| AutomationOccurrence | 持久规格摘要、领取身份、准入结果 | 生命周期、worker fact、Run binding、终态 receipt | UI 的本地运行布尔值 |

JSON 仅在 wire/外部载荷边界编码。领域方法须表达身份、确定性、失败和恢复条件；客户端不得解析错误文字来决定重跑。

## 2. 两档权限与活动政策

CLI 工作区是默认工作目录和项目上下文，不是文件系统沙箱。普通工作区外路径不因位置被标为敏感，也不要求先调用 `workspace_access`；敏感资源、覆盖/删除、未知进程效果、显式拒绝及 OS 权限分别核验。模型判断内容敏感时可主动申请具体读取审批，获批后不能再因工作区边界阻断同一调用。原生 OS 授权及配置明确限定的 Skill 资源范围仍有效。当前实现与验证范围见[权限契约](../模块/07-权限与平台/PERMISSION_BOUNDARY_CONTRACT.md#filesystem-scope-and-model-requested-sensitive-reads)。

补充执行证据约束：直接命令因超时、取消或等待错误返回时，也须保存已捕获 stdout/stderr 原文后再生成有限预览；读取失败显式记录，不能以空字符串冒充没有输出。若停止 helper 仅发信号而未给出受身份保护的进程树停止证明，结果必须为 unknown，分别记录中断原因与停止请求，不声称 process_group_terminated。此时保留原捕获文件用于后续核对；返回的输出只是捕获时快照，不是已结束的完整流，不授权重放命令。

产品只提供 `cautious`（谨慎，默认）、`allow_all`（全部允许）。删除 safe/recommended 等旧值和对应 UI、别名及读取回退。
Core 依据具体操作、资源和经 Host 核验的事实分类，不匹配用户文本关键词。
谨慎允许普通非敏感读取、公开检索、普通新文件创建及已批准范围内可逆操作；删除、已有内容覆盖、敏感数据访问、向外发送数据/消息、建立新的外部连接或认证会话先确认。
公开检索使用已配置检索服务不逐 HTTP 请求确认；新 MCP/SSH/账户连接、上传私人内容、发布/发送必须确认。未知执行效果不能被谎称为只读，应给出实际操作范围供确认。
外发范围以用户 2026-10-17 的澄清为准：上传文件/数据、发送消息，而不是下载、普通网页读取或搜索。既有只读检索服务即使用 POST 实现查询，也不因此升级为消息发送；普通 HTTP 请求不是新的 MCP/SSH/账户连接。由可信工具契约与实际执行器保证操作边界，不按 HTTP 动词、工具名称片段或提示关键词猜测。不得为此新增通用 HTTP 产品、聊天渠道回复框架，或把全部网络读取改为逐次确认。
全部允许跳过全部 Nola 应用审批，包括敏感操作、目录范围申请和委派子任务；不因工具名称、是否 MCP 或换 Host 再建另一套确认。
OS 强制授权、资源不存在、凭据撤销、协议身份不符仍是实际约束，明确报错或系统授权，不制造第二层 Nola 确认。
取消和用户已拒绝的具体调用不因切全部允许复活；新的用户操作可以形成新准入。

配置编辑始终独立提交 CAS，不能被“运行中不保存流式元数据”跳过。
模型/生成参数变更用于下一 Run；权限配置 CAS 与 owner/Run 政策命令入队须在同一事务提交，投递可重试且按命令身份幂等。活动 Core 消费后，尚未物理准入的副作用使用新 policy revision；不能在配置已提交但命令丢失的间隙谎称生效。
UI 在配置提交及活动 ACK 前显示切换中，不冒充已经生效。已经物理准入的操作不能撤回重写；待授权请求经 Core 原子重评估、关闭并继续同一调用，不额外请求模型。

各客户端的活动权限提交/读取/ACK 展示使用同一精确 owner 解析：canonical 活动 Run、正式 source submission 的 Host/client/Run/root assistant 及当前 Run 终态证明。spinner/传输 Task 的 `isRunning` 或 `blocksInput` 不是 Run 生命周期；冷观察或断流恢复不能因此将源端配置降级为本地镜像写。未知、缺来源或相互冲突的 owner 必须拒绝并保留编辑，不自动 rebasing 或只写镜像；终态后的普通配置保存须先有正式终态或确定无活动 Run 的事实。原源端 CAS 已提交而本地镜像失败，仍只读对账，不重放源端写。移动端保存协程捕获原 execution/session；跨 await 后不得从当前选中会话重新取 owner、配置或传输。终态后残留 journal identity 不是新的活动 Run 证明。

上述写入核验与展示读取分离：SwiftUI getter 只读类型化 owner 投影缓存，不能因逐 token 重算状态而重复同步执行 Application。异步事实读取复用现有只读任务边界，在同一会话的活动身份前后 fencing；选择、canonical activeRun 身份变化和正式终态使该 owner 失效并刷新，不扫描/轮询全部会话。未知不是 inactive，缓存不得作为源端 CAS 授权；保存与显式刷新仍重新读取正式事实。
政策降低后，Core `Dispatched` 但尚未收到正式 `ExecutionStarted` 的请求须由 Application 原子撤销旧投递并 fence 已领取但未开始的 worker，再按新政策重新准入。Core 生成封套或 Host 领取本身不证明已物理开始；已物理准入和结果未知的操作不重放。跨会话互不影响；拒绝、取消、未知副作用仍保留精确来源。
自动化保存自己的执行政策；子任务继承显式父政策和允许范围，无关任务不借当前选中会话的模式。

具体工具 effect 携带 Core 准入时的类型化 permission_profile，属于已提交执行封套，不属于模型参数。Host 的目录/敏感资源校验消费这个具体 effect 的政策，而非进程环境或一个可变共享布尔值。活动政策修改不原地改写已提交请求：尚未物理准入的旧请求经正式撤销/fencing 后形成新准入，已物理开始的 effect 保留原政策及执行事实；并发 effect 各自保持其政策。静态自审：不能只更新 Core 的 Ask/Allow 而让 Host 继续使用旧目录模式，也不能用修改共享缓存来追溯改变正在执行的操作。

### 2.1 MCP 连接意图、批准与复用

MCP 配置存在、enabled、保存按钮、目录刷新或插件安装均不构成连接批准。初始目录只编码 Host 已校验的配置身份及待连接状态，不联网、不发 initialize、不启动 stdio；native/Web/插件及自动目录刷新遵守同一边界。模型只能调用 Host 提供的 mcp_connect，输入只选择已登记目标，不能提交或替换 endpoint、程序、参数、cwd、环境或凭据。Core 使用正式资源解析与同一 permission profile 准入，谨慎新 HTTP 连接/stdio 启动要求确认，全部允许不附加另一套审批。

资源身份绑定 Host、会话、配置摘要和连接代次。未连接实例还持 Host 随机 admission_id，在实际新握手前锁内消耗并轮换，避免初次 generation=null 的会话批准在失联或握手失败后重新使用；冷实例重新生成该身份。摘要覆盖实际 HTTP endpoint/headers 或 stdio 程序/参数/cwd/有效环境，密钥及秘密参数不进入模型和 UI；不同会话不共享批准或活连接。解析只读取 Host registry；执行在同一精确 registry entry 的锁内复核冻结配置/代次后才允许握手或启动。已批准且仍存活的同一代连接复用不重复申请新连接授权，工具本身的敏感/外发/未知风险仍独立准入。关闭、进程退出、传输失联、配置改变或 Host 重启后不隐式重连，必须重新取得具体新连接批准；目录变化只可在原连接上发现，不能在发现失败后新建另一个连接。

stdio 有效环境只继承明确列举的运行环境并合并用户显式 server env，冻结于 Host 私有内存，实际启动 env_clear 后使用该快照；不得把父进程全环境或继承密钥写回配置 JSON、描述目录、checkpoint 或模型。构造过程中已 spawn 但尚未交给正式 client 的 Child 也由独占 guard 负责 kill/wait。执行前事实变化为正式 NotStarted；启动/握手后失败为 Unknown，不将失败概括成未执行。成功回执在连接锁内取得精确代次，记录实际 connect effect 与该代 client/descriptor 存活观察；复用不捏造新的连接 effect。

冷恢复仅从冻结 Host 描述的无凭据 mcp_route（server/tool/reference/config digest）重建惰性路由，重新核当前 Host/session/config；它不是活连接授权。没有原代 client 时，旧工具调用正式返回 NotStarted，必须先调用当前 mcp_connect。连接后发现的已有 schema 变化或工具移除不能偷偷改写冻结目录，须经既有正式刷新边界接纳；新发现工具按精确 activation 加入。HTTP 不自动跟随重定向到未批准目标；当前没有显式 MCP proxy 配置，因此 no_proxy 禁用未冻结的父进程代理环境，不扩大为全应用代理设置。

成功连接只发布真实握手所得的工具描述，通过现有精确 Host capability activation 接入当前 Core；不将远端 readOnlyHint 当作独立权限授予，不将连接成功证明为后续工具已执行。正负回归需覆盖零预连接、谨慎拒绝零握手/零进程、全部允许、原代复用、配置与会话隔离、失联零自动重连及刷新不扩权。先完成所有当前调用者和源码反例，再集中运行验证；本节是本批修复设计，未宣称已有真实验收。

MCP 的 readOnlyHint 也不能证明执行静止。MCP origin 不享受普通 Host 内部读取的缺 receipt 停止例外；实际调用显式产出 ExecutionReceipt，发送前确定拒绝为 NotStarted，成功返回为 Completed，已发送后取消、超时、断链或远端错误效果不明为 Unknown。Unknown 不得转成 CancellationConfirmed 或安全重放。

### 2.2 进程执行身份与会话授权范围分离（2026-10-20 修订）

`ProcessInvocation` 记录 Host、命令、工作目录与调用参数身份。它既不证明只读，也不保证脚本、环境或数据内容不变；但这不构成取消会话授权的理由。此前“凡 ProcessInvocation 只允许本次”的规则将执行快照与授权范围混为一谈，已撤销。

“一次允许”只准入原调用。“本会话允许”必须是用户明确选择的持续授权：当前范围限定为原会话、Host、capability/operation、命令、cwd 和调用参数，不是整个 `bash` 工具，也不从可执行文件名称推导命令族授权。Core 保留选择来源和回执，后续匹配范围才可复用。配置中的显式 `command_glob` 是另一种用户政策，不因会话选项而扩大。

每次调用仍先取得新的 Host 资源观察，再匹配授权与现行权限规则；不能用缓存结果代替资源解析。进程观察风险进入授权匹配；风险改变须重新决策，敏感读取还绑定 Host 证据，变化后重新确认，不能借相同命令跟随新的敏感符号链接目标。一般不透明进程的明确执行授权允许该命令使用当时的依赖/环境，并非批准一份冻结正文；Host 无法静态证明其全部副作用时不得将它标为普通读取。停止或副作用未知仍不得自动重放。

Core 对有效的具体进程范围提供 `allow_conversation`，Host/客户端只消费此资格。CLI 编号 2 展示实际命令与工作目录；确实不可提供会话选项的挑战保留禁用项及原因，并去掉数字 2 的快捷键提示，不再静默跳号。任何选项都不允许客户端提交 `*` 来扩大 Core 冻结的范围。

回归覆盖：checkpoint 恢复后的用户选择、相同范围的后续调用重新解析并复用、命令/目录/风险改变重新审批、敏感目标变更、混合资源、明确拒绝、一次授权，以及面板显示/键盘结果一致。普通可信读取仍默认无需逐次确认；全部允许模式的语义不变。此修订不迁移或改写用户已有会话与授权数据。

## 3. 工具结果三分及浏览器执行

工具结果在适配边界拆成执行回执、模型证据和 UI 控制数据。完整外部原文可保留在受限 blob 中；模型、压缩、召回、输出搜索读取同一安全证据投影，不通过再次读取完整 JSON 绕过隔离。
预览令牌不是正文；不只过滤顶层字段，还必须避免嵌套序列化 text 再携带控制字段。
大页面结果提供有界元素/来源/稳定 ref，按结构和范围读取；文本搜索必须按字节/命中片段限制，不能将整个巨型单行 JSON 当作一条命中返回。
工具发现使用冻结目录下显式协议；普通恢复不临时撤下所有 schema 再切回。新工具加入实际请求必须准确改变缓存身份。

浏览器目标是 target + owner + page/tab + generation，不是“当前前台标签”。
owner 不存在、扩展重启丢映射、页面关闭或 generation 失效时返回明确 stale target；不退回另一个页面。
动作回执独立于后续截图/DOM 观察：导航已提交但截图超时应保留“已导航，观察失败”，重试只重取观察。
注入代码必须独立可执行，不能引用未注入的打包闭包 helper。managed/native 的展示来自结构化 target，标题来自统一结果投影。

### 3.1 目标约束、schema 与在途所有权

工具合法参数不能与执行器条件分离：managed 动作引用快照的 page/generation、ref/revision；attached 动作要求明确定位方式。对外 schema 表达条件组合，执行端仍对具体目标核验；不能用参数校验错误来代替 schema 契约。
用户明确要求的执行目标由模型解释并记录在类型化任务约束及其版本中，不由客户端扫描用户文本、匹配“Chrome”等词强制选工具。诊断可检查其他后端，但替代 target 的成功不满足原约束；改变执行目标须明确提出，不静默降级。

BrowserSession 拥有页面集合、当前页版本、引用表及操作序列。模型动作、手动预览输入和观察均通过同一 owner 内调度边界；命令带已选择的页身份，不在执行到一半时再次读取全局 activePage。跨 owner 可并行，同 owner 的互斥范围应覆盖动作及其关联观察，不覆盖其他会话。
引用失效返回结构化可恢复错误及应重取的观察，不盲重试已经执行的动作。容量/闲置回收检查在途操作引用；正在执行的 session 不因另一个 session 申请容量而被关闭。传输响应期限与具体动作期限分别记录；直连子进程也有响应匹配、取消和期限，不持全局锁无限等待读取。

新弹窗只加入 owner 的页面集合，不以浏览器异步事件替换当前选择。Managed ref 绑定观察时的确切 DOM 元素句柄和主文档代次，不保存会在导航/重排后重新定位的 nth locator；同 URL 重新加载也改变页身份。重复 URL 或失去精确恢复身份时不凭索引选另一个页面，保留未选定状态供显式列出/选择；元数据格式错误明确拒绝，不删除或重建。句柄随引用批次释放，避免长期保存每轮 DOM 的远端对象。

### 3.2 文件读取观察与编辑前置证据

**操作语义决定前置条件，不采用“一切修改之前必须把旧文件全文交给模型”的统一门槛。** 输入中的完整目标正文属于全量替换；rename/move/delete 属于资源身份操作，均不依赖模型看过旧正文。它们仍须通过具体资源权限、Host 新鲜身份/版本复核、明确覆盖意图和实际执行回执；`expected_sha256` 如有提供必须严格核验。普通 rename 在 `overwrite=false` 下使用原子不可覆盖操作，不能以先检查不存在再执行覆盖式 rename 代替。二进制和大文件的移动/删除不能要求不可获得的 UTF-8 全文读取凭据。全量 UTF-8 写入亦不以解码旧二进制正文作为准入条件，预览可明确表示旧内容为二进制；不伪造旧文本。

依赖位置或旧内容的编辑采用其实际语义：行/范围编辑必须绑定已返回的该版本实际范围；精确文本替换通过唯一 preimage/匹配数量与锁内乐观并发复核，不额外强制重读全文。写入、格式化、回滚或 `expected_sha256` 都不是模型的读取观察，不能把它们记成 `full_read`。因此既不靠伪造读取凭据减少往返，也不为了沿用一个全局 guard 让删除 PDF、移动图片、整文件替换变成不可能完成的操作。包含 import 更新的移动须另外对每个正文修改维持其权限/版本及完整回执，不把 rename 的批准扩大成任意目录修改。

纯追加不按旧正文定位，也不要求先把已有内容全文交给模型；包括非 UTF-8 原字节均须原样保留。追加仍是对已存在具体资源的修改，谨慎模式下原权限与一次批准不变，执行器仍冻结当前版本、严格核对显式 `expected_sha256`、有序加锁并重复复核，使用 `O_APPEND` 或不存在目标的 `create_new`。这不是对任意外部路径替换竞态的完整防护，也不产生读取观察。冷恢复不能因为 Host 内存读取账本已消失而要求无语义依赖的全文读取，更不能把一次批准扩成会话批准。

自动 import 更新采用 catalog 显式声明的 `derived_file_collection`：Core 冻结 normalized input、其 digest 与该集合 demand，Host 只对已声明集合返回完整、有限的成员列表。每个成员包含精确文件资源/访问、实际旧版本、计划新版本、风险与证据身份；集合 digest 绑定 resolution/Host/input/demand 和有序成员，外层正式 Host effect/response 同时校验冻结 catalog revision/availability。root 只是发现边界，不进入目录写批准；Core 将成员展开为逐文件权限资源并逐成员评估风险。未声明集合、重复/越界成员、错误类型/版本/digest、解析失败或超限均拒绝，不能截断成员后继续执行；空集合仅表示明确禁用或可信解析确无候选。执行前及有序文件锁内重新解析完整计划和每个版本，任何差异须重新解析/批准。执行回执分别记录实际 rename、各 importer edit 及失败/回滚事实，不能将部分执行伪称全部成功。

全量写入或精确批量替换已提交后，格式化或读回失败仍保留实际资源效果与原版本，整体回执标记 `partial`，不能声称动作未开始或自动重放。最终新版本来自实际观察：文件确实不存在时记录 `absent:v1`，观察失败时为未知，不沿用原版本或计划正文 digest 冒充最终结果。自动 import 更新仅执行已冻结的精确正文补丁，不顺带运行可能扩大写入集合的格式化器。

目标文件所需父目录仍可自动创建，但属于已授权修改的一部分，不是无副作用预检。源/目标版本、完整 import 集合、锁集合与取消状态全部复核后，才逐级以不可覆盖的 `create_dir` 创建目标祖先目录；首个 mkdir 前复算的缺失祖先必须属于冻结的目录锁集合，已存在父目录消失导致集合扩大时零副作用拒绝并重新规划，不在锁内补锁。只记录本次实际创建的目录，不冒领竞争者创建的目录。每级目录有精确 URI、`create_directory` 效果及创建前缺失/创建后身份（无法观察则未知），无需把目录冒充文件产物。创建部分失败、取消或随后文件写入/移动失败都保留这些实际效果并标记 `partial`，不能退回 `not_started`，也不擅自删除目录作为隐式回滚。全量写入、创建式 append 和移动共用此边界；批准目标所必需的祖先创建不扩大为其他目录的写入权限。

文件读取返回展示正文和独立的 typed 观察凭据。凭据由实际打开的文件、同次读取的内容版本和实际返回覆盖产生，不由 `start_line`/`line_count` 是否出现来猜测完整性；从首行读到 EOF 且未截断可完整，字节截断、仅部分范围、二进制文本提取不可冒充原始全文读取。

Host 的 Run 级读取账本只在结果确实进入返回内容后合并观察。批量读取超出总输出预算而未返回的 section 不入账；同路径内容版本改变必须清空旧 `full_read` 和范围，不能更新 digest 后保留旧覆盖。读取与版本绑定使用同次内容证据，避免读取旧正文后另开文件计算新 digest 的 TOCTOU。

原始读取字节上限与模型展示预算独立。`read_file` 在通用结果裁剪之前，按完整原文行生成预算内的直接正文，连同标题、行号、元数据与继续读取说明一起计量；观察凭据只包含最终保留的完整行。若还有未返回内容，`next_start_line` 指向实际未返回的第一行，指示对原文件继续调用 `read_file`，不把全文保存引用当作已读。单行超过原始或展示预算时明确报告该行未返回，不授予整行覆盖，也不跳过该行声称取得进展。批量读取同时计入最终 join 分隔符和省略提示，只收录实际预算内的 sections；后续项出错而整体未返回时，先前内部读取也不入账。该投影不提高通用限额，不从 JSON preview 反推覆盖；同版本的分段原文覆盖仍可合并为完整读取并支持精确行编辑。

会话权限缓存不是 Run 身份：warm Host 可跨 Run 复用同一权限 scope。文件观察使用独立、不可变的读取 generation，由已提交执行循环在派发 effects 前绑定正式 canonical Run ID；同 Run 恢复保持该 generation，新 Run 替换读取 generation 而不清空用户批准缓存。已派发工具持原 generation 的 clone，其延迟返回只能写原账本，不能归入后继 Run。隔离验收须覆盖同一个 warm Host 的连续 Run，而不只创建两个全新权限 scope。

读取凭据是编辑前置条件，不是权限批准，不改变谨慎/全部允许政策。写入仍复核当前版本；覆盖范围不足则返回可恢复前置错误。对 Notebook/符号/诊断片段等派生视图只能记录它实际能证明的覆盖；已成功写入也不能无条件把未见的保留内容标成模型已完整读取。所有生产者及调用者同时采用当前契约，不保留旧参数推断旁路。

验收至少覆盖：短文件带过量 line_count 仍完整、非首行/字节截断不完整、批量预算舍弃不入账、旧全文→外部改动→新局部读取不能继承全文、跨 Run 隔离，以及读取/记录间文件变化的版本不冒领。

## 4. 语义进展与历史能力

无进展判断使用语义资源身份、相关查询和证据摘要；排除传输时间、随机输出 ref、截图编码及无语义 revision。
分页/限长等呈现参数不能令同一证据自动变成新进展；资源真实变化仍允许继续观察。失败恢复必须产生可验证新证据或改变策略，不能只刷新包装重置门禁。
跨会话历史通过带 authority/owner 的 canonical 搜索/读取端口提供，不交给模型猜数据库结构。
BM25/索引返回来源和原文范围；是否允许访问由具体数据范围判定，不因使用 shell 而间接绕过，也不默认将自己的所有会话都列为敏感。
最终答复可引用的来源必须存在于 ModelEvidence；链接、图片和 PDF 的 UI 解析不重建未经模型看到的结论。

### 4.1 Skill 验证不是字符串声明

复用现有 execution evidence 和产物引用，不再创建无法解析的“验证字符串”命名空间。Skill 验证输入区分模型判断与实际检查；模型可以表达检查结论，但不能凭 passed=true 将其升级为 Host 检查已执行。
证据引用解析到相同授权 owner、正式执行记录、受约束的原文范围或产物版本；引用不存在、类型不符、跨 owner 未获授权或产物已经改变时拒绝该验证更新。检查回执带执行者、检查方法及对应证据版本。
对引用支持性等语义检查允许显式 model_judgment，不强制另启独立代理；机械检查则需要实际检查回执。Skill 完成依据该 Skill 声明的适用检查，不用非空引用和 passed 布尔代替适用性及来源验证，也不要求普通问答套用全部工作流。

### 4.2 需求到已接受输入的模型投影

`rN` 保留该需求原始 `source_refs`，并引用单一共享的有界来源索引，而不是只给“交付已接受范围”的抽象描述。索引仅从当前 scope 的正式 InputApplied/admission、destination Turn 与 transcript item ownership 联合定位原文；缺失、重复身份或外来 Turn 明示不可用，不借旧 Run 或最新消息补齐。Message 摘录保留原 role/origin，工具结果、附件 URI 和压缩摘要不升级为用户任务正文。

来源正文最多 16 项、每项 512 Unicode 字符、全局 4096 字符，同源只投影一次；超额来源计数和正文截断均显式报告，引用身份不截成伪 ID，完整原文仍由 canonical 历史拥有。该投影在每次请求从当前正式状态派生，冷恢复同样适用，不新增一份持久正文或迁移格式。

解释、自然语言回答或用户指定格式的文本本身可以是任务交付，不要求为其制造工具调用或外部执行证据；普通情况直接回答。若使用结果控制，`answered` 表示文本交付，`completed` 仍须实际工作及适用证据。来源映射不强制任何 verdict、不将模型负评改为成功，也不按提示关键词判别任务类别。

### 4.3 工具 transcript 来源与 canonical Part 绑定

模型 transcript 的 ToolCall、ToolResult 与可见 Tool Part 是不同身份域。Application 在接受实际 Core 工具变更的同一持久事务中，将原始 item ID、类型、call ID、精确 conversation/Run/Turn/message/Part owner 及原文摘要绑定；原文使用既有不可变 canonical text 分块保存。调用可先于结果绑定，结果到达后仅追加其来源；既有绑定和正文不可改绑或覆盖。普通 Host 工具与 Core 控制事务共用此边界，展示 preview 不代替原文。

来源读取固定 conversation revision 并重新验证正式 Part/Turn 来源；不依赖最新 checkpoint、可裁剪 outbox 或 ID 前缀。冷历史水合沿正式来源绑定保留 item 身份，但仍作为历史数据及历史 call 映射，不恢复执行或授权。压缩来源读取同一原文端口，有界预览必须标明截断，缺失、重复、跨 owner 或摘要不符均拒绝，不删除控制工具来源以伪造完整性。最新用户指令不纳入普通历史摘要。

本地来源区分 `AcceptedRun` 与 `VerifiedLocalDerivation`。后者只由正式 branch 事务在已有 `PartDerivation` 后建立：会话命名空间保留原 item ID、原 accepted owner 快照和 body digest，独立复制目标正文；读取核对目标、直接来源、operation 与本地派生证明。删除原会话不会删除分支自有正文，也不会把历史调用变成可执行或可授权调用。未绑定的展示 JSON、远端声明和归档声明不能自行生成该证明。

上述本地提交、冷来源读取和本地分支的验证只对应归档扩展前的已测快照：工具来源专项 880 通过、0 失败、1 忽略，以及一次明确注入上下文错误后的真实 192 模型恢复通过。不能据此推断随后修改的工作树已通过编译或恢复验收，详见[工具来源合同与历史证据](../模块/06-工具与证据/TOOL_TRANSCRIPT_SOURCE_ARCHITECTURE_20261017.md)。

2026-11-08 源码核对：来源归档 validator/installer 及对应消费已存在，旧暂停交接中“未实现、不可编译”的描述不再是当前事实。当前边界见[工具来源合同](../模块/06-工具与证据/TOOL_TRANSCRIPT_SOURCE_ARCHITECTURE_20261017.md)；旧阶段证据保留原日期，不能反向当作现在仍禁止编译/测试或已经全链路验收。外来 claim 仍须完整核验与事务安装，不能自行成为本地可信来源。

跨端同步本轮明确排除且未完成。只传 visible Tool Part、正文或自述的 `LocalBranch` 均不能建立来源证明；接收端缺少可信绑定时显式不可用，不回退到展示 JSON，不把历史来源变成可执行或可授权调用。本段不构成继续实施同步的计划或授权。

## 5. 缓存、上下文和计量

缓存身份取实际 PreparedModelRequest 的模型、协议、system/工具字节投影、thinking/工具选择等影响前缀的设置；完整目录摘要只作目录版本，不能代表实际发送 schema。
目录发现和恢复不得通过每轮无序增删工具集合破坏热前缀；在 Run 基线内稳定排序、保留已激活工具；必须改变时明确记录变化原因。

Run 拥有已暴露 Host schema 的单调工作集，按冻结目录验证来源并保存实际定义；同一工具 ID 在 Run 内不得悄悄改变定义。成功执行、临时协议恢复、调查/验证阶段变化或“最后一轮”提示不删除该工作集。未知工具仍须发现，恢复建议不授权调用；输入校验、重复无效调用、资源批准与预算在具体调用准入处执行。关闭模型工具能力、显式能力撤销以及正式纯文本终结阶段可以缩小实际工具面，但需作为真实协议边界计量，不伪称缓存身份不变。Core 自身阶段控制工具不借 Host schema 缓存获得额外授权。

谨慎风险输入分为工具目录契约声明与 Host 资源事实。公开只读、删除、敏感访问、外发、新连接等语义由可信工具契约声明；“目标是否存在、是否覆盖、解析到哪个实际文件、shell 是否确为受支持的只读操作”由目标 Host 通过只读解析取得。复用 PermissionResourcePlan/ResolutionFacts 的输入摘要、执行目标和证据绑定，不接受模型自报低风险或已获授权来降低审批要求。模型可通过 `sensitive_read_reason` 主动申请敏感读取审批；Host 将普通读取提升为敏感读取事实，仍由 Core 按当前政策决定，不能把这一声明当作用户批准。解析不产生业务副作用；执行前资源版本变化则重新解析/审批，不沿用旧版本批准。实现及验收状态以当前任务和集中验收记录为准，不能把工具名分类器或一处 schema 修改作为全链已实现的证明。
提示只渲染一次；配置指令、参考内容、不可信工具正文保留来源，不重复包同名标签。Host 传递类型化动态 ContextComponent 的原始内容与来源，Core 的 context engine 根据 kind 唯一渲染配置指令/参考数据边界并计量；Host 不先将其变成已封装字符串再让 Core 重包。System 字符串是已组成的政策或 Host 事实，结构化 System 合同保持对象直至 Core 校验；不得通过剥掉全部信任标签节省 token。
压缩继续遵守稳定前缀和未压缩尾部的热分叉，不将 UI 句柄或旧授权注入摘要。
会话缓存率 = 去重物理 Attempt 的 cache_read_input_tokens 总和 / 可比较 input_tokens 总和；未知覆盖单独标记，不平均每轮百分比，不将缺数据记零。
分解准备、首 token、模型、工具、IPC/存储及用户等待。性能结论带设备/样本/覆盖度；用户等待不算模型执行耗时。

当前上下文预算估算、上次请求实测用量、累计计费与缓存前缀诊断是不同投影。估算带上下文 generation，实测及诊断带物理 request/attempt 身份；新请求估算可合法不同于旧请求实测，不以“实测优先”拒绝后续有效增长。
canonical 冷读和实时订阅保留相同诊断及来源。缺失诊断不能靠 UI 沿用旧身份填补，估算更新也不能清除已提交累计账单。UI 选择展示字段时不得将不同物理请求的数据拼成一次观察。

## 6. 空等待、准入与恢复

会话输入所有者同时绑定 conversation ID 与存储寿命（persistent/process），一经绑定不可因子任务或恢复入口而换主、升格。持久会话通过所属 Application 的正式 FIFO 和命令回执确认接收；`--no-save` 只使用所属进程邮箱，不向默认持久数据库提交输入或生成持久恢复日志。CLI 的“下一轮”语义保持不变，不能为修交付失败把后续消息偷偷送入当前轮。

客户端恢复日志的文件所有权使用规范路径核验，服务传输地址则沿用原 Application 连接定位符。二者职责不同：不可将日志层规范化后的路径交给按路径生成 socket/client ID 的传输层，否则 `/var` 与 `/private/var` 等同一数据库的路径会误建两个服务入口。恢复继续使用原 request/submission 身份与原 Application 回执，不通过另建队列或换 ID 避开未知结果。

等待命令是只读查询/订阅；队列为空不生成 CommandReceipt。真正领取必须在事务内原子竞争并拥有幂等回执；只读窥视不构成授权或领取证明。
不能把只读检查和修改无条件合成一个高频日志命令，也不能通过删历史来掩盖写放大。

自动化定义保留原 execution_spec 与提交摘要，读回核对原始意图而非拿两个本地重建值比较。
Occurrence 生命周期区分 queued→claimed/preparing→admitted(Run binding)→terminal，具体类型可复用现有状态和 worker observation，但语义不得丢失。
绑定前确定未准入的启动异常提交 launch_failed observation 并原子关闭 occurrence；绑定后按原 Run 对账。
异常发生在请求已提交但 ACK 未知时，先按 invocation/request identity 解析是否已准入，不声明未执行，不盲重跑。
冷恢复覆盖无 binding 的领取记录：验证持久准入证据及 worker facts，确定未执行则失败/安全重新领取，结果未知则保留可操作的诊断状态。
不得仅凭租约过期或 PID 不存在重做外部动作。日志/异常落库失败本身暴露为未对账，不清本地状态后装作完成。

### 6.1 客户端观察流与取消控制所有权

一条观察流拥有独立 generation。`onTermination`、被拒绝的第二次 start、延迟返回的授权观察及旧驱动清理，只能影响其创建时的 owner；不得调用无身份的全局 cancel。Run、模型请求、工具执行和 UI 观察流不是同一个生命周期。

用户取消先撤销新动作的本地 admission permit，再向原 Run 提交幂等取消命令。关闭 UI 观察流不代表执行已停止，更不代表 Core 已 sealed。取消控制带原 effect/delivery 身份；只有目标执行已停止或能证明尚未物理准入才可确认，不得借取消确认掩盖未知外部副作用。

异步驱动重入不能丢弃已领取的取消控制。客户端须在原执行停止后仅收口原 Run 的控制请求，或提供可达的 control-only 恢复，不执行旧模型/工具、不创建替代 Run。最终验收读取正式 `Cancelled` seal、原授权请求和控制投递状态；仅验证按钮复位、流结束或用 call ID 查询权限不存在均不足。

AutomationDefinitionID、OccurrenceID、RunID、NotificationID 是不同类型和关联：活动按定义聚合，按 occurrence/Run 查询执行，通知 ID 只作通知投递去重。禁止用单个 sourceID 字符串同时承担四种身份。
自动化数据准备逐项消费冻结 contextRefs；请求 reminders 不扩大成联系人、日历、健康等整个个人数据集。依赖刷新按引用返回可追溯结果；某依赖失败不被抹成笼统“准备失败”，也不假定所有平台依赖均必须刷新。

历史 Attempt/工具失败保持不可篡改；当前阻塞和待处理告警是另一个有来源的投影。正式 retry/supersession/恢复结果可解除对应告警，但后续任意成功不自动消除全部历史失败；客户端不通过扫描错误文案猜测恢复关系。

### 6.2 通知观察与回执的并发边界

通知列表是观察快照，不持有任务执行权。读取待授权通知后，另一个入口可能已经批准原申请；客户端不可再将旧快照作为被动待授权通知展示。展示后 ACK 也可能晚于正式批准或问题回答，不能把这种合法过时当作整个会话的致命错误。

通知 ACK 返回唯一类型 `RuntimeTaskNotificationAcknowledgement`：`Delivered` 表示本次写入确切 occurrence/consumer/command 的展示回执，`AlreadyDelivered` 表示同一回执重放，`Superseded` 表示确属该 owner 的正式历史权限/问题 occurrence 已不再有效，且不写入展示回执。未知 occurrence、外来 owner 和 command 身份冲突仍明确拒绝。不得按错误文案吞错、用任务最新状态代替来源核验，也不得把通知展示或过时解释成授权、回答、业务完成。

权限面板准备对象持有实际展示的完整 PermissionRequest。用户选择只能提交其原 request ID，并复核 task、child、输入及范围身份；不得在选择后按 task ID 再取“最新待授权”。旧通知与面板申请不一致时不展示；等待期间原申请已关闭/被替代时拒绝该选择，不将选择转投新申请。

Store 辅助调用及来源观察统一使用既有写事务所有权封装：顶层先 `BEGIN IMMEDIATE` 再读 owner/CAS，嵌套复用当前工作单元的 savepoint；失败由 guard 回滚并对清理失败设写屏障。禁止裸延迟 savepoint 先读后升级写入，避免与归档线程竞争产生 `BUSY_SNAPSHOT`。

### 6.3 自主续行的正式输入来源

Goal 自主续行不是新用户发言。Host 在原 Application 准入边界提交已有 Developer AgentItem 承载的类型化 trigger packet：正式 trigger/submission 身份、canonical conversation owner、Core session owner、原始上下文摘要，以及当前 Goal ID/revision。自由文本 Goal 上下文仍是独立上下文，不因包装成 trigger 而升级为 Developer 指令。Core 核对当前 Goal/owner/上下文；Application 另核 canonical owner，不从旧 Run 借用输入或需求来源。

已有非 live 的 context-only 输入仍合法。ScheduledAction、Replay、SystemRecovery、DelegatedAgent、GoalAudit 等由 Core 在当前输入准入处把实际上下文的 owner/origin/摘要显式化为同一种 Developer trigger，再经 InputAccepted → InputApplied → 当前 Run requirement scope → typed RunResult/seal 入账；不新增 provider Item 变体，不把上下文伪装成 User 消息。仅有空上下文或未知来源不能生成执行 Run。Maintenance 保留其独立生命周期，不建立用户需求 scope。

正式 batch 的应用以 batch 是否存在为准，不以可见用户文本长度为准。trigger 只证明本次内部调度因果，不携带 live-user authority，不创建权限 grant；敏感资源、覆盖、删除和新连接仍由具体工具准入独立审批。验收覆盖真实新 Goal 续行的当前 Run InputApplied/scope/result/seal、零新增 User 消息和零伪授权，以及其他现行自动来源与 Maintenance 的正负边界。

自主续行建立新的当前 Run requirement scope，不等于获得清空既有执行目标约束的授权。目标约束保留其原声明 scope、正式输入和模型来源，并明确记录续承到当前 scope 的关系；不可把原声明的 scope ID 改写成新 scope，也不可把旧 Run 输入混入新 Run 的输入承诺。没有新用户方向的内部 trigger 不能替换原目标；恢复和替代后端诊断仍须遵守它。当前消息的可变 run_id 也不能证明历史回答 Part 的归属，回答来源始终按正式 Part/Turn/Run binding 核验。

### 6.4 内部续行复用消息不改变历史 Part 来源

Goal 内部续行可将新 Run 的内容追加到同一可见 assistant 消息，但消息当前 `run_id` 不是其所有历史 Part 的执行来源。Answered 的原文引用须经正式 `assistant_turn_part_bindings` 与对应 `assistant_turn_message_bindings` 核验同 conversation/Run/Turn/Part/message，不能用可变的消息归属代替不可变接受记录。冷读旧结果在消息已交接给新 Run 后仍须可验证；反之新 Run 不能借复用同一消息认领旧 Part，缺失或外来绑定必须拒绝。

单项读取和批量展示遵循同一规则：历史只读必须同时具备正式 Turn/Part 绑定与当前、历史消息 owner 的已接受交接关系；未绑定 Part 仅可作为其当前 Run 的创建中对象，且不得已绑定其他 Run。读取成功不授予旧 Run 写权限，写入仍必须匹配消息当前本地 Run；已经接受的 Part 来源不可由新 Run 重新绑定，即使共用同一消息也必须拒绝整笔事务。删除交接关系、混入外来会话或缺失对应 Turn 绑定均须拒绝，不能从正文、checkpoint 或“最新 Run”推断来源。

### 6.5 后台执行的时间、续租与资源观察

Task 的输入、Run 绑定、物理进程和观察采样不是同一个生命周期。输入与权限仍绑定原 owner、attempt、resource、delivery；创建 Task 或展示“执行已封存”不证明业务成功。子任务须由原 Run 的正式结果和证据封存，`Incomplete`、`Cancelled` 不能被结果摘要或完成文案改写为成功。测试模型也须消费实际工具结果并提交当前需求的正式评估，不以尾部标记代替证据。

持久准入、续租和调度观察统一采用 RuntimeDriver 的真实 wall epoch，每次观察 SystemTime 并以原 Atomic 下界保证同一进程不倒退。禁止用进程启动时 wall clock 加 Instant 推出跨进程持久时间：长寿命父进程与新 Host 的锚可偏移，不能使后继领取写出 updated_at 早于 created_at/started_at。Instant 只用于本地等待、采样耗时和 watchdog 的剩余期限，不作为持久 epoch。wall clock 前跳可能使绝对 lease 已过期，旧 token 必须失效，不能保留“首 heartbeat 前永不失效”的假设或人为延长 expiry；后跳且当前进程时间落后正式持久前沿时，Store 同一写事务拒绝 claim/recovery，原 Task/attempt/events 原样保留，待真实时间追上，不通过未来 lease 截止倒推 now 或自动改写数据。跨进程仍核 owner/generation/token/expiry，不把时间当授权来源。

本次真实工件显示原 Host created/started=1792174517233/7264，而长寿命父恢复/再领取=1792174456966/7005，倒退约 60 秒；预算观察随后正确拒绝，故不得放松预算断言或把父恢复改成新子进程来隐藏问题。当前回归保留父/子冷恢复，另覆盖 wall epoch 前后跳、旧 token 过期拒绝，以及 direct/fair claim/recovery 在事务内对 created/started/updated/heartbeat/正式 attempt claimed 前沿的零写入拒绝。

Shell 的租约心跳独立于资源采样、输出读取和命令轮询，从新鲜 CAS 后开始，持有原数据库 locator 与同一 attempt。另一个不接触数据库或 lease mutex 的 deadline watchdog 仅使用已确认的 expiry；发起续租不延长执行权，续租往返阻塞也不能越过原 deadline。续租失败或已确认期限到期撤销原执行权，停止原进程组并保留未知副作用的对账事实；不能更换 token、调大租约或伪造成功。终态提交与心跳共享同一正式 lease handle，心跳停止和线程回收有明确所有者。

停止范围属于持有的进程树对象，而不是一个可复用的 root PID。Unix 在仍保留 leader 身份时观察/收口同组后代，再回收 leader；root exit=0 但仍有后代执行不构成 Task 成功。Windows 由执行前绑定的 JobObject 句柄拥有树及停止权，不能以 `Child.kill` 只停 root 代替整个树的停止；绑定失败须在业务代码执行前拒绝并回收，禁止未经文档化的恢复入口或 root 回收后的数字 PID 猜测。各平台 adapter 输出同一明确的已停止/残余/未知事实。

停止请求与停止确认是两个不同的 typed 事实：`kill`/`TerminateJobObject` 返回成功也不是确认。Unix 在 leader 尚未回收时有界观察同组无活进程，Windows 保留原 Job 句柄并有界观察 ActiveProcesses=0，才记 Confirmed；过程中的 signal 错误必须保留。确认的采样、轮询和 root 回收均不持有 Child mutex 跨阻塞等待，不能挡住 deadline watchdog。失败、超时或未知保存 Unknown 与不可安全重试诊断，不能写 stopped/Cancelled/Completed 来代替对账。

冷重启只有持久 PID/租约过期时，不具备原 Child/Job 对象或可验证的创建身份；PID 仍存活也不是原执行所有权证明。该路径不能发数字 PID/PGID 信号，必须保留原 Task、Run、Unknown physical stop 和不可安全重放事件。Windows Job 的 kill-on-close 也不能由“lease 已过期”推断为已经发生的正式死亡事实。

同理，PID=0 不是尚未执行证明：真实 spawn/resume 与后续 PID 回执之间存在崩溃窗口。Shell 交付使用正式 Task metadata 中的严格 typed witness，绑定当前 Task、attempt ID、worker/generation 与 token digest；不以独立文件与数据库双写保存“未启动”标志。时序为：同一事务 claim 精确 attempt 并初始化 Prepared → 在任何 worker 创建或接收请求前，CAS 将同一 witness 提交为 MayHaveExecuted 并取得 ACK → 才允许 spawn/传请求。后一步失败不恢复 Prepared；同一 attempt 禁止逆转、删除 witness 或改变绑定。恢复在同一 Store 写事务内重读 Task 与当前 attempt，仅精确 Prepared 且原 lease 已过期时可撤销该 attempt 并排队一次安全重试；MayHaveExecuted、缺失、外来或损坏 witness 均不允许凭 PID=0 重放。事务失败须保持原 witness、attempt、Task 和事件全量回滚；并发迟到交付不能借旧 Prepared 快照通过恢复。冷 reaper 仅在正式 expired-failure 事务提交成功后派生 status/SOP reconciliation；续租、重领或并发终态使事务拒绝时，不得由旧快照写旁路状态。

进程采样是有界观察：`ps` 等子进程同时受单调 deadline、输出字节上限和进程回收约束，stdout/stderr 必须并行排空，不能持管道等退出形成死锁，也不能占据续租线程。超时、解析失败或根进程缺失分别返回明确事实；没有样本不等于零资源。输出日志 stat 失败同样是未知，不是 0 bytes。预算强制执行依赖采样时，无法取得样本须停止/对账，不能忽略错误继续执行。验收保留真实进程预算、严格租约到期、迟到回执拒绝、取消及冷恢复的正负断言。

### 6.6 取消意图、执行调度与物理终结分离

取消意图可以立即将原业务 effect 从可派发 outbox 中撤下，但不证明它的物理 delivery 已停止。Core 的原 target 及精确 cancel control 在确认前继续成对保留；读取执行所有权、冷恢复与取消观察均包含该 target 的实际 lease，不因其 outbox 已 acknowledged 而漏掉。普通恢复只验证这一正式取消关系并等待原控制，不为 cancelling target 生成 Retry/Resume，也不把它当作丢失普通 pending request 而使整个恢复失败；无对应确切 control 的孤立 active attempt 仍拒绝。

只有当前受 fencing 的 cancel Host 回执被 Core 接受、精确 target/control 均从 pending journal 移除，Application 才在同一次提交结算该 target 的 active physical attempt：尚未开始记录 RejectedBeforeExecution，已开始记录 Cancelled，不伪造 ExecutionStarted、不改写历史 terminal attempt。该确认凭据来自控制执行，不借用目标旧 lease 的继续执行权；目标 lease 已过期不等于允许重放，也不阻止可信控制报告它已经停止。错误 target、过时控制、失败回执或仅取消意图均不能产生该结算。正式取消 Run seal、物理目标结算和控制回执必须原子提交，事务故障全部回滚。

正常 Host 与冷取消入口遵守同一证明标准。正常 Host 只可使用自己在同 host/session/turn/effect 下实际完成且终态响应已接受的同步 dispatch 事实，或目标 delegated worker 已退出并 join 的事实；发送 cooperative cancel、空的本地注册表、控制消息已入队都不是停止确认。已请求停止的本地同步模型 worker 实际返回是独立局部事实，不因旧内容响应被拒绝而擦除，也不代表远端效果回滚；任意外部工具不得借用这一模型边界。权限同步 handler 明确返回 StopRequested/Settled 只记录该 wait 已返回的局部事实，不发决定或冒认 Core 已取消；随后仍须单独取消控制确认。非终态 WorkerUnavailable/传输中断不构成此证明，同 effect 再次交付先撤下旧证明。delegated 输出及其接受回执先排空，再确认控制；排空失败、再次挂起或 owner 不匹配保留未对账。冷启动没有上述内存事实，必须经持久 target/control 及物理 owner 核验的取消入口，不得因新进程注册表为空而提前封存。

取消已退休目标的旧回应须先校验完整冻结身份、有效 delivery、精确 Cancel/target 关系及模型原 Attempt 身份，再作无内容/无账本修改 ACK；不得先走普通采样或终态 Attempt 修改。该 ACK 不增加正文、不覆盖真实 usage、不关闭取消控制；正式封存仍只由后续精确 CancellationConfirmed 驱动。

主动取消与断线的分类必须绑定当前 execution control 和确切权限请求：只有该控制已请求停止、且本地同步权限等待已实际返回，才能报告 StopRequested。普通 Disconnected 仍为传输中断，不据此生成停止证明；不得将远端失联或工具断线泛化为停止。

foreground 停止意图只有一个绑定 execution/Run 的 boundary producer；同步等待先返回与 boundary poll 先提交必须收敛到同一取消身份及正式 ACK。首次 effect claim 前也须处理 boundary，不能依赖模型/工具继续发响应。外层收尾不另造 Interrupt。Application 的现役 RequestRunCancellation 对精确 conversation/Run/assistant 作事务内取消/已取消/终态裁决；失败保留原请求和错误，不全局放宽 Core 重复 Interrupt。typed 已有取消只证明当前状态，不把请求身份回显冒充历史提交，也不替代随后停止控制及正式 seal。

取消控制在进入 ExecutionStarted 前须核对当前可用的精确停止证明或实际持有的 worker 控制权。无法启动的控制保持正式可恢复状态，不得先消耗投递机会再返回无归属错误；实际开始后若停止仍未知，则保留需对账状态，不伪造拒绝或失败以清空控制。取消批次可以跳过普通业务派发，但不能因此跳过同批后续 Cancel。恢复收尾读到 Cancelling 且无可领取项，不代表成功：应返回有来源的待对账结果。主动取消的正常完成必须有正式 Cancelled seal，不能仅因未进入 Failed 状态便成功退出。

被取消跳过的同批 target 可有精确局部 NotStarted 事实，但仅限当前已绑定 conversation/Run、有效冻结 Host/catalog/delivery、从未启动且无旧 cursor/worker 的实际待派发请求。不得用队列缺席、冷恢复或空注册表补出该事实，不为已启动、恢复或外来 owner 生成证明；该局部事实仍须由独立 Cancel 确认后才能封存。

工具终态 ACK 不覆盖物理停止不确定性。当前 typed ToolResult 的 Unknown/Partial/Deferred receipt 不因 Rust 调用返回或线程 join 变成 quiescent；Failed 自身也不证明停止。只有已有精确 owned-worker/tree stop 或启动前事实可独立补证。业务 data、输出文案与伪 `_nola_execution` 无权提升 receipt；仅可信冻结 effect=Investigate 的普通同步只读缺 receipt 保留当前局部返回边界，不伪造成显式 Completed。非 read 缺 receipt 的 producer 在取消时必须保留待对账限制，不自动重试。

ToolResult V2 将本地 OS 停止观察独立表示为必填 nullable local_stop，不改 Unknown/Partial 的业务语义。Host 私有 RAII 绑定每次 invocation 的随机 nonce、Host/session/Run/effect/request/call 及实际 delivery attempt，producer 只可在 owned group/Job 的真实停止观察后复制；消费必须整对象匹配当前 dispatch，不能接受前次/外来 identity 或业务 data 自述。MCP 不获得内建本地执行凭据。停止事实在同步 dispatch 返回后独立于业务 ACK 保留；它只支持后续 Cancel 控制，不能证明需求达成、远端回滚或安全重放。无停止证据的原生客户端 producer 明确写 null，缺字段拒绝。

命令的效果状态与本地执行生命周期分别记账：`ExecutionReceipt.local_stop` 是当前 Host 实际持有的 execution group/Job 停止观察，不改变 `Unknown` 效果、不授予业务成功或安全重放。它携带 Host 为本次具体物理 invocation 生成的 nonce 及 host/session/turn/effect/request/call 绑定，producer 只能从 Host 私有执行作用域取得，不能由模型参数或业务 JSON 自报；消费者逐项与当前 invocation 对照，旧 nonce/错 owner/错 call 均拒绝。Unix 保留原 Child leader 的内核身份，发信号后独立有界观察同组无 live 成员，最后才 reap；Windows 在任何业务线程执行前绑定原 Job 并等 ActiveProcesses=0。仅发出 kill、handler 返回、组观察失败或无原对象都不能产生该事实。Unix group 观察不证明已逃逸后代或外部效果停止，因此字段明确为 owned process group，不伪称任意 process tree 全停；未知 effects 与不可重放限制原样保留。

## 7. 验收边界

### 终端帧与历史所有权

当前 CLI 使用 alternate screen 与自己的历史 viewport，不能把原生终端 scrollback 当作完整对话历史。持久日志、待显示的语义内容、实际已提交帧和用户当前阅读位置是不同状态：model/Core 可先完成入账，渲染按有界视觉行预算推进；不可在一次 paint 中 drain 全部历史后只显示末屏，导致首段从未出现。超高 Markdown cell 也须有渐进呈现边界，不能提前把末尾 mutable tail 接到尚未呈现的前缀上。用户阅读历史时固定文档锚点，只有主动回底才重新跟随。

冷恢复已完成历史是已提交文档，不是本次正在生成的正文。历史 replay 装载完毕后，在 Idle 且没有可变正文的边界建立文档 tail 基线，保留完整已装载 source 和 PageUp/PageDown 锚点；它不生成执行/通知回执，也不声称旧历史每行刚在屏幕出现。之后新正文、首个 `/help` 和权限通知仍从该基线按原顺序呈现，不能被大段旧历史的逐帧动画阻塞。进行中输出或未完成 Markdown 不允许借此跳过渐进呈现。10M 恢复验收仍保持 15 秒、256MiB 分配及 384MiB 进程树 RSS 上限，不延长时限掩盖旧文档 paint backlog。

验收用标准 VT100 回放完整同步提交帧，不拼接被清除的文本，也不把合法 cursor 定位视为重复 footer。流式首段须在实际提交帧中出现；长历史另通过真实 PageUp/PageDown 检查 viewport 保留。输入框及 footer 在每帧唯一，运行中常驻输入框不等于已完成；取消后由正式 seal/RunResult 允许后续新输入。真实模型 runner 保留原始 capture、已提交帧、数据库及失败证据，以独立 `NOLA_HOME` 和临时存储隔离，不重设系统 `HOME`，不在登记证据后删除数据库。

### 上下文计量与缓存诊断的来源契约

配对移动端修改活动权限时，写入目标必须为实际执行 Host 的 canonical 会话，而不是只修改手机的副本。权限配置端口只接受两档 profile 和 CAS revision，并核对 expected Host、client、Run、根 assistant 与正式 source submission 归属；它不接受任意 Application 命令或全局 Host 配置。配置已保存与 active_policy ACK 分开，切换会话/Run 后旧异步回复不得修改新会话。首次提交前的本地选择仍随首次冻结提交入账，不伪造尚不存在的远端 Run。

`ContextUsageView` 与已提交 Run 用量分别携带 `measurement`、`prompt_cache_measurement`、`prompt_cache_diagnostic`。
前两个对象为 `{request_id, attempt_id?, context_generation?}`：request 是 Core 实际请求，attempt 仅在有物理请求证据时填写，不把逻辑请求冒充物理 Attempt。
当前预算估算属于下一次请求；Provider 用量和前缀诊断属于完成的那次请求。新估算可以保留旧诊断，但必须保留诊断自己的来源，禁止改挂到新请求。
没有来源时显示未知，不按时间邻近猜测；会话累计计费继续从物理请求账本去重加权，不由预算估算或最后一次比例反推。
该信息进入原始正式事件、冷读、远程提交摘要和客户端投影，不能只存在实时日志。当前 Run 用量协议为 1，摘要域为 `NOLA-RUN-CONTEXT-USAGE-V1`；无旧协议转换。

浏览器动作/观察共用 owner FIFO，跨 owner 并行；排队与执行均保护 owner 不被回收。预览控制带 session generation，元素 ref 带 page/generation/revision，旧预览不得作用于重启后的同名会话。动作已完成与观察失败分别返回；动作结果未知只允许观察对账，桥内不补发另一种输入实现。截图须定址真实 tab，不以当前前台页代替。Playwright 子进程就绪等待与每次动作 RPC 均有独立期限，不能持全局锁等待整个浏览器动作。

大输出写入采用模型证据投影；历史文本也先投影、再搜索或切片。范围偏移明确属于 `model_evidence_utf8` 视图，不能从原始 UI 控制 URL 中间切出令牌片段后再尝试脱敏；原始用户文件/证据不被此过程重写。单行命中有界，重复上下文行去重，输出预算在生成工具结果前执行。

Shell 的结构化 stdout/stderr 保存字段不得预先进行 head/tail 截断。完整结构化结果先交给统一证据保存器，由其生成全文引用及有界模型预览；展示文本可以提前缩短，但不替代结构化原文。否则分页读完的只是被省略过的副本，不能满足完整证据恢复契约。输出保留失败明确报告，不能宣称全文仍可恢复。
