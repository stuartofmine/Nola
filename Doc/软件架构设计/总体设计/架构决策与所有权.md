# 架构决策与所有权

日期：2026-10-15。性质：目标设计与本次静态核对结论；不是实现完成报告。
本文件定义跨模块数据写权，模块细节由专题维护；术语与边界见[总纲](SOFTWARE_DESIGN.md)，信封与回执见[公共协议](../模块契约.md)。
发现冲突须同时修正文档及任务，不按文件时间选择另一套规则；差距进入[当前任务总账](../../当前任务/README.md)。

## 1. 核心问题不是文件数量，而是允许多个对象修改同一事实

分目录、拆 class、增加协议都不能自动解决会话串状态、错误恢复、重复授权或配置丢失。
模块成立必须同时具备：单一权威、受限写端口、不可变输入输出、明确生命周期、失败出口和可验证不变量。
同一状态在 ViewModel、settings JSON、profile、Core checkpoint 中分别可写，就是多个权威，不是缓存。

## 2. 聚合、仓储与进程不是同一个概念

会话独立存储是逻辑隔离，不要求一会话一数据库、一进程或一套服务。
复用现有 canonical store，以带 authority/store scope 的 ConversationRef 标识归属；跨端不能只凭裸 conversation ID 合并数据。
authority 是业务写入来源，Host 是执行位置，两者不必相同；会话改执行设备不自动改变身份或 authority。
会话包含不同子域的引用，不是一个可整体替换的大 JSON 对象。

| 数据/对象 | 权威与唯一写入路径 | 生命周期/持久化 | 禁止行为 |
|---|---|---|---|
| 模型目录、默认值 | Application 的目录用例 | Host/账户级持久配置，凭据仅安全引用 | 新默认值静默覆盖已有会话 |
| ConversationConfiguration | 配置命令，经 Application 提交 | 会话级，独立配置版本为目标 | metadata/profile 绕过配置命令 |
| 消息、Part、工具结果 | Core transition → Application 事务 | 会话/Run 归属，追加并封存 | 从 UI trace 反建权威正文 |
| Run/Attempt/Effect | Core 语义，Application 提交，Supervisor 执行 | 独立于窗口，持久执行身份 | 用网络断开推断失败或未执行 |
| Context/摘要 lineage | Context 决策 → Application 提交 | ConversationRef + participant/协调 Context，原文引用可验证 | 覆盖原文或授权事实 |
| Goal/Plan/Task | 各自命令与 Core 决策 | 会话内作用域和显式父子引用 | 子代理直接改父 Goal 或全局配置 |
| usage/缓存计数 | 物理模型 Attempt 回执 → Application 去重提交 | 归属原 operation/Run，会话关联汇总 | View 局部计数、父子重复记账或平均百分比 |
| 未提交草稿/附件 | 设备本地 DraftRepository 的条件写入 | device + store + conversation/draft，独立版本 | 以草稿恢复覆盖已创建会话配置 |
| 滚动、折叠、导航 | 窗口展示对象 | window + conversation，可按产品策略保存 | 控制运行或另一会话输入框 |

Application 是写入协调者，不代替每个领域对象拥有所有决策。Store 实施事务和完整性约束，不根据客户端名称制定业务政策。

### 统一对话、Agent 与 Context 的目标所有权（2026-10-20）

[统一对话设计](../../UI和交互设计/MULTI_AGENT_NAVIGATION.md#71-数据所有权来源作用域与生命周期)细化单人/多参与者共有的数据合同；当前代码仍需收敛，不将此节标为已实现。

- Agent 只拥有可复用配置及其版本，不拥有会话历史、正在运行的任务、权限批准或跨会话滚动上下文。Agent 管理不创建聊天；唯一新对话入口创建 Conversation 及参与者。
- Conversation 拥有成员关系、唯一公共消息流、提交/响应组及会话政策。ParticipantConfiguration 拥有该成员实际采用的指令、模型、参数和能力/资料选择；配置来源是加入时的 Agent 快照，更新须显式提交。
- Context 归属精确 ConversationRef + participant；协调 Context 独立，不能混用成员私有历史。Context 压缩与模型输入是规范来源的派生结果，不覆盖公共消息或自动产生长期记忆。
- Run/Attempt/工具结果与产物保持原 Context/执行来源；公开时间线引用规范正文。共享对话、相同 Agent 或物理存储去重均不授予跨 Context 原始证据访问权。
- 附件暂存归 Draft，正式接收后的引用归 Message/Conversation；长期记忆、资料源和凭据分别归自己的存储与安全 owner，Context 仅使用获准且带来源/版本的引用。
- 草稿归设备与明确 editor owner，导航展示归窗口。首次正式提交事务与本地 ACK 绑定分别处理；不虚构本地/远端原子写，也不按 Agent 建立聊天草稿。

下表中的会话级执行配置在多参与者场景应区分共享政策与成员配置；单人也采用同样的 Participant/Context 结构，不维持第二套独占 Agent 会话路径。详细读取范围、跨成员披露和生命周期以统一对话设计第 7.1–7.3 节为准。

### 其他领域的所有权与删除边界

以下为跨模块目标，具体 schema、已实现范围及错误契约由对应模块维护。

| 对象 | 所有者与使用方式 | 更新、撤销与删除边界 |
|---|---|---|
| 模型连接、账户与凭据 | 连接目录拥有端点/模型身份，安全存储拥有凭据；成员配置只引用选择 | 目录更新不静默更换旧 Run；凭据撤销在实际派发时生效，不将密钥复制进 Agent、消息或同步投影 |
| 长期记忆 | Memory 仓储保存 scope、provenance 与版本；Context 按政策检索引用 | 对话压缩不自动写记忆；删除会话不隐式清空独立记忆，记忆删除/更正由自身命令处理 |
| 资料源与快照 | DataSource 管理连接及刷新；快照有来源、版本、时效，Context 保存本次引用 | 选择资料不授予读取权限；撤权阻断后续访问，历史引用不伪装为最新快照 |
| Skill、插件、MCP | 安装/连接配置拥有目录和 schema 来源；Run 冻结能力基线，Core 准入具体调用 | 安装不等于授权，文本不能提升权限；变更/卸载不能静默改写已派发工具调用 |
| 自动化定义与触发实例 | Automation 拥有调度定义及版本，每次触发有独立持久身份并进入相同准入链 | 修改定义只影响之后触发；停用不等于取消已准入 Run，取消须提交到原运行所有者 |
| 远程 Host 与同步镜像 | 原 authority/store 拥有业务事实，执行 Host 返回回执，镜像保存来源及水位 | 换设备不改变写入权威；断连不删除源数据，也不能将镜像计为另一份执行/费用 |
| 索引、导出与诊断 | 从规范来源派生并保留来源标识；不拥有消息、任务或授权事实 | 可重建索引不等于可重建用户数据库；导出失败不回滚已提交业务事实，日志不反写正文 |

跨领域删除必须明确目标、引用影响和保留策略；不能靠级联删除猜测用户意图。归档只是可见性/生命周期变更，不等于撤权、停止任务或擦除原始证据。

### 字段归属不能按现有 JSON 容器名判断

| 字段语义 | 目标所有者/写端口 |
|---|---|
| 模型身份、生成参数、推理档位、成员工作指令 | Conversation 内的 ParticipantConfiguration；Run 冻结实际值 |
| 会话默认执行位置及具体 Host 绑定 | ConversationConfiguration 的默认位置；Run/Effect 绑定实际目标，不从当前窗口推导 |
| customSystemPrompt、responseStyle、enableRetrieval 等影响成员输入的设置 | ParticipantConfiguration；streamOutput 等调用协议策略由有效 Invocation 冻结，不能因放在 clientModelPresentation 就当成纯 UI |
| permissionModeRawValue/permissionProfile | Conversation 共享政策；派发时仍核对有效授权与撤销 |
| memory/retrieval 策略 | ParticipantConfiguration 的选择；Memory/DataSource 所有者决定实际可读范围，不随成员选择扩大授权 |
| 标题、固定/归档等非执行元信息 | ConversationMetadata 的显式命令与白名单 |
| showThinking、展开、滚动、动画 | 窗口/设备展示设置；持久化也不取得业务写权 |
| knowledge 文档、Goal/Plan 约束与人工修订 | 各自带版本的内容对象，由 Context 引用，不随整包模型设置覆盖 |

此表是目标归属，现有代码与写端口须按该语义重构并更新全部调用者，不能只将旧 JSON 换个类型名；不转换或改写用户已有存储，不匹配格式明确拒绝。
Patch 的“缺字段”表示不改；Set、清空值与重置到默认分别表达，字段不支持的动作明确拒绝。
重置时若非显式动态继承，应解析并保存当时默认值；不能留下隐式空洞待下一窗口自行补全。

## 3. 配置优先级与冻结点

新会话显式初始化有效默认值。之后已有会话的模型、参数、权限和执行位置由自身配置管理，不能再次偷偷读取当前全局值替换。
确需动态继承的字段必须显式建模为继承策略，不能把字段缺失、null、清空、恢复默认混成一种含义。
发送时解析会话配置和目录版本，冻结 EffectiveInvocation；进行中的 Run 不随 UI 选择变化。
冻结的是语义参数、路由身份、版本和安全凭据引用，不冻结密钥明文或永不过期的访问权。
每次物理 Attempt 解析仍有效的凭据；轮换可继续，撤销应阻断。目录后来修改不重新解释旧 Run 的模型/端点。
权限变更是显式活动政策例外：不回写旧调用快照；配置 CAS 提交后通过持久 owner/Run 命令及精确 ACK 更新后续未派发操作的政策。切到全部允许可以关闭原待授权并继续同一调用，不能复活拒绝、取消或重跑未知副作用。细节见[执行权限与证据边界](执行权限与证据边界_20261016.md)。
模型目录删除或凭据失效应返回明确配置错误，不能偷偷换端点或模型。

聊天推理控件展示模型声明的原生 effort，不压缩成三档，不将回答风格、提示词模板、工具集合与 effort 绑定为一个界面选择。精确 `reasoningPreference` 由 Application 校验并冻结；`reasoningTier` 仍可承接显式 agent 策略意图，但不与原生档位形成重复聊天入口。详细优先级见[生成参数合同](../模块/08-模型配置与调用/GENERATION_OVERRIDE_CONTRACT.md)。
推理档位不是权限模式，不授予工具授权，也不因控件选择永久剥夺任务所需能力。工具发现按版本化目录扩展，具体调用仍按同一权限链路处理。
改变实际档位、工具数组或系统内容会影响请求与缓存前缀，必须冻结新的调用快照并计量；没有 usage 不显示为 0%。
Run 冻结允许的能力/schema 基线，单次模型请求冻结实际暴露的工具数组。
发现并激活该基线中的延后工具可在模型边界形成新 Attempt 快照；新安装插件或改变 schema 不能静默替换既有基线。
如需扩大基线，须显式重新准入相关配置/权限或创建新 Run，旧已派发请求保持原绑定。

## 4. 面向对象和协议边界

- 值对象：身份、版本、资源引用、冻结配置。构造即校验，不持有服务定位器或可变全局单例。
- 聚合：封装状态迁移和不变量，只经命令变更；不向外暴露可变集合。
- 用例服务：编排读取、领域决策、事务提交；不承担 UI 布局、provider wire 或系统权限弹窗。
- 端口：命令、查询、订阅、仓储、模型调用、工具执行和用户交互分开。按消费者实际需要设计，不建立包含全部能力的万能接口。
- 适配器：Swift/Kotlin/HTTP/FFI/SQLite/provider 实现端口，不拥有另一套业务状态机。
- 装配根：连接实现和生命周期；不得成为绕过 Application 的业务入口。

接口至少规定作用域、版本、前置条件、输入、输出、错误、取消、幂等和提交时点。
wire 可使用 JSON，但领域边界必须是可枚举的类型；外部任意工具数据只能存在于明确的扩展载荷位置。
移除旧入口时迁移所有调用者并删除旁路，不新建同义 adapter 维持旧接口。

## 5. 版本与并发

目标区分 configurationRevision、transcriptCursor、taskRevision、draftRevision；不是给每个字段无限增加版本。
每个版本对应可独立并发修改的一致性边界。跨边界命令携带依赖版本并在同一事务验证，例如发送同时核验配置版本和父消息位置。
客户端携带读取时的版本；冲突刷新原 owner 并保留编辑，不自动把 expectedRevision 改成最新值重放。
重复 Application request_id + 相同命令/前置条件返回同一回执；同身份不同内容拒绝，具体去重作用域见公共协议。
事件按 owner、Run、generation、cursor 核验，窗口切换不能改变其写入对象。

当前实现仍共用 conversations.revision；本节是整改目标，不声称版本拆分已经落地。

## 6. 文件持久化与数据库不双写

Goal、Plan、任务约束、进度和压缩记录须持久化；可读文件导出用于审阅、恢复和模型查阅。
canonical 事务是唯一业务提交。文件含 owner、revision、来源摘要，由已提交事实生成；文件写失败不伪装业务回滚，也不丢失可重试导出意图。
人工编辑文件须经导入命令与版本冲突校验，不直接覆盖数据库。原文、工具大输出存为内容引用；BM25 和展示缓存可重建。
设备本地草稿文件另有自身单一仓储，不加入第二份消息/任务账本。

## 7. 权限、能力和展示分离

产品模式只有 `cautious`（谨慎，默认）与 `allow_all`（全部允许）。谨慎对删除、覆盖、敏感数据访问、外发与新连接确认；普通读取和检索不逐次审批。全部允许不再出现 Nola 应用确认。删除原三档及旧值兼容，详见权限模块规范。

模型声明支持工具 ≠ 某次调用已授权；自动批准 ≠ OS 已授权；工具成功 ≠ Task 完成。
不可覆盖的资源/OS 约束与显式撤销先求交，再在有效范围内应用产品默认和用户授权；不能用“最后匹配 allow”覆盖高优先级限制。
自动批准模式不再询问本可自动批准的应用层操作，但不能越过平台强制授权、不可获得资源或用户明确限制。
普通 CLI 路径不因超出工作区而请求目录确认；敏感读取和操作审批使用具体 Core 请求，只有操作系统实际要求时调用系统授权窗口。
Skill/MCP 内容不能授予自己权限；模型从 schema 选择能力，禁止客户端通过自然语言关键词强制路由。
独立审查是模型可选择的工作方式，不是所有任务的强制阶段。

## 8. UI 只消费投影，但投影本身是正式协议

消息由稳定 Message/Part identity 与顺序组成，执行过程按因果顺序保留思考、工具、结果，最终正文独立呈现。
思考/执行过程区域在最终正文上方；区域内部不能按“所有工具放最后”重排，也不能把 commentary 一律标成思考。
完成封存已有对象，不替换整条消息；组件只订阅自身变化。底部跟随与用户阅读历史是窗口状态，不是业务状态。
正式投影与临时 live overlay 有独立身份和来源，overlay 不写正式正文或任务状态；Trace 只用于诊断。
CLI 同样只有一个布局所有者，禁止普通 stdout 和交互 renderer 同时写输入区域。
具体样式留给 UI 设计文档，本目录约束数据与更新协议。

## 事务权威、执行权与显示权的裁决表（2026-10-28核对）

这些边界在同一界面并存；不能为了“多端复用”让客户端Store同时取得源Run写权。

| 对象 | 唯一可变业务事实 | 可独立存在的显示/物理状态 | 禁止的越权路径 |
| --- | --- | --- | --- |
| 配置选择 | 源Conversation configuration CAS | 窗口未保存参数与选择菜单 | 将不同选择字段分次写入，或让旧Run追随最新默认模型 |
| 已准入Run | 原执行authority的checkpoint/事件/outbox/terminal | 多个观察者、流连接及本地副本 | SSE结束就标完成；关闭页面就提交业务取消 |
| Task child | 不可变admission、父/child binding、attempt及canonical结果 | 单独worker、只读child页面、父任务已结束的页面 | 父answered代替child终态；镜像投影创建本地任务；到期后清cancel标志重跑 |
| 审批 | Core原pending请求、正式settlement与grant | 原生权限弹窗、重示trace、等待中的编辑框 | 重新展示等于Allow；刷新参数后沿用旧审批；旧attempt回执被新投递接纳 |
| Surface | owner/generation、revision、data/tree、phase与当前action handle | IME、焦点、输入缓冲、未提交preview | 任意JSON路径编辑；历史handle控制当前Surface；LLM自报owner |
| Context | 该请求工作集、覆盖区间、component来源/授权与usage | UI token条与可读摘要 | 检索结果直接当系统指令；授权状态由新鲜度代替；摘要覆盖原文 |
| Memory | namespace内记录/版本、commit intent与来源 | 召回候选、索引、模型对记忆的自然语言描述 | 候选获取等于准许披露；后台旧digest覆盖用户新编辑 |
| Remote replica | 经验证的源记录及摘要链 | 本地conversation显示修订/草稿 | 把本地revision当源Core版本，或把remote记录再次作为本地发布写回 |

执行Host控制真实I/O并提交观测，但不知道“业务是否已经完成”的最终答案；Core也不能凭lease到期证明外部进程已停止。取消在这两个权威之间需要exact target/control及已提交结果闭环，而不是一个共享布尔值。

纯值结构、DTO抽取和shared组件只能共享表示；业务复用的判断标准是所有客户端调用同一个准入/裁决/提交端口。由Web自行生成压缩、由SwiftUI合成审批身份、由Compose重推Task终态，即使DTO名称相同也仍是并行状态机。
