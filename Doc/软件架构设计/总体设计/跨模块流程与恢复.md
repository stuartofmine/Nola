# 跨模块流程与恢复

状态：目标流程，2026-10-15。与[所有权决策](架构决策与所有权.md)配套。名称为职责表达，复用已有 Domain/Application 协议，不新增平行执行框架。

## 当前调用入口与流程图的边界（2026-11-08）

下文流程描述业务不变量，不保证每个逻辑名称都有同名 DTO。桌面 Service、移动 embedded 和源 Host 的实际入口见[实现映射](CURRENT_IMPLEMENTATION_MAP.md)；状态机实现属于 agent engine，正式接纳/持久提交属于 Application/Store，Driver/Host 执行物理效果。

统一对话目标不等于当前 Room submission/成员 Context 已删除；自动化 typed execution_spec、发生实例和 Run 绑定也不是 metadata-only 页面流程。内存句柄、物理快照、命令回执和跨设备镜像不可混为恢复权威。已确认的 memory owner 与 bootstrap 配置恢复差距见[源码核对](ARCHITECTURE_SOURCE_AUDIT_20261108.md)，本页不以理想流程掩盖它们。

## 统一主链路

```text
客户端命令
  → Application 核验身份、版本、幂等
  → Core 决策
  → Store 事务提交：事实 + checkpoint + outbox + 投影游标
  → Supervisor 领取已提交 effect
  → Model/Tool/Interaction Host 执行
  → Application 接受原身份回执并提交
  → 客户端按游标读取已提交投影
```

持久准入前不得确认业务接受或派发副作用；Accepted 与 Committed 的含义见[公共协议](../模块契约.md)。
客户端断连不撤销提交，重连先查询原 request_id，不重新发起已提交任务。
checkpoint 保存解释运行状态所需事实，不能依靠 UI 内存或最新自然语言摘要恢复。

## F1 创建、编辑、发送和切换会话

1. 唯一“新对话”动作进入设备本地草稿；Agent 管理只编辑配置，不创建会话。草稿保存成员选择、模型引用/参数及暂存附件；首次正式发送原子创建 Conversation、成员配置快照与首条消息，明确回执后绑定草稿归属。
2. 编辑配置带读取版本。成功回执仅更新该 owner；冲突保留编辑并显示解决入口。
3. 客户端先保存发送意图：稳定 request_id、ConversationRef、草稿读取版本、内容/附件摘要和必要安全引用。
   Application 核验会话、配置/父消息前置条件及已提交附件引用，提交唯一用户消息、submission 与成员分派意图，按准入结果创建对应 Run/effect 并返回回执；多成员不能复制用户消息形成多个公共事实，待分派也不伪称全部 Run 已开始。
   设备本地草稿版本由 DraftRepository 核对，远端服务不能原子检查本机文件或 IndexedDB。
4. Committed 后条件退休发送所捕获的草稿版本；期间新输入保留。若版本已变，仅将发送意图标为已提交并保留当前草稿；
   只有仓储拥有明确编辑操作 lineage 时才可退休对应范围，不能用字符串前后缀猜测并删除内容。
   响应丢失或进程退出先按发送意图查询原 request_id；本地退休失败可幂等重试，不能重发用户消息。
5. 切换只换展示订阅与本地草稿读取。A 的输出、失败、待授权继续写 A，不阻止 B 的独立发送；资源限制以明确调度结果展示。

故障断点：创建提交后客户端退出、发送提交后 ACK 丢失、附件晚到、删除后回调、A→B→A、同 ID 不同 Host。
跨数据库与本地草稿文件不假设分布式事务；由提交回执和幂等退休记录完成恢复。

## F2 模型调用与工具执行

Context 提供输入计划，配置解析器提供冻结 Invocation，模型 Host 只负责协议适配、流解析、取消和 usage。
模型提出工具调用后，Core 校验 schema、资源、权限和预算；Application 提交等待或执行意图。
需询问时保存 wait identity，再交给客户端呈现。选择只形成原等待的回答，不修改原参数后沿用旧授权。
工具返回调用状态、业务数据、展示预览、完整结果引用和执行证据；缺少证据不能补造成功。
工具结果与后继 Core transition 原子接受后，再继续模型请求；工具成功不会自行封存 Goal。

中断分别处理：模型流未完整结束、工具明确失败、调用尚未开始、已派发但结果未知。不能全部折叠成“重试”。
未知副作用先核对，不可核对则呈现 unknown/blocked 和可行操作；不得自动重复写文件、付款或外部消息。

## F3 动态上下文、热分叉与截断续写

输入先绑定 ConversationRef、participant/协调 Context、来源游标与配置版本；同一 Agent 在不同会话不共享滚动历史，协调 Context 只取得允许公开的有界材料。
正常输入由稳定系统/工具前缀、已压缩块、未压缩尾部、权威任务引用组成。
达到窗口约束时预留真实输出和协议开销；压缩选择未压缩范围，不反复总结全部旧摘要。
热分叉使用可验证的上一正常物理请求快照，保留模型、系统、tools、历史和推理设置，在尾部添加摘要指令。
同时保留原 tool_choice 等影响前缀/协议的设置；只用追加指令要求不调工具，意外调用丢弃候选后按冷路径回退。
不能为了禁止工具而删 tools 或改系统/角色，再把该请求标为相同热分叉。
发送完整可复用前缀不等于把全部历史再次纳入摘要；摘要范围由来源引用明确限定。
是否热分叉由快照身份、协议支持、窗口、缓存时效证据和成本策略决定；不能从“同一会话”推断命中。

候选输出带源范围、fingerprint、lineage 与 usage。提交比较计划覆盖的来源与 context 边界，
不能仅以 conversation 总 revision 改变拒绝所有候选。源范围仍是原样有序前缀时可保留计划后追加的尾部，
在同一提交重新计算完整请求预算；源被改写、删除或另一压缩改变边界时拒绝或显式重计划。
Goal/权限更新只保留其独立权威引用，不能被候选旧快照覆盖。
“完整候选”指传输正常结束、结构与来源/预算校验通过，不意味着模型摘要已被证明语义无遗漏；
关键约束通过独立 Goal/Plan 记录保留，摘要质量仍需真实任务验收。
取消、空结果、工具调用不执行摘要请求中的工具，也不提交残缺摘要；按有界策略回退或报告失败。
截断有正文时保存候选片段并续写，去重衔接，直到完整或达到明确总预算/取消条件。
不设置固定 4096 之类的内部摘要硬上限；仍遵守 provider 上限、窗口限制和用户成本预算，不能无限循环。
原文保留，通过授权范围内 BM25/引用读取；外部文本和摘要不提升为指令。

压缩导致旧前缀变化是正常成本，须如实计量。清理工具输出按批次产生新上下文版本，不每轮无意义改写历史。
摘要块追加后也须计入预算；达到块数/输入目标时以显式 consolidation 操作合并已压缩块，保留原文范围与 lineage。
普通压缩仅处理未压缩部分；consolidation 单独记录成本及缓存失效，不能静默每轮重写旧摘要。
手动压缩仅在当前主交互通道和 effect 已静止时准入；自动压缩在模型边界进入。
活动时的手动请求返回 busy 并保留原任务，不创建新维护循环，具体见 Context 模块。

## F4 主对话、辅助决策、Goal 与子代理

各 LLM 场景共用调用解析及 Attempt 计量，场景声明目的、输入投影、输出 schema、工具政策、取消 scope、总预算和恢复方式。
辅助决策不隐式借用当前选中模型；摘要、命名、计划或审查均有所属会话/操作身份。
可保存 Agent 是配置对象，运行时子代理是任务执行关系；保存、修改或归档 Agent 不自动创建或取消子任务。
子代理接收已持久化的任务、约束、资源范围、有效配置和预算；结果作为父级输入，不直接修改父级完成状态。
父取消按持久任务关系传播到子级，子级失败不能取消兄弟；重启恢复持久任务关系，不恢复旧内存句柄。
独立审查由模型按任务需要选择。复杂档位可改变资源预算，不强制开启审查或子代理。

## F5 usage 与缓存统计

以物理请求 Attempt 为去重粒度，记录 provider 原始计量和归一化口径，主对话、压缩、续写与子代理都不能漏账。
有缓存读数的请求：已计量部分缓存率 = 缓存读取输入 token 总和 / 同一口径下输入 token 总和。
只有计量覆盖完整时才能不带限定地称会话总体缓存率；缺测时明确覆盖数，不能据已知部分推断全部请求。
分母包含缓存读取部分；各 provider 的 input/cache read/cache write 先归一化，不能直接混加异义字段。
不报告 usage 的请求记 unknown，同时展示计量覆盖范围；不当作零，不用估计值冒充真实命中。
协议明确无缓存能力与计量缺失不同：可证明未缓存的完整输入可记零缓存读数，缺少证据仍为 unknown。
响应迟到或重订阅更新原 Attempt，而非重新累加。缓存统计持久化后按会话投影，窗口切换不重置。
子代理 Attempt 只保存一次，由明确的归属关系汇入会话；父 Run 的包含子费用摘要不能再加一次。
远端累计快照按源 Run/epoch/水位替换，本地执行账本和远端镜像不可重复作为两份物理请求。
有累计 token 但尚无可信终帧的请求标注 provisional；最终 usage 不可得则保留 unknown，不把丢失的尝试删掉。

## F6 重启、取消与恢复

恢复先读取 canonical Run、等待、取消意图和 effect 回执，再核对 Host 状态。
网络已断、worker 租约过期、操作系统进程退出是三种观察，不自动证明外部副作用结束。
“检查状态”是查询；“继续”是有前置条件的新命令；“重试”只适用于允许重试的阶段，不共享一个无差别按钮。
取消提交回执与执行停止确认分开；投递失败保留原取消意图，不能重新创建另一个取消目标。
取消有界核对后可封存“取消且仍有效果未知”，未知效果以独立记录继续核对；不能谎称已回滚，也不能永远等待不可能取得的 OS 确认。
移动端进程回收时保留可恢复/受阻状态；持久任务不代表 OS 允许后台持续执行。
某会话不可恢复不得全局锁住其他会话。确有单资源约束时返回资源等待，而非伪装为另一会话未完成。

## 流程验收

每条流程至少覆盖正常、重复提交、乱序、提交后断连、进程重启、取消竞争、版本冲突和跨 owner 拒绝。
验收不只断言文案，还要断言持久状态、实际副作用次数、原文完整性、费用账本和新会话是否可用。

## 当前实现补充（2026-10-28）

发送前读取源submission frontier，冻结配置与父消息前置条件；选模已创建但尚无消息/Run的会话允许首次准入。恢复保留原Run/调用配置，先回收过期delivery再准备Core effect恢复；审批重示不产生授权。取消观察只detach，业务取消须经持久控制及canonical seal确认。Core与Store版本分别验证，远程usage/journal保留源协议键和摘要。详见[当前接口](../模块/01-领域与协议/CURRENT_RUNTIME_INTERFACES.md)。

## 故障切点与恢复责任（2026-10-28核对）

| 切点 | 已有持久事实 | 恢复动作 | 不能做的动作 |
| --- | --- | --- | --- |
| 选模提交后、首次Run前 | 配置CAS与可能存在的配置checkpoint，无执行历史 | 读取源frontier并冻结首次发送前置条件 | 将任意checkpoint视为已有Run owner |
| reduce后、Store commit前 | 只有热候选/未提交事务 | 回滚Store及Runtime工作单元 | 将热delta或UI占位消息当已提交结果 |
| Store COMMIT返回错误 | 提交结果未知 | poison/reopen后核对原回执 | 仅凭rollback成功认定未执行并换ID重试 |
| Store commit后、热状态adoption失败 | 持久事实可能完整、热状态不可用 | 以原Store重新建立Runtime | 为迎合内存状态改写持久记录 |
| 审批等待中进程退出 | 原pending approval与delivery/attempt | 按独立lease恢复，正式Core重示 | 把采集取消当业务拒绝或批准 |
| child取消已请求、前worker失联 | 原bound Run、cancel意图及尚未核清效果 | cancellation_only推进精确取消 | 新claim开始普通工作、重发模型或直接settle Task |
| Surface编辑后、动作排队失败 | 同事务候选尚未公开 | 整笔回滚，保留客户端草稿 | 仅提交Surface或仅向模型补发文本替代原action |
| journal内容下载中、另一观察者已提交 | exact header与已提交manifest | 精确重放确认，沿原cursor继续 | 丢弃所有冲突或创建新stage绕过顺序 |

这些切点对应不同命名域的重试。transport重连、Application同键回读、effect恢复、模型新attempt与新Run继续任务不能合并为通用retry按钮。恢复UI只呈现Core允许的动作，不自行根据错误文本决定Retry/Resume/Allow。
