# MOD-01：Domain / Protocol

状态：现行模块职责；2026-11-08 核对当前实现入口及依赖。规范要求、静态接线与历史运行证据分别说明，不将未复测路径标记为通过。

## 设计、输入输出与生命周期

- 所有者：`nola-domain` 定义业务身份/值；`nola-host-protocol` 和 `nola-protocol` 定义边界信封，不决定业务。
- 输入：构造参数或已收到的 wire 值。输出：经过结构校验的 DTO 或 admission 错误。
- 必须表达：身份、资源、执行回执、证据、任务结果、权限决策、配置快照和版本。
- 无数据库/网络/系统时钟；不依赖客户端。Domain 枚举不能由 UI 文案反解析。
- 验证：序列化 round-trip、未知字段/缺字段、非法联合类型拒绝；逻辑相等不依赖平台语言。

## 对象封装与依赖协议

跨模块边界以[架构决策与所有权](../../总体设计/架构决策与所有权.md)及[流程与恢复](../../总体设计/跨模块流程与恢复.md)为准，本文细化本模块职责。

Identity、Resource、Command、Receipt 为不可变值对象；协议 DTO 不持有业务服务。
所有跨边界输入输出遵循[公共信封与错误契约](../../模块契约.md)。对象命名为设计职责，不要求新增同名类型或 crate。
模块不得暴露可变内部状态；写入必须由其权威所有者处理。具体接口复用已有类型，缺少类型化边界列入整改，不用别名或额外包装宣称解耦完成。
