# Code Mode：受控工具编排

状态：2026-10-18主链路已实现并取得跨层验证；最终回归与逐项证据见当前任务台账。故障恢复采用transport故障注入，客户端验证为协议/投影与Web组件渲染，不宣称全平台人工UI走查。

## 目标与非目标

模型提交JavaScript，在一次模型请求内完成依赖结果的工具调用、条件分支、循环和有限并行，并只输出需要的结果。执行真实JavaScript，不用预定义任务DSL或关键词路由代替。普通工具调用仍可使用；由模型选择编排，不按用户文本强制切换。

此次包含执行、等待/取消、会话隔离、嵌套权限、输出归档、故障恢复和真实模型验收。不包含CSV作业系统，不允许脚本直接访问文件、网络、进程、环境变量或客户端凭据。

## 参考及现状

已读本地 `参考资料/codex-main/codex-rs/code-mode-protocol/src/description.rs` 与 `code-mode/src/cell_actor/types.rs`：借鉴隔离执行、异步工具回调、cell等待、取消传播及终态单一提交点，不照搬其进程内状态作为Nola持久化权威。

Nola的Core `agent/runtime/tool_driver.rs` 持有权限判断、待授权工具状态及ExecuteTool效果；Host执行器不能替它授权。现有HostResponse与CommittedRuntimeDriver需要扩展嵌套调用协议，不能在CLI工具实现里递归调用execute绕开Core。

## 模块及所有权

| 模块 | 输入 | 输出 | 责任 |
|---|---|---|---|
| Domain CodeMode契约 | owner、cell身份、预算、调用序号 | 类型化cell/嵌套调用/观察结果 | 身份、状态、预算边界；无执行与数据库依赖 |
| Core编排准入 | 已绑定cell的嵌套工具请求 | 普通权限判定和冻结ExecuteTool效果 | 复用目录、schema、资源、授权及未知效果规则；不授予脚本整体工具权限 |
| Application/Store | Core转移、cell观察与回执 | 原子持久化记录、精确恢复查询 | 原Run/会话所有权、调用去重、终态与输出游标；不存第二份任务真相 |
| Host JavaScript执行器 | 源码、预算、受控回调 | 调用请求、显式输出、终态 | CPU/堆/时间限制、异步Promise执行、取消；无裸OS能力 |
| RuntimeSupervisor适配 | cell生命周期、取消、Host断连 | 现有任务监督/回收 | 不新建平行任务调度器，不重放未知写入 |
| 客户端 | 规范工具/授权/任务事件 | 执行过程、权限面板、结果 | Mac/CLI/Web/iOS/Android复用现有投影；不能自行推导成功 |

## 模型接口

- `code_mode_exec`：源码、有限执行预算和首次观察等待时间；返回完成结果或稳定cell引用。使用普通JSON工具schema承载源码，兼容外部模型协议，不要求provider支持freeform。
- `code_mode_wait`：精确cell引用、输出游标、等待时间及可选terminate；只观察原cell，不创建新执行。超时返回running，不能当作失败或自动重启。
- `await tools.<tool_name>(arguments)`：访问本Host真实目录中的工具。对不能作为标识符的名称支持方括号访问，避免名称规范化碰撞。目录可发现性不是授权。禁止递归启动Code Mode导致预算/取消链逃逸。
- `text(value)`：追加显式模型可见输出；超预算保留归档引用，不静默丢弃。未显式输出的中间结果不自动塞回模型上下文，但其执行回执仍归档。
- `ALL_TOOLS`：Host提供的名称、说明和schema发现入口；不包含凭据，不接受脚本自行注册Host函数。

第一版不承诺任意JS对象跨cell持久化。后续cell依赖显式结果或现有原文引用，而非无法恢复的内存对象；这不限制同一cell中的普通JavaScript变量和异步组合。

## 执行流程与故障边界

1. Core验证外层执行请求，绑定conversation/run/call/cell身份与预算；提交后Host启动隔离器。
2. 每次嵌套调用携带cell、父call及单调序号；Application验证来源并持久化，Core按当前目录与具体操作执行正常准入。脚本等待对应Promise，不阻塞权限回复通道。
3. ask使用原会话的权限面板；deny作为结构化工具失败返回脚本；允许后执行原冻结计划。回执仅能完成对应序号一次，迟到或跨owner结果拒绝。
4. 并行调用受cell及现有Host并发预算限制。脚本取消停止新请求、取消下游；已经发生的修改不能谎称回滚，未知效果沿现有恢复机制处理。
5. 首次等待到期返回cell引用。观察输出使用明确序列游标，重试读同一页稳定；客户端确认前不得破坏性消费输出。
6. 正常结束、异常、限额、取消共用一个终态提交点；JS结束时仍未等待的工具调用必须取消/结算，不能把悬空写入视为成功。
7. Host崩溃后不重放源码来恢复JS堆。持久化cell标记中断/待核对；已完成调用与输出可查，未知副作用不能自动重发。已完成cell冷查询不运行模型或脚本。

## 引擎与资源预算

### 提前返回的双生命周期契约

原实现把 exec 父工具的 Running 与 cell 的 Running 绑定，这是首次等待返回尚未完成的根因。不得仅把父工具改成 Completed，或借用后台任务 TaskPromoted 来提前返回：这会关闭原 Host effect 的回调入口、丢失后续工具结果，或重复写入父 ToolResult。前台结果可使用 Deferred 表示执行未结束，但必须由独立非终态 CodeModeYielded 回执驱动，不能作为原 effect 的 ToolCompleted 或 TaskPromoted 发送。

必须区分以下权威状态：

| 对象 | 提前返回时 | 脚本最终结束时 |
|---|---|---|
| 模型的 exec 调用 | 提交一次工具结果，包含 cell 引用和已提交输出游标 | 不追加第二个同 call ID 的工具结果 |
| 原 StartCodeCell effect | 保持可接收精确 owner 的子请求、输出、终态；继续受租约约束 | 消费一次终态回执并结束 effect |
| CodeCellState | Running；持久化已向模型返回的事实 | 转终态并归档；未知效果仍需核对 |
| 后续 wait 调用 | 独立 call ID；观察同一 cell，不获得执行权限 | 从 Core 账本读取终态与剩余输出 |

Host 需要独立、非终态的提前返回回执；Core 必须先验证原 effect/身份/代际，再记录该事实和唯一父工具结果。重送不得再次请求模型。Host 的最后回执不能再被当成同一个父工具的新完成结果。输出和子工具回执继续提交到原 cell，其所有权不随当前模型轮次变化。

调度必须拆分“本轮模型调用已经全部返回”和“本 Run 的执行全部结束”。前者允许模型发 wait 或继续其他工作，后者仍要求 cell 与未知 effect 已结算。子调用完成不得擅自启动第二个并发模型请求，也不得把 AwaitingModel 改写为 AwaitingTools。原父调用返回后，子调用准入依据有效 cell 身份与相位，而不是父工具必须 Running。

首次等待预算是观察预算，不是脚本 wall-time；超时只导致提前返回，不停止 worker。待授权子调用同样允许提前返回，但权限面板继续归属原会话。终态到达与提前返回竞态必须由 Core 的一次性状态转移仲裁：先终态则返回最终结果，先提前返回则只更新 cell 并由 wait 查询结果。

### 观察请求与内部调度

`code_mode_wait` 的一次模型调用只拥有一次模型可见结果。Host 为执行嵌套调用而交还调度权，不等于观察超时，不得发送该 wait 的 ToolCompleted。观察请求必须保留原 call/effect/lease、cell generation、输出游标和最初截止时间；恢复或子调用返回不得重新开始完整等待预算。

- 有新增显式输出、Cell终态、原观察截止时间到达：交付一次观察结果；超时不停止Cell。
- 子调用排队或返回、Promise继续执行：只交还/恢复内部调度，不唤醒模型，不消耗模型轮次。
- 等待用户授权：允许返回当前观察状态，把控制交还用户；不能将授权等待报告为执行失败。
- 取消：观察请求不获得超出原Cell所有权的控制权；仍等待原取消回执，不伪造回滚。
- Host丢失：保留已提交输出和不确定状态，不重放源码；观察重试不能接管新代际。

Runtime沿现有parked delivery机制保留观察租约；Core通过非终态CodeModeObservationSuspended区分内部让出与终态观察回执。Host保存独立观察登记（原effect、call、游标、deadline、序列），Poll/Resolve推进原观察；同effect重投不得延长deadline或重复登记。取消观察只结算该观察，不停止Cell或兄弟观察；显式terminate仍须通过Core原Cell取消控制。Host控制请求ACK之前提交已经取得的输出，但ACK先后顺序本身不能替代上述观察状态机。

当前验证范围：Host真实JS worker回归覆盖挂起、重复登记、超时、观察取消及一次性结算；真实LAN样本完成动态依赖和并行汇总。实际CLI权限入口覆盖生产文件写入、curl POST逐次授权；真实SessionStore/Application覆盖冷历史wait及Host断连后的待核对恢复，不重放源码。Runtime另覆盖固定时钟快速pump及慢兄弟effect期间的独立心跳。

终态仲裁必须在观察归约之后：观察归约可能结算最后一个Cell并触发模型预算终止，若先判终态再归约，Run会缺少结果决策而无法生成完成凭据。Cell已结束也不表示Poll/Resolve控制请求已确认；父执行终态早于控制ACK时，等待该ACK后才能关闭Run，不能把仍在途的内部控制误标为未知副作用。

最终纯文本综合阶段无可调用工具，Core 必须附带当前 Cell 的显式输出观察快照，避免仅提供状态而丢失结果。快照读取已提交观察，不重跑脚本、不伪造第二个 ToolResult；作为标明“不可信执行数据、非新请求”的 user 数据消息进入模型上下文，不能提升为系统指令。每个 Cell 使用普通分页规则，所有页的序列化数据总计最多 64 KiB；遗漏 Cell 数量及 has_more_output 必须保留，不能把截取结果当作完整证据。嵌套工具原始输出与脚本源码不得自动注入。

冷恢复不得重放 source。提前返回事实、输出游标、未结算调用及 effect 引用必须共同进入 checkpoint；canonical-only 恢复还需可查询 cell 的最终记录，不能把历史来源字段当成完整执行状态。新 Run 不得悄悄接管旧 cell 的运行权限。

### 独立于 checkpoint 的历史观察记录

Core 的 retired_code_cells 仅保留紧邻上一 Turn 的已结算观察，开始后续 Turn 时整体轮换（上一 Turn 无 cell 也清空该热缓存）；不随会话无限追加。更早 cell 由同会话历史查询读取。checkpoint 校验拒绝未结算或混合多个历史 Turn 的 retired 集合，不承担历史数据库职责。

历史观察与运行恢复是两个接口，不能把历史 cell 重新塞进 active_turn 来模拟恢复：

- 运行恢复以原 Run checkpoint 和 effect journal 为权威，能够继续接收原代际回执，但不能重建或重放 JS 堆。
- 历史观察以同一会话事务中提交的 cell 观察记录为权威，提供 phase、settled、分页输出、完成错误和完整输出引用；不提供执行权限、源码或嵌套调用参数。
- 记录的键必须包含 store/conversation/Run/cell/generation；仅 cell_id 不是跨会话查询凭证。记录绑定 canonical 父工具 Part，不能从模型提供的父 ID 推导归属。
- Application 每次提交 Core 转移时，在现有事务中同步受影响 cell 的观察记录及输出序列，与 checkpoint/Part/journal 一起成功或回滚。不另设后台同步任务，不把 UI 缓存作为数据源。
- 历史读取走专用仓储端口，按已验证会话和精确 cell 定位；不依赖模型上下文的 32 条消息窗口或 32 KiB 历史摘录预算，不一次装载所有旧 cell。
- canonical-only bootstrap 只恢复模型上下文。历史 wait 生成已提交的只读观察请求，由 Runtime 的 Application 分派端口交给当前 SessionStore，再通过同一 Application 连接查询；不交给物理 Host，不将旧 Run worker 注册到新 Run。请求仍经过执行开始和完成回执的正常准入，不绕过 outbox 所有权。未结算历史记录明确显示待核对，不能当作可继续运行。
- revert/fork 不自动转移原 cell 的控制所有权；原文引用可审计读取，取消和继续执行仍只能作用于原有效 Run。

## 完成门槛

必须同时取得：

1. 真正JS依赖调用与有限并行；工具结果用于后续参数，非预录脚本结果。
2. 无OS访问及CPU/内存/输出边界回归；未知工具、停用工具和递归编排有明确拒绝。
3. 嵌套读取/写入/网络调用经过同一Core权限；授权一次不扩大成整个脚本授权；跨owner拒绝。
4. wait分页、取消、重复回执、Host丢失及冷查询不重放测试。
5. 各客户端沿规范事件显示嵌套工具和原会话授权，不引入独立执行状态。
6. 192本地模型完成至少一个依赖链和一个并行汇总任务，独立检查真实文件/结果；对照普通工具模式记录模型往返、耗时、schema/输入输出量。收益按实测报告，不预设一定更快。
