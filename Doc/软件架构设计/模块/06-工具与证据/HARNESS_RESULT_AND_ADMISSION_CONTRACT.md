# Harness 结果与批次准入契约

## 可选完成评估与实际验收

显式requirements评估由模型按需选择，不是普通任务或修改任务的必经步骤。发生修改不自动要求调用评估工具；没有评估也可正常结束为`answered`。`action_completed`继续表示具有显式评估的结果，不把普通回复自动升级成已验证完成。已知失败、未完成执行、待授权、负面评估等状态仍不得被普通回复抹去。

验收分别检查正常回合终态和任务外部后置条件。`answered`与`action_completed`均不是成功证明；终端送达/退出/完整输出、Git提交选集/保护约束等必须独立核对。不得仅因未调用可选评估而判失败，也不得仅凭模型自评通过放弃检查真实结果。

### 声明范围与历史事实

排除来源为 `assistant_suggestion` 时，允许保存为讨论中的范围建议，但不能支持 assessed `action_completed`：该排除仍未解决。只有基于实际用户输入的范围解释才可参与完成声明；不得为绕过拒绝而将建议直接改标为用户要求。此检查验证来源类别，不证明模型解释的自然语言含义正确。工具说明负责在执行前明确选集语义；完成门禁不能补救已经执行的遗漏。

模型选择 `action_completed` 时，每个当前 requirement 必须具有非空 declared 资源范围，并满足其具体回执覆盖；`undeclared` 是未知，不是空集合或已覆盖。Core 提案和 Domain/Store 封存共同拒绝未知范围，错误同批次的评估原子回滚。`task_scope_update` 是非终结的可选范围入口；普通回答仍无需调用它或完成评估。资源声明是模型对用户意图的解释，不是用户授权，也不能证明自然语言需求无遗漏。

### 独立动作与验证回执的联合覆盖

声明含predicate时，允许先完成动作、再由独立只读验证工具观察同一结果；验证回执不得伪造write effect。除既有同回执action/postcondition证明外，联合覆盖须由本次assessment同时明确引用两条已成功完成的回执：动作effect的resource_uri/operation与claim精确相等，after_version与验证postcondition.version精确一致；验证的resource_uri/predicate与claim精确相等，claim显式version若存在也必须一致。两观察属于同一turn及Host，独立验证的Core revision必须严格晚于动作。不得从未引用、历史turn、其它资源、其它版本、先验证后执行或失败/未知回执补全证明。

动作之后已观察到该资源版本改变、删除或修改结果未知时，旧版本联合证明失效；后续重新写回并验证必须引用新的有序证据。普通read不使事实失效。此规则只证明声明资源上的动作与具体postcondition，不扩大用户授权、不证明整个自然语言需求完整，也不免除既有工程验证门禁。

失效扫描按原Host所有者隔离，另一Host上相同URI不是该资源。扫描不按turn过滤：虽然常规新scope会把旧观察移入独立historical集合，若当前证据frontier确有同Host后续turn的真实变更，仍须使旧证明失效。版本改动再恢复不复活旧证明；必须明确引用恢复动作及其后新检查，未引用恢复或只有旧检查均拒绝。

新回合和 maintenance 清除当前范围/评估时，旧类型化观察移入 `historical_observations`，保留原来源、turn、call 和版本并进入 checkpoint。只投影最近 8 条及省略数，不将历史记录加入本轮 eN、用户来源或权限。历史事实可用于理解追问，但不能直接作为本轮范围接受或完成证明；历史正文仍由原 transcript/证据存储拥有。

- Core 拥有调用身份、准入决策、队列与终态；Host 执行具体能力；结果存储不解释用户语言、不负责工作区授权、不构造 UI。

## 已实现的契约

1. `ToolOutputStore` 负责原子写入、根目录边界和 UTF-8 范围读取；不依赖权限或 UI。
2. 读取返回 `tool_output_slice` 对象，包含 `content/offset/bytes_returned/next_offset/size_bytes/has_more`。错误有稳定代码；越界和非字符边界偏移不得静默修正。
3. 读取同时受内容字节预算与 JSON 编码后的响应预算约束；模型必须使用返回的 `next_offset`，不能自行累加请求大小。结果页不得因为转义膨胀再次被保存成截断结果。
4. Host 保持结果页为结构化对象，不把它重新包装成 JSON 字符串。结果引用由专用读取工具解释，不要求授予缓存目录工作区权限。
5. Skill/SOP 激活与其他调用混合时，Host 整批拒绝，反馈所有被拒绝调用 ID 和“未执行”，在有限纠正预算内重规划；不得只挑第一个调用执行。
6. Core 重复调用与能力预算拒绝保留原始调用身份，经普通工具生命周期生成明确终态和结果，不创建 Host 执行请求。不能通过删除调用制造表面的成功或空批次。
7. `ToolContext` 显式持有结果存储依赖。内置工具、MCP 和代码分析结果统一写入 `<database>.outputs/<session digest>/`；读取、列表和搜索只能访问本会话目录，不能通过全局缓存或权限线程局部变量推断所有权。相同数据库和会话重启后引用保持有效；未完成的暂存文件不公开。

## 尚待整体验收，不能宣称完成

### 完整文件写入的创建与替换边界

`write_file`创建不存在的目标无需原版本；替换已有且内容不同的文件必须提交观察到的`expected_sha256`。缺失时返回`existing_file_version_required`并明确未执行；不将“允许新增”解释为允许覆盖。相同内容返回`changed=false`，不改mtime、不产生新变更。`dry_run`只预览，不授予写入权限。版本摘要是并发保护，不是用户授权，禁止据此扩大用户允许的修改范围。

Host在操作前观察目标，在路径锁内再次比较资源身份和版本；新文件采用不覆盖的原子发布，已存在目标采用明确替换路径。目录准备后的再次校验仍保留，不能通过先创建目录绕过版本变化检查。此契约不新增旧接口回退；模型及各客户端使用同一当前schema。

- 结果存储已绑定会话/数据库，生命周期清理仍需与会话删除及保留策略统一；当前不自动删除旧缓存，以免破坏用户已有证据。
- 需要检验真实大型审计中不同参数但相同证据的重复调查，不以语言关键词或命令字符串黑名单代替进展判断。
- 未暴露工具、错误参数、纠正耗尽、取消、重启恢复必须拥有可追溯且有界的状态转换。
- CLI 使用真实模型完成原始规模用例后，再由 Mac 验证同一类用例的 Markdown、工具过程和用户滚动意图。
