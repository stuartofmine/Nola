# Test Evidence Standard

## Purpose

A passing test is useful only when its name and release claim match the boundaries
it actually crosses. A test that calls a reducer with hand-built events is not an
end-to-end test. A UI fixture is not evidence that the production transport,
persistence, or host process works.

## Evidence levels

| Level | Required boundary | Valid claim |
| --- | --- | --- |
| Unit | One function or type, dependencies replaced | Local behavior |
| Contract | Serialized request/event/schema against the shared contract | Protocol compatibility |
| Integration | Two or more production components with a controlled external boundary | Component integration |
| Vertical E2E | Production transport, state reduction, persistence, and rendered UI | One product flow |
| System E2E | Shipped executable or app, real UI input, real local transport/process, durable state | User-visible release behavior |

A controlled upstream model is valid in an E2E test when the model service is not
the behavior under test. The controlled service must still speak the real HTTP/SSE
protocol and must not inject events directly into application state.

## Canonical Agent Trace fixture

All platform Trace contract tests use:

```text
core/tests/fixtures/long_task_trace_v1.json
```

A build may copy this fixture into a platform test bundle, but the copy must be
byte-identical or generated from the same source. A platform-specific fixture
with different event meaning is not cross-platform contract evidence.

The canonical fixture must exercise one stable assistant message through
waiting, thinking, multiple tools, incremental Markdown, usage, validation, and
terminal completion. Required assertions are:

| Concern | Test must prove |
| --- | --- |
| Stable identity | The pending bubble, active bubble, first delta, committed Markdown, and completed bubble retain their IDs |
| Tool detail | Expanded detail exposes redacted parameters, resource path/URL plus operation, and the real bounded/truncated result |
| Semantic no-op | Repeated semantic state advances the journal cursor but causes zero UI-state publication or DOM mutation |
| Gap and replay | Projection pauses at a sequence gap, resumes from the exclusive cursor, and does not duplicate content or animation |
| Isolation | Identical provider tool call IDs cannot merge across `trace_id`, `run_id`, or `conversation_id` |
| Persistence | Refresh/restart reconstructs process rows, resources, text, usage, validation, and terminal state in sequence order |

Tests must inspect intermediate projections and rendered identity. Comparing
only final text, a screenshot after completion, or a count of received events
does not satisfy this contract.

## Canonical Core Part lifecycle fixture

The stable Core Item/Part wire contract is generated by the real `AgentCore`
state machine and committed at:

```text
core/tests/fixtures/canonical_part_lifecycle_v1.json
```

`core/tests/canonical_part_lifecycle_fixture.rs` drives two Turns through the
public submission/effect boundary. The completed Turn covers the immediate
assistant shell, reasoning, permission suspension, tool running/completion,
source and citation projection, incremental text, canonical text replacement,
and one terminal completion. The cancelled Turn covers partial text,
cancellation acknowledgement, and a correlated late model response that must
not mutate the snapshot or emit another event.

The committed JSON is not an independently authored sample. The contract test
regenerates it in memory through `AgentCore`, compares the complete serialized
value, and verifies envelope cursor order, journal and projection revisions,
Part ownership, first-seen Part order, required lifecycle states, and exactly
one terminal event per Turn. After intentionally reviewing a Core wire-contract
change, regenerate it with:

```bash
cd core
NOLA_UPDATE_CANONICAL_PART_FIXTURE=1 cargo test --test canonical_part_lifecycle_fixture canonical_part_lifecycle_fixture_is_generated_by_core_without_drift
```

Client contract tests must consume this committed fixture directly. They must
not maintain a semantically similar platform-specific Part fixture. The Trace
fixture remains the presenter/activity contract; this fixture is the authority
for Core event envelopes and stable Part lifecycle.

The macOS pure production-decoder/reducer contract gate reads that same fixture
in place (it does not copy or regenerate events):

```bash
NolaMacTests/ProcessHarnesses/run_mac_canonical_part_lifecycle_harness.sh
```

CLI and Web consume the same committed file through their production reducers;
neither test owns a translated event copy. Run the cross-surface gates with:

```bash
cd cli && cargo test --quiet canonical_core_parts_drive_cli_human_and_json_projections
web/.venv/bin/python -m pytest -q web/tests/test_agent_trace_runtime.py -k shared_core_part_lifecycle
```

These gates compare stable Part identity, first-seen order, latest projection
revision, reasoning, tool, source, citation, authoritative text replacement,
terminal Turns, and the fixture's rejected late-response probe.

The iOS production decoder/reducer gate also reads the committed fixture directly:

```bash
xcodebuild test -project Nola.xcodeproj -scheme Nola \
  -destination 'platform=iOS Simulator,name=<available simulator name>' \
  -only-testing:NolaTests/AgentCoreCanonicalPartLifecycleTests
```

The Android production decoder/reducer gate reads the same fixture in place and must run on JDK 17:

```bash
cd android
JAVA_HOME=$(/usr/libexec/java_home -v 17) ./gradlew testDebugUnitTest \
  --tests '*AgentCoreCanonicalPartLifecycleTest*'
```

It verifies per-Turn projection reset, stable Part identity/order/revision, canonical
text and reasoning replacement, tool permission/state, sources/citations, and terminal
freeze after completion or cancellation. It does not maintain an Android fixture copy.

## Pending-effect exactly-once gate

Checkpoint recovery must resume the Core-owned pending effect. A client must never
turn a restored permission wait, tool execution, or model stream into new user input
or a new Turn. The acceptance gate must prove all of the following across a real
process/runtime reconstruction:

1. `session_id`, `turn_id`, `request_id`, and `effect_id` are unchanged after restore.
2. `resume_after_sequence` is the lower bound for the next Host response sequence.
3. Wrong owner, wrong request/effect, duplicate, and late responses are rejected.
4. Cancellation completes the Core interrupt/cancel/ack transition rather than only
   cancelling a client coroutine.
5. A terminal transition clears the pending-effect journal and durable checkpoint.
6. Rejected responses do not mutate canonical Part identity, text, or terminal state.

The CLI gate launches independent child processes and treats the saved checkpoint as
the only handoff:

```bash
cd cli && cargo test --test pending_effect_recovery
```

The iOS and Android tests use the production Core bridge/coordinator and persisted
journal. They are contract/integration evidence, not substitutes for device UI E2E:

```bash
xcodebuild test -project Nola.xcodeproj -scheme Nola \
  -destination 'platform=iOS Simulator,name=<available simulator name>' \
  -only-testing:NolaTests/AgentCoreDeviceExactlyOnceTests

cd android
JAVA_HOME=$(/usr/libexec/java_home -v 17) ./gradlew testDebugUnitTest \
  --tests '*DeviceHostExactlyOnceCoordinatorTest*'
```

## Typed prompt gate

Clients send a typed model envelope produced by the Core prompt composer. The system
policy, immutable Turn facts, references, and user query remain separate fields. Tests
must prove that an active Turn retains its prompt digest and fragment IDs when Host
configuration changes, while the next Turn observes the new revisions. Client tests
must inspect the production provider request; checking a standalone composer result is
only contract evidence. Private client prefixes, CLI prompts, keyword routing, and
concatenating the user query into the system prompt are regressions.

## Core TaskHandle gate

Only a Host response that explicitly promotes work may create a Core `TaskHandle`.
Ordinary short tool calls must remain message Parts and never enter the task center.
The shared task projection contract covers `queued`, `running`, `waiting`, and one
terminal state, stable owner session/Turn, progress/current step, `result_ref`, cancel
request, checkpoint restoration, stale revision rejection, and exactly-once terminal
convergence.

macOS consumes the production decoder/reducer with an independent process harness:

```bash
NolaMacTests/ProcessHarnesses/run_mac_core_task_projection_harness.sh
```

CLI and Web must additionally prove that the footer/task center and restored DOM are
driven by the same projection, and that cancellation submits the Core task command.
A manually constructed task card or a reducer-only final-state assertion is not E2E.

## Required streaming gates

A streaming test must fail when the final result is correct but the user experience
is wrong. It must observe at least these intermediate states:

1. The assistant message exists immediately after user submission, before the first
   model text arrives.
2. Thinking and tool events update the same assistant message identity.
3. A complete Markdown block renders before a later response segment is released.
4. The transport has not completed while the intermediate UI assertions run.
5. Completion preserves exactly one assistant message and keeps earlier messages.
6. Persisted history restores tool artifacts and authoritative context usage.

At least one transport test per client must split an SSE JSON frame across network
writes. Sending one complete frame per fixture callback does not exercise line
buffering.

## Platform evidence

### macOS

- `MacChatWorkspaceBehaviorTests`: message identity/order, incremental Markdown,
  context persistence, title synchronization, artifacts, and visible Host events.
- `MacAgentCapabilityEndToEndTests`: real Agent Host capability and permission path.
- `MacBuiltInSkillEndToEndTests`: real Agent Host routing for each built-in skill.
- `MacChromeMessagingEndToEndTests`: native Chrome broker round trip.
- `MacCodeReferenceVisualEndToEndTests`: real file and target-line presentation.

### iOS

- `EndToEndFlowTests`: real loopback TCP server, production `URLSession`, encrypted
  request envelope, paced SSE, split frames, and event order.
- `WebAgentProviderTests`: payload, crypto, event, artifact, and URL contracts.
- UI tests must state when they use a launch fixture; fixture UI tests do not replace
  the real transport integration test.

### Android

- `SseClientEndToEndTest`: real Ktor CIO request and loopback HTTP/SSE response.
- `ChatHostVerticalEndToEndTest`: real Ktor stream plus reducer, Room persistence,
  and Compose intermediate/final UI gates.
- `compileDebugAndroidTestKotlin` proves only that device tests compile.
  `connectedDebugAndroidTest` is required before claiming device E2E passed.

### CLI and Web

- `cli/tests/pty_interaction.rs`: shipped CLI binary inside a pseudo terminal,
  including cursor editing, interruption, footer stability, and permission input.
- `web/tests/test_agent_host_full_e2e.py`: shipped Web host, browser login, real DOM
  interaction, permission approval, tool execution, streaming gates, and persistence.
- DOM-only runtime tests remain integration tests even when they cover streaming.

## Failure handling

Do not weaken an assertion merely because a real-boundary test fails. First decide
whether the failure is in the product or in the test server/protocol fixture. Test
servers must emit valid HTTP framing, close responses gracefully, retain connection
state for the request lifetime, and expose explicit latches for intermediate-state
assertions.

## Tool, permission, and artifact acceptance gate

A successful final answer is not sufficient evidence for an agentic task. Real-flow
tests for tool-capable clients must also assert:

1. Requested interaction mode: when a user explicitly asks to use a visible browser,
   desktop app, or connected device, the recorded tool sequence must contain that
   capability. A search/fetch fallback that happens to find the same content is not
   equivalent.
2. Permission readability: the primary prompt must fit the viewport and describe a
   concise action and target such as opening a host, deleting a file, or running a
   script. Interpreter prefixes, bundle paths, digests, and full JSON belong only in
   expandable details.
3. Grant reuse: a conversation-scoped approval must be exercised by a later matching
   invocation in the same real run, while a different resource or materially different
   command still prompts.
4. Artifact propagation: a successful file-producing tool must emit a structured
   artifact/resource, survive transport and persistence, appear in the client file or
   change surface, expose its real location, and support the platform's reveal action.
5. Cleanup semantics: deleting a temporary output must remove it from the durable
   artifact projection without removing unrelated final deliverables.

These checks require an intermediate event/UI assertion. A unit test for a title
formatter, a direct reducer fixture, or an existence check on the final file covers
only one boundary and cannot be reported as vertical E2E evidence.

### Regression analysis rule

When a defect escaped despite green tests, record the missing boundary rather than
adding another final-state assertion. Typical misses are model/tool selection,
permission decision round trips, resource metadata loss, long localized labels, and
restored-history behavior. The new test must fail on the original event sequence.

## Release report

Every release report must list:

- Exact commands and passed/failed counts.
- Simulator/device model and OS when relevant.
- Tests that compiled but could not run because no device was attached.
- Controlled external boundaries such as deterministic model providers.
- Known warnings that will become errors under the next language mode.
