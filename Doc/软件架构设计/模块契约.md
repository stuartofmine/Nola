[Core 与 Host 接口](模块/01-领域与协议/CURRENT_RUNTIME_INTERFACES.md)给出当前实现的类型、HTTP入口和恢复约束。以下公共信封仍是跨模块职责说明，不表示所有HTTP载荷共享同一字段布局；具体命名与版本以各接口类型为准。Core事件版本、Store提交CAS、Goal控制generation和HTTP协议版本不得互换。

## 公共信封与错误

以下区分当前 wire 与跨模块语义要求；不能把目标字段当成现有载荷。客户端使用当前 Service/embedded 用例，不建立第二个兼容总线。
公开信封沿用 `protocol_version, request_id, client_id, expected_revision, command` 的命名。
`command_id` 是本文档旧稿对同一命令幂等身份的称呼，现统一写 request_id；不能因此新建双 ID/双别名。
Host delivery 中现有 request_id 属于不同协议命名域，绑定 effect/attempt/generation；不能与 Application request_id 混用。

### 作用域、前置条件与幂等

- scope 为明确 tagged identity：Application/Account、Store/Host、Conversation 或 Run；每类带其必需身份。
  模型目录和账户维护命令不伪造 conversation_id。远端资源须携带 authority/store scope。
- command 使用领域用例类型。修改带对应配置/计划等读取版本；新增带不存在条件；
  跨对象用例携带依赖版本并在一笔本地事务核验。查询使用读快照与 cursor，不套写版本。
- 幂等键由认证主体/客户端身份、authority scope、request_id 组成，并绑定命令及前置条件摘要。
  同键同内容返回原回执，同键异内容拒绝；client_id 是关联值，不能替代认证。
- effect 回执绑定原 Run/Turn/effect/delivery/attempt、worker generation 与 sequence；
  各身份按对应协议必需，不给无需执行的目录命令强加 Run 字段。
- 空字符串不充当缺省身份。纯 Core 消费显式时间等事实，重放使用原输入；租约和过期的判断由对应权威验证。

### 提交回执

| 结果 | 保证 | 后续 |
|---|---|---|
| Accepted | 请求身份及处理意图已持久接收，尚未保证领域用例完成 | 继续查询同 request_id |
| Committed | 该用例相关业务事实、回执和后继意图已提交 | 返回提交版本/引用，不等于 Goal 或外部工具已完成 |
| Rejected | 已确定未接受该命令的业务变更，附类型化原因 | 修正后可提交新意图 |
| Conflict | 前置版本/不存在条件不满足，未应用本次变更 | 保留编辑，读取原 owner 解决冲突 |
| TransportUnavailable/CommitUnknown | 客户端无法确认数据库是否提交 | 查询原回执，不伪装 Rejected、不直接生成新 request_id 重发 |

`CommandReceiptOutcome` 当前只有 `accepted/committed/rejected/conflict` 四类。表中的 TransportUnavailable/CommitUnknown 是客户端/提交确定性语义，不是第五、第六个持久 receipt tag。

只读查询可直接返回结果，不持久化一条空业务回执。传输 ACK 只表示传输接受，不能当作 Accepted 或 Committed。
COMMIT 结果不明与外部 effect 结果不明分别处理：前者核对命令回执，后者核对 effect/Attempt 和外部证据。

当前 `ProtocolFailure` 的实际字段是 `code, message, recoverable, details?`；部分内部端口仍返回 `String`。`origin_module/scope/execution_certainty/recovery_action/correlation_id` 是需要表达的错误语义，并非已存在的统一 wire 字段。提交不明也不能凭 recoverable=true 推断可安全重试。
用户信息使用本地化 key 与脱敏参数，原始 provider body/凭据只允许安全诊断策略处理。
`retryable=true` 不能单独触发重试，必须有剩余预算、动作、幂等/重放类别与取消检查。

| 错误类 | 例子 | 必需后继 |
|---|---|---|
| admission | schema/配置不合法、能力不支持 | 不执行，返回修正字段 |
| authorization | 明确 deny、OS 拒绝 | 拒绝或等待不同层授权，不静默扩大权限 |
| conflict | revision/owner/sequence 冲突 | 刷新事实/重放 ACK，不重做副作用 |
| transport | 中断、超时 | 查询 effect 回执；不能推断没执行 |
| provider | 限流、窗口溢出、输出截断 | 分别退避、上下文计划、原请求续写 |
| evidence | 范围未知、版本冲突、检查不通过 | LC-03/04，不能统称失败重试 |
| persistence | 提交失败、COMMIT 回执不明、内容摘要不匹配 | 无已提交见证不发成功；查询原回执，不能假定全部回滚 |
| invariant | 跨会话结果、封存后写入、非法状态 | 拒绝且保留诊断，不“修正”为成功 |
