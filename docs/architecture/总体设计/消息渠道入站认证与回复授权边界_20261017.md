# 消息渠道入站认证边界与范围澄清

## 入站凭据必须失败关闭

渠道 enabled、配置保存时校验成功均不能证明回调时密钥仍存在。每次 Telegram、WhatsApp、微信公众号和企业微信回调/验证请求，必须先取得当前非空白密钥，再比较 token、计算 HMAC/SHA1 或解密。缺失、空串及纯空白一律拒绝，不执行入站消息插入或连接状态更新。判断空白不改变实际参与验签的密钥字节。通用密码学原语不承担渠道配置存在性的推断。

负例覆盖密钥撤销后的有效连接：Telegram 无 header 不能与空密钥相等；WhatsApp 即使提供按空密钥计算的正确 HMAC 仍必须拒绝；其余验证 token、签名 token 和企业微信 AES key 同样不得使用空白值。原有效签名、验证 challenge、接收身份校验和消息去重断言保留。测试仅用自有本地 D1/合成消息，不发送私人消息。

## 真实本地 HTTP 验收的配置隔离

`--local` 不是配置隔离：Wrangler 会自动读取 config 旁的 `.dev.vars`，其全局参数处理也会读取工作目录 dotenv。当前 runner 必须在独占临时目录生成最小 Wrangler config（当前 Worker 和 migrations 的绝对源码路径、合成 D1 名称/ID，无生产 routes），所有 dev/D1 命令固定该 config、明确空 `--env-file`、`--local` 和独占 `--persist-to`。不复制或读取生产环境文件。

所有子进程使用白名单环境，保留系统 HOME 而不重新定义；XDG config/cache/data、临时文件和 Wrangler 日志指向 fixture。关闭 process-env 注入、dotenv secret 注入、遥测和错误报告。Wrangler 优先使用旧 `~/.wrangler` 而不是 XDG，故发现该路径存在即拒绝执行，不读取内容、不移动或删除它。HTTP client 只接受 literal loopback HTTP、禁代理且禁重定向；dev 显式仅监听 127.0.0.1。所有 provider 密钥均为 runner 合成值，仅访问入站回调/验证和 health，不调用任何实际发送接口。保留本次独占 D1 和 Worker 日志以检查失败，不能以清理证据冒充零写入。

该隔离源码及其负例尚未运行；必须由之后的真实本地 HTTP 验证证明，不能以 typecheck 或单元 mock 代替。

## 用户澄清后的实施范围

用户所说“消息外发”指通过 curl 或其他网络手段发送信息，不是要求新增专门消息渠道回复业务。本轮误扩出的 reply scope、专用工具、schema 和调用接线已撤回，不作为待办或当前协议保留。现有渠道调用流程未因该方案改变；只有独立、已确定的 Webhook 缺密钥失败关闭修复保留。

本次入站验签修复不能证明网络外发审批已完成，也不把渠道 enabled、配置存在或验签通过解释为外发授权。后续统一网络外发的实际资源审批沿既有 Core 权限链处理，不使用用户文本或命令关键词选路。
