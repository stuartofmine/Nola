# 会话独立配置与数据：统一契约

状态：草稿批次与模型身份批次已完成定向验证；完整契约仍有下文明确列出的未收口边界，不等同于全端真实交互验收完成。

## 决策

会话是独立的配置与数据单元。切换会话只选择、读取和订阅目标会话，不通过搬运共享可变字段、清空上一会话字段再逐项补齐来构造目标状态。

独立存储指逻辑所有权和事务隔离，不要求每个会话单独数据库。复用现有 Core 数据库及会话表；资源文件按会话归属管理。禁止另建一套消息、Run、缓存统计账本。

## 所有权层次

2026-10-20 目标补充：单人/多成员采用统一 Conversation，成员配置与 Context 独立归属；下方历史定向验证不代表该目标已经实现。对象边界以[总体所有权](../../总体设计/架构决策与所有权.md)为准。

| 层 | 所有者与内容 | 变更规则 |
| --- | --- | --- |
| 应用目录与默认值 | 本地账户/Host：模型目录、凭据引用、新会话默认配置 | 不作为当前会话状态；创建会话时显式初始化 |
| 会话聚合 | ConversationRef：成员关系、共享权限政策、公共消息、正式附件引用、任务与统计关联 | 通过带 owner 的命令写入；不隐式继承另一会话或新全局默认值 |
| 成员与上下文 | ConversationRef + participant：成员模型/参数/指令快照、独立 Context/摘要 lineage；协调 Context 单独标识 | Agent 仅为配置来源；不跨成员混读私有历史，摘要不覆盖原文 |
| 本地草稿 | device + store + editor owner：未提交文本、成员选择和暂存附件 | 独立 DraftRepository 条件写入；与远端业务提交通过回执衔接，不假定跨存储原子性 |
| 执行快照 | ConversationRef + participant/Context + run ID + 配置 revision | 准入时冻结；修改会话配置只影响下一次执行；后台输出始终写原 owner |
| 页面呈现 | conversation ID + window ID：滚动锚点、折叠、选择等 | 与执行状态分离，按会话隔离；不得成为模型配置真相源 |

跨 authority/store 的 conversation ID 不保证唯一，远端引用须带完整作用域，不能仅用字符串 ID 混合索引。
Host 是执行位置，不等于业务 authority；改变执行位置不自动迁移会话身份。凭据不写入草稿或普通 JSON 快照，只保存安全引用。

### 仓储分工：业务聚合与设备本地草稿

配置、消息、Run、上下文、Plan/Goal 和使用统计继续由现有 Core canonical store 持久化。未提交草稿由设备本地 `ConversationDraftRepository` 保存，键至少包含 Host/store scope 与会话身份；这仍然是独立会话存储，不是全局当前输入框。允许平台采用已有设置存储、文件或浏览器数据库作为实现，但统一 create/load/update/remove/promote 契约，不增加第二套业务账本。本轮不承诺草稿跨设备同步。

新草稿有独立 draft ID；创建 canonical 会话时通过 promote 迁移归属，不能同时保留两份可编辑真相。附件只恢复已持久化内容或有效的受控引用；临时 URL/授权不能假定在重启后仍有效。恢复失败须保留文本并明确提示，不静默丢弃或改投另一会话。
promote 是跨本地草稿仓储与 canonical 用例的可恢复协议，不是跨数据库事务：
保存稳定发送/创建意图，查询 Committed 回执后按旧草稿版本退休，崩溃重试不重复创建会话或发送消息。
远端 Application 不校验本机 draft revision；该条件由设备 DraftRepository 执行。

## 仓储与交互契约

- `create(defaultsSnapshot)`：生成独立身份并保存初始会话配置。未提交草稿也有独立身份，不能让所有 nil 会话共享对象。
- `load(key)`：读取该会话已保存的配置和数据投影。缺失、不完整、无法读取分别返回明确状态，不用当前页面配置补全。
- `observe(key)`：更新绑定 owner 的快照；选择变化只切换订阅，不能把旧回调写到新 owner。
- `updateConfiguration(key, expectedRevision, patch)`：沿用 canonical 配置命令及并发冲突处理；不得顺便修改全局默认值。
- `updateDraft(key, operation, change)`：所有成功、失败、取消和 finally 均写同一 owner；持久化文本与可恢复附件引用，不序列化活动 Task、密钥或无效访问权限。
- `submit(key)`：读取目标会话配置，冻结 Run 快照。界面选择不是请求身份。
- `delete(key)`：通过现有事务删除所属数据并使未完成页面操作失效；迟到结果不能复活会话。

切换期间允许显示目标会话的加载态或缓存快照，但绝不显示上一会话内容冒充目标数据。取消观察不等于取消执行。回到后台运行的会话，应从持久化状态/日志恢复，而非靠旧 View 存活。

## 持久化与性能边界

- 草稿写入在串行后台队列执行；输入状态先更新内存投影，磁盘完成后再更新保存状态。删除和提交清理必须与此前写入保序，不能被排队的旧写入复活。
- 读取失败不等于空草稿；附件部分损坏时恢复正文和仍有效的附件，同时保留可见告警。
- 多窗口写入使用读取时的 revision；冲突保留本地未保存内容，不以“重新读取最新 revision 后覆盖”冒充冲突解决。
- 切换不重建后台执行、不全量重放历史，不在 SwiftUI/Svelte/Compose 每次渲染时读库。执行事件按原会话增量更新。
- 执行轨迹在 Application 接受事务中持久化，呈现层只订阅。没有打开页面也必须能读取已提交的执行历史。
- 验收记录切换加载耗时、输入期间主线程磁盘写次数、草稿写入队列积压和跨会话污染次数；后两项不能靠吞掉持久化错误来改善。本轮尚无新的实测性能结论。

## 配置解析

### 模型身份收口批次（实施前契约）

会话的模型选择只由 `modelSelectionID` 表达；`selectedModelInfo` 是按该身份查目录得到的内存投影，不再序列化为第二份选择。模型参数与身份使用同一稳定 key；不得把 upstream/wire 模型名当 profile 主键。共享配置写入应在同一事务内验证身份、初始化必要参数并执行 revision CAS，普通 metadata 不能绕开这条契约。

读取会话与准入执行必须分开：模型缺失、停用或暂不可用不阻止浏览历史，也不能创建替代会话；页面保留会话身份并显示配置不足，提交时明确拒绝。目录解析不能使用上一会话、当前默认或旧展示快照作为回退。模型目录标准字段应足以构造展示投影，不能要求它必须来自某个平台的私有 JSON 编码。

WebHost 连接入口与具体模型是不同对象；未指定远端模型时保持连接绑定语义，不能制造 `configured:web-host`。完整 connectedHost 模型解析只在具备 Host scope 和具体模型引用时成立，尚未实现的路径必须明确不可用。已有用户数据库不清理、不自动改写；本批不增加旧接口兼容分支，缺失配置通过显式选择重新配置。

移动端现有 Host 入口保留：`executionHostBinding = {baseURL, tlsCertificateSHA256?}` 只保存连接定位与可选证书固定值，不含token；凭据按该连接从设备安全存储读取。`clientHostParameters` 使用canonical生成参数字段（包括tagged seed），不得直接序列化各语言的ModelParameters类型；共同显示选项放 `clientModelPresentation["execution-host"]`。该专用展示key不是模型identity，不能写入modelOverrides充当虚拟profile。选择Host绑定与清除本地 `modelSelectionID` 在一次配置CAS中完成；选择具体本地/configured模型时清除Host绑定，不能让两个字段分别暗中控制同次请求。

本批分 iOS、Android 和共享 Core 三个实现模块，全部修改完成后统一验证。至少覆盖：同 wire 名不同 profile、同 ID 不同来源、外部修改 canonical 选择后移动端重新加载、模型删除后仍可浏览但不能执行、配置 CAS 冲突与参数保留、普通元数据无法绕过验证。前一批草稿验证不作为本批通过证据。

全局默认仅用于显式初始化或明确配置的继承字段。会话覆盖先于场景策略；场景策略仅填空和施加能力约束。执行快照冻结最终配置。模型 profile 不存在或 revision 冲突时显式提示，不悄悄换成当前窗口/上个会话模型。

不复制模型凭据。模型目录可共享，但每个会话的选择、参数和权限策略必须独立保存。缓存命中率从该会话请求账本累计生成，未知不等于零，切换或重启不得重置或重复累加。

## 当前进度

### Mac 编辑版本与执行位置：本批实施契约

模型/参数编辑携带页面读取配置时的 canonical revision，提交不得临时改用最新 revision；即便模型身份先变更再变回，也必须识别过期编辑。加载配置与版本来自同一份 canonical 快照，成功回执只更新原会话。普通 metadata 回执不得把未读取的外部配置版本伪装成页面已读版本。现有 conversation revision 同时受内容变更影响，保守冲突必须显式提示重载，不静默重试覆盖。

`executionHostRawValue` 沿用 Mac 既有执行位置语义，但由配置命令拥有。模型选择需要调整执行位置时在同一配置 CAS 内提交；普通 metadata 不再写该字段。独立切换执行位置仍是显式配置编辑，不通过模型名称或用户文本推断。共享 Core 校验枚举、持久化和回执保持一致；不新增兼容接口或另一份业务账本。

整包 settings 与 native profile 更新在同一写事务检查模型身份、Mac 执行位置和 Host 绑定，拒绝改变这三项的旧快照；明确修改必须走配置命令。该保护不等于所有参数/metadata 已实现完整 CAS：整包参数更新与 Web 既有显式 profile 路径仍有单独边界，详见 [共享执行位置契约](../08-模型配置与调用/SHARED_EXECUTION_HOST_CONFIGURATION_20261015.md)。`executionHostRawValue` 表示 Mac 的执行位置偏好，不是跨设备通用 Host 身份，不能代替带 scope 的连接绑定。

### 移动端收口批次：实施前约束

本批继续修复未提交草稿配置恢复和同会话多窗口覆盖，不新增另一份会话业务账本。未创建会话的草稿可持有不含凭据的模型引用与参数快照；创建后，配置权威必须移交 canonical conversation，草稿只负责编辑中的文本与安全附件。恢复时按引用解析模型目录，引用不存在则提示重新选择，不读取另一会话或当前全局默认替代。

移动端文件仓储以“读取时的 revision → 条件写入”为契约；跨实例检查和写入必须位于同一锁范围。删除保留墓碑，旧窗口和迟到附件结果不能重建已删除草稿。异步保存失败或冲突保留本地编辑内容并提供可见错误，不能通过刷新 revision 自动覆盖他人内容。内存已接受不等于磁盘已提交。

模型身份与原子创建同时审查：展示用模型信息不得成为第二个可编辑的配置来源；创建/选择模型和初始化参数应由同一 canonical 事务提交。尚未迁移的调用点须明确记录，不以局部仓储测试宣称全端已统一。

实施分为 iOS、Android 两个独立模块，共享契约由主代理审查；全部代码完成后再集中编译与回归。具体输入输出、冲突行为和测试记录分别写入 `../../../历史任务/实施与审计/IOS_DRAFT_AGGREGATE_20261015.md` 与 `../../../历史任务/实施与审计/ANDROID_DRAFT_AGGREGATE_20261015.md`。

创建回执是模块边界的一部分：移动端 `createConversation` 只有收到 `created: true` 才能成功返回。Core 的 `created: false` 表示该 ID 已有聚合、输入配置没有写入，不得把旧聚合当作刚创建的新会话。适配层显式拒绝，已有配置保持不变。这与可重放的提交/Run回执是不同契约，不能为了统一“重试”而吞掉冲突。
