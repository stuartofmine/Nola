# 增量工作上下文与缓存安全压缩

日期：2026-10-10。状态：实施中；不是已完成验收报告。

## 目标与不变量

正常请求由稳定系统提示和工具定义、按时间排列的摘要块、未压缩原文、
新增消息组成。动态维护不等于每轮重排。原始消息和工具结果追加保存，
压缩只替换模型工作集，不改写原文。摘要不是授权来源，不替代 Goal、
任务、subagent、权限等持久化状态。

常规压缩只总结未压缩范围，新增摘要块不重复生成旧摘要。摘要保留来源
item ID、来源指纹、原始 token 数；现有 AgentItem::Compaction 已有这些字段，
优先复用，避免再引入一套并行存储。摘要与保留原文必须纳入统一预算。

## 参考与取舍

- Claude Code 的缓存安全分叉：保留实际请求前缀，末尾追加总结指令。
  参考：https://code.claude.com/docs/en/prompt-caching ，以及仓库参考版本
  `参考资料/claude-code/src/services/compact/compact.ts`。
- OpenCode 的持久化原文、完成后才生效的 checkpoint、安全执行边界：
  https://dev.opencode.ai/v2/docs/compaction/ 。其更新旧摘要、禁用工具的
  独立摘要路径不作为我们的正常缓存复用路径。

增量摘要块和原文检索是 Nola 的设计选择，不声称参考项目原样实现了它们。

## 压缩事务

1. Core 冻结工作集版本、待总结原始消息 ID 与指纹。保留旧摘要和近期
   完整工具事务，不将未结束调用拆开。新输入排队，不改变冻结范围。
2. Host 基于实际物理请求快照构造分叉，追加完整新增响应和消息，再追加
   总结指令。总结范围通过边界映射指定；不修改已发送消息来添加标记。
3. 发送完整当前工作上下文，但只总结指定未压缩范围。模型、工具定义、
   system、thinking、tool_choice 等影响缓存的设置保持一致。维护请求返回的工具调用
   不执行；空输出、截断、无效输出不进入工作集。
4. 校验来源版本、范围、输出完整性、工作集预算及实质压缩收益。原子提交
   新摘要、来源关系和新边界。失败或取消保持旧工作集；用量照实记账。
   来源核对以冻结范围及 context 边界为准，兼容的新尾部保留并重算预算；不能仅凭总 conversation revision 拒绝。
   工具调用与结果按完整事务保留/压缩，不拆散尚未完成的调用。
5. 进程重启恢复待处理事务，重复响应不能重复推进边界。所有客户端只观察
   同一 Core 状态，不各自维护摘要。

## 缓存与快照

物理请求快照应可持久恢复，包括协议、模型、工具/system 哈希、消息序列、
配置版本、请求时间和缓存证据。不保存密钥，通过安全凭据引用解析。
缓存资格区分支持、不支持和未知，不能把缺少 usage 当作不支持。
客户端保存请求不等于保存服务端 KV cache；压缩后的替换位置之后仍可能
重建缓存。普通轮次只追加，工具输出不原地反复清理。

## 原文索引与工具

### 工具结果首次投影与稳定历史

工具过程不是每轮重新摘要。Host 首次返回时把普通长结果保存在会话原文
存储中，默认预览预算从 8,000 降为 4,000 字符，Web 结果从 16,000 降为
8,000；按需读取每页最多 2,500 字节，并同时限制序列化响应大小。
退出状态、失败和未完成标志、原文引用不能被纯文本截断掩盖。
预算包含 JSON 转义与元数据；极小预算仍优先保留必要的状态和引用。
Skill 激活是控制协议，沿用原有独立校验，不能按普通日志截断。

Core 不再在每轮结束时删除工具调用、结果、推理或中间消息，Host 不再在
新用户消息到来时把历史工具交换改成 assistant 文本。已入上下文的有界
投影保持稳定，直到完整事务被压缩替换。原文通过现有会话级
`tool_output_search` / `tool_output_read` 查询；截断不要求自动翻完所有页。
这里的稳定性仅覆盖工具历史，不代表 system/tools 或所有协议请求已逐字节
通过真实模型缓存验收。

原文是唯一事实源；索引可重建且有索引进度水位。
`history_search` 使用 BM25、中文分词或 n-gram、路径/错误码精确匹配，
返回预算内片段及稳定来源 ID。`history_read` 按 ID 读取原文、邻近上下文和
完整工具事务。默认仅当前会话，跨会话单独校验权限；由模型自主选择工具，
禁止关键词路由。索引滞后不能被解释成没有历史，需提供有界读取回退。

## 摘要层预算与恢复

摘要块不能无限增长。达到单独预算后，显式合并最旧的一组摘要，保留旧块及
来源映射，记录新的上下文版本和缓存重建成本。它是低频维护，不是每次压缩
重写全部摘要。容量不足必须明确报告，不能悄悄丢掉约束。超长原子项和冷请求
需要独立、有界恢复路径，不再把串行全量重写当成正常路径。

## 实施顺序与验收

1. Core 保留旧摘要块，常规规划只选择原文，新块放在旧块之后；复用 checkpoint
   中已有的持久化摘要与来源信息。测试连续两次压缩和重启。
2. 物理快照持久化、完整工作集分叉与增量范围协议；消除进程本地快照依赖。
3. 原文搜索/读取、中文召回、索引恢复和权限隔离。
4. 摘要层低频合并、预算调度和五端状态展示。

必须覆盖请求前缀比较、工具事务完整性、重复提交、取消、重启、范围冲突、
多轮约束保留、跨会话隔离。真实模型验收记录耗时、输出量、缓存读写量、
压缩后首轮延迟和原文召回。缓存率按累计 token 加权；未知不显示成零。
不能用结构测试代替摘要质量和真实延迟验收。

### 后续修复：请求与已完成响应分离

快照 v2 单独保存被接受的最终响应；Host 先采用完整流式文本，再保存响应。
恢复后仅在原请求末尾追加该响应及维护指令，原请求正文不变。未完成工具
事务、空回答和截断回答不能作为完整响应追加。Responses 原生输出项沿用
普通请求的续接投影，避免把加密推理项或工具协议改写成普通文本。

范围仍做精确匹配：对整个有序选择比较最早和最晚匹配位置，而非要求每条
短回答在历史中只出现一次。这样重复 ACK 可以由周围消息定位，真正歧义
仍拒绝。分叉的物理响应上限与摘要正文目标分开，并检查追加响应、维护指令
和输出预留是否能一起放入窗口；摘要验收仍使用 Core 的正文预算。

### 小窗口冷恢复：分离生成与滚动摘要预算

### 2026-10-11：冷恢复协议控制与实测分段校准

确认上轮慢请求使用 OpenRouter，而 `thinking_enabled=false` 没有映射为
该网关的关闭字段。现按明确 provider 身份或官方 endpoint 识别 OpenRouter，
冷恢复发送 `reasoning.enabled=false`；正常 automatic 请求保持默认，热缓存
分叉继续复制原始请求。网关识别优先于模型名称中的厂商特征，避免给经
OpenRouter 路由的 DeepSeek 模型发送原厂专用字段。
协议依据：[OpenRouter reasoning 文档](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)。

冷恢复先按保守字节预算发送；成功后用本次摘要请求的实际输入 token
校准后续分段，预留 50% token 余量、最大合并到初始字节额度的两倍。
只合并原样连续片段，不截断用户原文；发生恢复拆分后停止自动合并，
避免拆分/合并循环。这仍是估算，不是服务商 tokenizer 的精确计数。

### 输出额度规则修正（替代上述固定上限设计）

按用户要求，压缩不设独立输出上限。热缓存分叉与冷恢复都使用当前模型
已配置的输出额度，不再收窄为 4096，也不再经过内部 8000 上限。
删除 4KB 摘要拒绝条件和提示词中的 1024-token 强制目标。
压缩标记只冻结模型配置额度，不再产生独立额度。保留模型参数合法性、
请求上下文窗口和完成后摘要能否放回工作上下文的检查；不暗中调低配置
来适配小窗口。输出仍可能触及模型配置或服务商限制。

### 截断续写事务（2026-10-11）

Host 将 `length` / `max_tokens` / `max_output_tokens` 与输入窗口错误分开处理。
有文本、无工具调用的输出截断不再拆分原文，而是基于刚完成的物理请求，
追加该次 assistant 输出和“只续写剩余摘要”的 user 指令。系统、工具、模型、
