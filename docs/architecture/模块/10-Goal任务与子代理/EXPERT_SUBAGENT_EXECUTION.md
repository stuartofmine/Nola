# 主 Agent 与专家的统一执行契约

状态：2026-11-13。按单一主 Agent 调度架构实现与验收，旧专家互调测试不作为本契约完成的依据。

主 Agent 是唯一的对话入口，负责理解用户需求、分配工作、处理澄清并汇总最终回复。专家是它可调用的持久子代理，使用自己的模型、推理档位、角色提示词、精简工具包与 Skill。专家向主 Agent 返回结果或说明缺少的信息，不继续调用其他专家，也不派生普通 subagent。

临时 subagent 与专家复用同一套 Task 准入、执行、等待、取消、恢复和结果回传。区别是目标配置与上下文的选择：临时 subagent 使用任务选定的冻结 profile 和独立子上下文；专家使用当前主会话已加入成员的冻结 revision 及持久专家子会话。不能另外建立专家执行引擎或结果账本。

## 调度与权限

只有真实主会话中的主 Agent Run 能使用 `delegate_expert`。模型只填写业务参数：查询可用成员、向精确目标提交任务、读取或等待规范结果，以及请求取消。来源会话、Run、effect、凭据和权限由 Host/Core 提供，模型不能指定。接收 Task 不等于任务完成；等待超时不等于取消或停止。

Host 保留原始工具请求。Core 验证实际已开始的 effect、主会话与 Room 的双向归属、冻结的目标及配置，准备同一类 Agent Task。提交 `TaskPromoted` 并取得持久化 ACK 后才唤醒已有 worker，随后沿用 claim、lease、执行泵、恢复和 canonical terminal receipt。不确定 ACK 保留原请求，不能把可能已经存在的任务误报成永久失败。

Core 拒绝专家上下文发起新专家调度或普通子代理派生；专家的能力目录和模型 schema 也不提供 `request_user_input`。专家缺少信息时通过 Task 返回说明，由 Main 负责用户澄清。隐藏客户端按钮或提示模型不要调用不能替代这一边界。普通临时 subagent 的既有权限规则保持独立。专家执行具体工具时仍使用自己的权限配置，不继承主 Agent 的密钥、临时授权、完整历史或可写状态。

来源使用明确的 `main_agent` 类型并绑定真实主会话，不能伪造一个专家成员充当主 Agent。旧专家来源 metadata 和历史仍可读取，可恢复任务继续依据原始冻结事实核验。含 Main 专属控制或直接提问入口的旧捕获明确拒绝执行，保留原始历史与停止通道，不改写冻结配置以绕过检查。这些记录不授予新专家互调的权限。

冷恢复、回答已有问题和在途模型结果都按真实 Task/Run 绑定检查。Host 回复及 active submission 的候选变更若产生开放的问题等待，在持久化前再次检查专家约束，覆盖权限回调等入口；失败不提交候选状态。已验证的取消态仍可接受迟到结果完成原有停止协议，不能把安全限制变成无法停止旧任务。

移动端取消复用同一条提交与停止链路：只中止目标 effect 的 mailbox 传输等待，让执行泵领取 Core 已提交的精确 Cancel，不关闭整个泵。原生适配器停止并等待该目标的实际执行结束，取得停止证据后才确认取消。传输错误、流结束或客户端协程退出都不是成功 ACK，也不能单独作为 Task 已取消的证据；单个操作失败不能阻断后续 Cancel 的处理。

模型服务的工具调用 ID 保持原值，用于协议内的调用与结果关联；它不能直接充当全局消息组件 ID。移动端提交流式工具增量时，用 Core 已确认的实际模型 attempt 标识限定组件 ID，保证同一调用的增量稳定、不同 Run 或重试不会覆盖旧组件。Store 的 Run/Message 归属检查保持严格，旧历史无需改写。

工具来源绑定也必须限定在当前 Part 的精确 Turn/Message：相同调用 ID 的历史项不作为新调用的来源。当前范围仍检查能力与执行来源一致；缺少归属、当前范围存在重复项，或已完成工具缺少原始调用与结果对时明确拒绝，不能从历史记录补成当前执行的证据。

新工具调用不能继承已关闭组件的消息归属；没有流式工具增量时，也应依据当前已接受的原始调用建立独立组件。在途工具的结果仍归原调用所有，即使用户补充输入已开启新的助手消息段，也不能把迟到结果归到新消息。

## 用户选择与持久历史

`@` 选择专家是当前用户输入的类型化选择，由 Core 核对 ID、观察 revision 和归属，并作为可信上下文交给主 Agent。它不创建第二条用户消息，不改写用户原文，也不绕过主 Agent 直接执行专家 Room 回复。

每次专家执行产生独立 Task/Run，后续任务可继续同一专家上下文。当前主会话的上下文参与者区域按需读取专家规范历史，主会话列表不展示专家子树，也不维护第二份消息库。专家子会话是只读阅读入口；用户返回主会话后继续与主 Agent 交流。

重新引入新配置时建立新专家上下文，旧上下文继续挂在原主会话下供只读查看。历史的角色、revision 和发送者来自当时冻结的来源，不能由当前目录覆盖。

## 远端与兼容边界

远端客户端沿用主 Agent 的规范 Run、source receipt 和 AssistantJournal 同步路径；宿主机身份、Store epoch、会话和实际 Run 必须一致。历史专家 Room 消息及其规范主会话镜像继续只读兼容，不作为新发送路径。错误来源或断裂前驱不得产生部分写入。

新增字段使用兼容的可选扩展或有明确判别字段的类型；不改变已发布 `AgentTaskAdmission` 的版本，不删除旧消息、重建数据库或静默转换用户数据。普通 Application JSON 不能调用私有 Host 准备和来源导出命令。

## 验收要求

真实主 Agent 请求必须经过原始 effect、实际 TaskPromoted ACK、相同 worker、专家独立配置和规范结果回传。覆盖持久子会话续接、取消的真实停止证据、进程恢复、不确定 ACK、失败准备回滚及错误来源拒绝。另验证专家调用其他专家或 spawn 的请求被 Core 拒绝，不能靠模型“答应不调用”作为证明。

真实模型验收、原生适配器测试和界面验收分别记录。旧 A→B 或 A→B→C 专家递归协作结果不能用来宣称单主 Agent 架构通过。

`scripts/test_real_expert_roles.py` 通过隔离 Store 和现有模型连接验证四轮主会话：首次派发、专家历史续接、专家返回缺失信息、主 Agent 收到用户澄清后再派发。断言实际 Task/Run、持久来源、专家独立推理档位和无递归工具，并检查主会话只有原始四条用户输入。该真实模型回归已通过；它不替代各客户端的原生链路及界面测试。
