# Nola Mobile · IM v24

2026-11-09 同步。**移动端交互原型；本轮对照真实客户端修复更新，不作为客户端实现本身。**

打开 `docs/design/nola-ui-prototype/index.html`，视口不超过 700px 自动进入本提案；宽屏继续显示既有桌面工作区。原型为本地虚构数据，不调用模型、不读取登录状态或文件、不保存密钥、不执行真实任务。对照当前本地客户端的[逐页验收记录](../../../../Doc/当前任务/CROSS_PLATFORM_PAGE_MATRIX_20261109.md)，不再用旧发布提交代表当前实现。

## 1. 重新审视

此前移动界面把桌面功能压进手机：今日看板占据默认入口，列表是没有识别锚点的文档目录，聊天顶栏同时摆放多组工具，模型和执行细节又占用输入区域。动作虽然能点到，整体仍不像可以自然持续交谈的 IM。

本次主张：**先找回一段会话，再继续一句话；只在需要时看工作状态。**

借鉴 Telegram 的紧凑列表、稳定身份、会话内操作和列表到聊天的连续性，不复制品牌蓝、壁纸、联系人/通话/故事等无关功能。Nola 的独特之处是明确的 AI 执行状态、会话资料范围以及水面渐显的新文字。没有人际消息的送达/已读勾，避免把网络完成、显示完成、外部操作完成混为一谈。

## 2. 导航与页面

```text
对话（默认） → 聊天 → 会话详情 → 模型 / 参与者 / 上下文 / 任务 / 资料
活动         → 待授权 / 待补充 / 已完成 → 详情 → 来源会话
资料         → 会话知识 / 长期记忆 / 文件与数据源 → 来源
设置         → 模型与账户 / Agent与执行器 / Skills与MCP / 外观 / 通知 / 软件更新 / 权限 / 资料 / 记忆 / 计划
```

- 四个主入口均直接可见，没有“更多”集合页。主导航是目的地，不承担新建或停止动作。
- 聊天作为全屏会话层隐藏底栏，把空间留给消息与键盘；明确返回按钮和系统返回保持可达。这是为 IM 沉浸式聊天作出的取舍，不能把所有子页都无规则隐藏导航。
- 普通闲聊不自动变成 Goal。活动不是全部聊天记录，也不冒充跨设备完整历史；只反映 Core 当前可见的记录。
- 资料页不把 Wiki、原始对话、摘要、长期记忆合成同一份内容；来源和读取权限继续分别保留。

| 页面 | 本次结构与关键交互 | 原型可操作范围 |
| --- | --- | --- |
| 会话列表 | 无头像文字列表、单行标题、两行预览、时间、草稿、必要状态；全部/待回应；新建直接可见 | 搜索、筛选、新建、进入/返回、独立草稿 |
| 对话 | 紧凑身份顶栏、搜索、消息流、内联审批、模型入口、附件、单行起步多行输入 | 发送合成回复、复制、引用、编辑到草稿、允许/拒绝演示、回放/停止 |
| 会话详情 | 完整标题、参与者、模型、执行位置、任务、资料、上下文 | 路由与说明；不会创建假权限或后台任务 |
| 活动/详情 | 待授权、待补充、已完成分别呈现；回来源会话处理 | 列表、结果摘要、精确语义的来源入口；不另造审批引擎 |
| 资料 | 知识、记忆、文件入口和最近资料 | 展示来源与访问边界；具体内容为示例说明 |
| 设置 | 账户、能力、偏好分组；没有大图标门户卡片 | 页面导航、外观、减少动态效果、大字、iOS/Android预览 |
| 模型/详情/添加 | 先选 API、ChatGPT、本地或文件来源；默认模型和连接状态分开 | 默认选择与表单布局；不登录、不发请求、不伪造验证成功 |
| 计划 | 计划时间、开启/暂停状态 | 只展示已有演示计划，不触发自动化 |

### 列表

默认不设置左侧大字、头像或图标列。标题从左侧 20px 起，时间在同一行靠右；预览紧随标题，相距 5px。行高至少 86px，两行预览自然增高。待回应是文字状态，不只依赖圆点；普通对话不铺满状态徽章。草稿优先于上次回复预览，归属会话 ID。大字时允许标题换行、行高增长。

列表位置、筛选、搜索与每段草稿应保持。原型已保存独立草稿和聊天阅读位置；列表长按/归档的完整交互不在本次可操作范围，不能把说明弹层当作已经实现的行管理。

### 本次列表方向比较与选择

- **A · 文字优先（采用）**：去掉整列识别标记，以标题识别会话；右侧时间弱化，预览最多两行。草稿用温和棕色文字，待确认用苔绿色，部分未完成用错误文字，不另起状态行、不堆徽章。
- **B · 轻量 SVG 标记（未采用）**：每行放 15px 的共享状态图标，无大头像。实际比较后，普通行的气泡图标重复、状态行又与文字重复，占用了窄屏的标题空间。可通过 `?list=marker` 查看对照，但不是默认方案。

自评：A 更安静，也更符合 Nola 以事情标题认出会话的特点。它牺牲了人际 IM 的头像扫描方式，换来更长标题与预览；需要回应时仍有明确文字和筛选。390px 浅深色、320px 窄屏与独立草稿已实际查看；没有把浏览器原型当作客户端验收。

### 聊天

顶栏左侧返回、中央可点击的会话身份，右侧搜索。模型、参与者、Host、上下文等通过会话详情直接呈现，不在窄顶栏并排堆六个按钮。普通消息默认 17px / 1.6 行高，左右气泡自然收缩；长内容仍按阅读宽度约束。

保留既有专家姓名和头像在气泡外、八色历史一致、操作位于气泡外的要求。专家背景直接消费已有 `expert-separators.css` 色值；颜色不能代替姓名。用户消息靠右，低饱和背景，不使用蓝色选中框。复制/引用可直接点，长按提供同组上下文操作；原生文本选择不能被长按抢走。

输入栏保持原生文本输入、中文 IME、选择与撤销。起步 44px，多行最高约 128px，附件/发送触区 44px。IME 组合阶段不得触发发送。系统键盘、安全区和滚动锚点的真实配合必须在客户端实现阶段验收，浏览器视口不能证明它们已经通过。

代码和表格只在自身容器横向滚动，不让整段消息或输入区横移。原型设置中的“长内容排版”可查看对应例子。

### 模型连接

把“添加来源 → 填写/预览 → 确认 → 验证 → 使用”分清。API 配置导入不能假装 ChatGPT 订阅登录；官方账户登录必须由本人授权，导入成功和模型请求成功是不同事实。状态和错误留在对应详情，已有内容不丢失。原型没有真实密钥输入或测试成功按钮。

## 3. 动效与滚动契约

| 情境 | 目标规则 | 原型 / 原生边界 |
| --- | --- | --- |
| 列表 → 聊天 | 300ms 横向推进，旧页面轻移 22%；返回反向还原，不给整页再做淡入 | 保留可见旧页面的 Web Animation 预览；最终原生使用系统导航转场 |
| 交互返回 | 边缘拖动跟手，露出原列表；取消回弹，完成恢复列表 | 浏览器可拖动预览；iOS 系统侧滑、Android predictive back 仍待原生实现 |
| 发送 | 新气泡约 240ms 的 9px 轻位移与微缩放渐显，输入立即清空并保留失败恢复能力 | 本地样例，不发送网络请求 |
| 流式新增文字 | 只对新增片段做约 520ms 的低模糊/透明度浮现；旧片段不重新动画 | 本地合成输入流；不是模型速度或真实网络延迟测量 |
| 解析边界 | 段落、代码、表格的稳定 part 身份与测量；提交块/尾部交换不能全量淡入 | 本原型只演示新增文本及静态富文本排版，完整解析转换待客户端验证 |
| 接收完成 | 显示尽快追平，不用延迟伪造思考时间；传输/显示/业务终态分离 | 合成包到达后立即插入全部新增文字；接收结束时剩余渐显加速至最多 160ms，不能当真实模型指标 |
| 用户上翻 | 暂停跟随，新增内容提示；点最新内容才恢复，输入区不随消息横移 | 原型可滚动与点恢复；原生需使用稳定锚点 |
| 减少动态效果 | 遵循系统 Reduce Motion 和用户偏好；立即显示收到的文字，无模糊/位移动画 | 原型使用媒体查询和预览开关，状态仍用文字说明 |

网络接收、Core 权威消息缓冲与渲染游标必须分离。UI 结束动画不得写 Run 完成；停止、授权、恢复仍调用原有 Core 精确指令，等待物理停止确认。切换页面不停止任务。原型的回放状态只是演示状态，不是另一套产品任务状态机。

实际色值计算：正文对卡片背景 14.97:1 / 13.71:1；次级文字对页面 5.15:1 / 8.54:1；主按钮文字对底色 7.92:1 / 9.52:1。专家八色仍用已有共享调色板；最终高对比度模式须在原生系统中检查。

系统字体为主。导航标题 17px，消息正文 17px，列表标题 17px，预览 14px，说明 12px，时间 12px。大字预览用 21px 根字号观察重排；这只覆盖浏览器样例，不能冒称验证了 iOS 全档 Dynamic Type。主动作 44px 以上；选中主要靠轻微背景、字重和可读标签，键盘焦点仍可见。

## 5. 平台与共享边界

- iOS：标准 push/交互返回、原生键盘，列表右上新建；VoiceOver 读取标题、草稿和待回应状态，不逐 token 播报。
- Android：同一信息与状态契约；列表新建可用右下可达按钮，尊重系统 predictive back 和 IME Insets，不拷贝 iOS 手势识别器。
- 平板/桌面：本次不重新设计。现有桌面工作区、单顶栏、内容标签和常驻对话保持；浏览器宽度超过 700px 切回既有桌面原型。
- Rust Core 继续拥有消息/任务/权限/模型冻结状态。两端只实现原生导航、测量、键盘和动画适配；水面渐显沿用共享增量游标规则，不另建平台业务链。

## 8. 动效细化 · 2026-11-04

- 区分 push/pop 和主导航切换；旧页面是短暂的只读快照，原列表和聊天保持视觉连续。修正旧导航进入聊天重复 render 导致入场被销毁的问题。
- 侧滑期间页面直接跟随手指，列表反向轻移；短距离松手回弹，超过屏宽 32% 或快速超过 55px 完成。松手后接续当前位置，不重新播放入场；回弹中可重新抓取当前位置。此为浏览器 pointer 原型，不等同 iOS 系统交互返回。
- 输入框按内容自然增高，原本在底部时维持底部；历史阅读位置不因输入框增高被拉回。手机回车换行，点击发送才发送。
- 流式接收和渐显独立：每个合成包立即进入页面，按三个字符的小片段做 520ms 由模糊到清晰的浮现，旧片段去掉动画类后保持稳定；无逐字等待队列。结束时只加速仍在浮现的片段，最多再收尾 160ms。
- 上翻即暂停自动跟随，内容仍接收；新内容提示轻浮现，点它恢复。减少动态效果时不做转场、模糊或消息位移，数据到达即显示；交互拖动仍忠实跟随用户输入。

已以虚构消息采集深色发送/流式/上翻/回底、短侧滑取消和快速返回、浅色减少动态效果的原始连续帧，并逐张核对代表帧。可播放视频由实际时间戳合成，未用补帧伪造 60fps；采样存在间隔，不能据此宣称原生动画性能或完整中断手势已验收。没有调用模型，没有修改客户端。

## 9. 移动端实施状态 · 2026-11-04

本提案已开始落地到 iOS/Android 未发布工作树：会话优先的四个目的地、文字列表与草稿、聊天轻顶栏/当前已加载消息搜索、模型条与多行输入、普通回复气泡、活动/计划入口、三类资料入口、分组设置和浅深色角色。既有 Core/API/权限与执行生命周期保持权威；没有把原型的合成任务状态接进产品。

iOS/macOS 继续共用 `Shared/Presentation/AppleStreamingMarkdown.swift` 的新增文字身份与浮现规则；浮现约 520ms，完成时连续加速并在 160ms 内收尾，不重播旧文字。Android 在原 Markwon TextView 内对新增渲染文字加临时 ink spans，保持接受文本、布局及复制立即可用，完成和减少动态效果立即收敛，不采用整块重复淡入。三端共用 SVG 源并生成原生资源。

实际边界：iOS 正常主界面使用隔离数据库，已实看浅色空列表并修复系统黑底断层；Android 当前构建的非空列表在系统无响应弹窗后可见，未算完整视觉通过。原生桌面工具返回自动解锁失败，未推断真实锁屏、未绕过。完整聊天/键盘/侧滑/流式录屏、活动详情、资料与设置详情尚未逐页操作验收；Android 目前是普通进入/返回转场，跟手 predictive back 尚未落实；跨页面返回聊天时的阅读位置恢复也尚未接齐，不能把流式期间保持位置当作此项通过。模型连接详情等既有功能页保留，未把没有重做的页面说成新版已完成。

两端最终增量构建、共享 Apple ink 定向检查以及 scanner/iOS/Android/Web 本地化门禁已通过。Web 门禁只临时复用 lock 完全相同的现有 QA 依赖缓存，随后移除链接；没有安装新依赖。没有真实模型调用、提交或推送。


## 10. 原生实施补充 · 2026-11-04

- iOS 设置分为连接/能力、外观通知权限、记忆计划三组；Agent 管理与 Skills/MCP 入口分开，前者使用现有管理页面，不再把 Skills/MCP 页面标成 Agent。
- iOS 资料改为紧凑标题、无装饰图标框的分组入口；两端活动把当前已加载且需要回应的记录优先展示，仍显示 Core 原始状态，不把其余记录都标作已完成。Apple 活动加载失败可以原位重试。
