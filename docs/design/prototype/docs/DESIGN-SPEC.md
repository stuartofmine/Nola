# Nola 设计规范 · 当前原型

2026-11-11 核对；移动端以 [移动端视觉与交互](MOBILE_UI_DESIGN.md) 为准，桌面沿用现有工作区。此文的桌面及共享身份规范继续有效；移动端使用中性底色、直接排版的回复和轻量设置列表。原型不等于客户端已实现。

## 1. 共同语言，不同任务逻辑
优雅来自清楚的主次、稳定的动作位置和适当留白，而不是堆叠卡片或大面积主题色。手机以会话列表为默认入口，通过活动承接需要回应的事项；桌面是生产力工具，提供统一四入口侧栏、简洁 48px 单顶栏与右侧三区扁平检查器。普通聊天不被强制任务化。

## 2. 色彩与字体
- **三层表面层级（Warm Paper / Warm Ink）**：以 [tokens.json](../../../../shared/design-tokens/tokens.json) 为跨端唯一真源，彻底告别纯黑 `#000000` 或冷蓝灰表面：
  - `canvas`（画布主底）：浅色 `#FAFAFA`、深色 `#0b0b0c`（阅读主画布及原生启动底色，防止冷启动白闪）。
  - `surface`（内容与输入表面）：浅色 `#FFFFFF`、深色 `#131315`（卡片、输入栏、对话侧栏与主面板）。
  - `surfaceSubtle`（次级与凹槽表面）：浅色 `#F2F2F4`、深色 `#1a1a1d`（导航侧栏、分段底槽、禁用控件与弱化容器）。
  - `surfaceElevated`（抬升浮层表面）：浅色 `#FFFFFF`、深色 `#242428`（弹窗、Popover、浮动 `@专家` / `/` 面板，仅靠语义阶梯与轻阴影与底层拉开层次）。
- **文字与对比度**：普通正文 `ink`（`#111113` / `#F5F5F7`），次级文字 `inkSecondary`（`#52525B` / `#A1A1AA`），元信息 `inkMuted`（`#63636E` / `#8E8E93`）；所有文本色在三层表面上均满足 WCAG AA `>= 4.5:1`。深色模式主动作按钮必须使用高对比度深墨文字搭配明度足够的鼠尾草绿底色（如 `#F5F5F7` / `#0B0B0C` 或 `#76C48C` / `#0C1C13`，对比度 `>= 4.5:1`），禁止使用白字配浅鼠尾草绿（`1.76:1`）。
- **色调悬停、按压与禁用反馈**：
  - 主动作按钮悬停/按压采用色调加深（如 `button.primary:active` 收深至 `#3A855A` / `#62B278` 或 `color-mix(in srgb, var(--button) 78%, var(--bg))`），严禁出现惨白/淡绿闪白或引发位移的 `scale()` 缩放。
  - 危险操作（`danger`）悬停叠加 `12%` 危险色柔光（按压 `20%`）并点亮危险描边，常态不抢占主视觉。
  - 禁用态输入框与按钮使用高可读低饱和语义色（`color: var(--muted); background: var(--soft); border-color: var(--line); cursor: not-allowed`），避免单纯降低整体透明度导致文字不可辨。
  - 桌面与 WebView2 滚动条统一收窄为 `8px` 暖色细轨（`scrollbar-width: thin` + `::-webkit-scrollbar-thumb` 使用 `border` -> 悬停 `outline`），消除原生粗灰滚动条割裂感。
- 手机一级页标题和桌面新会话标题使用系统衬线字体，中文回退至宋体。操作、列表和正文沿用系统无衬线。桌面正文 16px/26px，手机对话 17px/28px。
- 正文段落间 12px；列表上下 12px、缩进 20px、相邻条目 8px；正文小标题上 24px/下 12px。元信息 12px/18px，紧凑桌面列表主要条目 13px。
- 标题层级基础为 28/36、20/28、16/24。不要把每一面板都当独立大标题页面。

## 3. 间距与边界
- 一般内容页左右边距：320px 手机 16px，390px 手机 20px，平板中等宽度 32px，宽桌面 40px；这些是内容页基准，检查器/气泡采用各自局部间距，不机械套到每一层。
- 阅读列上限 720px；长文不铺满超宽屏。表格、diff 与资料布局可按内容扩展。
- 桌面全局顶栏固定 48px，只一行：左侧放置侧栏开关与新建对话，居中显示当前会话或管理分区标题，仅在对话分区显示右侧会话内搜索与带简短文字标签的「任务 / 产物 / 上下文」检查器按钮（语义图标分别为目标进度、双页产物、上下文脑图；`< 900px` 窄窗收为纯图标 + Tooltip）。正文三栏从 y=48 开始。全局图标 18px、桌面触区 36px；移动操作触区至少 44px。
- 检查器「任务 / 产物 / 上下文」与顶栏分段一体化，桌面停靠态不再在 48px 顶栏下方叠放第二条 44px 标题栏（避免 92px 双顶栏）；内部采用无外层手风琴的直接滚动区域（分隔线轻量分隔，独立保留滚动位置与草稿）；宽度 320–480px，紧凑桌面按可用空间限宽。
- 产物预览与代码审阅通过独立弹窗/审阅窗查看，不再使用顶部浏览器式内容标签；独立 820×620 双栏设置窗口收敛通用、模型服务、智能体、连接、数据与诊断六类配置。

普通内容表面使用语义实色和单层边框，不叠加渐变、内高光或阴影。浮动弹层
按需保留阴影；按下不缩放发送按钮。通用内以标题、间距和内容分组建立层次，
原型调试开关收起，不与产品偏好争夺首屏。

## 4. 主 Agent 发言与专家过程展示
主对话时间线中，**主 Agent（`Nola`）是唯一面向用户发言的角色**（对齐 [多智能体导航契约](../../shared/MULTI_AGENT_NAVIGATION.md)）。专家角色不作为顶层聊天气泡直接发言，也不提供 8 色专家聊天气泡配色。

| 视口 | 助手身份表达 | 用户气泡内边距 | 专家协作呈现 |
| --- | --- | --- | --- |
| 桌面 | 正文上方 `n` 标记与 `Nola` 签名 | 12px 16px | 回复下方的内联过程摘要卡片 +「查看专家会话」只读入口 |
| 手机 390 | 正文上方 18px 标记与 `Nola` 名称 | 12px 15px | 回复下方的内联过程摘要卡片 +「查看专家会话」只读入口 |
| 手机 320 | 正文上方 18px 标记与 `Nola` 名称 | 12px 15px | 回复下方的内联过程摘要卡片 +「查看专家会话」只读入口 |

助手正文直接排布在中性页面底色上，不包裹彩色专家气泡；用户气泡使用主题内中性浅灰（桌面右上圆角 5px、其余 16px；手机四角 20px），不添加漫画尾巴、阴影或双边框。专家子任务的状态、摘要与只读会话入口统一收纳在 `Nola` 回复内的轻量过程卡片（`.expert-process-card`）及右侧「任务 > 专家会话」中。

用户可以在同一句中点名多个专家。草稿中的名字参与文本编辑，已发消息中的名字支持点击和键盘聚焦，打开本次绑定的专家资料。名字采用正文基线和主题强调色。任务卡由主 Agent 的派发记录驱动；查看资料或浏览旧记录都不会新增任务。桌面与手机实图见[消息内的专家提及](../../shared/EXPERT_MENTIONS.md)。

## 5. 消息操作与特殊内容
消息级复制、重试、用户编辑重发位于消息内容下方外部，贴合对应内容列。用户操作靠右。行间距 5px、按钮间距 2px，桌面按钮最小高度 32px、手机 44px，图标 14px。始终占位并可访问，不只悬停出现。用户「编辑重发」先校验原消息及提及身份。准入成功后在原会话替换该轮及后续回复，连同被替换轮次派发的专家记录一起回溯。失败留在编辑器，原对话仍可阅读。

错误/等待/流式占位统一归属 `Nola` 主回复，专家子任务的部分未完成状态在内联过程摘要与只读专家子会话中核查。工具授权卡片是内容本身，操作保留在卡片上下文。代码块自身横向滚动；长链接换行，不撑破页面。代码/列表的合成像素测试不表示生产 Markdown 渲染及真实内容链路已完成验收。

## 6. 可访问性与动效
图标提供名称、悬停/焦点提示及中性选中态；不能只看颜色辨识。保留可见键盘焦点（`:focus-visible` 使用 `2px solid var(--focus)` 与 `3–4px` 外偏移，与选中底色分离）、原生单选语义、标准 Tab 路径以及工具/标签的箭头导航。更多菜单与模态框支持 Escape 关闭并返回焦点。

- **动效与微交互人因**：
  - Popover 采用 `160ms ease-out`、Modal/Dialog 采用 `180ms ease-out` 的 `@starting-style` 进出场曲线（伴随 `4px` 轻位移与 `backdrop-filter: blur(3px)` 遮罩过渡，配合 `allow-discrete`）。
  - 严格遵循 `prefers-reduced-motion: reduce` 与原型减弱动效开关：过渡与动画时长归零、`scroll-behavior: auto`，状态直接切换且不丢失焦点。
  - 按压反馈采用干脆的色调变化，禁止会对相邻布局产生抖动或位移的形变动画（`transform: none`）。
  - **零冷启动白闪**：Web/Tauri 启动页（`startup/index.html`）与原生窗口背景在首帧渲染前即同步绑定 `canvas` 语义底色（浅色 `#FAFAFA` / 深色 `#0b0b0c`），彻底消除深色模式冷启动白屏闪烁。

主题切换不改变层级、内容或流程。浏览器存储与演示限制详见交互规范。

## 7. 审美与人因工程基线（2026-11-20 1.0.0 审阅）

### 移动与平板导航及 Sheet 人因
- **严禁 L2-dismiss-then-L3-present 弹层接力**：工作工具、设置子页、反馈与详情等次级流程必须在现有 Sheet 内部的 `NavigationStack`（iOS）或 `AnimatedContent`（Android）内推入栈页面，绝不先关闭 L2 Sheet 再重新弹出 L3 Sheet，避免视觉闪烁与手势上下文丢失。
- **零首帧入场重排（Zero Frame-1 Relayout）**：页面在异步数据就绪前必须预留稳定几何尺寸——禁止 `.toolbar(.hidden -> .visible)` 引起的顶栏跳动、禁止整页 `opacity: 0` 淡入造成的白帧闪动、禁止嵌套 `WindowInsets` 导致的双倍状态栏内边距，并在带动画的子页切换间提升（hoist）滚动状态以防止回弹跳动。
- **触控与输入法（IME）人因**：iOS 主要触控区不小于 `44pt`，Android 不小于 `48dp`；所有带输入的 Sheet 与底栏必须声明 `.imePadding()`（或等效键盘安全区避让）；SwiftUI `List`/`Form` 内包含多个可点按钮的行必须显式声明 `.buttonStyle(.borderless)` 或 `.plain`，防止整行误触发全部按钮。

### 桌面端人因
- **最小窗口尺寸**：桌面客户端最小窗口约束为 `720×520`，安全高于 `700px` 移动端断点，确保桌面窗口缩放时不会意外退化为窄屏移动壳层。
- **双栏 `/settings` 导航**：桌面设置采用固定左侧分类导航 + 右侧独立滚动详情的双栏结构，避免长表单迷失层级。
- **浮动 `@expert` / `/` 组合器浮层**：输入框触发的 `@专家` 与 `/` 指令候选以浮动层锚定在输入区上方，不挤压或重排上方消息时间线滚动位置。
- **表单脏状态保护与统一破坏性确认**：模态编辑器存在未保存修改时，关闭（关闭按钮、遮罩点击或 Escape）必须弹出脏状态确认；删除、清空、撤销等破坏性动作统一使用带危险语义的确认对话框，明确后果且不将危险按钮设为默认回车焦点。

### 视觉节奏与状态表达
- **空态（Empty States）**：居中克制排版，包含轻量标记/图标、清晰一句话引导与唯一主动作，不堆砌无意义插画或次要噪声。
- **加载态（Loading Skeletons & Spinners）**：骨架屏与旋转指示器使用高对比度语义色调（`surfaceSubtle` 基底配 `inkSecondary`/`accent` 指示），在减弱动效下保持静态可见。
- **可恢复错误横幅与内联恢复**：错误横幅与内联错误卡始终提供明确的「重试（Retry）」与「忽略（Dismiss）」动作，并完整保留用户已编辑草稿与上下文，不静默丢弃输入或以“成功”状态掩盖未确认写入。

## 移动导航 v24
默认进入对话，四项底栏为对话／活动／资料／设置。列表、会话、详情与外观的当前规范和可操作范围见 [移动端视觉与交互](MOBILE_UI_DESIGN.md)。聊天为全屏会话层，返回恢复列表位置、筛选和草稿；主功能没有“更多”集合页。


## 页面同步与交互状态（2026-11-17）

- 手机输入文字独占满宽一行，下方为附件、模型、按声明显示的推理档位及发送/停止；回放入口放在设置的原型预览，不长期占据输入框上方。
- 设置只有一个页面标题；资料、记忆、计划按实际来源返回。除沉浸式聊天及其所属模型选择流程外，移动管理页保留四项主导航。
- 桌面左侧统一为「对话 / 专家与技能 / 自动化中心 / 记忆与数据源」四项主导航 + 常驻对话搜索与列表 + 底部单一设置入口（820×620 独立设置窗口），取消顶部「对话 | 资源」双图标切换与浏览器式内容标签栏；不在网页画布内绘制假 macOS 红黄绿窗口栏。「专家与技能」采用 `专家 | 技能 | MCP` 分段，「记忆与数据源」采用 `记忆 | 来源 | 使用记录` 分段，全局管理页自动隐藏右栏检查器。
- 右侧检查器的「任务 / 产物 / 上下文」移除外层 9 组手风琴与「工作概览」，并消除桌面停靠态 48px + 44px 双顶栏；「上下文」顶部展示「原始消息数量 · 摘要数量」与默认收起的知识点/会话 Wiki/会话回忆编辑区，「托管浏览器」仅在扩展未连接或报错时提示；全界面不显示 SHA-256 摘要或字节偏移。桌面输入栏收敛为**框内底部单行工具栏**（左侧「上下文侧」：`+`、工作区、`@ 专家`；右侧「执行侧」：模型/外部代理/主机、推理强度、权限模式、语音、发送/停止），输入框上方仅在存在已选附件或 `@专家` 提及胶囊时按需浮现，不再常驻第二条顶栏。本地模型推荐、UTC+8 中国用户默认 ModelScope 与直链粘贴详见 [本地模型体验设计规范](../../shared/LOCAL_MODEL_EXPERIENCE.md)。iOS 与 Android 均开放专家选择与「管理专家」入口。
- 设置分类、文本操作使用中性主题悬停/按下反馈与内边距；复制动作始终无背景和边框。焦点使用语义主题色。
- 更新、清单失败、保存未确认分别表达；重试或核对是明确动作，不能用“成功”关闭未确认的编辑器。所有检查和安装步骤都标注原型演示，不下载或调用真实服务。

实际范围与对比见 [IMPLEMENTATION-COMPARISON.md](IMPLEMENTATION-COMPARISON.md)。

## 业务场景评审视图（2026-11-10）

`scenarios.html` 复用白底／墨色的中性方向，提供目录、平台预览与状态说明。目录和说明只在评审页存在，不能复制进产品页面作为额外导航。桌面正文 14px、手机正文 16px，手机操作至少 48px；320px 下可预览 125% 大字。主动作与次动作区分，拒绝不与允许同时使用实色主按钮；主题焦点和减少动态效果保留。

Host 任务展示来源、执行位置与里程碑；权限完整审阅可原地展开；MCP 的 HTTP／stdio、模型目录启用／选中、五档推理／继承、字体标本分别使用自己的组件。复制只有真实剪贴板写入成功才显示已复制，失败保留手动选择。所有来源、进度、模型与统计均为明确标记的样例，系统栏不自绘假 macOS 窗口控制。

设计依据采用 apple-design 的本地参考：`privacy.md › Requesting permission` 要求“Request permission only when your app clearly needs access”；`motion.md › Best practices` 要求“Make motion optional”。评审页的布局、数值和样例属于本项目设计选择，不是原生平台验收结论。


## 过程标题与文献引用（2026-11-12）

- 运行中展示当前活动，步骤间为“正在处理中”；展开历史也不提前变成“执行过程”。已结束历史使用中性标题，具体失败保留在对应步骤，技能未完成保持未完成。
- 正文和表格中的内联外部链接同样使用小号灰色，不随正文或表头继承粗体蓝色；原链接目标保持不变。
- 文献置于回复末尾，以编号、标题及必要定位构成列表，默认三条；展开/收起为文字动作。引用不铺卡片背景、不逐条加箭头。技能统计只在信息入口中显示，不在正文放运行 ID、原始毫秒或协议字段。
- 原型引用为 12px 主题辅助灰色；生产客户端使用各自可缩放的 caption/bodySmall 与语义主题色，不强制同一物理字号。灰色文字须保持普通小字至少 4.5:1 对比，触控区域独立于视觉字号保留。
- [独立预览](../reply-preview.html)与完整桌面/手机比较会话共用 `reply-presentation.js`、`reply-presentation.css`。31 条来源、耗时、状态切换均为合成样例，不证明真实研究或验收完成。

生产行为与原型区别见[客户端对比](IMPLEMENTATION-COMPARISON.md)，已执行证据及系统限制见[验证记录](VALIDATION.md)。
