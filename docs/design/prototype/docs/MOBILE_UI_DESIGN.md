# 移动端视觉与交互

2026-11-11。当前移动端原型以本页为准；[v24](MOBILE-IM-V24.md) 保留早期导航和手势探索的历史。中性主题、完整阅读宽度、用户气泡、输入边框与设置分组已同步到 iOS/Android 原生实现；浏览器预览仍只演示合成数据。

## 设计方向

内容先于外壳。移除整屏绿色和双边大气泡，用文字、对齐和间距建立主次。助手回复直接排版，用户消息使用浅灰气泡；主会话只显示 Nola；专家身份仅在只读任务详情中区分，时间不在每条消息下重复。权限请求、错误恢复及来源范围继续明确呈现。

| 元素 | 当前规则 |
| --- | --- |
| 页面 | 浅色白底、深色近墨底；主题色只表达动作和状态，不染整屏 |
| 根页面 | 左对齐 28px 标题；详情/聊天保留紧凑的返回栏 |
| 列表 | 标题 16px、中等字重；一行预览，时间退为辅助信息；普通行不增加头像列 |
| 回复 | 正文 17px，约 29px 行高；助手无底色卡片，用户气泡圆角 20px |
| 身份 | 回复上方 18px 标记和 12px 名称；身份不占用整列阅读宽度 |
| 输入 | 单一圆角 25px 容器，满宽文字；附件、模型、实际档位、发送/停止在底栏 |
| 设置 | 偏好、连接与能力、安全；无叠套卡片，以标题和分隔线分组 |
| 模型 | 已配置列表只有一个添加入口；空状态保留一个清楚的开始动作 |
| 触摸 | iOS 主要操作至少 44px，Android 48px；图标尺寸不等于点击面积 |
| 颜色 | 正文和辅助文字在各自背景上均验证至少 4.5:1；不使用蓝色常驻边框 |

浅色基础文字 `#242423`、辅助文字 `#6c6b66`；深色背景 `#141413`、基础文字 `#eeede9`、辅助文字 `#a8a69f`。用户气泡浅色 `#f2f1ee`、深色 `#292927`。边界使用主题内的中性色。

## 平台与导航

iOS 保留导航行的轻量指示和右上新建；Android 隐藏重复行尾指示，新建使用其列表浮动主动作。聊天隐藏主底栏，返回保留会话、筛选与草稿。模型档位仍来自模型声明，不增加第二套三档选择器。手势、输入法、真实键盘和安全区仍需原生设备验收，浏览器原型不能替代。

普通按钮以颜色变化反馈按下，不让发送按钮明显缩放。新内容渐显遵循减少动态效果；已显示内容不因切换面板重新淡入。复制保持无常驻背景或边框。

## 原生实现

iOS 颜色入口为 `apps/ios/UI/DesignSystem.swift`，Android 为 `apps/android/app/src/main/java/com/nola/ui/theme/Theme.kt`。聊天背景使用同一中性页面角色；回复身份放到正文上方，普通助手回复不再着色或占用头像侧列。专家作者只在只读子历史与任务详情中保留，主时间线由 Nola 统一回复。

会话列表采用左对齐根标题、单行普通预览与辅助时间；错误和待回应状态保留必要空间。设置首页以偏好、连接与能力、安全分组，保留各平台原有入口、导航与数据行为。iOS 字号继续使用 Dynamic Type，Android 使用可缩放的 sp。

Android 的 Markdown TextView 与 Compose 正文共享字号和行高的缩放来源，不能让回复正文在大字设置下保持原字号。原生回归同时检查真实 TextView 的字号与合成页面截图，覆盖 200% 字体；iOS 覆盖最大辅助字号。身份标记也应随字号预留空间，避免裁切。

## 审阅

使用 [手机预览](../mobile.html) 在宽屏上操作移动原型。平台、明暗和宽度是外部审阅控件，不属于产品界面；切换外观和平台保留 iframe 内的草稿。`verify_mobile_ui.cjs` 检查实际排版、点击面积、对比度、单一添加入口和草稿，其他完整业务回放继续检查表单、返回、档位及错误恢复。
