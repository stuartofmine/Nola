# 会话 UI：行为契约与分阶段落地

状态：五端代码已落地，统一回归与移动端交互验收中；不是全端视觉/性能验收完成。2026-10-15。

## 目标与参考边界

Nola 的界面首先服务于阅读答案、理解真实执行进度和控制任务。视觉特征是
安静的正文、可追溯的执行过程、按需展开的产物，而不是日志控制台或多层卡片。

参考 Caho1/open-claude-ui，审查版本
`2834bc158a4849f21c97cbb2e0b10525f6e646f1`：

- [滚动意图](https://github.com/Caho1/open-claude-ui/blob/2834bc158a4849f21c97cbb2e0b10525f6e646f1/code-examples/useClaudeScrollPinning.ts)：用户主动操作优先、底部容差、跳至最新。
- [语义表面](https://github.com/Caho1/open-claude-ui/blob/2834bc158a4849f21c97cbb2e0b10525f6e646f1/code-examples/cds-theme.css)：用少量表面层级表达关系，不堆边框。
- [富输入](https://github.com/Caho1/open-claude-ui/blob/2834bc158a4849f21c97cbb2e0b10525f6e646f1/code-examples/RichComposerWithMentions.tsx)：输入法、候选菜单和提交需要统一事件优先级。
- [容器适配](https://github.com/Caho1/open-claude-ui/blob/2834bc158a4849f21c97cbb2e0b10525f6e646f1/code-examples/ContainerResponsiveBar.tsx)：按实际可用空间调整次要操作。

这些是独立作者的还原实现，不作为 Claude 官方行为的证明。不复制模拟成功的
MCP 定时器、不禁止生成中折叠、不采用文本关键词推断执行状态，也不引入 React。
Mac/iOS 保持 SwiftUI/AppKit/UIKit，Android 保持 Compose，Web 保持 Svelte。

Apple 设计依据：`layout.md › Visual hierarchy` 的渐进披露、
`accessibility.md › Vision/Mobility` 的对比与操作区域、
`motion.md › Providing feedback` 的克制动效，以及
`scroll-views.md › Best practices` 的最小必要自动滚动。
本文方案是 Nola 的设计判断，不声称这些指南规定了某种聊天气泡样式。

## 当前代码基线

已有 `MacDesignTokens`、`MacTranscriptScrollController`、IME marked-text 保护、
`MacJournalProcessProjection`、会话/Run 绑定的 presentation owner 和局部等值头部。
保留这些实现，逐项收敛，而不是再建立平行的 UI 状态系统。

初始问题是助手回复外框包裹执行过程内框，正常内容也有背景与描边；信息层级过重。
现在减轻正常内容装饰，错误、待授权、搜索定位等信息仍保留明确入口。

## 模块的输入、输出与所有权

| 模块 | 输入 | 输出 / 允许拥有的状态 |
| --- | --- | --- |
| Core / Journal 投影 | 执行事件、授权结果、持久化记录 | 真实运行状态、稳定 Run/Part ID；UI 不补造终态 |
| 会话工作区 | conversation ID、Run ID、用户操作 | 会话草稿、附件、选择配置；不能借用另一会话的忙碌状态 |
| 消息呈现 owner | 稳定身份、递增游标、分页正文 | 局部增量投影、展开偏好；游标变化不能重建整条消息身份 |
| 滚动控制器 | 用户手势、内容几何、导航意图 | 跟随最新 / 阅读历史 / 显式导航；不得从 token 文本猜意图 |
| 输入组件 | 当前会话草稿、提交能力、IME 状态 | 编辑与提交意图；不因点击发送就假定提交成功 |
| 执行过程组件 | 有序 reasoning/tool/activity Parts | 原顺序过程、可操作折叠标题；点击批准只提交决定 |
| 产物面板 | 稳定 artifact ID、类型、加载状态 | 文件/图片/PDF 等预览；加载失败有重试，不影响主对话 |

## 不变量与流程

权限及配置生效遵循[两档权限与恢复交互](权限配置与恢复交互_20261016.md)：只有谨慎/全部允许；运行期用户配置提交不得被流式保存节流吞掉。以下历史验收不证明本批问题已修复。

1. 用户滚离底部立即停止自动跟随；只有用户回到底部或点击“最新”才恢复。
2. 流式追加采用直接定位，不为每个 token 启动平滑滚动。最终落盘、正文换行和
   工具折叠不能把阅读位置变成空白；不得使用固定大块底部占位掩盖布局问题。
3. 思考与工具按事件顺序保留在执行过程里，最终答案独立呈现。正常完成默认
   收起过程，但用户主动展开/折叠优先，生成中也可以操作。
   分组边界是最后一个有类型的 reasoning/tool Part：此前的公开说明、思考和工具
   保留原顺序，此后的公开文本为答案。不能简单把工具抽到顶部而颠倒说明顺序；
   不改写持久化 Journal，也不依靠文本词汇识别思考或工具。
4. 新 token 只更新活跃正文。完成工具的标题、详情开关和消息操作栏不重播动画。
5. 授权、排队、运行、拒绝、取消、失败、结果未知分别呈现。传输结束不等于成功。
6. 中文候选确认先于发送；菜单候选导航先于普通 Enter；Shift+Enter 保持换行。
7. 切换会话不能清除另一会话草稿，也不能把另一会话的停止按钮带过来。

## 视觉与交互规范

常规宽度：`会话侧栏 | 正文 + 执行过程 + 输入框 | 按需产物预览`。
紧凑宽度：`正文 + 执行过程 + 输入框`；导航与产物由显式入口打开。

- 正文无闭合外框，沿现有阅读列对齐；用户消息保留轻量气泡以区分发言者。
- 执行过程使用一层次级表面；普通状态不加连续外描边。需要处理或提高对比度时
  恢复边界，始终保留文字/图标状态，不只用颜色表示失败。
- 权限和错误保留局部明确容器，不把整段已有答案染红。
- 复用原生语义色：windowBackgroundColor、controlBackgroundColor、labelColor、
  secondaryLabelColor、separatorColor 和现有品牌强调色。此轮不新建固定十六进制
  调色板；实际对比度必须在系统浅/深/增强对比外观下测量，不能虚报固定比值。
- 复用 4/8/12/16/24pt 间距与现有正文排版，过程操作区至少 28pt 高，键盘可达。
- 只允许新增内容短暂显现；Reduce Motion 时关闭非必要动效。输入框保持不透明。

自审：照搬暖色、衬线体或弹簧常数无法解决 Nola 的状态与刷新问题，因此不采用。
本次先删除一层正常回复装饰，而不是增加品牌动画。

## 实施顺序与验收

### A：Mac 会话阅读层级（已落地）

- 移除助手正文闭合外框及多余内缩；保留局部失败提示和既有 accessibility ID。
- 普通过程减少描边，需要处理或增强对比度时显示边界。
- 回归生成中折叠、终态收起、交错事件顺序、窄窗口、浅深色与增强对比度。

### B：会话状态与滚动

- 对已有控制器补齐会话切换、图片/PDF 延迟高度变化、长表格、完成时折叠的测试。
- 验收目标：阅读历史时零非请求跳转；完成不出现空白落点；会话草稿零串扰。
- 采集帧耗时、正文追加与稳定子树刷新次数；目标 60Hz 下主线程帧预算 16.7ms，
  报告 p95 和设备/内容规模，不以单元测试代替性能测量。

### C：输入与产物

- 输入配置按容器空间渐进收起；不更改用户已选模型或参数。
- 右侧优先呈现产物、来源与待处理项，运行统计降为辅助信息。
- 明确预览加载/失败/重试与焦点回归；移动端使用原生导航，不强塞双栏。

### D：跨端对齐（已落地）

- 将上述不变量映射到 iOS、Android、Svelte；共享行为测试矩阵而非 UI 实现代码。
- iOS / Android / Web 已接入有序过程分组与答案分离；CLI 保留终端追加语义，
  修正流式增长和输入区高度变化时历史视口漂移。具体证据见第三批记录。

测试必须使用隔离数据与 Mac `Test` configuration，不覆盖签名的 Debug 应用。
截图检查与真实交互未完成前，只报告编译/契约结果，不宣称视觉验收完成。

## 第二批：导航与滚动生命周期

- 修复历史原文定位的异步归属：每次请求使用独立 ID；切换会话或离开视图时
  撤销 UI 请求身份。旧请求返回不能清除新请求的忙碌状态，也不能显示旧错误。
  此处撤销的是呈现资格，不声称已经取消底层历史读取。
- 切换会话同时清除旧定位提示，避免新会话继承上一会话的错误条。
- 滚动结束通知只对仍有效的用户手势生效；会话重置、显式导航和跳至最新

- 新增真实 NSScrollView 回归：会话切换后的迟到手势、导航期间迟到手势，

### 并行收尾发现

- iOS 原生多行输入框补上 SwiftUI 焦点绑定；提示文字不再继承编辑器标识。
  UI 自动化已验证修复后可点击、输入与发送，而非仅编译检查。
- iOS 新会话选择通知可能迟于发送执行：存储的空窗口曾覆盖尚未落盘的提交，
  并清除 active assistant ID。改为按会话维护提交呈现层，按消息 ID 与持久化
  窗口合并；持久化数据优先，隐藏会话更新仍归属原会话。
- iOS fixture transport 原先绑在一次 provider 实例上，会被会话模型恢复替换。
  现在仅 DEBUG 在 ModelService 实例内绑定明确端点的 transport，仍执行真实
  Core 与 Journal，不绕过生产状态机，也不把模型永久固定为测试模型。
- Android 系统文档选择器跨 Activity 重建时，原 remember owner 会丢失。
  owner 现随草稿保存，返回结果只消费一次；新增恢复回归，定向 JVM 3/3 通过。
