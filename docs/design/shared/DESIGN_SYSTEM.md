# Nola 视觉系统与组件规范

核对：2026-11-14。现行组件行为以本页、[对话设计](CONVERSATION_UI_DESIGN.md)和[检查器规范](CONVERSATION_INSPECTOR.md)为准。跨端颜色角色、字号阶梯、圆角与间距以机器可读真源 [shared/design-tokens/tokens.json](../../../shared/design-tokens/tokens.json) 为准，并由 `python3 scripts/check_design_tokens.py` 执行跨平台对齐与 WCAG AA 对比度门禁。原型[视觉规范](../prototype/docs/DESIGN-SPEC.md)保留总体视觉方向，避免从历史截图复制另一套常量。

## 适用范围与层级

这份规范记录接受的视觉方向及跨端映射；原型是静态 HTML/CSS/JavaScript 演示，不等于生产客户端已实现。源码功能依据和已测范围见[能力覆盖矩阵](../prototype/FEATURE-COVERAGE.csv)，原型检查与生产验收边界见[验证说明](../prototype/docs/VALIDATION.md)。

日期化色值、平台截图与原型版本不另立一套现行色板。各端通过语义主题资源定义实际表面、强调、边界与状态色；历史记录不得覆盖当前交互和可访问性要求。执行、审批和数据语义仍分别由[对话与工具设计](CONVERSATION_UI_DESIGN.md)、[权限恢复契约](权限配置与恢复交互_20261016.md)及 Core 契约约束。

## 共同视觉方向

- 手机默认呈现会话列表；活动承接待回应与执行事项，资料和设置独立。普通闲聊不自动变成任务。
- 桌面面向持续对话和生产力：唯一 48px 全局顶栏、统一左主侧栏（「对话 / 专家与技能 / 自动化中心 / 记忆与数据源」+ 常驻会话列表 + 独立设置窗口）及按需展开的三区扁平右侧检查器。侧栏搜索与右侧工具切换不替换中央对话内容。
- 不在画布放置额外大标题或第二层全局导航；使用内容自身层级、安静留白和中性色背景组织页面。
- 主对话流仅由主 Agent（`Nola`）面向用户发言，正文排布在中性底色上；专家协作通过回复内的可展开过程摘要与只读子会话（「查看专家会话」）呈现，不渲染独立专家聊天气泡，也不设置 8 色专家气泡预设。复制、重试及编辑重发位于消息气泡外。
- 图标和颜色不能单独承载状态；焦点、键盘、触控目标、系统字号和减少动态效果必须可用。

## 平台适配

桌面客户端（macOS/Web）采用同一信息层级与单顶栏/标签/侧栏关系，遵循原生窗口与输入方式。移动客户端（iOS/Android/Web 窄屏）遵循会话列表优先、全屏聊天和原生触控语义，不将桌面三栏缩小后照搬，也不将手机列表直接放大成桌面首页。共用语义不要求像素布局相同。

CLI 只呈现相同的内容、执行及权限事实，不模拟图形窗口或装饰布局。

## 组件和验收约束

消息身份、气泡外操作、工作工具、授权卡与编辑重发遵循现行对话与检查器契约；原型只证明它自身的演示行为。工具输出不是回答正文；待处理授权不得藏在普通折叠区域；客户端不可由提示词或外观推导授权。实际执行和权限仍服从当前服务契约。

原型自身的浏览器/DOM/合成像素检查仅说明原型范围。生产 UI 的真实窗口、键盘焦点、滚动锚定、动态状态、授权与恢复必须按[视觉验收契约](VISUAL_ACCEPTANCE_CONTRACT.md)单独验证。未实际检查的页面、平台或状态必须标为未验证。

## 统一表面与语义色板（Monochrome Obsidian & Porcelain）

所有图形客户端与交互原型共享同一套极简纯黑白黑曜石（深色）与瓷白（浅色）核心表面定义：中性界面克制无色偏、深沉通透，状态色仅用于真实的成功/警告/危险/信息反馈，不再用荧光绿或亮蓝抢占主视觉；机器可读定义位于 [tokens.json](../../../shared/design-tokens/tokens.json)：

| 语义角色 | Token 键 | 浅色（Light） | 深色（Dark） | 说明 |
| --- | --- | --- | --- | --- |
| 画布主底 | `canvas` | `#FAFAFA` | `#0B0B0C` | 页面与会话阅读主画布、Windows 启动宿主底色 |
| 卡片与输入表面 | `surface` | `#FFFFFF` | `#131315` | 面板、卡片、输入框、弹层主体 |
| 次级与侧栏表面 | `surfaceSubtle` | `#F2F2F4` | `#1A1A1D` | 侧栏、分段底槽、列表填充与弱化容器 |
| 抬升表面 | `surfaceElevated` | `#FFFFFF` | `#242428` | 浮层与抬升容器语义色 |
| 主要正文 | `ink` | `#111113` | `#F5F5F7` | 主标题、正文与主图标 |
| 次级文字 | `inkSecondary` | `#52525B` | `#A1A1AA` | 摘要、辅助说明与次级标签 |
| 弱化元信息 | `inkMuted` | `#63636E` | `#8E8E93` | 时间戳与次要元数据 |
| 细分隔线 | `border` | `#E4E4E7` | `#26262A` | 发丝分隔线与面板描边（暗色优先用半透明 `white 7%–10%` 增强通透感） |
| 控件描边 | `outline` | `#71717A` | `#7A7A82` | 可交互输入框与次按钮边界（非文本对比度 >= 3.0:1） |
| 主动作与焦点 | `accent` / `onAccent` | `#18181B` / `#FFFFFF` | `#F5F5F7` / `#0B0B0C` | 浅色深墨黑按钮配白字、深色纯白按钮配黑字；分段选中态与侧栏高亮采用柔和中性磨砂玻璃 |
| 状态语义色 | `success` / `warning` / `danger` / `info` | `#147537` / `#925605` / `#C81E1E` / `#2563EB` | `#5CD68D` / `#F0B85A` / `#F28080` / `#78B4F8` | 仅表达真实状态，在浅/深表面均满足 WCAG AA `>= 4.5:1` 文本对比度 |

## 图标语义与入口归属原则（每个 Icon 为什么放这里）

功能为 UI 服务：每个图标与入口必须落在用户意图自然产生的位置，避免“猜图标”与双层重复工具栏。

| 区域 | 入口与图标布局 | 为什么放这里 |
| :--- | :--- | :--- |
| **桌面唯一 48px 顶栏** | 左：`侧栏开关` + `新建对话`（与系统红黄绿交通灯垂直中线对齐）；中：当前会话标题（可点重命名）或管理分区标题；右（仅对话分区）：`会话内搜索` + 磨砂玻璃分段检查器入口（`任务` / `产物` / `上下文`，宽屏带短文字标签，窄屏退化为语义图标 + Tooltip，仅挂载当前激活区域避免编辑器穿透）。 | 左上角固定全局导航与“随时开启新话题”；右上角聚焦当前会话的检索与检视；三栏共用同一条 48px 顶边线，检查器停靠时不叠加第二条 44px 标题栏。 |
| **桌面左主侧栏** | 顶部 4 项一级导航（`对话 / 专家与技能 / 自动化中心 / 记忆与数据源`）→ 搜索框 → 置顶与最近会话列表 → 底部单一 `设置` 入口。 | 保持 4 个安静的一级分区不膨胀；模型中心锚定在**输入框模型选择器底部（「管理与下载模型…」）**与**设置 → 模型服务**，挑模型时 1 步直达。 |
| **桌面输入框与弱化上下文条** | 输入框正上方左侧放置**轻量无边框弱化条**（`选择文件夹`、`@ 专家`，常态低对比度 `opacity ~0.78`，悬停或激活时点亮），不抢输入框主视觉；输入框采用克制 1pt 柔焦细边（暗色 `white 22%`，告别刺眼纯白框），框内底栏左侧仅放 `+ 添加资料`，右侧为无边框极简执行胶囊（`模型选择 ▾`、`推理档位 ▾`、`权限盾牌`、`语音`、同心圆 `发送 / 停止`）。 | 把低频上下文（工作区目录与专家）轻放到框外上方，给框内底栏留出充足呼吸空间，同时消除“大框套五个小框”的视觉噪声。 |
| **移动端四项底栏** | `对话`（消息气泡）、`活动`（铃铛/提醒徽标，而非容易误解为历史记录的时钟）、`资料`（文件夹）、`设置`（齿轮）。容器延伸至全屏安全区边缘，选中胶囊带平滑滑动动效（减少动态效果下直接切换）。 | 与移动高频心智对齐：聊过什么 → 什么在等我 → 我存了什么 → 系统偏好。 |
| **移动端聊天顶栏与输入栏** | 顶栏：`返回` | `会话标题 ›`（轻量右箭头明示点击进入会话详情）| `搜索`；底栏单行：`+`（资料/图片/专家统一收进单栈 Bottom Sheet）、`模型 ▾`、`推理 ▾`、同心圆 `发送 / 停止`（44pt/48dp 触区 + 36pt 视觉同心圆）。 | 给标题补齐可点击线索，不再让用户盲猜“会话详情藏在哪里”；手机端保持单行紧凑与高对比度触控精度。 |

## 当前组件规则与实现映射

| 组件 | 当前约束 | 实现入口 |
| --- | --- | --- |
| 边框与焦点 | 使用主题语义色，不硬编码蓝色；焦点与选中态分开 | Apple `DesignTokens`/`MacDesignColor`，Android `NolaSurface`，Web `theme.css` |
| 桌面按钮 | 浅/深色均有悬停和按压反馈，尺寸不变；图标动作有可访问名称 | `MacPageChrome.swift` 与 `NolaControlHover/Pressed` 资源 |
| 回答复制 | 无常驻边框/背景；移动端不依赖悬停才发现 | `MacMessageView`、`MessageCopyAction`、`ChatMessageActions.svelte` |
| 手机输入 | 满宽文本 + 底部紧凑操作；不常驻堆叠多排状态/参数 | `ChatComposer`、`ChatScreen`、`Chat.svelte` |
| 推理选择 | 当前模型声明的完整档位，紧凑菜单与选中标记；不并列三档控件 | 各端 `ReasoningEffortMenu`/`ChatReasoningMenu`、`MacComposerView` |
| 检查器 | 独立展开、单一主滚动区，不设置页面选择器 | `MacChatInspectorView`、`Chat.svelte` |
| 动效 | 会话筛选的选中背景在两个文字标签之间移动。减少动态效果开启时直接切换。流式正文只呈现新增片段 | iOS 会话列表、手机交互原型、各端流式渲染器 |

表中名称用于定位当前源码，不意味着所有平台使用相同控件或相同像素尺寸。触控目标、长文本、动态字号、320/390 窄屏及深浅色须分别检查。

审阅手机一级页时，在同一设备、字号与主题下，将四个标签页并排比较标题起点与安全区间距。审阅筛选滑动时，检查录屏的中间帧能否看见选中背景经过两个标签之间的位置，再开启减少动态效果检查直接切换与焦点保留。

## 全功能跨端交互一致性基线（引导、模型接入、权限卡、能力中心与设置）

- **首次引导与 API 模型接入**：首次引导必须提供清晰路径（本地模型 / 云端 API / 账号或宿主机），不再把用户丢进空白原始 URL 表单；API 接入页提供主流服务商一键预设（OpenAI / Anthropic / DeepSeek / OpenRouter / Ollama / 自定义）并支持同页填写密钥，底层线协议（`Responses` / `Chat Completions` / `Anthropic`）与原始字段名（`max_tokens` / `max_completion_tokens`）统一收敛进「高级设置」。已配置模型置顶，行内仅保留主动作（`使用 / 运行中`），其余操作收进 `•••` 菜单。
- **权限审批卡与工具/思考过程**：权限审批卡遵循「标题 + 友好执行位置胶囊 + 简短说明 + 主动作（`允许一次` / `拒绝`）」的紧凑结构，将「补充说明」与「参数/技术详情」默认折叠，严禁向用户展示原始 `hostId` 哈希、UUID 或多行 KiB 免责壁；工具调用与思考过程最多两层展开，避免五层嵌套 `<details>` 与无高度上限的思考刷屏。
- **专家、技能、MCP 与插件**：专家统一展示色块/首字头像与模型标签，列表与编辑器分离（桌面双栏、移动推入或 Sheet）并带未保存离开确认；Skill 默认 Markdown 预览 + 切换编辑；MCP/Plugins 统一卡片空态与结构化输入，不将多段表单塞进窄 `AlertDialog`。
- **活动、资料与设置**：移动端「活动」页顶栏提供通知中心铃铛入口；「资料」下知识点以可搜索、可折叠卡片呈现，数据源直达无多层跳板；记忆的「置信度」对用户手动条目隐藏或转为「高/中/低」人话表达；设置页统一行样式、分段外观开关、真实绑定的快捷键与统一的「Nola Server」术语，诊断日志入口必须在设置内可达。
