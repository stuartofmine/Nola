# 专家子会话与历史阅读

专家上下文属于邀请它的主会话。会话列表只展示主会话，不显示专家子树或空的专家会话提示。macOS 在当前会话右侧“上下文 → 参与者”提供专家历史，展开后按需分页读取，不为列表每一行预加载正文或创建房间。左侧“专家库”独立管理配置：系统内置七个 Core 角色可浏览完整提示词、工具与 Skill，通过“创建可编辑副本”保存为用户专家；浏览不写入目录，也不改变当前会话的专家选择。

每个专家上下文有独立的 conversation ID、participant ID、规范 revision 和消息数量。读取使用 Core `child_conversations` 的版本 1 投影，绑定主会话、Room 和来源运行时。分页必须保持同一个 Room revision；父会话、来源或游标变化后，旧请求不得追加到新页面。读取失败保留已确认的页并提供重试；重复 child、非前进游标、未知版本或归属不一致明确拒绝。

点击子会话打开规范正文阅读器，不打开普通发送输入栏。保留分页阅读、文本选择、复制、附件和已归档界面的查看；不在历史视图提交表单、补充任务指引、取消任务或触发模型执行。当前专家上下文可通过“回到主会话继续”返回主会话并选中该专家，继续沿用当前 Room 成员快照；不因目录已有新配置而自动升级。

重新引入专家后，旧上下文仍挂在原主会话下，并标记“旧专家配置 · 只读”。历史条目的 `agent_revision` 可能未知，客户端保留空值，不能用当前目录的 revision 补造历史。旧上下文不提供继续发送或隐式重新引入入口；采用新配置须回到主会话明确选择并确认。

macOS 使用独立的只读分页状态，通过 Core `child_history` 在同一快照读取正文窗口和专家来源，不创建执行 owner，也不读取无主会话范围约束的正文。专家请求按规范消息 ID 显示冻结的来源专家名，不从正文或最新专家目录猜作者；分页保持来源 Host、epoch 和 Room revision 一致。主窗口的选中会话与草稿保持独立；子会话本身没有第二套消息库。原型仅使用内存合成记录，重新引入时保存旧消息快照，绝不读取真实 Host 或调用模型。

专家是具有固定角色和持久上下文的子代理。临时 subagent 与专家须复用同一套 Task 准入、执行、取消、恢复和结果回传；专家通信只增加来源、目标及请求/回复关系，不能建立第二套执行状态机。展示专家历史或选择树节点均不授予专家通信权限，也不把显示名称作为路由标识。详细边界见[专家与子代理统一执行契约](../../architecture/模块/10-Goal任务与子代理/EXPERT_SUBAGENT_EXECUTION.md)。

验证入口：`MacExpertChildHistoryTests`，以及原型 `verify_expert_roles.cjs`、`verify_expert_roles_browser.cjs`。本轮实现中的新增断言须在源码冻结后统一运行，不能以静态原型代替真实客户端或模型验收。
