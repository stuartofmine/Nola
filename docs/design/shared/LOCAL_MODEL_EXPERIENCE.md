# 本地模型发现、下载与切换交互设计

更新：2026-11-22。本规范以 **“用户先看到清晰的 UI，再自然发现并完成能力——功能为 UI 服务”** 为原则，统一 macOS、Windows、Web、iOS 与 Android 的本地模型体验，消除前置工程表单、推荐卡顿与多步启停迷宫。

---

## 1. 核心产品原则

1. **先见模型，再谈参数**：打开本地模型页或弹窗时，首屏优先呈现**本机已安装模型**与**贴合本机算力的推荐模型卡片**；推理引擎（`MLX` / `llama.cpp` / `vLLM`）、下载源、量化后缀与上下文估算全部降级为次级信息或按需展开的「技术详情」。
2. **动态在线推荐 + 秒开体验**：推荐目录应根据用户硬件动态从在线仓库拉取，而非写死静态清单；同时通过**磁盘 + 内存 TTL 缓存（stale-while-revalidate）**、**按实际内存自适应上下文早停**、**并发候选探测**与**总耗时预算上限**，实现缓存命中瞬开、冷拉取 1–3 秒内出结果。
3. **中国区（UTC+8）零门槛默认 ModelScope**：中国大陆用户无法直连 Hugging Face。凡本地时区为 `UTC+8`（或语言偏好为 `zh-Hans` / `zh-CN`）且用户未手动指定下载源时，全端默认使用 **ModelScope**；在 ModelScope 模式下不阻塞等待 `modelfit.io` 超时（短超时竞速或直接走动态 ModelScope 家族检索）。下载源切换入口保持轻巧可见，随时可切回 Hugging Face。
4. **支持直接粘贴模型链接或仓库地址**：搜索框同时承担“关键词搜索”与“直达地址解析”。用户直接粘贴 Hugging Face 链接（`https://huggingface.co/{owner}/{repo}` / `hf-mirror.com`）、ModelScope 链接（`https://modelscope.cn/models/{owner}/{repo}`）或 `owner/repo` 标识时，系统自动识别对应下载源并解析出可直接下载的模型卡片，无需切换标签页或手动切源。
5. **1–2 步闭环（下载即用 / 切换即启）**：消除“当前查看 / 用于启动（Use for Start）/ 启动 / 设为默认”多态割裂。已下载模型提供一键 **「使用 / 切换并启动」**（自动停止前一个运行中的本地模型、拉起新模型并设为当前活跃模型）；下载中的任务在模型中心顶部持续可见，关闭发现弹窗不丢失进度，失败或取消后保留候选卡片并提供**一键重试**。

## 2. 信息架构与视觉层级

| 区域 | 放置位置与内容 | 为什么放这里 |
| :--- | :--- | :--- |
| **我的本地模型** | 位于页面最上方（有已安装模型时展开，空态自动收起让位给发现区）。显示人类可读名称、状态胶囊（`运行中` / `就绪` / `下载中 64%`）、占用体积与唯一主操作（`使用` 或 `停止`）。 | 高频动作是“切换并开始聊天”，不该被硬件参数表和搜索表单挤到屏幕下方；切换引擎过滤绝不隐藏其他引擎已安装的模型。 |
| **搜索与直达地址栏** | 发现区首行唯一焦点输入框，占位提示明确写出：`搜索模型，或粘贴 Hugging Face / ModelScope 链接…`。 | 用户脑中只有两个意图：“帮我推荐/找一个”或“我有现成链接”，统一入口免去双表单切换。 |
| **轻量环境与源信息条** | 搜索栏下方单行安静展示：左侧为人类可读本机算力摘要（如 `本机 16 GB · 推荐 4B–8B 模型`、`GPU 加速 (Vulkan)` / `Apple Silicon`）；右侧为两个紧凑胶囊：`下载源（ModelScope ▾）` 与桌面端 `引擎（MLX ▾）`。 | 既透明告知推荐依据并保留手动切换权，又不以厚重下拉表单打断浏览节奏。 |
| **模型推荐卡片** | 主行：清洗后的可读名称（如 `Qwen 2.5 7B Instruct`）+ 适配徽章（`最适合本机` / `轻量流畅` / `大参数`）+ 统一 `GB` 体积；次行：一句话擅长场景与预计内存占用；右侧：`下载` 主按钮；底部可展开 `技术详情 ▸`（原始 repo ID、GGUF/MLX 变体名、推荐上下文、协议与来源）。 | 日常用户 3 秒内即可凭“名称 + 适配等级 + 大小”做决定；进阶用户展开详情仍可核对全部工程事实。 |
| **持久化下载进度条** | 采用 `.monospacedDigit()` / `tabular-nums` 等宽数字展示 `百分比 · 已下载/总大小 · 实时速度 · 预计剩余时间` + 取消/重试。 | 避免数字每帧跳动；关闭弹窗后仍在模型中心顶部常驻可见，不让用户怀疑下载是否中断。 |

## 3. 性能与后端采集契约（支撑流畅 UI）

1. **三级缓存策略**：
   - 硬件探测结果短期磁盘缓存（约 5 分钟，macOS 原生侧可直接透传 `ProcessInfo`/Metal 信息），消除单次流程重复拉起 3 次 `system_profiler` 或冷启动 `powershell.exe` + WMI。
   - ModelFit 元数据（6 小时 TTL）与按 `(source, engine, hardware_bucket)` 键控的推荐结果（30 分钟 TTL）持久化至 `NOLA_HOME/cache/model_acquisition/`，支持缓存命中瞬开与显式刷新。
   - 确认下载复用预览阶段已缓存的 manifest 与 config，不再重跑整套 HTTP 瀑布流，并按核心身份（source、repo、engine、files/revision）校验，避免次要元数据波动导致下载被拒。
2. **内存自适应上下文早停 + 并发探测**：
   - 不再对 8–16GB 机器硬性要求 128K 上下文才允许早停；按设备可用内存分层设定早停目标（`<=8GB → 8K`，`<=16GB → 32K`，`<=32GB → 64K`，`>32GB → 128K`），同时仍优先保留更高原生上下文的候选。
   - 并发执行候选仓库 `preview()`（有界并发 4–6），单请求超时收紧（连接 5s / 读取 10s），总推荐耗时设置 6–8s 上限，超时即返回已收敛的最优结果而非无限挂起。
3. **零主线程磁盘解析**：
   - macOS 与 iOS 的本地模型完整性校验（读取 `tokenizer.json` 等大文件）必须在后台线程执行并缓存已下载集合，禁止在 SwiftUI `body` 渲染或进度回调中同步读取磁盘。

## 4. 跨平台一致适配

| 平台 | 入口位置 | 默认引擎 / 下载源 | 平台专项约束 |
| :--- | :--- | :--- | :--- |
| **macOS** | 对话输入框模型选择器底部「管理与下载模型…」+ 设置 → 模型服务 → 本地 | Apple Silicon 默认 `MLX`；UTC+8/`zh-Hans` 默认 `ModelScope` | 统一内置预设与 Hub 下载器的进度/删除体验；一键「切换并启动」；扩大弹窗候选列表可视高度 |
| **Web / Windows** | 对话输入框模型菜单底部「管理模型…」+ `/models` → 本地 | 默认 `llama.cpp`；浏览器/系统 UTC+8 或 `zh-CN` 默认 `ModelScope` | 模块级缓存跨路由保留；友好化显示 `GPU 加速 (Vulkan)` / `仅 CPU` 说明；失败保留候选一键重试 |
| **iOS** | 模型页 → 本地（`ModelDownloadView`） | MLX；UTC+8/`zh-Hans` 默认 `ModelScope` | 补齐顶部/行内可见的下载源切换；校准内存推荐档位（<=6GB 推 0.8B，8GB+ 推 4B）；移除重复进度条并启用等宽数字 |
| **Android** | 模型页 → 本地（`ModelsScreen`） | llama.cpp；UTC+8/`CN` 默认 `ModelScope` | 提供 ModelScope 镜像与源切换；按真机 RAM 动态展示推荐徽章；下载迁入应用级协程避免切页取消；点击「选择」自动启动已安装模型 |
