# 主会话、专家与任务导航

状态：当前产品与执行合同。主 Agent（Nola）是唯一与用户交流的入口，专家是由主 Agent 调度的叶子 Task。视觉规则见[对话规范](CONVERSATION_UI_DESIGN.md)、[检查器规范](CONVERSATION_INSPECTOR.md)与[原型视觉规范](../prototype/docs/DESIGN-SPEC.md)；执行边界见[专家与 subagent 执行](../../architecture/模块/10-Goal任务与子代理/EXPERT_SUBAGENT_EXECUTION.md)。原型合成数据与实际平台、真实模型验收分别记录。

## 1. 对象与所有权

| 对象 | 用户理解 | 持久化与执行边界 |
| --- | --- | --- |
| 主会话 | 与 Nola 围绕一个主题交流 | 一条主历史、一个输入区、一份有归属的草稿；普通 Main Run 接收用户消息与附件 |
| 主 Agent | 理解目标、安排工作并统一回复 | 使用主会话所选模型、参数和权限；决定是否调用专家或普通 subagent |
| 专家配置 | 可复用的专门职责 | 稳定 Agent ID、配置 revision、提示词模板、独立模型/档位、Skill 和权限 |
| 专家成员与上下文 | 这段主会话采用的专家配置快照 | participant ID、agent revision、独立 child conversation；历史挂在主会话下，只读 |
| Task | 主 Agent 派发的一项工作 | 使用现有 Task worker、租约、审批、终态与恢复；专家结果返回主 Agent |
| Room | Core 内部父会话与成员关联 | 沿用已发布格式和接口，不另设产品聊天入口，不凭 UI 改造删除协议或用户数据 |

所有引用都属于其 Host/store/epoch。裸 ID、当前页面或显示名不能替代来源验证。主会话保留自己的统一模型；专家数量不会隐藏或替换主模型。专家执行使用各自冻结的自有配置，不继承主 Agent 的模型、档位、凭据或已批准权限。

## 2. 导航与唯一发送入口

- “新对话”进入未发送的 Main 草稿。空白草稿选专家只保存 ID/revision，不为了 `@` 创建空会话、Room 或运行。首次实际提交由 Core 准入。
- 普通会话列表在分页前排除专家上下文与临时 Task child，避免顶层重复。专家历史在当前会话的上下文参与者区域按需分页，不挂在左侧会话列表；重新引入前的旧上下文仍可访问。
- 点击主会话恢复主历史、草稿与阅读位置。点击专家历史进入只读视图，不显示普通发送输入区。
- 当前专家上下文可明确“返回主会话并选择此专家”，之后仍由 Main 接收下一条输入。旧上下文保持只读，不能冒充最新配置或静默升级。
- 专家配置详情用于编辑、复制和归档，不自动开聊、不调用模型。配置草稿、未发送主会话草稿与已有会话草稿分别拥有身份。
- 侧栏展开、搜索与筛选只改变导航，不改变任务、权限或作者身份。加载失败保留同来源已知数据；晚返回不能覆盖另一个 Host/父会话的页面。

桌面保持主内容与检查器的清楚分区。手机以对话列表和主聊天为中心，专家历史使用可返回的只读页面或抽屉。所有 disclosure 与操作必须有足够点击区域、键盘与读屏语义；不为每行增加无意义箭头。

## 3. 专家配置与推理档位

名称、职责简介和完整工作指令分别呈现。名称用于辨认，职责帮助 Main 判断用途，提示词模板才承载完整角色指令；同名不按文本推断身份。

内置角色包括编写、审查、测试、秘书、画师、PPT 与论文。目录、模板 UUID、提示词、工具组合和 Skill 由 Core 提供。客户端可预览明细，不能维护另一套角色正文。替换已有模板需要明确操作，保留其他编辑内容；保存失败保留草稿与所观察 revision。

- 专家模型可明确选择，也可跟随应用默认模型；这不等于跟随某个父会话的临时模型选择。
- 推理档位来自实际模型声明，按真实档位展示，不再另设重叠三档。未知能力只提供继承，不制造 `none` 默认。Core 在实际目标模型解析后校验并冻结选择。
- 模板、模型与档位更新影响后续明确引入；已加入的上下文继续其旧快照。重新引入创建新上下文，保留旧历史、作者与不可变记录。
- 当前运行或尚未完成的提交阻止重新引入。失败保留选择与输入，并提供可操作说明，不能让“刷新”形成死循环。
- 工具组合和 Skill 是能力引用与工作指导，不是授权。缺少平台能力时说明实际执行 Host 与接入路径，不能把文字提纲当作已生成文件。

## 4. `@` 与普通 Main 提交

`@` 候选来自所属 Host 的 active 专家目录，包括尚未加入本会话的配置。选择保存稳定 ID/revision；已有成员可附精确 participant/context 成对引用。已加入的旧快照可以继续，不要求自动追到最新目录。

用户发送时依然只有一条原始用户消息、一个 submission 身份和一个普通 Main Run。客户端不能复制或改写原文、插入另一条 user、直接向专家 fanout，或按中文/英文关键词决定工具与目标。

本机将选择作为 `UserInput.turn_context_components` 的 `main_expert_selection` 类型组件提交；Host HTTP 使用可选 `selected_experts`，由可信准入层转换为同一组件。Core 在 Begin 的同一事务检查选择、按需关联成员，拒绝时不留下部分 user/Room join/Task。

远端选择冻结目录返回的 `expected_source_store_epoch`，不能用之后 prepare/frontier 的新 epoch 偷换。Host 更换、恢复或重建造成不匹配时明确拒绝并保留草稿。旧 Host 缺少 `main_agent_delegation` 能力时引导升级或重连；普通未选择专家的聊天保持兼容。

主模型必须支持工具调用，且冻结能力目录中专家调度可用。否则引导更换支持工具的主模型、启用专家工具或移除选择。选择专家是 Main 的有类型指导；Main 有能力时也不被强迫无意义地调用工具。

专家 chip 是可取消的会话选择，提交后仍保留；只消费该次原始正文与附件草稿。取消 chip 不等于移出成员，不删除专家上下文或改变已有任务。

无 `@` 时也是同一个 Main，由模型根据工具 schema 与真实任务决定是否使用专家。不存在轮换的成员协调者、跳过 Main 的点名直达或默认全部回答。

## 5. 主 Agent 调度与专家叶子

Main 使用 `delegate_expert` 的 directory/request/read/wait/cancel。Core 依据真实已开始的 Main effect、source Run/call 和同父关联验证分派；模型文本不能指定 actor、伪造 authority 或读写其他私有上下文。

专家与普通 subagent 共享 Task 执行底层。专家目标捕获自己的模型/effort、模板、Skill、工具与资源策略，并在冻结前移除调度控制。专家上下文和普通 Task child 都不能新调用专家调度；专家叶子也不再 spawn 临时 subagent 或直接调用 `request_user_input`。

专家只返回工作结果或缺失信息说明。需要向用户澄清、权限决定或最终汇总时由 Main 负责。主时间线不出现多个专家冒充用户交流；必要任务状态可展开，历史工具调用默认收起。审批仍绑定实际工具、资源和执行 Host，不能因是内部任务自动批准外部操作。

Task 的准备、ACK 丢失、观察、取消与冷启动恢复沿既有持久流程，但只有仍满足当前安全合同的捕获可以恢复执行。旧冻结专家配置若包含主 Agent 专属控制（包括 `request_user_input`），明确拒绝继续执行，保留原历史与可用取消操作；不静默改写捕获，也不假装恢复成功。历史 `expert_exchange` 与直接专家提交仅用于精确旧记录读取/恢复；新模型不广告旧工具，也不能用恢复别名重新开放专家互调。

## 6. 历史、作者与加载

- 专家 child 历史必须经父会话与 child 双向归属验证，不能仅凭 child ID 读取。读取不新建 Run，不续跑模型。
- 新任务请求作者为 Main；历史旧专家来源仍按冻结的显式作者记录显示，不能把专家输入标为“你”，不能用最新目录名覆盖旧作者。
- 当前/已退役状态来自 Core 关联，不凭标题、正文关键词或时间推断。
- child 列表与历史各自懒加载分页；旧游标不能进入新父会话/筛选；失败保留当前同查询快照并可重试。
- 远端来源通过现有认证、加密、Host ID、URL/token/pin 与 epoch 固定；返回 `source_owner=local` 只代表已验证 Host 自身所有权，不能绕过来源绑定。
- 正常远端 Main 继续 SourceSubmission 与 AssistantJournal 的真实准入和镜像；不本地伪造 user、Run、终态或空结果来替代未贯通接口。

## 7. 草稿、错误与编辑重发

发送准备不等于准入。收到持久准入事实后才消费原草稿；结果不明时保留原提交身份并观察原操作，不新发第二份。明确拒绝提供恢复指引，保留文本、附件与专家选择。

编辑重发在同一主会话回溯到编辑点并重新提交，删除编辑点后的主输出由 canonical 操作控制；不另开会话、不客户端伪造历史。专家子历史和已冻结来源不得作为普通可编辑主历史。

同一已有主会话的多窗口草稿以 revision/编辑身份防覆盖；不同会话及未发送草稿各自保存。导航离开不等于取消 Task，流式结束不等于已验证成功，过程区域不标记整段思考“成功/失败”。

## 8. 验收边界

必须分别验证主模型与专家目标配置、Main 原文/ID 不变、空白 `@` 首次准入、已有旧快照、显式重新引入、错误 epoch/旧 Host/无工具主模型拒绝、Task 真实 worker、叶子无递归工具、sealed 终态与冷恢复、专家历史分页/只读/作者、跨 Host 晚回调和草稿恢复。

原型覆盖桌面/手机、浅色/深色与可读交互，不证明模型、权限或持久执行。实际 Browser Use、Android 模拟器、Apple 测试、真实 provider 与未运行的 Windows 原生范围见[验收范围](../../quality/VALIDATION_SCOPE.md)。不能把旧专家互调测试、静态字符串审查或纯 DTO 测试计为当前 Main→专家全链路通过。
