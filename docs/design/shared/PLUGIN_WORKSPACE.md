# 插件在 Nola 工作区中的位置

「能力库 → 插件」是管理入口。工作区侧栏是使用入口。两处指向同一个已安装页面，共用标题、选中状态和所在设备。用户可以从刚安装好的那一行直接开始工作，次日从侧栏继续。

## 用户会看到什么

| 时刻 | 画面与操作 |
| --- | --- |
| 第一次打开能力库 | 「技能」「MCP」「插件」各占一个类别。插件集合为空时，显示空状态与一个「添加插件」主操作。桌面使用当前设备；手机先选择已经配对的 Host，尚未配对时直接提供连接操作。 |
| 添加插件 | 从添加面板选择 Pi 或 DeepSeek Harness，填写包名。DSH 在这里选择终端或 Web 配置；Mac 也可选择本地目录。安装前集中展示来源、目标设备以及执行第三方代码的影响。取消返回原处。 |
| 安装完成 | 原集合显示新的条目。带页面的包显示页面名，点击即打开；一个包声明多个页面时逐项列出，使用同一组来源信息。只有工具的包以包名显示。运行时与配置使用次要文字。 |
| 日常使用 | 桌面从能力库或侧栏进入同一主内容区。插件获得内容空间；导航、关闭页签和返回仍由 Nola 控制。手机使用具体 Host 的插件集合和页面，设备名称留在入口和安装确认处。 |
| 移除 | 从条目的次要管理操作移除，确认内容指明包和位置。成功后同步撤回该包的所有入口；正在使用的页面退出或显示失效状态。 |
| 某个运行时不可用 | 保留其他运行时的条目与页面。失败范围显示在所属配置处，提供重新读取；未成功读取的配置不能当作空清单。 |

## 视觉与交互

用一列可扫描的内容组织插件。名称和可点击的页面是第一层，包来源与运行位置是第二层。安装表单按需展开。没有安装任务时，把空间留给可用内容。页内按钮使用平台已有的主题、字阶和焦点样式。移动端沿用系统返回与宿主配对流程；桌面侧栏沿用工作区已有的选中态。

假设同时安装了「研究工作台」和一个终端状态插件，集合里可以直接看到工作台的「任务看板」「参考资料」两个页面，以及状态插件的包名。侧栏只增加工作台实际提供的两个入口。DSH 设置插槽与 Pi 自绘 TUI 仍在各自运行时使用。已部署的外部站点显示目的域名，让用户在离开 Nola 前就能辨认。
