# 权限、配置生效和恢复交互

日期：2026-10-16；2026-11-10 补充首次引导与系统申请。状态：交互规范及分阶段记录，实际实现与动态证据按各小节注明，不推定未复测条目已通过。
适用 macOS/iOS 原生、Android Compose、Web Svelte 与 CLI；共享行为，不照搬桌面布局到手机。
对应[架构边界](../../architecture/总体设计/执行权限与证据边界_20261016.md)与历史实施记录（本地工作记录，不随仓库分发）；最新状态见当前任务（本地工作记录，不随仓库分发）。

## 设计目的与原则

让人知道当前会话正在做什么、哪些操作需要确认、修改是否已经生效，以及失败后能安全做什么。
安静正文、局部明确状态；不增加一排技术开关，不把原始日志当普通错误提示。
Apple Design 参考：`settings.md › Best practices` 的 “Minimize the number of settings you offer”；
`feedback.md › Best practices` 的 “Consider integrating status feedback into your interface”；
`privacy.md › Requesting permission` 的按需请求和具体用途说明。
两档权限及即时生效策略是本产品决定，不声称由 HIG 规定；全部允许不是绕过 OS 权限。
Android/Web 采用上述可理解性和可访问性原则，不套用 Apple 独有导航。

## 1. 权限入口仅两个选项

- **谨慎**：普通读取、检索和新建直接执行；删除、覆盖、敏感数据访问、向外发送内容和新连接先确认。
- **全部允许**：此会话内所有 Nola 操作无需确认；系统权限和资源错误仍可能阻止执行。

默认谨慎。删除“安全/推荐/自动”等第三档和旧值别名，不把权限与简单/中等/复杂推理档位混在一起。
入口位于当前会话输入框下方，设置页默认值只影响新会话；切换会话读取它自己的配置及生效状态。
CLI `/allow` 与图形界面提交同一类型化配置，数字键即选择并提交，不需要再按 Enter。

## 2. 配置编辑、提交与活动执行

控件内部区分用户编辑值、已提交值和活动 Run 生效值；不把临时选择当授权依据。
点击后显示局部“切换中”；收到配置提交回执才标为已保存，收到原 Run 的政策 ACK 才标为当前生效。
失败保持原生效值，保留编辑以便重试；冲突显示具体操作，不偷偷改版本重放。
模型与生成参数在有活动 Run 时提示“下次发送生效”；权限模式按活动命令生效，不要求用户取消重发。
切到全部允许时，当前尚未派发的授权等待由 Core 重评估并继续同一工具，不再单独弹一次批准。
已拒绝、取消及执行结果未知的操作不复活；已经物理准入的操作不能在 UI 上假装撤回。Core 已生成或 Host 已领取、但尚未越过物理执行边界的旧政策投递，只有在 Application 正式撤销并完成 fencing 后才能显示为已撤销，不能由界面自行推断。
仅更新原 owner 控件及待授权卡，切换会话后迟到回执不能改变当前输入框。

活动权限的 owner 由正式未终态 Run 和已准入 source submission 确定，不由输入框转圈、`isRunning` 或 `blocksInput` 推导。Mac、iOS、Android 冷启动观察、断流待恢复时，只要原源端 Run 仍活动，权限切换仍对该源 Host 提交精确 CAS 并等待原 Run ACK；不退化为仅保存本地镜像。源身份缺失、观察失败或 owner 冲突时保留草稿及待提交选择，明确待核/失败；只有正式终态或已确认没有活动 Run 才走非活动配置保存。Web 同样以活动 Run 身份而非 busy 判断生效。切换会话后的迟到结果仅归原 owner，不启动新 Run，也不恢复旧工具。

展示状态只读取按会话/Run 绑定的类型化 owner 投影缓存，不在 SwiftUI getter 或每个 token 刷新中同步查询 Store/Application。选择会话、canonical 活动 Run 身份变化及正式终态触发所属会话的异步刷新；读取前后核对 owner，并用请求代次丢弃迟到结果。未知缓存显示待核，不当作已保存；保存/显式刷新边界仍重新核验正式身份，展示缓存不授予写权限。

## 3. 谨慎确认卡

卡片说明具体动作、对象/接收方、影响和授权范围；不是只显示 bash、MCP 或“运行命令”。
主要操作为“允许一次”；只有 Core 提供可复用范围时才显示“允许此范围（本会话）”，范围可读。
拒绝和返回编辑明确区分。相同 request ID 只有一个入口；重复点击有提交中状态，不能重复执行。
CLI 普通目录不因位于工作区外显示目录确认卡；只有真实 OS 授权要求才打开系统界面。敏感读取沿用具体操作确认卡，显示读取对象、范围和敏感原因；模型提出的原因不是用户批准，也不展示敏感正文来证明其敏感性。批准后不再因同一路径超出工作区追加目录确认；OS 拒绝或资源变化仍单独说明。
全部允许时不创建 Nola 确认卡；OS 拒绝显示“系统权限未授予”，不误称“请再次授权本会话”。

### 3.1 新连接与网络数据外发的确认对象

范围澄清（2026-10-17）：用户所说的外发是上传文件或数据、POST 等方式发送消息，不是下载、普通网页读取或搜索，也不是新增聊天渠道回复授权系统。普通下载/读取/搜索不因联网新增确认；按可信操作契约区分读取与发送，不能仅按 HTTP 方法或用户措辞分类。以下为待落地规范，不是视觉验收结果。沿用现有会话内确认卡，不另建权限模式。

- MCP HTTP 连接显示服务名、目标主机及端口、所属会话；本地 stdio 显示“启动本地服务”、实际程序和工作目录。密钥、认证头及含秘密的参数不出现在卡片、复制内容或辅助功能描述中。配置保存只显示“已保存，尚未连接”，不得先握手再补确认。
- 已批准连接失效后显示“连接已断开”；谨慎模式重新连接产生新的具体请求，不用“重试”按钮暗中复用失效批准。连接成功不展示成“该服务所有操作已允许”，工具的具体风险仍有自己的确认。
- 上传或发送消息时显示可核实的目标主机、端口、操作和数据来源摘要；涉及上传时说明文件及数据范围，秘密不直接显示。不将普通下载的请求参数或搜索词一概当作需要确认的上传。
- “允许一次”只批准卡片绑定的操作；只有 Core 确实提供范围授权时才显示相应选择。目标、内容或数据来源变化不能沿用旧的一次批准。对于无法可靠枚举网络效果的命令，应明确说明未知效果，不用命令关键字猜测安全性；相同命令文本不代表引用文件或环境变量的内容没有变化。
- 目标和范围在默认视图可见，不能全部藏到诊断详情。窄窗口按标签/值纵向排列，长接收方可换行；保持键盘焦点与读屏顺序，不靠颜色表达等待、失败或生效。切会话不搬移原会话的卡片。
- 网络操作结果不明确时展示“执行结果待核实”，不能把连接中断等同于未发送，也不能自动重放可能产生副作用的请求。全部允许不产生 Nola 确认卡，但仍如实展示系统权限、连接及服务端错误。

依据：apple-design 中 `privacy.md › Best practices` 的 “Give people precise control over their data”、`feedback.md › Best practices` 的上下文内反馈、`settings.md › Best practices` 的减少设置；具体的连接/外发授权边界是 Nola 的产品决定。该节不改现有配色和字号，采用既有语义文本与原生控件；对比度、窄屏和读屏效果仍须实际渲染验证。

## 4. 浏览器、来源与工具结果

浏览器卡显示真实执行目标及页面标题；不能把 managed 显示成系统 Chrome。
已打开页面但截图失败显示“页面已打开，暂未取得页面内容”，重试观察不再次打开页面。
原 owner 页面不可用时提示重新选择明确页面，不偷偷控制当前前台页。
工具过程按真实顺序追加，最终正文独立；稳定标题、详情按钮、复制栏不随每个 token 重建/动画。
终端自己的历史视口按有界视觉行分帧追加，不能一次消费整个 provider delta 后只画末屏。首段至少进入一个完整提交帧，后续帧逐步追上输出；用户阅读历史时保留锚点，不因新输出强拉到底。完成可先入账，不将尚待显示的内容伪称仍在请求模型，也不丢弃它。真实屏幕测试核唯一输入框/footer和实际历史翻页，不用剥除 ANSI 后拼出的文字冒充可见内容。
图片/PDF/来源使用实际证据引用；预览控制令牌只由 Host/UI 获取，不在消息可复制正文和发送模型内容中出现。
检索答复应包含可打开来源，超长链接可紧凑显示，不把 URL 原文重复当整个链接标签。

用户明确选择的浏览器目标与实际目标同时可核对；切到另一后端不悄悄当成同一次成功。managed 的 ref 失效显示“页面已变化，请重新观察”，不要求用户理解原始 selector/协议报错。
浏览器预览是一个持续页面：会话/endpoint generation 改变才切换预览文档，截图帧和 updatedAt 变化不调用整页 load。预览暂停、重连和动作失败在原位置反馈，不能清空画面后反复呈现加载态。此为产品交互约束，实际闪烁和帧率须动态验收。
执行不阻断只读历史：加载更早消息、查看压缩原文、返回最新与运行 busy 解耦。历史页固定自己的快照，实时执行继续更新原 Run；返回最新需用户明确选择，不能因新 token 到达强拉阅读位置。
Skill 的“模型判断通过”与“检查已执行通过”使用不同的事实描述；证据不可打开或不可解析时不展示成已验证。不给用户再增加技术开关，详情只解释证据来源及缺项。

## 5. 自动化与恢复

状态明确区分“等待执行／准备中／执行中／等待确认／结果待核实／已完成／失败／已取消”。
启动前失败显示可读原因和安全重试条件；活动记录和数据库终态一致，不永久停在运行中。
结果未知的“检查状态”只对账原 invocation，不创建新 Run；真正安全重试另有操作，说明是否会重新执行。
恢复操作属于该会话或自动化 occurrence，不阻断其他会话输入，不借用全局 busy。

后台通知是带确切 occurrence 的观察快照。原权限已被批准/拒绝、问题已被回答时，丢弃该过时待处理提示；若状态在实际展示与 ACK 之间变化，消费正式 `Superseded` 结果继续交互，不退出会话、不写假展示回执、不重放授权面板。未知来源和跨会话回执仍报错，不能把所有 ACK 错误都当成过时吞掉。

自动化任务卡按定义展示最近 occurrence，通知去重身份不参与“属于哪个任务”的判断。无执行记录与记录读取失败分开显示；准备、等待确认、启动失败和正式终态都能回到对应 occurrence。
已恢复的历史错误留在过程详情，主状态和默认展开依据当前未解决阻塞。保留正式失败来源，不把一次后续成功推导成其他错误全部解决，也不让初次编译失败在修正成功后永久充当当前告警。

## 6. 累计计量、动效和可访问性

会话缓存率随会话持久化：显示 Provider 已报告且去重后的累计加权比例；覆盖未知显示“暂无数据/部分请求未报告”，不显示伪造 0%。
诊断可展开查看实际前缀变化原因；不把完整目录未变写成请求前缀稳定。
等待确认时间不计入模型处理耗时。原始错误放诊断详情，普通层给可操作说明。
沿用系统语义色及现有 4/8/12/16/24pt 间距，正文不透明，稳定子树不重播动效；Reduce Motion 关闭非必要动画。
状态用文字/图标而非只靠颜色；桌面操作区至少 28pt，iOS 44pt、Android 48dp，Web 键盘焦点可见，长范围说明可换行。
关键失败与确认除输入区外也在所属任务提供入口，避免窗口底部被遮挡后不可操作。

当前预算占用可标“预计下次请求”，实测项标明对应请求；累计缓存率保持独立，不随占用估算切换清空。缓存诊断需要 canonical 持久来源，不能只有实时事件能看到、切会话或重启就消失。不要把相邻两次请求的合法占用变化绘制为整块卡片的反复加载动画。

补充审查依据：`scroll-views.md › Best practices` 要求自动滚动仅在帮助保留上下文的必要范围内；`motion.md › Providing feedback` 建议避免频繁交互中的多余动效；`generative-ai.md › Outputs` 要求更正生效有明确反馈、错误给出清楚下一步。上述具体状态、身份及缓存分拆是产品判断，不冒称 HIG 规定了 Nola 的执行协议。

## 自审与验收要求

运行中按 Enter 提交后续消息，持久会话仅在正式输入回执确认后清草稿并显示“已排队”；进程保留会话在本地所属邮箱接收后清草稿，不冒称可跨重启恢复。交付失败保留原文及原输入身份，恢复不能重复产生用户消息，也不能因权限面板切换把草稿发到别的会话。

自审先检查状态/回执和所有权，再检查布局；未测截图/对比度/帧率不填写虚构数值。
代码全部改完后统一执行跨端模式列表、切会话迟到回执、流式局部更新、批准/拒绝/取消、全部允许零弹框、恢复幂等测试。
Mac 使用 Test configuration；真实 UI 回放检查详情不闪、跟随到底部完成不空白、阅读历史不被拉回。
原系统签名 Debug 应用不被无签名测试替换；系统 NSXPC 警告需查真实来源，禁止屏蔽日志充当解决。

按 apple-design 对既有第二轮 8 张真实 NSHosting 组件截图进行人工视觉复核，范围仅为 `<evidence-dir>/nola-mac-unified-validation.BYgEjy/process-ui-second/`，不是最新整窗或真实模型验收。该执行过程组件的工作是让用户顺序核对推理与工具，并让最终结果保持主阅读层；此范围内评价为 Good，不外推整个 Mac 应用已完成。

已观察到：760pt/380pt 下执行过程与最终正文可分辨，思考和工具交错顺序保留；完成默认收起，用户主动展开后可重开查看；窄窗深色及较高对比场景无可见正文裁切；正式恢复后历史失败未继续占据主状态。依据 `layout.md › Visual hierarchy`，使用层级及分组而非一块无差别文本；依据 `feedback.md › Best practices`，状态就近呈现，而非将常规进度改成弹窗。保留安静、可核对的过程树，不为了“优雅”给稳定详情重复加动画（`motion.md › Providing feedback`）。

这些静帧不能证明无闪烁、帧率、键盘焦点或 VoiceOver 连续性；没有从截图猜测对比度比值。窄窗德语标题的三行断词有优化空间，但属于后续低优先级排版，不因此打断权限/所有权主线，也不将测试中刻意混合语言的 fixture 正文判断为产品自动翻译失败。最新 Test App 仍须完成批准/拒绝、流式局部更新、完成落点和切换会话的实际运行回放。


### CLI 会话授权选项（2026-10-20）

编号 2 为“本会话允许”，由 Core 的具体授权范围决定资格，不能把 Shell 工具整体设为不可复用。面板显示实际命令与工作目录；用户选择只授权所展示的当前范围，不推导命令族或整个工具权限。后续调用重新解析资源并检查风险与撤权。

选项编号保持稳定：1 本次、2 本会话、3 返回输入、N 拒绝。确实不具备会话资格的挑战保留编号 2 并显示不可用原因，方向键跳过该项，提示只包含有效快捷键；显示、数字输入、方向键和实际 Core 回执须一致。

## 首次引导与系统授权（2026-11-10）

首次引导只说明真实操作入口，不承担模型准入或系统授权。iOS、macOS、Android 的运行方式和来源卡片为说明内容；移除只保存偏好、却未接入执行器的单选/多选。已有偏好键保留原值，不迁移、不删除。用户可以跳过引导；完成后在“设置 → 模型”添加连接、启用并选择模型，或下载兼容本地模型。CLI 的未配置指引使用 `nola model manage` 展示配置地址和 Host 启动命令；`nola init` 生成项目说明，不用于配置模型。

系统权限、来源上下文访问策略、具体工具调用授权分开呈现。系统授权允许读取，不代表所有资料自动发送给模型；远程模型会接收获准加入上下文的内容。不得展示“数据永远不会离开设备”等与所选远程模型矛盾的承诺。

Mac 数据来源页的授权按钮显示请求中状态，同类请求不能重复进入。系统请求抛错保留错误原因和重试/系统设置指引，不仅刷新成未授权。拒绝和受限状态提供设置恢复说明，分别定位通讯录、日历、提醒事项或通知设置；返回应用时重新读取实际状态，不因打开设置就显示授权成功。组织限制不能承诺可由用户在应用中解除。HealthKit 只读授权状态仍以实际读取结果为准，不把授权面板结束等同于全部指标可读。
